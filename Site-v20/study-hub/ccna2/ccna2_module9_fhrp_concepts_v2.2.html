9.1First Hop Redundancy Protocols▾

9.1.1 Default Gateway Limitations

Every host on a LAN is configured with a single default gateway IP address. This is the router the host sends all external traffic to. This single gateway creates a single point of failure — if that router or its interface goes down, every host using that gateway loses access to all external networks.

  Normal operation:
  PC1 ──────── [R1 = default gateway 10.0.0.1] ──── Internet
  PC2 ──────── [R1]
  
  R1 fails:
  PC1 ──── × ──── [R1 DOWN — 10.0.0.1 unreachable]
  PC2 ──── × ──── [R1 DOWN]
  
  [R2 = 10.0.0.2 exists and is up, but hosts still point to 10.0.0.1]
  → PC1 and PC2 are isolated from all external networks
  → Even though R2 is fully operational, hosts have no way to use it

The fundamental problem: IPv4 hosts are configured with a static default gateway address. When that address becomes unreachable, there is no automatic mechanism to switch to an alternate gateway. The host keeps sending traffic to the dead router indefinitely.

💡
IPv6 Note: IPv6 devices receive their default gateway from ICMPv6 RA messages and can receive a new RA from a backup router relatively quickly. However, IPv6 devices still benefit from FHRP for faster, more reliable failover — especially in enterprise environments.

9.1.2 Router Redundancy — The Virtual Router

The solution is to configure multiple physical routers to collectively present the illusion of a single virtual router to hosts. The virtual router has its own dedicated IP address and MAC address that never change from the hosts' perspective — regardless of which physical router is currently active.

🔄 How the Virtual Router Works
Virtual IP:10.0.0.1 — configured as the default gateway on ALL hosts. This IP never changes.
Virtual MAC:0000.0c07.ac01 — auto-generated by FHRP. Hosts ARP for the virtual IP and receive this MAC.
R1 (active):Physical IP 10.0.0.2 — currently processes all frames sent to the virtual MAC
R2 (standby):Physical IP 10.0.0.3 — monitors R1 and ready to take over instantly
Hosts see:Only 10.0.0.1 / 0000.0c07.ac01 — they have no awareness of R1 or R2 as separate devices

When frames are sent from hosts to the default gateway, they ARP for the virtual IP address and receive the virtual MAC in response. Frames sent to the virtual MAC are physically processed by whichever router is currently the active router. The physical router handling the traffic is completely transparent to hosts.

✅
The key insight: Hosts are configured once with the virtual IP as their gateway. They never need reconfiguration regardless of which physical router fails or recovers. The virtual IP and virtual MAC are stable identifiers that move between physical routers as needed.

9.1.3 Steps for Router Failover

When the active router fails, the FHRP transitions the standby router to the active role automatically and transparently. The entire process takes about 10 seconds with default HSRP timers.

  1. Standby router stops receiving Hello messages from the active router. Active and standby routers continuously exchange Hello messages. When the standby's hold timer expires (10 seconds by default) without a Hello, it concludes the active router has failed.
  2. Standby router assumes the role of the active (forwarding) router. The standby transitions to active state and begins forwarding all traffic for the FHRP group.
  3. New active router assumes the virtual IP and virtual MAC address. Because the new active router responds to the same virtual IP and MAC, hosts see no disruption. Their ARP caches already have the correct mapping — no ARP refresh, no host reconfiguration needed.
✅
The failover is completely transparent to end devices. From a host's perspective, the default gateway never changed — the same IP and MAC still respond, just on a different physical device. No error messages, no connection drops (beyond a brief pause during the hold timer).

9.1.4 FHRP Options

The FHRP used depends on equipment type, vendor requirements, and whether load balancing is needed:

HSRP — Hot Standby Router Protocol
Cisco Proprietary

IPv4 only. Active/standby model — one router forwards, others are idle. Most commonly tested on the CCNA exam. Cisco's primary FHRP for enterprise networks.

HSRP for IPv6
Cisco Proprietary

Same HSRP logic applied to IPv6 environments. Uses a virtual IPv6 link-local address derived from the HSRP virtual MAC address.

VRRPv2 — Virtual Router Redundancy Protocol v2
IEEE Open Standard

IPv4 only. Master/backup model — functionally similar to HSRP but works across multiple vendors. Use when network includes non-Cisco equipment.

VRRPv3 — Virtual Router Redundancy Protocol v3
IEEE Open Standard

Supports both IPv4 and IPv6 in a single protocol. More scalable than VRRPv2. The modern open-standard choice for multivendor environments needing IPv6 support.

GLBP — Gateway Load Balancing Protocol
Cisco Proprietary

IPv4. The only FHRP that provides true load balancing — multiple routers all actively forward traffic simultaneously using different virtual MAC addresses. Each router in the group serves as the active forwarder for a subset of hosts.

GLBP for IPv6
Cisco Proprietary

Same GLBP load-balancing functionality applied to IPv6 environments.

IRDP — ICMP Router Discovery Protocol
RFC 1256 — Legacy

An older IPv4 FHRP solution. Rarely used in modern networks. Know the name for the exam but it is not a focus area.

🎯 EXAM TIP — FHRP Key Distinctions
  • HSRP = Cisco proprietary, IPv4, active/standby (one active at a time)
  • VRRP = Open standard (IEEE), works with any vendor. VRRPv2 = IPv4. VRRPv3 = IPv4 + IPv6
  • GLBP = Cisco proprietary, IPv4, the ONLY FHRP with load balancing
  • HSRP and VRRP waste standby routers — they sit idle. GLBP uses ALL routers to forward traffic

9.2HSRP▾

9.2.1 HSRP Overview

HSRP (Hot Standby Router Protocol) is Cisco's proprietary FHRP for IPv4. It creates a virtual router group where one physical router is active (forwarding all traffic) and one is standby (monitoring the active and ready to take over instantly).

HSRP CharacteristicDetail
StandardCisco proprietary — only between Cisco devices
IPv4 or IPv6IPv4 (separate protocol for IPv6)
Active routersOne active router per HSRP group — others are standby or listen
Virtual IP addressConfigured by the administrator — this is what hosts use as their default gateway
Virtual MAC addressAuto-generated: 0000.0c07.acXX where XX = group number in hex
Hello timer3 seconds (default)
Hold timer10 seconds (default) — standby waits this long before taking over
Default priority100 — higher value wins the active role
HSRP virtual MAC address format 
Virtual MAC format: 0000.0c07.acXX  (XX = HSRP group number in hex)

Group  0: 0000.0c07.ac00
Group  1: 0000.0c07.ac01   ← most common in labs
Group 10: 0000.0c07.ac0a
Group 16: 0000.0c07.ac10

! Hosts ARP for the virtual IP address (e.g., 10.0.0.1)
! and receive this virtual MAC in response
! When failover occurs, the new active router answers to this same MAC
! Hosts never need to update their ARP cache

9.2.2 HSRP Priority and Preemption

HSRP Priority

HSRP uses a priority value to determine which router becomes active. The router with the highest priority wins the active role.

  • Default priority: 100
  • Range: 0 to 255
  • If priorities are equal: the router with the highest IPv4 address wins
  • Configure with: standby [group] priority [value]
🔍 PRIORITY EXAMPLE
R1: HSRP priority = 150 → becomes ACTIVE (highest priority)
R2: HSRP priority = 100 (default) → becomes STANDBY

If priorities were both 100:
R1: IP = 10.0.0.2, R2: IP = 10.0.0.3
R2 wins (higher IPv4 address) → R2 becomes ACTIVE

HSRP Preemption

By default, once a router becomes active, it stays active even if a higher-priority router comes online later. This is called non-preemptive behavior.

❌ WITHOUT Preemption (default behavior)

R1 (priority 150) is active. R1 fails. R2 (priority 100) takes over as active.

R1 recovers and comes back online.
R1 just becomes standby — R2 remains active even though R1 has higher priority.

The higher-priority router does NOT automatically reclaim the active role.

✅ WITH Preemption enabled on R1

R1 (priority 150, preempt enabled) is active. R1 fails. R2 (priority 100) takes over as active.

R1 recovers and comes back online.
R1 detects it has higher priority → forces a new election → reclaims active role.
R2 returns to standby.

Configure: standby 1 preempt on R1.

⚠️
Preemption works only for priority — not for IP address tiebreakers. If two routers have equal priority and the higher-IP router is active, preemption will NOT trigger a re-election based on IP address alone. Preemption only forces re-election when a router with a strictly higher priority value comes online.

9.2.3 HSRP States and Timers

When an interface is configured with HSRP or first activated, the router transitions through a series of states before reaching its final role. Only one router per group is Active and only one is Standby — all others are in Listen state.

Initial
HSRP is not yet running — entered when the interface first becomes available or when the configuration changes
Learn
Router has not yet determined the virtual IP address and has not seen a Hello from the active router — waits passively for information
Listen
Router knows the virtual IP but is neither active nor standby — listens for Hello messages from the active and standby routers. Most routers in a group stay here.
Speak
Router sends periodic Hello messages and actively participates in the election of the active and standby router
Standby
Router is the next-in-line to become active — sends periodic Hellos and monitors the active router. Only one router per group reaches this state.
Active
Router is currently forwarding traffic for the HSRP group. Sends Hello messages every 3 seconds. Only one router per group is in this state.

HSRP Timers

TimerDefaultPurpose
Hello timer3 secondsHow often the active and standby routers send Hello messages to the HSRP group multicast address
Hold timer (Dead timer)10 secondsHow long the standby waits without receiving a Hello before declaring the active router failed and taking over
HSRP failover timeline with default timers 
Active router fails at T=0
Standby router waits 10 seconds (hold timer) without receiving a Hello
At T=10 seconds: standby declares active dead → transitions to Active state
Total failover time ≈ 10 seconds (default timers)

! Reducing timers speeds failover but increases CPU usage:
! Minimum Hello timer: 1 second
! Minimum Hold timer: 4 seconds
! Rule: Hold timer must be at least 3× the Hello timer
!
! Example — aggressive timers (faster failover):
R1(config-if)# standby 1 timers 1 3
! (1 second Hello, 3 second Hold)
! Failover time ≈ 3 seconds instead of 10 seconds
💡
Timer tuning rule: The hold timer should always be at least 3× the Hello timer. Setting Hello=1, Hold=3 gives fast failover (~3 seconds) with acceptable CPU impact. Do not set Hello below 1 second or Hold below 4 seconds — this causes excessive CPU usage and unnecessary state changes.

9.2.4 HSRP Configuration — Optional (Not Tested on CCNA Exam)

⚠️
HSRP configuration is explicitly labeled optional in the NetAcad curriculum (section 9.3.3). You are NOT required to configure HSRP for the CCNA exam. This section is included so you can follow along with the Packet Tracer activity and understand what the commands do.
R1 — Active HSRP router configuration 
R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# standby version 2               ! Use HSRPv2 (recommended)
R1(config-if)# standby 1 ip 10.0.0.1          ! Group 1, virtual IP = 10.0.0.1
R1(config-if)# standby 1 priority 150          ! Higher priority → becomes active
R1(config-if)# standby 1 preempt              ! Reclaim active role if recovered
R1(config-if)# end
R2 — Standby HSRP router configuration 
R2(config)# interface GigabitEthernet0/0/0
R2(config-if)# standby version 2
R2(config-if)# standby 1 ip 10.0.0.1          ! Same group, same virtual IP
R2(config-if)# standby 1 priority 100          ! Lower priority → becomes standby
R2(config-if)# end                             ! (or just leave default of 100)

🎯Common Exam Traps — Module 9▾
❌
Trap 1: HSRP is Cisco proprietary — VRRP is the open standard.
When the exam asks for a multivendor-compatible FHRP, the answer is VRRP. VRRPv2 = IPv4 only. VRRPv3 = both IPv4 and IPv6. HSRP and GLBP are Cisco proprietary and cannot be used with non-Cisco equipment.
❌
Trap 2: Higher HSRP priority = active router.
Students sometimes assume "higher priority = standby" based on other protocols. In HSRP, higher priority wins the active role. Default is 100. To make a router active, set its priority above 100 (e.g., 150).
❌
Trap 3: Without preemption, a recovered router does NOT automatically reclaim the active role.
If R1 (priority 150) fails, R2 takes over. When R1 recovers, it just becomes standby — R2 stays active. Only with standby preempt on R1 will it force a re-election and reclaim the active role.
❌
Trap 4: Preemption works only for priority — not for IP address tiebreakers.
If two routers have equal priority and the higher-IP router is currently active, preemption will NOT trigger a re-election based on IP address alone. Preemption only forces re-election when a router with a strictly higher priority value comes online.
❌
Trap 5: GLBP is the ONLY FHRP that provides load balancing.
HSRP and VRRP only allow one active router at a time — all standby routers sit completely idle. GLBP assigns different virtual MAC addresses to each router so different hosts use different physical routers, distributing load across all routers in the group simultaneously.
❌
Trap 6: Hosts configure the HSRP virtual IP as their default gateway — NOT the physical router's IP.
If hosts pointed to R1's physical IP (e.g., 10.0.0.2), they'd lose connectivity when R1 fails. The virtual IP (e.g., 10.0.0.1) always works because it moves with the active role. This is the entire point of FHRP.
⚠️
Trap 7: Default Hello = 3 seconds. Default Hold = 10 seconds.
If standby doesn't receive a Hello for 10 seconds, it assumes the active has failed and takes over. Total failover time ≈ 10 seconds with defaults. Reducing timers speeds failover but increases CPU load. Hold timer must be at least 3× the Hello timer.
⚠️
Trap 8: HSRP virtual MAC = 0000.0c07.acXX where XX is the group number in hex.
Group 1 = 0000.0c07.ac01. Group 10 = 0000.0c07.ac0a. This MAC is what hosts receive when they ARP for the virtual IP. The virtual MAC stays the same during failover — the new active router simply starts responding to that MAC.
⚠️
Trap 9: The failover is transparent to end devices — no ARP refresh needed.
Hosts never see the failover. The virtual IP and virtual MAC remain the same — only which physical router responds to that MAC changes. Existing host ARP caches remain valid throughout the failover.
⚠️
Trap 10: Only one router is Active and only one is Standby per HSRP group.
All other routers in the group are in Listen state. Listen state routers monitor the group but do not participate in forwarding unless both Active and Standby fail. There is never more than one active router per HSRP group.
⚠️
Trap 11: VRRPv3 supports both IPv4 and IPv6 — VRRPv2 supports only IPv4.
If the exam asks which open-standard FHRP supports IPv6, the answer is VRRPv3. VRRPv2 is IPv4 only. Don't confuse version numbers with IPv6 support.
✅
