4.1Inter-VLAN Routing Operation▾

4.1.1 What is Inter-VLAN Routing?

VLANs create isolated broadcast domains — great for security, but it means hosts in different VLANs cannot communicate without a Layer 3 device. Inter-VLAN routing is the process of forwarding traffic from one VLAN to another using a router or Layer 3 switch.

❌ Legacy Inter-VLAN Routing
  • One physical router interface per VLAN
  • Runs out of router ports quickly
  • Historical context only — never used today
⚠️ Router-on-a-Stick (RoaS)
  • One physical interface with subinterfaces (one per VLAN)
  • Good for small to medium networks (<50 VLANs)
  • Shared link creates a bandwidth bottleneck
✅ Layer 3 Switch with SVIs
  • Uses Switched Virtual Interfaces (SVIs)
  • Hardware routing at wire speed
  • Scales to hundreds of VLANs — enterprise preferred

4.1.2 Legacy Inter-VLAN Routing

The original method used one dedicated physical router interface per VLAN. Each interface connected to a switch port in that VLAN and served as the default gateway.

  PC1 (VLAN 10: 192.168.10.10) --Fa0/11--[S1]--Fa0/1--  R1 G0/0/0 = 192.168.10.1
  PC2 (VLAN 20: 192.168.20.10) --Fa0/24--[S1]--Fa0/12-- R1 G0/0/1 = 192.168.20.1
  
  PC1 sends to gateway 192.168.10.1 -> R1 routes -> out G0/0/1 -> VLAN 20 -> PC2
🚫
Why it was abandoned: Each VLAN needs its own physical router port. A 4-port router only supports 4 VLANs. Covered for historical context only — never used in modern networks.

4.1.3 Router-on-a-Stick Inter-VLAN Routing

Solves the scalability problem by using one physical router interface divided into subinterfaces — one per VLAN. The physical interface connects to a trunk port on the switch, carrying all VLAN traffic on a single cable.

         [R1]
          |
          | G0/0/0  (ONE physical port -- NO IP address here)
          |   +-- G0/0/0.10  encapsulation dot1Q 10  ip 192.168.10.1/24
          |   +-- G0/0/0.20  encapsulation dot1Q 20  ip 192.168.20.1/24
          |   +-- G0/0/0.30  encapsulation dot1Q 30  ip 192.168.30.1/24
          |
    trunk link (802.1Q tagged)
          |
         [S1]--trunk--[S2]
          |                |
     PC1 VLAN 10      PC2 VLAN 20
⚠️Does not scale beyond ~50 VLANs. Creates a bandwidth bottleneck because all inter-VLAN traffic shares one physical uplink.
🎯 EXAM TIP
The physical interface (G0/0/0) gets no IP address — only no shutdown. Only subinterfaces (G0/0/0.10, G0/0/0.20) get IP addresses. A broken config with an IP on the physical interface is a classic exam question.

4.1.4 Inter-VLAN Routing on a Layer 3 Switch

The modern preferred method. A Layer 3 switch operates at both Layer 2 and Layer 3. It uses Switched Virtual Interfaces (SVIs) — created with interface vlan [id] — to route between VLANs entirely inside the switch hardware.

FeatureRouter-on-a-StickLayer 3 Switch (SVI)
Routing speedLimited by one physical linkWire speed — hardware routing
External router needed?YesNo (for local VLANs)
Max VLANs~50Hundreds
CostSwitch + separate routerOne multilayer switch
Best forSmall/medium networksMedium to large enterprise
4.2Router-on-a-Stick Configuration▾

4.2.1 Router-on-a-Stick Scenario

Standard NetAcad lab topology: two switches (S1, S2), one router (R1), two PCs in different VLANs:

  PC1 (192.168.10.10/24, VLAN 10) --Fa0/6--[S1]--Gi0/1--[R1]
  PC2 (192.168.20.10/24, VLAN 20) --Fa0/18--[S2]--Fa0/1--[S1]
  
  R1 Subinterfaces:
    G0/0/0.10  192.168.10.1/24  (default gateway VLAN 10)
    G0/0/0.20  192.168.20.1/24  (default gateway VLAN 20)
  
  Path: PC1 -> S1 -> trunk -> R1(.10) -> R1(.20) -> trunk -> S2 -> PC2
📋All inter-VLAN traffic must travel up to R1 and back down through the trunk — even if both PCs were on the same switch. This shared link is the bandwidth bottleneck of router-on-a-stick.

4.2.2 S1 VLAN and Trunking Configuration

S1 — VLANs, Access Port, Trunk to S2 and R1 
S1# configure terminal

! Create VLANs
S1(config)# vlan 10
S1(config-vlan)# name LAN10
S1(config-vlan)# exit
S1(config)# vlan 20
S1(config-vlan)# name LAN20
S1(config-vlan)# exit

! Assign PC1 port to VLAN 10
S1(config)# interface fa0/6
S1(config-if)# switchport mode access
S1(config-if)# switchport access vlan 10
S1(config-if)# exit

! Trunk to S2
S1(config)# interface fa0/1
S1(config-if)# switchport mode trunk
S1(config-if)# switchport trunk native vlan 1000
S1(config-if)# switchport trunk allowed vlan 10,20,1000
S1(config-if)# exit

! Trunk to R1
S1(config)# interface gi0/1
S1(config-if)# switchport mode trunk
S1(config-if)# switchport trunk native vlan 1000
S1(config-if)# switchport trunk allowed vlan 10,20,1000
S1(config-if)# end

4.2.3 S2 VLAN and Trunking Configuration

S2 — VLANs, Access Port, Trunk to S1 
S2# configure terminal

! VLANs must exist on every switch in the path
S2(config)# vlan 10
S2(config-vlan)# name LAN10
S2(config-vlan)# exit
S2(config)# vlan 20
S2(config-vlan)# name LAN20
S2(config-vlan)# exit

! Assign PC2 port to VLAN 20
S2(config)# interface fa0/18
S2(config-if)# switchport mode access
S2(config-if)# switchport access vlan 20
S2(config-if)# exit

! Trunk to S1
S2(config)# interface fa0/1
S2(config-if)# switchport mode trunk
S2(config-if)# switchport trunk native vlan 1000
S2(config-if)# switchport trunk allowed vlan 10,20,1000
S2(config-if)# end
⚠️VLANs must be created on every switch in the path. Forgetting VLAN 20 on S1 means VLAN 20 frames cannot transit S1 on the trunk, even if S2 is perfectly configured.

4.2.4 R1 Subinterface Configuration

The most exam-tested configuration in the module. Three strict rules apply:

🎯 THREE RULES FOR SUBINTERFACES — MEMORIZE THESE
  1. Physical interface gets no shutdown — NO IP address
  2. encapsulation dot1Q [vlan-id] MUST come before ip address
  3. VLAN number in encapsulation dot1Q must exactly match the switch VLAN
R1 — Router-on-a-Stick Subinterface Configuration 
R1# configure terminal

! Physical interface: bring up, NO IP address
R1(config)# interface g0/0/0
R1(config-if)# no shutdown
R1(config-if)# exit

! Subinterface for VLAN 10
R1(config)# interface g0/0/0.10
R1(config-subif)# encapsulation dot1Q 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config-subif)# exit

! Subinterface for VLAN 20
R1(config)# interface g0/0/0.20
R1(config-subif)# encapsulation dot1Q 20
R1(config-subif)# ip address 192.168.20.1 255.255.255.0
R1(config-subif)# end
💡
Cisco best practice: match the subinterface number to the VLAN ID (G0/0/0.10 for VLAN 10). This makes configs readable and easier to troubleshoot.

4.3Inter-VLAN Routing Using Layer 3 Switches▾

4.3.1 Layer 3 Switch Inter-VLAN Routing

A Layer 3 switch performs both Layer 2 switching and Layer 3 routing. It uses Switched Virtual Interfaces (SVIs) created with interface vlan [id]. Each SVI acts as the default gateway for that VLAN and routing happens in switch hardware at wire speed — no external router required for local traffic.

🖥️
An SVI is only up/up when both conditions are true: (1) the VLAN exists in the VLAN database, AND (2) at least one active port is assigned to that VLAN. If either condition fails, the SVI shows down/down.

4.3.2 Layer 3 Switch Scenario

  PC1 (192.168.10.10/24) --Fa0/6--+
  PC2 (192.168.20.10/24) --Fa0/18-+-- [D1 Layer 3 Switch]
  PC3 (192.168.30.10/24) --Fa0/11-+
                                   |
                        SVIs configured on D1:
                   Vlan10  192.168.10.1/24  (gateway VLAN 10)
                   Vlan20  192.168.20.1/24  (gateway VLAN 20)
                   Vlan30  192.168.30.1/24  (gateway VLAN 30)

  All three PCs communicate -- all routing done inside D1

4.3.3 Layer 3 Switch SVI Configuration

Four steps — most students get steps 1, 2, and 4 right but miss Step 3.

D1 — Complete Layer 3 Switch SVI Configuration 
D1# configure terminal

! STEP 1: Create the VLANs in the database
D1(config)# vlan 10
D1(config-vlan)# name LAN10
D1(config-vlan)# exit
D1(config)# vlan 20
D1(config-vlan)# name LAN20
D1(config-vlan)# exit
D1(config)# vlan 30
D1(config-vlan)# name LAN30
D1(config-vlan)# exit

! STEP 2: Create SVIs -- one per VLAN -- assign IP and bring up
D1(config)# interface vlan 10
D1(config-if)# description Default Gateway VLAN 10
D1(config-if)# ip address 192.168.10.1 255.255.255.0
D1(config-if)# no shutdown
D1(config-if)# exit

D1(config)# interface vlan 20
D1(config-if)# description Default Gateway VLAN 20
D1(config-if)# ip address 192.168.20.1 255.255.255.0
D1(config-if)# no shutdown
D1(config-if)# exit

D1(config)# interface vlan 30
D1(config-if)# description Default Gateway VLAN 30
D1(config-if)# ip address 192.168.30.1 255.255.255.0
D1(config-if)# no shutdown
D1(config-if)# exit

! STEP 3: ENABLE IP ROUTING -- THE #1 MOST FORGOTTEN COMMAND
D1(config)# ip routing

! STEP 4: Assign physical access ports to VLANs
D1(config)# interface fa0/6
D1(config-if)# switchport mode access
D1(config-if)# switchport access vlan 10
D1(config-if)# exit

D1(config)# interface fa0/18
D1(config-if)# switchport mode access
D1(config-if)# switchport access vlan 20
D1(config-if)# exit

D1(config)# interface fa0/11
D1(config-if)# switchport mode access
D1(config-if)# switchport access vlan 30
D1(config-if)# end
🎯 THE #1 MOST FORGOTTEN COMMAND IN MODULE 4

ip routing

Without this command the Layer 3 switch acts as a pure Layer 2 device. SVIs will have correct IPs and show up/up — but inter-VLAN packets will NOT be routed. This is the number one reason Layer 3 switch inter-VLAN routing fails in both labs and on the CCNA exam.

4.3.4 Layer 3 Switch Verification

show ip route — VLANs appear as connected via Vlan interfaces 
D1# show ip route

      192.168.10.0/24 is variably subnetted, 2 subnets, 2 masks
C        192.168.10.0/24 is directly connected, Vlan10
L        192.168.10.1/32 is directly connected, Vlan10
      192.168.20.0/24 is variably subnetted, 2 subnets, 2 masks
C        192.168.20.0/24 is directly connected, Vlan20
L        192.168.20.1/32 is directly connected, Vlan20
      192.168.30.0/24 is variably subnetted, 2 subnets, 2 masks
C        192.168.30.0/24 is directly connected, Vlan30
L        192.168.30.1/32 is directly connected, Vlan30
show interfaces vlan 10 — verify SVI is up/up with correct IP 
D1# show interfaces vlan 10

Vlan10 is up, line protocol is up
  Hardware is CPU Interface, address is 0060.3e35.1d80
  Description: Default Gateway VLAN 10
  Internet address is 192.168.10.1/24
  MTU 1500 bytes, BW 100000 Kbit/sec
🚨
SVI shows down/down? Two causes:
1. VLAN does not exist in the database — check show vlan brief
2. No active ports assigned to that VLAN
Fix: create the VLAN and assign at least one active access port to it.

4.3.5 Routing on a Layer 3 Switch

Layer 3 switches handle local inter-VLAN routing using SVIs. For traffic destined to the internet or external networks, a routed port connects the Layer 3 switch to an upstream router.

  [Internet / WAN]
        |
      [R1]  -- 10.10.10.1/30
        |
   /30 point-to-point link
        |
  10.10.10.2/30 -- [D1 Layer 3 Switch] -- VLANs 10, 20, 30
  
  D1 routes locally between VLANs using SVIs.
  D1 sends internet-bound traffic upstream to R1 via default route.

4.3.7 Routed Port Configuration on a Layer 3 Switch

A routed port is created with no switchport, removing the port from Layer 2 operation entirely. It then receives an IP address like a router interface and no longer appears in show vlan brief.

D1 — Routed Port + Default Route to External Router 
D1# configure terminal

! Convert Gi0/0/1 from a Layer 2 switchport to a Layer 3 routed port
D1(config)# interface gi0/0/1
D1(config-if)# no switchport
D1(config-if)# ip address 10.10.10.2 255.255.255.252
D1(config-if)# no shutdown
D1(config-if)# exit

! Default route -- send all non-local traffic to R1
D1(config)# ip route 0.0.0.0 0.0.0.0 10.10.10.1
D1(config)# end
💡
no switchport permanently converts the port from Layer 2 to Layer 3. After this command, the port disappears from show vlan brief and behaves exactly like a router interface — assign an IP address directly.

4.4Troubleshoot Inter-VLAN Routing▾

4.4.1 Common Inter-VLAN Issues

Troubleshoot bottom-up: physical first, then Layer 2, then Layer 3.

IssueWhere It LivesDiagnostic Command
Missing VLANsVLAN not in database on one or more switchesshow vlan brief
Trunk Port IssuesVLAN not in allowed list; native VLAN mismatchshow interfaces trunk
Access Port IssuesPC port assigned to wrong VLANshow interfaces [int] switchport
Router/L3 Config IssuesWrong encapsulation; IP on wrong interface; missing ip routingshow ip route, show running-config

4.4.2 Structured Troubleshooting Approach

  1. Check physical connectivity — are cables connected? Are interfaces up/up?
  2. Verify VLANs exist on every switch in the path using show vlan brief
  3. Check trunk links — correct VLANs in allowed list? Native VLANs match on both ends? Use show interfaces trunk
  4. Check access ports — is each PC port in the correct VLAN? Use show interfaces [int] switchport
  5. Check router or L3 switch — encapsulation correct? IP on right interface? ip routing enabled? Use show ip route and show running-config
  6. Test with ping and traceroute from end devices to isolate exactly where traffic stops

4.4.3 Missing VLANs

A VLAN must exist on every switch in the path — not just on the switch the PC is directly connected to.

🔍 TROUBLESHOOT SCENARIO
PC1 on VLAN 10 can ping its gateway but cannot reach PC2 on VLAN 20. Check if VLAN 20 exists on S1:
show vlan brief — look for missing VLANs 
S1# show vlan brief

VLAN Name                             Status    Ports
---- -------------------------------- --------- ----------------------------
1    default                          active    Fa0/3, Fa0/4, Gi0/2
10   LAN10                            active    Fa0/6
1002 fddi-default                     act/unsup
! NOTICE: VLAN 20 is completely missing from S1!
! VLAN 20 frames cannot transit S1 on the trunk -- they are dropped.
Fix — Create the missing VLAN on S1 
S1(config)# vlan 20
S1(config-vlan)# name LAN20
S1(config-vlan)# end

4.4.4 Switch Trunk Port Issues

Two common trunk problems: a VLAN is missing from the allowed list, or there is a native VLAN mismatch between the two ends of a trunk.

🔍 TROUBLESHOOT SCENARIO
VLANs exist. Gateways respond. But PC1 (VLAN 10 on S1) cannot reach PC2 (VLAN 20 on S2). Check the trunk:
show interfaces trunk — check allowed VLANs 
S1# show interfaces fa0/1 trunk

Port        Mode         Encapsulation  Status        Native vlan
Fa0/1       on           802.1q         trunking      1

Port        Vlans allowed on trunk
Fa0/1       1-9,11-4094
! PROBLEM: VLAN 10 is missing (list jumps from 9 to 11)

Port        Vlans allowed and active in management domain
Fa0/1       1,20
Fix — Add VLAN 10 to the trunk allowed list 
S1(config)# interface fa0/1
S1(config-if)# switchport trunk allowed vlan add 10
S1(config-if)# end
🚨
Critical Trap — Always Use "add": The command switchport trunk allowed vlan 10 without add replaces the entire allowed list with only VLAN 10, removing all others. Always use switchport trunk allowed vlan add 10 to safely append.

4.4.5 Switch Access Port Issues

If a PC port is in the wrong VLAN, the PC is in the wrong subnet and cannot reach its gateway — even if everything else is correctly configured.

🔍 TROUBLESHOOT SCENARIO
PC2 should be on VLAN 20 but cannot ping its gateway 192.168.20.1. Check the port assignment:
show interfaces fa0/18 switchport — check VLAN assignment 
S2# show interfaces fa0/18 switchport

Name: Fa0/18
Switchport: Enabled
Administrative Mode: static access
Operational Mode: static access
Negotiation of Trunking: Off
Access Mode VLAN: 1 (default)
! PROBLEM: Port is in VLAN 1, not VLAN 20
Fix — Assign port to the correct VLAN 
S2(config)# interface fa0/18
S2(config-if)# switchport access vlan 20
S2(config-if)# end

🎯Common Exam Traps — Module 4▾
❌
Trap 1 (RoaS): IP address on the physical interface.
Physical interface must have NO IP — only no shutdown. Only subinterfaces get IPs. The exam shows a config with an IP on G0/0/0 and asks what is wrong.
❌
Trap 2 (RoaS): encapsulation dot1Q VLAN mismatch.
If encapsulation dot1Q 10 is on the subinterface for VLAN 20, traffic goes to the wrong VLAN. The encapsulation VLAN ID must exactly match the switch configuration.
❌
Trap 3 (Layer 3 Switch): Forgetting ip routing.
Without this command the switch acts as Layer 2 only. SVIs will be up/up with correct IPs — but inter-VLAN packets will NOT be routed. Always verify this is in the running config.
❌
Trap 4: SVI shows down/down.
An SVI is only up/up when: (a) the VLAN exists in the database AND (b) at least one active port is assigned to it. Deleting a VLAN makes its SVI go down even if the SVI has a correct IP.
❌
Trap 5: switchport trunk allowed vlan without add.
Replaces the entire allowed VLAN list. Always use add to append. This mistake removes all existing VLANs from the trunk and is one of the most destructive misconfigurations in networking.
❌
Trap 6: Physical interface shutdown kills all subinterfaces.
If G0/0/0 is shut down, every subinterface on it (G0/0/0.10, G0/0/0.20, etc.) goes down immediately — even if the subinterfaces themselves are not individually shut down.
⚠️
Trap 7: VLAN missing from an intermediate switch.
VLANs must exist on every switch in the traffic path. A VLAN missing from any intermediate switch will drop traffic for that VLAN on trunk links transiting that switch.
⚠️
Trap 8: TTL as a routing indicator.
TTL=127 (one less than Windows default 128) confirms one routing hop. TTL=128 means routing never happened. This appears on the exam as a diagnostic question about whether routing actually occurred.
✅
RoaS vs Layer 3 Switch — at a glance:

Router-on-a-Stick: interface g0/0/0.[vlan] + encapsulation dot1Q [vlan] + ip address. No IP on physical interface.

Layer 3 Switch: interface vlan [id] + ip address + no shutdown + ip routing.

The exam shows configs of both methods — know which commands belong where and immediately spot when something is misplaced.
