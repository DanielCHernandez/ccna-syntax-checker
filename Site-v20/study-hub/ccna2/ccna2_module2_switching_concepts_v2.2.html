2.1Frame Forwarding▾

2.1.1 Switching in Networking

A LAN switch makes forwarding decisions based entirely on destination MAC addresses. Before understanding how frames move, you need to know two key terms that describe frame movement through a switch:

TermDefinitionSimple Way to Remember
IngressThe port where a frame enters the switch"In" — the frame comes IN on the ingress port
EgressThe port where a frame leaves the switch"Exit" — the frame exits on the egress port

The switch maintains a single master MAC address table — a strict mapping of MAC addresses to ports. A frame with a given destination address always exits the same egress port, regardless of which port it came in on.

🚨
Absolute rule — never forgotten: A frame is NEVER forwarded back out the same port it arrived on. This applies in every scenario, including floods. The ingress port is always excluded from forwarding.
  PC1 ──Fa0/1──┐
  PC2 ──Fa0/2──┤  [Switch S1]  ──Fa0/4── PC4
  PC3 ──Fa0/3──┘

  Frame from PC1 arrives on Fa0/1 (INGRESS)
  Switch looks up PC4's MAC → found on Fa0/4
  Frame sent out Fa0/4 (EGRESS)
  Fa0/1 is NEVER used as an egress port for this frame

2.1.2 The Switch MAC Address Table

A switch learns which devices are on which ports by building a MAC address table. This table maps MAC addresses to the switch port they were last seen on.

TermMeaning
MAC address tableThe table that maps MAC addresses to switch ports — the switch's primary intelligence
CAM tableSame thing — stands for Content Addressable Memory table. CAM is a special high-speed memory type optimized for table lookups
Entry aging timeDefault 5 minutes (300 seconds) — if no frame is received from a MAC address within this window, the entry is removed
💡
The MAC address table is sometimes called the CAM table on the exam — both names refer to exactly the same thing. CAM (Content Addressable Memory) is the hardware that enables the switch to perform very fast MAC lookups.

2.1.3 The Switch Learn and Forward Method

Every frame that enters a switch goes through a strict two-step process. This happens on every single frame, in order, every time.

⬆️ Step 1 — LEARN (Examine the Source MAC Address)

The switch examines the source MAC address of the incoming frame and the port it arrived on:

  • Source MAC not in table → add the MAC address and ingress port number as a new entry
  • Source MAC already in table on the same port → refresh its 5-minute aging timer
  • Source MAC in table but on a different port → update the entry with the new port number (device was moved or reconnected)
⬇️ Step 2 — FORWARD (Examine the Destination MAC Address)

The switch examines the destination MAC address of the frame and makes a forwarding decision:

  • Destination MAC found in table (known unicast) → forward out the specific port listed
  • Destination MAC not in table (unknown unicast) → flood out all ports except the ingress port
  • Destination MAC is a broadcast (FF:FF:FF:FF:FF:FF) → flood out all ports except the ingress port
  • Destination MAC is a multicast → flood out all ports except the ingress port (unless multicast snooping is configured)
Destination MACIn Table?Action
Known unicast✅ YesForward out the single specific port
Unknown unicast❌ NoFlood — forward out ALL ports except ingress
Broadcast (FF:FF:FF:FF:FF:FF)N/AFlood — forward out ALL ports except ingress
MulticastN/AFlood out ALL ports except ingress (default behavior)
⚠️
Unknown unicast = flood, not drop. Students often assume the switch drops a frame when it doesn't know the destination. It doesn't — it floods. The switch only drops frames in store-and-forward mode when they fail the FCS/CRC check.
🔍 SCENARIO — Watch the MAC Table Build
PC1 (MAC: AA) sends a frame to PC3 (MAC: CC). The switch is brand new — empty table.

Step 1 — Learn: Source = AA, arrived on Fa0/1 → add AA:Fa0/1 to table
Step 2 — Forward: Destination = CC → not in table → FLOOD out Fa0/2, Fa0/3, Fa0/4

PC3 replies to PC1. Source = CC, arrived on Fa0/3 → add CC:Fa0/3 to table
Destination = AA → found in table on Fa0/1 → forward ONLY out Fa0/1

After two frames, the table has learned two MACs and the next PC1↔PC3 exchange is a direct unicast.

2.1.5 Switching Forwarding Methods

Switches use ASICs (Application-Specific Integrated Circuits) — dedicated hardware chips — to make forwarding decisions extremely fast without involving the CPU. There are two forwarding methods, plus one hybrid:

✅ Store-and-Forward — Cisco Default
  • Receives the entire frame before making a forwarding decision
  • Performs full FCS/CRC error check on every frame
  • Corrupt frames are dropped — never forwarded
  • Handles speed mismatches between ingress and egress ports
  • Higher latency than cut-through
⚡ Cut-Through — Ultra-Low Latency
  • Reads only the destination MAC (first 6 bytes), then begins forwarding immediately
  • No error checking — corrupt frames are forwarded
  • Best for high-performance computing (HPC) needing latency ≤10 microseconds
  • High network error rates make cut-through worse, not better
⚖️ Fragment Free — The Middle Ground
  • Reads the first 64 bytes before forwarding
  • Catches runt frames and collision fragments (most errors occur in the first 64 bytes)
  • Does NOT catch all errors — full-sized corrupt frames still pass through
  • Lower latency than store-and-forward, better error filtering than cut-through

2.1.6 Store-and-Forward Switching

This is Cisco's primary LAN switching method and what you will encounter on all Cisco equipment. It has two defining characteristics:

Characteristic 1 — Error Checking (FCS/CRC)

Store-and-forward error check process 
Frame arrives on ingress port
  ↓
Switch stores entire frame in ingress buffer
  ↓
Switch calculates its own FCS value for the frame
  ↓
Compares calculated FCS  vs.  FCS in last field of received frame
  ↓
Match?  YES → Forward frame out egress port
        NO  → Drop frame silently (never forwarded)

The FCS (Frame Check Sequence) is a 4-byte value in the last field of an Ethernet frame calculated using a CRC (Cyclic Redundancy Check) algorithm. If the frame was damaged in transit, the switch's calculated FCS will not match the FCS in the frame.

Characteristic 2 — Automatic Buffering (Speed Mismatch Handling)

Store-and-forward buffers the entire frame before forwarding. This allows it to handle speed mismatches between ingress and egress ports:

  Example: Frame arrives at 1 Gbps, must leave at 100 Mbps

  [Ingress: 1 Gbps port] → frame stored in buffer
                         → FCS checked
                         → forwarded out at [Egress: 100 Mbps port]

  Without buffering, the faster ingress rate would overwhelm the slower egress port.
  The buffer absorbs the speed difference and prevents frame loss.
✅
Store-and-forward is the right choice whenever reliability matters more than raw speed — which is almost every enterprise network. It ensures no corrupt frames ever reach their destination.

2.1.7 Cut-Through Switching

Cut-through begins forwarding as soon as the destination MAC address (just the first 6 bytes of the frame) has been read and the egress port identified. It never waits for the rest of the frame.

  Store-and-Forward: waits for [DEST MAC | SRC MAC | TYPE | DATA | FCS]
                                                            entire frame ↑

  Cut-Through:       reads [DEST MAC] → starts forwarding immediately
                            ↑ only 6 bytes needed

🎯 EXAM TIP — Choosing the Right Method
The exam will give you a scenario and ask which forwarding method is appropriate:

  • "Network reliability is critical / minimize corrupt frames" → Store-and-Forward
  • "Ultra-low latency / high-performance computing / <10 microseconds" → Cut-Through
  • "Balance between speed and error filtering" → Fragment Free
  • "High error rate on the network" → Store-and-Forward (cut-through makes it worse)
  • "Speed mismatch between ports" → Store-and-Forward (only method that buffers for this)
2.2Switching Domains▾

2.2.1 Collision Domains

A collision domain is a network segment where two or more devices share bandwidth and frames can collide if they transmit at the same time. In legacy hub-based networks, all devices shared one collision domain — traffic from any device competed with traffic from every other device.

DeviceCollision Domains CreatedNotes
Hub1 — shared by ALL portsAll devices compete for one channel — collisions guaranteed under load
Switch (half-duplex port)1 per portEach port is its own collision domain, but half-duplex means collisions are still possible on that segment
Switch (full-duplex port)0 — no collision domainFull-duplex = simultaneous TX and RX — collision detection circuit disabled, collisions impossible
Router1 per interfaceEach router interface is its own collision domain
  Hub-based (1 collision domain — all devices compete):
  [PC1]──┐
  [PC2]──┤──[Hub]   ← ONE collision domain for all 4 devices
  [PC3]──┤
  [PC4]──┘

  Switch-based full-duplex (separate collision domain per port):
  [PC1]──[Fa0/1]  ← collision domain 1
  [PC2]──[Fa0/2]  ← collision domain 2   [Switch S1]
  [PC3]──[Fa0/3]  ← collision domain 3
  [PC4]──[Fa0/4]  ← collision domain 4
  A 24-port full-duplex switch = 24 separate collision domains

By default, Ethernet switch ports autonegotiate full-duplex when the connected device also supports it. If the connected device only supports half-duplex (e.g., a legacy hub), the switch port will match and operate in half-duplex.

✅
Full-duplex is selected when both devices support it AND can agree on the highest common speed. Full-duplex is required for Gigabit Ethernet (1 Gbps) and higher — these speeds cannot operate in half-duplex.

2.2.2 Broadcast Domains

A broadcast domain is the set of all devices that will receive a broadcast frame sent by any one device. When a switch receives a broadcast frame (destination MAC = FF:FF:FF:FF:FF:FF), it floods it out all ports except the ingress port — reaching every device connected to that switch and every switch connected to it.

A collection of interconnected switches = one single broadcast domain. Only a Layer 3 device (router) divides broadcast domains.

  ONE broadcast domain (no router):
  [PC1]──[PC2]──[S1]──────[S2]──[PC3]──[PC4]
                            |
                           [S3]──[PC5]──[PC6]
  Broadcast from PC1 reaches PC2, PC3, PC4, PC5, PC6 — ALL of them.

  TWO broadcast domains (router between S1 and S2):
  [PC1]──[PC2]──[S1]──[Router]──[S2]──[PC3]──[PC4]
  ←── Domain 1 ──→              ←─── Domain 2 ───→
  Broadcast from PC1 reaches PC2 only — router stops it.
DeviceDivides Collision Domains?Divides Broadcast Domains?
Hub❌ No❌ No
Switch / Bridge✅ Yes — one per port❌ No
Router✅ Yes — one per interface✅ Yes — one per interface
⚠️
Too many broadcasts = network congestion. Large flat switched networks with hundreds of devices in one broadcast domain suffer from "broadcast storms" — excessive broadcast traffic that consumes bandwidth and slows all devices. VLANs (Module 3) solve this by creating multiple logical broadcast domains on one physical switch.

2.2.3 Alleviate Network Congestion

Modern switches have four specific hardware characteristics that reduce network congestion. The exam asks you to name and explain all four:

FeatureHow It Reduces CongestionExample Specs
Fast port speedsHigher bandwidth means more data moves faster, reducing backlogsAccess layer: 100 Mbps / 1 Gbps
Distribution: up to 10 Gbps
Core / data center: 40–100 Gbps
Fast internal switchingHigh-speed internal bus or shared memory fabric moves frames through the switch without backplane bottlenecksASICs handle forwarding in hardware — no CPU intervention needed
Large frame buffersTemporarily holds frames when the egress port is slower than ingress — prevents frame drops during traffic burstsExample: 1 Gbps ingress → 100 Mbps egress; buffer absorbs the speed difference
High port densityMore ports per switch = fewer switches needed = less inter-switch traffic = more traffic stays localTwo 48-port switches instead of four 24-port switches reduces cost and keeps traffic on fewer hops
🎯 EXAM TIP — The Four Congestion-Relief Features
The exam may ask "which switch characteristic helps alleviate congestion?" — know all four by name:

  1. Fast port speeds — raw bandwidth capacity
  2. Fast internal switching — ASIC-based internal bus/shared memory
  3. Large frame buffers — absorbs speed mismatches and burst traffic
  4. High port density — fewer switches, more local traffic, lower cost

Note: large frame buffers handle speed mismatches and bursts — they are not for error correction. Error correction is store-and-forward's job.

🎯Common Exam Traps — Module 2▾
❌
Trap 1: A frame is NEVER forwarded out the port it arrived on.
This applies in every scenario — unicast, flood, broadcast, everything. The ingress port is always excluded from forwarding. If a frame arrived on Fa0/1, it will never leave on Fa0/1.
❌
Trap 2: Unknown unicast = FLOOD, not drop.
When the destination MAC is not in the MAC address table, the switch floods the frame out all ports except the ingress port. The switch does NOT drop unknown frames. Only store-and-forward drops frames — and only when they fail the FCS check.
❌
Trap 3: Store-and-forward is Cisco's default — not cut-through.
Cut-through has lower latency but no error checking. The exam frequently tries to trick you into choosing cut-through because it's "faster." Unless the scenario specifically calls out ultra-low latency (HPC, <10 microseconds), store-and-forward is the correct answer.
❌
Trap 4: Switches do NOT divide broadcast domains — routers do.
No matter how many switches you chain together, all devices across all those switches are in one single broadcast domain. Only a router (or a Layer 3 device acting as one) creates separate broadcast domains. VLANs also divide broadcast domains, but that's because they create logical Layer 3 separation — not because of the switch hardware itself.
❌
Trap 5: A 24-port full-duplex switch has 24 collision domains — not 1.
Each full-duplex switch port is its own isolated collision domain. A hub has 1 shared collision domain. Students mix these up constantly. Count the ports, not the switches.
❌
Trap 6: The MAC address table is also called the CAM table.
Both terms appear on the exam and refer to identical things. CAM stands for Content Addressable Memory — the high-speed memory type the table is stored in. Don't let the different name confuse you.
⚠️
Trap 7: MAC entries age out after 5 minutes (300 seconds) by default.
If a device stops sending traffic, its MAC entry is eventually removed. The next time that device sends a frame, the switch re-learns it. This aging process is normal behavior — not a problem.
⚠️
Trap 8: Cut-through makes things worse in high-error environments.
Because cut-through has no FCS checking, it forwards every frame — corrupt or not. In a network with high error rates, cut-through floods the network with bad frames, consuming bandwidth unnecessarily. Store-and-forward silently drops corrupt frames, keeping them off the network.
⚠️
Trap 9: Fragment free does NOT perform a full FCS check.
Fragment free reads the first 64 bytes and catches runt frames and collision fragments. However, a full-sized frame with a data corruption error (FCS failure) that occurs beyond byte 64 will still be forwarded. Fragment free is better than cut-through, but it is not equivalent to store-and-forward.
⚠️
Trap 10: Large frame buffers handle speed mismatches — not errors.
Buffers temporarily store frames when the egress port is slower than the ingress port. They prevent frame loss during speed mismatches and burst traffic. They do NOT fix corrupt frames — that is exclusively the job of store-and-forward FCS error checking.
✅
Quick summary — collision vs broadcast domains:

Collision domain: eliminated by switches (each full-duplex port = 1 domain). Hubs share 1 domain.
Broadcast domain: only divided by routers. All switches in a chain = 1 broadcast domain.

Quick memory trick: Switches segment collision domains but extend broadcast domains. Routers segment both.
