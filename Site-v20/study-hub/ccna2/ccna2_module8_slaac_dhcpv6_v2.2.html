8.1IPv6 GUA Assignment▾

8.1.1 IPv6 Host Configuration

IPv6 addresses can be assigned manually or dynamically. Manual configuration on a Cisco router interface:

Manual IPv6 GUA configuration 
Router(config-if)# ipv6 address 2001:db8:acad:1::1/64

Dynamic assignment is preferred for most hosts. When a host is set to auto-configure, it relies on ICMPv6 Router Advertisement (RA) messages from a router on the same link. Every IPv6-enabled host also automatically generates a link-local address (LLA) — starting with fe80:: — the moment its interface activates.

🚨
The default gateway is ALWAYS the router's LLA — never its GUA, and never provided by a DHCPv6 server. Only RA messages provide the default gateway. This is true for SLAAC only, stateless DHCPv6, and stateful DHCPv6 — without exception.

8.1.2 IPv6 Host Link-Local Address

A host auto-creates its LLA when the interface activates — even without a router or GUA:

ipconfig — LLA present, no GUA yet (no router on segment) 
C:\PC1> ipconfig
   IPv6 Address. . . . . . . : (blank — no GUA yet)
   Link-local IPv6 Address . : fe80::fb:1d54:839f:f595%21
   IPv4 Address. . . . . . . : 169.254.202.140
💡
The %21 appended to the LLA is a Zone ID / Scope ID — used by the OS to identify which network interface the LLA belongs to. It is display-only and is not part of the actual IPv6 address.

8.1.3 IPv6 GUA Assignment Methods

MethodWho Creates the IP?What Does DHCPv6 Provide?

The method used depends entirely on the A, O, and M flags in the RA message sent by the router.

8.2SLAAC▾

8.2.1 SLAAC Overview

SLAAC (Stateless Address Autoconfiguration) allows a host to create its own IPv6 GUA without any DHCP server. No server tracks which addresses have been assigned — it is entirely stateless.

  • Enabled by default when ipv6 unicast-routing is configured on a router
  • Routers send RA messages every 200 seconds automatically
  • Hosts can trigger an immediate RA by sending a Router Solicitation (RS)
  • The RA provides: prefix, prefix length, default gateway (LLA), MTU, DNS (SLAAC-only)
  • The host generates its own 64-bit Interface ID to complete the address

8.2.2 Enabling SLAAC

Enable IPv6 routing — required for SLAAC 
R1(config)# ipv6 unicast-routing

! Verify router joined all-routers multicast group (ff02::2):
R1# show ipv6 interface G0/0/1 | section Joined
  Joined group address(es):
    FF02::1    ← all-nodes (RAs sent to this address)
    FF02::2    ← all-routers (joined when ipv6 unicast-routing enabled)
    FF02::1:FF00:1
🚨
Without ipv6 unicast-routing, the router has IPv6 addresses but does NOT send RAs. Hosts on connected segments cannot use SLAAC. This is the single most common missing configuration step.

8.2.3 SLAAC Only Method (A=1, O=0, M=0)

This is the default. The RA contains everything the host needs:

Verify SLAAC is active — show ipv6 interface 
R1# show ipv6 interface g0/0/1 | begin ND
  Hosts use stateless autoconfig for addresses.   ← A=1 confirmed, no DHCPv6

C:\PC1> ipconfig
   IPv6 Address. . . . : 2001:db8:acad:1:1de9:c69:73ee:ca8c  ← self-created
   Link-local IPv6 Address : fe80::fb:1d54:839f:f595%21
   Default Gateway . . . . : fe80::1%6    ← R1's LLA — always LLA, never GUA

The host creates its GUA by combining the prefix from the RA (2001:db8:acad:1::/64) with a self-generated 64-bit Interface ID.

8.2.4 ICMPv6 RS and RA Messages

Hosts do not wait 200 seconds for the next scheduled RA — they can request one immediately:

  Host connects to network
    ↓
  Host sends RS (Router Solicitation) to ff02::2 (all-routers multicast)
  "Any routers out there? Please respond immediately."
    ↓
  Router receives RS → immediately sends RA to ff02::1 (all-nodes multicast)
    ↓
  Host receives RA → reads A/O/M flags → begins address configuration

8.2.5 Host Process to Generate Interface ID

MethodHow It WorksDefault On
Randomly generatedOS generates a random 64-bit value — MAC address is never exposedWindows 10+ (privacy preference)
EUI-64Takes 48-bit MAC, splits at the middle, inserts FFFE, flips the 7th (U/L) bitOlder OS, Cisco router interfaces
EUI-64 worked example 
MAC address:           00:05:9A:3C:7A:00
Split at middle:       00:05:9A  |  3C:7A:00
Insert FFFE:           00:05:9A:FF:FE:3C:7A:00
Flip 7th bit (U/L):    02:05:9A:FF:FE:3C:7A:00
Interface ID:          0205:9AFF:FE3C:7A00
Full GUA:              2001:db8:acad:1:0205:9AFF:FE3C:7A00

8.2.6 Duplicate Address Detection (DAD)

After generating a GUA, the host runs DAD to verify the address is unique before using it. Recommended for all IPv6 unicast addresses regardless of how they were obtained.

  Host generates candidate GUA: 2001:db8:acad:1:1de9:c69:73ee:ca8c
    ↓
  Host sends ICMPv6 Neighbor Solicitation (NS) to solicited-node multicast:
  FF02::1:FF:73ee:ca8c  (FF02::1:FF + last 24 bits of candidate address)
  "Is anyone already using 2001:db8:acad:1:1de9:c69:73ee:ca8c?"
    ↓
  No NA reply → address is unique → host starts using it
  NA reply received → address conflict → host generates a new Interface ID
💡
DAD uses the same ICMPv6 NS/NA mechanism as IPv6 Neighbor Discovery — the IPv6 equivalent of ARP. The solicited-node multicast address is FF02::1:FF + the last 24 bits of the candidate address.

8.3DHCPv6 Concepts▾

8.3.1 DHCPv6 Operation — The Full Six-Step Process

The DHCPv6 process begins with an RS/RA exchange — the RA is what tells the client which type of DHCPv6 to use. The process then splits at Step 5 depending on the flags in the RA.

📡 DHCPv6 Six-Step Process — Both Paths
1
Client → Router: RS sent to ff02::2 (all-routers multicast) — "Any routers out there? Respond immediately."
2
Router → Client: RA sent to ff02::1 (all-nodes multicast) — carries A/O/M flags. The RA source LLA becomes the client's default gateway.
3
Client → DHCPv6 Server: SOLICIT sent to ff02::1:2 (all-DHCPv6-servers — link-local scope, not forwarded by routers) — "Any DHCPv6 servers on this link?"
4
Server → Client: ADVERTISE sent as unicast to client's LLA — "I am available to serve you."
5
Client → Server: PATH SPLITS HERE based on RA flags:
  • O=1 (Stateless): INFORMATION-REQUEST — "Just give me DNS and domain name, I have my IP from SLAAC"
  • M=1 (Stateful): REQUEST — "Give me a full IP address, DNS, domain, and lease"
6
Server → Client: REPLY sent as unicast:
  • Stateless REPLY: DNS server + domain name only — no IP assigned
  • Stateful REPLY: GUA + prefix + DNS + domain + lease timers (preferred/valid lifetime)
  • Default gateway: NEVER included in either reply — always from RA source LLA
🚨
ff02::1:2 has link-local scope — routers do NOT forward it. This is exactly why a DHCPv6 relay agent is needed when the server is on a different subnet — the same fundamental problem as DHCPv4 broadcasts not crossing routers.

DHCPv4 vs DHCPv6 Message Comparison

8.3.2 Stateless DHCPv6 Operation (A=1, O=1, M=0)

The host uses SLAAC for its GUA but contacts a DHCPv6 server for DNS and domain name only. The server does NOT assign IP addresses and keeps no binding database — it is "stateless."

  RA flags: A=1, O=1, M=0

  Client reads RA:
    "Create your own GUA using SLAAC" (A=1)
    "Contact a DHCPv6 server for DNS and domain name" (O=1)
    ↓
  Client creates GUA using SLAAC prefix + self-generated interface ID
  Client sends DHCPv6 INFORMATION-REQUEST to ff02::1:2
  Server replies with DNS server address + domain name only
    ↓
  Client has:  GUA (self-created via SLAAC)
               Default Gateway (from RA source LLA)
               DNS + Domain (from stateless DHCPv6)
Enable stateless DHCPv6 on the router interface — sets O flag = 1 
R1(config-if)# ipv6 nd other-config-flag

R1# show ipv6 interface g0/0/1 | begin ND
  Hosts use stateless autoconfig for addresses.   ← A=1 (SLAAC still active)
  Hosts use DHCP to obtain other configuration.   ← O=1 (stateless DHCPv6 active)

8.3.3 Stateful DHCPv6 Operation (A=0, O=0, M=1)

The DHCPv6 server provides everything — GUA, DNS, domain, and lease. The server IS stateful because it maintains a binding database of assigned addresses, just like DHCPv4.

  RA flags: A=0, O=0, M=1

  Client reads RA:
    "Do NOT use SLAAC to create your own IP" (A=0)
    "Get everything from a stateful DHCPv6 server" (M=1)
    ↓
  Client sends SOLICIT → Server sends ADVERTISE
  Client sends REQUEST → Server sends REPLY with GUA + DNS + lease
    ↓
  Client has:  GUA (assigned by DHCPv6 server)
               Default Gateway (from RA source LLA — NOT from DHCPv6)
               DNS + Domain (from stateful DHCPv6)
               Lease timers (preferred lifetime / valid lifetime)
Enable stateful DHCPv6 on the router interface — sets M flag = 1 
R1(config-if)# ipv6 nd managed-config-flag

R1# show ipv6 interface g0/0/1 | begin ND
  Hosts use DHCP to obtain routable addresses.   ← M=1 (stateful DHCPv6 active)

Understanding the "Stateless" Naming

TermDoes the Server Track Clients?What the Server Provides
SLAACN/A — no server involvedNothing

Simple mental model: SLAAC alone = no server, client does everything. Stateless DHCPv6 = client creates its own IP, server just hands out DNS. Stateful DHCPv6 = server does everything, client just accepts what it's given.

Client Router Commands — The Two Most Confused

Stateless vs stateful client router configuration 
! Stateless client — SLAAC + get DNS from stateless DHCPv6 server:
R3(config-if)# ipv6 address autoconfig

! Stateful client — get full GUA + DNS from stateful DHCPv6 server:
R3(config-if)# ipv6 address dhcp

! These two commands are completely different — cannot be substituted:
! autoconfig → SLAAC process → self-creates GUA
! dhcp       → sends SOLICIT → requests GUA from stateful DHCPv6 server

8.4Configure DHCPv6 Server▾

8.4.1 DHCPv6 Router Roles

A Cisco IOS router can serve three DHCPv6 roles simultaneously on different interfaces:

RoleDescriptionKey Commands
DHCPv6 ServerProvides stateless or stateful DHCPv6 services to clientsipv6 dhcp pool + ipv6 dhcp server
DHCPv6 ClientInterface obtains its IPv6 configuration from a DHCPv6 serveripv6 address autoconfig or ipv6 address dhcp
DHCPv6 Relay AgentForwards DHCPv6 messages between clients and server on different networksipv6 dhcp relay destination

8.4.2 Configure a Stateless DHCPv6 Server (Five Steps)

R1 — Complete stateless DHCPv6 server configuration 
! Step 1: Enable IPv6 routing (required to send RAs)
R1(config)# ipv6 unicast-routing

! Step 2: Create the DHCPv6 pool (enters dhcpv6 config mode)
R1(config)# ipv6 dhcp pool IPV6-STATELESS
R1(config-dhcpv6)#

! Step 3: Configure pool — DNS and domain ONLY, NO address prefix
R1(config-dhcpv6)# dns-server 2001:db8:acad:1::254
R1(config-dhcpv6)# domain-name example.com
R1(config-dhcpv6)# exit

! Step 4: Bind pool to interface and set O flag = 1
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ipv6 address fe80::1 link-local
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64
R1(config-if)# ipv6 nd other-config-flag       ! Sets O flag = 1
R1(config-if)# ipv6 dhcp server IPV6-STATELESS ! Bind pool to interface
R1(config-if)# no shutdown
R1(config-if)# end

! Step 5: Verify on Windows client (ipconfig /all)
C:\PC1> ipconfig /all
   IPv6 Address. . . . . : 2001:db8:acad:1:1dd:a2ea:66e7 (SLAAC-created)
   Default Gateway . . . : fe80::1%6            ← R1's LLA — always LLA
   DNS Servers . . . . . : 2001:db8:acad:1::254 ← from stateless DHCPv6
   Connection-specific DNS Suffix: example.com  ← from stateless DHCPv6

8.4.3 Configure a Stateless DHCPv6 Client (Router)

R3 — Configure as stateless DHCPv6 client (SLAAC + DNS from server) 
R3(config)# ipv6 unicast-routing
R3(config)# interface g0/0/1
R3(config-if)# ipv6 enable               ! Creates LLA without needing a GUA
R3(config-if)# ipv6 address autoconfig   ! SLAAC + contact stateless DHCPv6
R3(config-if)# end

! Verify GUA created via SLAAC:
R3# show ipv6 interface brief
GigabitEthernet0/0/1   [up/up]
    FE80::2FC:BAFF:FE94:29B1           ← LLA (auto-created)
    2001:DB8:ACAD:1:2FC:BAFF:FE94:29B1 ← GUA (SLAAC-created)

! Verify DNS learned from stateless DHCPv6 server:
R3# show ipv6 dhcp interface g0/0/1
    DNS server: 2001:DB8:ACAD:1::254
    Domain name: example.com

8.4.4 Configure a Stateful DHCPv6 Server (Five Steps)

R1 — Complete stateful DHCPv6 server configuration 
! Step 1: Enable IPv6 routing
R1(config)# ipv6 unicast-routing

! Step 2: Create the DHCPv6 pool
R1(config)# ipv6 dhcp pool IPV6-STATEFUL
R1(config-dhcpv6)#

! Step 3: Configure pool — includes address prefix (server assigns GUAs)
R1(config-dhcpv6)# address prefix 2001:db8:acad:1::/64
R1(config-dhcpv6)# dns-server 2001:4860:4860::8888
R1(config-dhcpv6)# domain-name example.com
R1(config-dhcpv6)# exit

! Step 4: Bind pool to interface, set M flag = 1, disable SLAAC (A = 0)
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ipv6 address fe80::1 link-local
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64
R1(config-if)# ipv6 nd managed-config-flag            ! M flag = 1
R1(config-if)# ipv6 nd prefix default no-autoconfig   ! A flag = 0 (disables SLAAC)
R1(config-if)# ipv6 dhcp server IPV6-STATEFUL
R1(config-if)# no shutdown
R1(config-if)# end

! Step 5: Verify on Windows client
C:\PC1> ipconfig /all
   IPv6 Address. . . . . : 2001:db8:acad:1a43c:fd28:9d79:9e42 (from server)
   Lease Obtained. . . . : Sep 27 2019 10:45:30 AM
   Lease Expires . . . . : Sep 29 2019 10:05:04 AM
   Default Gateway . . . : fe80::1%6     ← still R1's LLA — NOT from DHCPv6
   DNS Servers . . . . . : 2001:4860:4860::8888
⚠️
Why `ipv6 nd prefix default no-autoconfig` matters: If A=1 is left active during stateful DHCPv6, Windows clients create a GUA via SLAAC AND request another from the DHCPv6 server — ending up with two GUAs simultaneously. Setting A=0 prevents SLAAC so the client only receives one GUA from the server.

8.4.5 Configure a Stateful DHCPv6 Client (Router)

R3 — Configure as stateful DHCPv6 client (full GUA from server) 
R3(config)# ipv6 unicast-routing
R3(config)# interface g0/0/1
R3(config-if)# ipv6 enable            ! Creates LLA
R3(config-if)# ipv6 address dhcp      ! Request GUA from stateful DHCPv6 server
R3(config-if)# end

! Verify GUA assigned by DHCPv6 server:
R3# show ipv6 interface brief
GigabitEthernet0/0/1   [up/up]
    FE80::2FC:BAFF:FE94:29B1
    2001:DB8:ACAD:1:B4CB:25FA:3C9:747C   ← GUA assigned by DHCPv6 server

! Verify lease and DNS:
R3# show ipv6 dhcp interface g0/0/1
    Address State is OPEN
    Address: 2001:DB8:ACAD:1:B4CB:25FA:3C9:747C/128
    DNS server: 2001:4860:4860::8888
    Domain name: example.com

8.4.7 Configure a DHCPv6 Relay Agent

When the DHCPv6 server is on a different network than clients, configure the router as a relay agent — directly analogous to IPv4's ip helper-address.

R1 — Configure as DHCPv6 relay agent (client-facing interface) 
! Topology:
! PC1 (2001:db8:acad:2::/64) ──G0/0/1──[R1]──G0/0/0──[R3 = DHCPv6 Server]
!                                                      (2001:db8:acad:1::2)

! Configure relay on the client-facing interface:
R1(config)# interface GigabitEthernet0/0/1      ! Client-facing interface
R1(config-if)# ipv6 dhcp relay destination 2001:db8:acad:1::2 G0/0/0
! Syntax: ipv6 dhcp relay destination [server-address] [egress-interface]
! Egress interface is REQUIRED when the next-hop to the server is an LLA
Verify the DHCPv6 relay agent 
R1# show ipv6 dhcp interface
GigabitEthernet0/0/1 is in relay mode
  Relay destinations:
    2001:DB8:ACAD:1::2
    2001:DB8:ACAD:1::2 via GigabitEthernet0/0/0

! On the DHCPv6 server (R3), verify binding was created:
R3# show ipv6 dhcp binding
Client: FE80::5C43:EE7C:2959:DA68
  Address: 2001:DB8:ACAD:2:9C3C:64DE:AADA:7857   ← PC1's assigned GUA

! On PC1 — confirm DHCP assignment:
C:\PC1> ipconfig /all
   IPv6 Address. . . . : 2001:db8:acad:2:9c3c:64de:aada:7857
   Default Gateway . . : fe80::1%6   ← from RA — never from DHCPv6
   DNS Servers . . . . : 2001:4860:4860::8888
💡
ipv6 dhcp relay destination is the IPv6 equivalent of ip helper-address. Both solve the same problem: DHCP multicast/broadcast messages cannot cross routers, so the relay agent intercepts them on the client-facing interface and forwards them as unicast to the DHCP server.

🎯Common Exam Traps — Module 8▾
❌
Trap 1: The default gateway is ALWAYS the router's LLA — never from DHCPv6.
Both stateless and stateful DHCPv6 servers never provide default gateway information. It comes exclusively from the RA source address — the router's LLA. This is the most fundamental difference from DHCPv4.
❌
Trap 2: A=1, O=0, M=0 = SLAAC only. A=1, O=1, M=0 = stateless DHCPv6. A=0, M=1 = stateful DHCPv6.
Memorize these three flag combinations. The exam gives a scenario and asks which method is in use or which flags to configure.
❌
Trap 3: `ipv6 unicast-routing` is required for the router to send RAs.
Without it, the router has IPv6 addresses but does NOT transmit RAs. Hosts cannot use SLAAC. This is the single most common missing configuration step in labs and exam scenarios.
❌
Trap 4: Stateless DHCPv6 does NOT assign IP addresses — ever.
It only provides DNS and domain name. The server keeps no binding database. Students constantly confuse stateless DHCPv6 (DNS only) with stateful DHCPv6 (full IP assignment) because both involve a DHCPv6 server.
❌
Trap 5: Stateful DHCPv6 pool uses `address prefix` — not `network`.
The IPv4 DHCP command is network. The IPv6 DHCPv6 command is address prefix. Using the wrong command is a very common lab configuration error. Without address prefix, the stateful server has no addresses to assign.
❌
Trap 6: `ipv6 nd other-config-flag` = O flag = stateless. `ipv6 nd managed-config-flag` = M flag = stateful.
These are mixed up constantly. Memory aid: "other" = other configuration = stateless (DNS only). "managed" = managed addresses = stateful (full IP assignment).
❌
Trap 7: DHCPv6 SOLICIT goes to ff02::1:2 — NOT a broadcast.
DHCPv6 uses the all-DHCPv6-servers multicast ff02::1:2 with link-local scope. Routers do not forward it — which is exactly why a relay agent is needed when the server is on a different subnet.
❌
Trap 8: DHCPv6 ports — 547 = client to server, 546 = server to client.
DHCPv4 uses 67 (server) and 68 (client). DHCPv6 uses 547 (client to server) and 546 (server to client). The direction is the opposite of what most students expect.
⚠️
Trap 9: Stateless client router uses `ipv6 address autoconfig`. Stateful uses `ipv6 address dhcp`.
Two completely different commands — not interchangeable. Wrong command = wrong behavior. autoconfig triggers SLAAC. dhcp sends a SOLICIT requesting a GUA from a stateful server.
⚠️
Trap 10: When A=1 and M=1 simultaneously, Windows clients create two GUAs.
One via SLAAC, one from the stateful DHCPv6 server. Best practice when using stateful DHCPv6: always set A=0 using ipv6 nd prefix default no-autoconfig to prevent SLAAC from also running.
⚠️
Trap 11: DHCPv6 relay uses `ipv6 dhcp relay destination` — not `ip helper-address`.
ip helper-address is IPv4 only. The IPv6 equivalent is ipv6 dhcp relay destination [server-address] [egress-interface]. The egress interface parameter is required when the next-hop to the server is a link-local address.
⚠️
Trap 12: `show ipv6 dhcp binding` is empty for stateless DHCPv6.
Stateless servers keep no state — they never assigned any addresses so there is nothing to display. Only stateful DHCPv6 servers maintain a binding database. Running this on a stateless server returns no output.
⚠️
Trap 13: RA messages sent every 200 seconds — or immediately in response to an RS.
Hosts do not wait 200 seconds at boot. They send an RS to ff02::2, which triggers an immediate RA response. This is how hosts quickly get their IPv6 configuration when they connect.
⚠️
Trap 14: DAD uses Neighbor Solicitation to the solicited-node multicast address.
Solicited-node multicast = FF02::1:FF + last 24 bits of the candidate address. No Neighbor Advertisement reply = address is unique and safe to use. NA reply = conflict — generate a new interface ID.
✅
Quick module summary — the three methods:

SLAAC only (A=1, O=0, M=0): No server. Client builds everything from RA.
Stateless DHCPv6 (A=1, O=1, M=0): Client creates IP via SLAAC. Server provides DNS only. No bindings.
Stateful DHCPv6 (A=0, O=0, M=1): Server assigns IP, DNS, lease. Client gets everything from server.

In ALL three cases: Default gateway = router's LLA from RA. Never from DHCPv6.
