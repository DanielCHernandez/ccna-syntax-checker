3.1Overview of VLANs ▾

3.1.1 VLAN Definitions

A VLAN (Virtual Local Area Network) logically segments a physical switch into separate broadcast domains. Devices on different VLANs cannot communicate directly — they require a Layer 3 device (router or Layer 3 switch).

💡 VLANs create logical broadcast domains that can span multiple switch segments. Ethernet frames sent by a device on a specific VLAN can only be seen by other devices in the same VLAN.
🎯 EXAM TIP
VLANs operate at Layer 2. To route between VLANs you need a Layer 3 device. This is the #1 concept tested in Module 3 and Module 4.

3.1.2 Benefits of VLANs

VLANs provide several key advantages in network design:

BenefitHow It Helps
SecuritySensitive departments (HR, Finance) are isolated from general users
Reduced BroadcastsBroadcast traffic is contained within each VLAN
Cost SavingsNo need for separate physical switches per department
FlexibilityUsers can be logically grouped regardless of physical location
PerformanceSmaller broadcast domains = less unnecessary traffic

3.1.3 Types of VLANs

You must know all five VLAN types for the exam:

VLAN TypePurposeKey Detail
Default VLANAll ports start hereAlways VLAN 1; cannot be deleted
Data VLANCarries user trafficAlso called "user VLAN"
Native VLANUntagged trunk trafficDefault is VLAN 1; change it for security
Management VLANSSH/Telnet access to switchAssign IP to its SVI interface
Voice VLANVoIP phone trafficUses CoS QoS priority tagging
⚠️ Voice and management traffic should never travel on the same VLAN as regular user data. This is a best practice and a common exam scenario.

3.2VLANs in a Multi-Switched Environment ▾

3.2.1 Defining VLAN Trunks

A trunk link is a point-to-point connection between two switches (or switch to router) that carries traffic for multiple VLANs simultaneously using 802.1Q tagging.

📡 Without trunk links, you would need a separate physical cable between every pair of switches for each VLAN — clearly impractical. Trunks solve this by tagging each frame with its VLAN ID.

3.2.3 802.1Q VLAN Tagging

The IEEE 802.1Q standard defines how VLAN tags are inserted into Ethernet frames. The tag is 4 bytes added between the Source MAC address and the EtherType field.

Tag FieldSizeDescription
TPID16 bitsTag Protocol ID — always 0x8100
PCP3 bitsPriority Code Point (CoS for QoS)
DEI1 bitDrop Eligible Indicator
VID12 bitsVLAN ID (0–4095; supports 4094 VLANs)
🎯 EXAM TIP
The native VLAN's frames are NOT tagged on a trunk. This is intentional — but both ends of the trunk must agree on the same native VLAN or you get a native VLAN mismatch error.

3.2.4 Native VLANs and 802.1Q Trunking

The native VLAN is the one VLAN whose frames traverse a trunk without a tag. Any untagged frame arriving on a trunk is assumed to belong to the native VLAN.

🚨 Native VLAN Mismatch: If Switch A has native VLAN 1 and Switch B has native VLAN 99, CDP will generate a warning and traffic can be delivered to the wrong VLAN. Always match native VLANs on both ends of a trunk.

3.3.1 VLAN Ranges on Catalyst Switches

💾 VLAN configurations are stored in flash:/vlan.dat — separate from the running-config. Deleting this file with delete flash:vlan.dat wipes all VLAN definitions.

3.3.2 VLAN Creation Commands

IOS — Create and Name VLANs 
Switch# configure terminal
Switch(config)# vlan 10
Switch(config-vlan)# name Sales
Switch(config-vlan)# exit

Switch(config)# vlan 20
Switch(config-vlan)# name Engineering
Switch(config-vlan)# exit

Switch(config)# vlan 150
Switch(config-vlan)# name Voice
Switch(config-vlan)# end

3.3.3 Assigning Ports to a VLAN (Access Mode)

IOS — Assign Access Port to VLAN 
Switch(config)# interface fa0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config-if)# end

3.3.4 Data and Voice VLANs on Same Port

Used when an IP phone is plugged into a switch port, and a PC is daisy-chained behind the phone. The port carries both a data VLAN and a voice VLAN simultaneously.

IOS — Configure Data + Voice VLAN on One Port 
Switch(config)# interface fa0/4
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config-if)# switchport voice vlan 150
Switch(config-if)# mls qos trust cos
Switch(config-if)# end
📞 mls qos trust cos tells the switch to trust the QoS (Class of Service) priority value set by the IP phone. This ensures voice traffic gets priority over data traffic.

3.3.6 Changing or Removing VLAN Port Assignment

IOS — Remove port from VLAN / Return to VLAN 1 
! Return port to VLAN 1 (remove VLAN assignment):
Switch(config)# interface fa0/18
Switch(config-if)# no switchport access vlan
Switch(config-if)# end

! Move port to a different VLAN:
Switch(config)# interface fa0/1
Switch(config-if)# switchport access vlan 20
Switch(config-if)# end

3.3.7 Deleting VLANs

IOS — Delete a Single VLAN 
! Delete one VLAN:
Switch(config)# no vlan 20

! Wipe the entire VLAN database (privileged exec):
Switch# delete flash:vlan.dat
🚨 Critical Trap: When you delete a VLAN, any ports still assigned to it become inactive. They do NOT automatically move back to VLAN 1. You must manually reassign them or they will be unable to pass traffic.

3.4VLAN Trunks ▾

3.4.1 Trunk Configuration Commands

Trunk ports carry all (or specified) VLANs between switches using 802.1Q tagging.

IOS — Configure a Trunk Port 
Switch(config)# interface gi0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 99
Switch(config-if)# switchport trunk allowed vlan 10,20,150
Switch(config-if)# end
🔒 Best practice: Change the native VLAN from the default (VLAN 1) to an unused VLAN (like 99) and restrict the allowed VLANs list to only what's needed. This reduces attack surface.

3.4.2 Resetting Trunk to Default

IOS — Reset Trunk Allowed VLANs and Native VLAN 
Switch(config)# interface gi0/1
Switch(config-if)# no switchport trunk allowed vlan
Switch(config-if)# no switchport trunk native vlan
Switch(config-if)# end

3.4.3 Verifying Trunk Configuration

show interfaces [int] trunk 
Switch# show interfaces gi0/1 trunk

Port        Mode         Encapsulation  Status        Native vlan
Gi0/1       on           802.1q         trunking      99

Port        Vlans allowed on trunk
Gi0/1       10,20,150

Port        Vlans allowed and active in management domain
Gi0/1       10,20,150

Port        Vlans in spanning tree forwarding state and not pruned
Gi0/1       10,20,150
📋 Read this output carefully on the exam. "Vlans allowed on trunk" = what you configured. "Vlans allowed and active" = what actually exists on the switch. If a VLAN is allowed but not active, it means it hasn't been created yet.

3.5Dynamic Trunking Protocol (DTP) ▾

3.5.1 Introduction to DTP

DTP is a Cisco proprietary protocol that allows switches to automatically negotiate whether a link becomes a trunk. It is enabled by default on all Cisco switch ports.

🚨 Security Risk: DTP should be disabled on all ports connecting to end devices (PCs, printers) and to non-Cisco switches. An attacker could send DTP frames to make a port trunk, gaining access to all VLANs.

3.5.2 DTP Negotiated Interface Modes

CommandMode NameBehavior
switchport mode dynamic autoDynamic AutoPassive — trunks only if the other side initiates (trunk or desirable)
switchport mode dynamic desirableDynamic DesirableActive — aggressively tries to form a trunk
switchport mode trunkTrunkAlways trunks; sends DTP frames
switchport mode accessAccessNever trunks; DTP inactive
switchport nonegotiateNonegotiateDisables DTP entirely; no frames sent
🎯 EXAM TIP — DTP Negotiation Matrix
SW1 \ SW2 Access Auto Desirable Trunk
Access Access Access Access Limited
Auto Access Access Trunk ✓ Trunk ✓
Desirable Access Trunk ✓ Trunk ✓ Trunk ✓
Trunk Limited Trunk ✓ Trunk ✓ Trunk ✓

3.5.3 Disabling DTP — Best Practice

IOS — Disable DTP on a Trunk Port 
! On uplink/trunk ports — disable DTP negotiation:
Switch(config)# interface gi0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport nonegotiate
Switch(config-if)# end
IOS — Disable DTP on an Access Port 
! On ports connected to PCs/printers — set to static access:
Switch(config)# interface fa0/3
Switch(config-if)# switchport mode access
Switch(config-if)# end
! Setting mode to 'access' stops all DTP negotiation

🎯Common Exam Traps — Module 3 ▾
❌
Trap 1: Deleting a VLAN with active ports.
Ports assigned to a deleted VLAN become inactive — they do NOT auto-move to VLAN 1. Students always forget this.
❌
Trap 2: Native VLAN mismatch.
If two switches have different native VLANs on a trunk, CDP generates a warning and traffic can land on the wrong VLAN. Both sides must match.
❌
Trap 3: VLAN 1 as native VLAN.
Leaving VLAN 1 as the native VLAN is a security risk. Best practice is to change it to an unused VLAN (e.g., 99) and never assign user devices to VLAN 1.
❌
Trap 4: DTP left enabled on end-device ports.
A malicious device can send DTP frames to convert an access port into a trunk, gaining access to all VLANs. Always run switchport mode access on end-device ports.
⚠️
Trap 5: Misreading show interfaces trunk.
"Allowed on trunk" = what you configured. "Allowed and active" = VLANs that actually exist. A VLAN can be allowed but inactive if it hasn't been created yet.
⚠️
Trap 6: auto + auto = NO trunk.
If both sides of a link are set to dynamic auto, neither side initiates, and the link stays in access mode. At least one side must be desirable or trunk for a trunk to form.
✅
Remember: The native VLAN frame is the only frame that travels across a trunk untagged. All other VLAN frames carry an 802.1Q tag.
