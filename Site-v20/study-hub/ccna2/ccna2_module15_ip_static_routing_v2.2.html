15.1Static Routes▾

15.1.1 Four Types of Static Routes

Static routes are commonly implemented even when a dynamic routing protocol is already running. Both IPv4 and IPv6 support all four types:

Standard Static Route

Explicit path to a specific remote network. The most common type — used to tell a router exactly how to reach a specific destination.

Default Static Route

Gateway of last resort — matches ALL packets that have no more-specific route. Zero bits need to match. IPv4: 0.0.0.0/0 — IPv6: ::/0.

Floating Static Route

Backup route — configured with a higher AD than the primary route. Hidden while the primary route is active. Activates automatically when the primary route disappears.

Summary Static Route

Combines multiple specific routes into one less-specific route. Example: one 10.0.0.0/22 instead of four /24 routes. Reduces routing table size.

15.1.2 Three Next-Hop Options

When configuring a static route, the next hop is identified in one of three ways — each creates a different type of static route entry:

Next-Hop Route — IP address only
ip route 192.168.2.0 255.255.255.0 172.16.2.2

Only the next-hop IP is specified. Router performs a recursive lookup to find the exit interface. Routing table shows: via 172.16.2.2

Directly Connected — exit interface only
ip route 192.168.2.0 255.255.255.0 s0/1/0

Only for point-to-point serial interfaces. Routing table shows: is directly connected, Serial0/1/0. Do NOT use on Ethernet.

Fully Specified — both interface AND IP
ip route 192.168.2.0 255.255.255.0 g0/0/1 172.16.2.2

Required on Ethernet (multi-access) networks. Routing table shows both: via 172.16.2.2, GigabitEthernet0/0/1. Also required when using link-local next-hop for IPv6.

15.1.3 IPv4 Static Route Command Syntax

ip route command — full syntax
Router(config)# ip route network-address subnet-mask { ip-address | exit-intf [ip-address] } [distance]
ParameterDescription
network-addressDestination IPv4 network address to add to the routing table
subnet-maskSubnet mask of the destination network
ip-addressNext-hop router IPv4 address — use on Ethernet/multi-access networks
exit-intfExit interface — use only on point-to-point serial links
exit-intf ip-addressFully specified — both interface and next-hop IP; required on multi-access Ethernet
distanceOptional AD value (1–255). Default = 1. Set higher to create a floating static route.

15.1.4 IPv6 Static Route Command Syntax

ipv6 route command — full syntax
Router(config)# ipv6 route ipv6-prefix/prefix-length { ipv6-address | exit-intf [ipv6-address] } [distance]

Same parameter structure as IPv4 — uses prefix/length notation instead of network + mask.

🚨
ipv6 unicast-routing must be configured globally before any IPv6 static routes will work. Without it, the router will not forward IPv6 packets regardless of how many ipv6 route commands are entered. This is the #1 IPv6 lab error.

15.1.5 Starting State — Before Any Static Routes

Reference topology: R1 ← serial → R2 ← serial → R3. Each router only knows its directly connected networks:

R1 routing table — before static routes 
R1# show ip route | begin Gateway
Gateway of last resort is not set
      172.16.0.0/16 is variably subnetted, 4 subnets, 2 masks
C        172.16.2.0/24 is directly connected, Serial0/1/0
L        172.16.2.1/32 is directly connected, Serial0/1/0
C        172.16.3.0/24 is directly connected, GigabitEthernet0/0/0
L        172.16.3.1/32 is directly connected, GigabitEthernet0/0/0

! R1 can ping R2's serial (directly connected) ✅
! R1 CANNOT ping R3's LAN 192.168.2.0/24 — no route exists ❌
15.2Configure IP Static Routes▾

15.2.1–15.2.2 Next-Hop Static Routes — IPv4 and IPv6

Only the next-hop IP address is specified. The router performs a recursive lookup to determine the exit interface from the next-hop address.

🔵 IPv4 — Next-Hop
R1(config)# ip route 172.16.1.0 255.255.255.0 172.16.2.2 R1(config)# ip route 192.168.1.0 255.255.255.0 172.16.2.2 R1(config)# ip route 192.168.2.0 255.255.255.0 172.16.2.2 R1# show ip route static S 172.16.1.0/24 [1/0] via 172.16.2.2 S 192.168.1.0/24 [1/0] via 172.16.2.2 S 192.168.2.0/24 [1/0] via 172.16.2.2
🟣 IPv6 — Next-Hop
R1(config)# ipv6 unicast-routing R1(config)# ipv6 route 2001:db8:acad:1::/64 2001:db8:acad:2::2 R1(config)# ipv6 route 2001:db8:cafe:1::/64 2001:db8:acad:2::2 R1(config)# ipv6 route 2001:db8:cafe:2::/64 2001:db8:acad:2::2 R1# show ipv6 route static S 2001:DB8:ACAD:1::/64 [1/0] via 2001:DB8:ACAD:2::2 S 2001:DB8:CAFE:2::/64 [1/0] via 2001:DB8:ACAD:2::2

15.2.3–15.2.4 Directly Connected Static Routes — IPv4 and IPv6

Only the exit interface is specified — no next-hop IP. The routing table shows "directly connected" even though the destination is remote.

⚠️
Only use directly connected static routes on point-to-point serial interfaces. On Ethernet multi-access networks, using an exit interface without a next-hop causes ARP proxy issues — the router ARPs for every destination address on that network. Always use a next-hop IP or a fully specified route on Ethernet.
🔵 IPv4 — Directly Connected
R1(config)# ip route 172.16.1.0 255.255.255.0 s0/1/0 R1(config)# ip route 192.168.1.0 255.255.255.0 s0/1/0 R1(config)# ip route 192.168.2.0 255.255.255.0 s0/1/0 ! Table shows "directly connected" — no via: S 172.16.1.0/24 is directly connected, Serial0/1/0 S 192.168.2.0/24 is directly connected, Serial0/1/0
🟣 IPv6 — Directly Connected
R1(config)# ipv6 route 2001:db8:acad:1::/64 s0/1/0 R1(config)# ipv6 route 2001:db8:cafe:1::/64 s0/1/0 R1(config)# ipv6 route 2001:db8:cafe:2::/64 s0/1/0 ! Table shows "directly connected": S 2001:DB8:ACAD:1::/64 [1/0] via Serial0/1/0, directly connected S 2001:DB8:CAFE:2::/64 [1/0] via Serial0/1/0, directly connected

15.2.5 IPv4 Fully Specified Static Route

Both exit interface AND next-hop IP are specified. Required when the exit interface is an Ethernet (multi-access) network — multiple devices may share the segment, so the router needs to know which specific device to ARP for.

IPv4 fully specified — Ethernet exit interface + next-hop IP 
! Link between R1 and R2 is Ethernet — G0/0/1:
R1(config)# ip route 172.16.1.0 255.255.255.0 GigabitEthernet 0/0/1 172.16.2.2
R1(config)# ip route 192.168.1.0 255.255.255.0 GigabitEthernet 0/0/1 172.16.2.2
R1(config)# ip route 192.168.2.0 255.255.255.0 GigabitEthernet 0/0/1 172.16.2.2

! Routing table shows BOTH interface AND next-hop:
R1# show ip route | begin Gateway
S        172.16.1.0/24 [1/0] via 172.16.2.2, GigabitEthernet0/0/1
S     192.168.1.0/24 [1/0] via 172.16.2.2, GigabitEthernet0/0/1
S     192.168.2.0/24 [1/0] via 172.16.2.2, GigabitEthernet0/0/1

15.2.6 IPv6 Fully Specified — Link-Local Next-Hop

A fully specified IPv6 static route is required when the next-hop is a link-local address (FE80::). Link-local addresses are not globally unique — the same FE80:: address could exist on multiple interfaces. The exit interface tells IOS which link the FE80:: address belongs to.

IPv6 link-local next-hop — MUST specify exit interface 
! This FAILS — IOS rejects link-local without exit interface:
R1(config)# ipv6 route 2001:db8:acad:1::/64 fe80::2
%Interface has to be specified for a link-local nexthop

! CORRECT — specify exit interface with link-local next-hop:
R1(config)# ipv6 route 2001:db8:acad:1::/64 s0/1/0 fe80::2

! Routing table shows both link-local address AND exit interface:
R1# show ipv6 route static
S   2001:DB8:ACAD:1::/64 [1/0]
    via FE80::2, Serial0/1/0      ← link-local + exit interface both shown
🚨
Link-local next-hop = fully specified route is MANDATORY. IOS explicitly rejects ipv6 route prefix fe80::x without an interface. This error message is tested directly — know both the error and the fix.

15.3Configure IP Default Static Routes▾

15.3.1 Default Static Route — The Quad-Zero Route

A default static route matches all packets that have no more-specific match in the routing table. Zero bits need to match — it is the gateway of last resort.

🔵 IPv4 Default Route
Network: 0.0.0.0 Mask: 0.0.0.0 Also called: "quad-zero route" Zero bits must match = everything matches Gateway of last resort
🟣 IPv6 Default Route
Prefix: ::/0 Zero bits must match = everything matches Equivalent to IPv4's 0.0.0.0/0 Gateway of last resort

When to use a default static route:

  • Stub router — has only one upstream neighbor; all non-local traffic goes to that one router
  • Edge router to ISP — the edge router doesn't need to know all internet routes; one default route sends everything to the ISP

15.3.2 Configure a Default Static Route

🔵 IPv4 Default Static Route
R1(config)# ip route 0.0.0.0 0.0.0.0 172.16.2.2 ! All unmatched IPv4 traffic → R2 at 172.16.2.2
🟣 IPv6 Default Static Route
R1(config)# ipv6 route ::/0 2001:db8:acad:2::2 ! All unmatched IPv6 traffic → R2 at 2001:db8:acad:2::2

15.3.3 Verify a Default Static Route

Verify IPv4 and IPv6 default static routes 
R1# show ip route static
Gateway of last resort is 172.16.2.2 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 172.16.2.2
!     ↑ S* = static candidate default route = gateway of last resort

R1# show ipv6 route static
S    ::/0 [1/0]
      via 2001:DB8:ACAD:2::2
💡
S* = static candidate default route. The asterisk marks this as the active gateway of last resort. The routing table header line "Gateway of last resort is 172.16.2.2 to network 0.0.0.0" confirms the default route is active.
15.4Configure Floating Static Routes▾

15.4.1 How Floating Static Routes Work

A floating static route is a backup route with a higher AD than the primary route. When the primary is active, the floating route is hidden — it only appears in the routing table when the primary disappears.

🔄 Floating Static Route — State Machine
NORMAL
Primary route (e.g., EIGRP AD=90) is in routing table. Floating static (AD=95) is NOT visible in show ip route — but IS visible in show running-config. Traffic flows through primary path.
FAILURE
Primary link goes down → EIGRP route removed from table → floating static route (AD=95) is now the best available path → router installs it in the routing table automatically.
RECOVERY
Primary link restored → EIGRP re-learns the route (AD=90) → floating static (AD=95) is removed from table → traffic returns to primary path automatically.

AD values to beat for common protocols:

Primary RoutePrimary ADFloating Static AD Must Be
Normal static route1≥ 2
Internal EIGRP90≥ 91
OSPF110≥ 111
RIP120≥ 121

15.4.2 Configure Floating Static Routes

The distance parameter at the end of the command sets the AD. No distance = default AD of 1.

Primary + floating default static routes — IPv4 and IPv6 
! Primary default routes → R2 (AD=1, default — preferred):
R1(config)# ip route 0.0.0.0 0.0.0.0 172.16.2.2
R1(config)# ipv6 route ::/0 2001:db8:acad:2::2

! Floating backup default routes → R3 (AD=5 — higher than 1, hidden until needed):
R1(config)# ip route 0.0.0.0 0.0.0.0 10.10.10.2 5
R1(config)# ipv6 route ::/0 2001:db8:feed:10::2 5
Verify — only primary routes appear in show ip route 
! Only the primary (AD=1) appears in the routing table:
R1# show ip route static | begin Gateway
Gateway of last resort is 172.16.2.2 to network 0.0.0.0
S*    0.0.0.0/0 [1/0] via 172.16.2.2   ← primary active

! But running-config shows BOTH routes are configured:
R1# show run | include ipv6 route
ipv6 route ::/0 2001:db8:feed:10::2 5  ← floating (AD=5) — in config, not in table
ipv6 route ::/0 2001:db8:acad:2::2     ← primary (AD=1) — in config AND in table

15.4.3 Test the Floating Static Route

Simulate failure by shutting R2's interfaces. R1 automatically detects the link down and installs the floating route:

After R2 failure — floating routes activate automatically 
! After R2 fails — floating routes now in table with AD=5:
R1# show ip route static | begin Gateway
Gateway of last resort is 10.10.10.2 to network 0.0.0.0
S*    0.0.0.0/0 [5/0] via 10.10.10.2   ← floating now active — note [AD=5]

R1# show ipv6 route static | begin ::
S    ::/0 [5/0]
      via 2001:DB8:FEED:10::2           ← floating IPv6 now active — note [AD=5]
✅
The AD value in brackets changes from [1/0] to [5/0] when the floating route activates — this is the clearest indicator that the backup path is in use. When R2 recovers, traffic automatically switches back to the primary (AD=1) path.
15.5Configure Static Host Routes▾

15.5.1 Host Routes — /32 and /128

A host route matches exactly one IP address — not a network:

IPv4 Host Route
/32
255.255.255.255

Matches exactly one IPv4 address. The longest possible prefix for IPv4.

IPv6 Host Route
/128
(no dotted-decimal equivalent)

Matches exactly one IPv6 address. The longest possible prefix for IPv6.

Three ways host routes appear in the routing table:

  1. Automatically installed (L routes) — IOS adds /32 or /128 for every IP address configured on the router itself
  2. Static host route — manually configured to reach a specific server or device
  3. Automatically obtained — through other methods covered in later courses

15.5.2 Automatically Installed Host Routes (L Routes)

When an IP address is configured on an interface and the interface becomes active, IOS automatically adds two routes — a C route for the network and an L route for the router's own interface address:

Automatically installed C and L routes 
Branch# show ip route | begin Gateway
      198.51.100.0/24 is variably subnetted, 2 subnets, 2 masks
C        198.51.100.0/30 is directly connected, Serial0/1/0   ← C = connected network
L        198.51.100.1/32 is directly connected, Serial0/1/0   ← L = router's own /32

Branch# show ipv6 route | begin ::
C   2001:DB8:ACAD:1::/64 [0/0]
     via Serial0/1/0, directly connected          ← C = connected network
L   2001:DB8:ACAD:1::1/128 [0/0]                 ← L = router's own /128
     via Serial0/1/0, receive
L   FF00::/8 [0/0]                                ← L = multicast (always present)
     via Null0, receive
💡
The L route (/32 or /128) allows the router to quickly recognize packets addressed to itself — so it processes them locally instead of trying to forward them. Without the L route, the router would have to do a full routing table lookup for every packet addressed to its own interface.

15.5.4–15.5.5 Configure and Verify Static Host Routes

Static host routes direct traffic to a specific single device — commonly a known server:

Static host routes to a server at 209.165.200.238 
! IPv4 static host route (/32):
Branch(config)# ip route 209.165.200.238 255.255.255.255 198.51.100.2

! IPv6 static host route (/128):
Branch(config)# ipv6 route 2001:db8:acad:2::238/128 2001:db8:acad:1::2

! Verify:
Branch# show ip route | begin Gateway
      209.165.200.0/32 is subnetted, 1 subnets
S        209.165.200.238 [1/0] via 198.51.100.2   ← /32 host route

Branch# show ipv6 route
S    2001:DB8:ACAD:2::238/128 [1/0]               ← /128 host route
      via 2001:DB8:ACAD:1::2

15.5.6 IPv6 Static Host Route with Link-Local Next-Hop

Same rule as any IPv6 route with a link-local next-hop — the exit interface is mandatory:

IPv6 host route with link-local next-hop — fully specified 
! Remove old route first:
Branch(config)# no ipv6 route 2001:db8:acad:2::238/128 2001:db8:acad:1::2

! Replace with fully specified — link-local next-hop requires exit interface:
Branch(config)# ipv6 route 2001:db8:acad:2::238/128 serial 0/1/0 fe80::2

! Verify — table shows both link-local AND exit interface:
Branch# show ipv6 route | begin ::
S   2001:DB8:ACAD:2::238/128 [1/0]
     via FE80::2, Serial0/1/0     ← link-local + exit interface both displayed

🎯Common Exam Traps — Module 15▾
❌
Trap 1: Directly connected static routes — serial only, not Ethernet.
Using only an exit interface on Ethernet causes ARP proxy problems — the router ARPs for every destination. On Ethernet multi-access networks, always use a next-hop IP address or a fully specified route (interface + IP).
❌
Trap 2: IPv6 link-local next-hop requires fully specified route.
ipv6 route prefix fe80::2 is rejected by IOS with the message: %Interface has to be specified for a link-local nexthop. Correct: ipv6 route prefix s0/1/0 fe80::2. This is tested directly in labs and quizzes.
❌
Trap 3: Floating static route is NOT visible in show ip route while primary is active.
The floating route only appears in the routing table after the preferred route disappears. To verify it is configured, use show running-config | section ip route — it appears there regardless of table state.
❌
Trap 4: Floating static AD must be HIGHER than the route it backs up.
To back up EIGRP (AD=90): use AD ≥ 91. OSPF (AD=110): use AD ≥ 111. Normal static (AD=1): use AD ≥ 2. If you set a lower AD, the floating route becomes the preferred route — defeating its entire purpose.
❌
Trap 5: ipv6 unicast-routing is always required for IPv6 routing.
Without this global command, no IPv6 static routes will forward traffic — even if every ipv6 route command is correct. Always configure ipv6 unicast-routing first on any router that needs to forward IPv6 packets.
❌
Trap 6: Default static route — 0.0.0.0 0.0.0.0 for IPv4, ::/0 for IPv6.
IPv4 quad-zero route: ip route 0.0.0.0 0.0.0.0 [next-hop]. IPv6: ipv6 route ::/0 [next-hop]. S* in the routing table = static candidate default = gateway of last resort is set.
⚠️
Trap 7: show run | section ip route vs show ip route static.
show ip route static only shows routes currently in the table. show running-config | section ip route shows everything configured — including floating routes that aren't active. Always use both for complete verification.
⚠️
Trap 8: Host routes — IPv4 = /32 (255.255.255.255), IPv6 = /128.
These match exactly one IP address. L routes in the table are automatically installed /32 or /128 for the router's own interface addresses. Static host routes use the same mask but are manually configured to reach a specific external device.
⚠️
Trap 9: Recursive lookup happens with next-hop-only static routes.
When only the next-hop IP is given, the router must do a second lookup to find the exit interface for that next-hop address. Fully specified routes eliminate this second lookup. Both work correctly — the difference is efficiency.
⚠️
Trap 10: Removing a static route requires exact match of parameters.
no ip route 192.168.2.0 255.255.255.0 172.16.2.2 — all parameters must match the original command exactly. If the original used an interface, the no command must also specify the interface.
⚠️
Trap 11: "Directly connected" in routing table for static route ≠ actually connected.
When you configure a static route with only an exit interface (no next-hop IP), the routing table displays "is directly connected, Serial0/1/0" — even though the destination network is remote. This is just how IOS displays exit-interface-only static routes.
⚠️
Trap 12: AD of floating route activates — look for [5/0] instead of [1/0].
When the floating route activates, show ip route static shows the AD value in brackets changing from [1/0] to [5/0] (or whatever AD was configured). This is the exam-tested indicator that the backup path is in use.
✅
Module 15 quick-reference — all static route command patterns:

Next-hop: ip route net mask next-hop-ip
Serial P2P: ip route net mask s0/1/0
Ethernet: ip route net mask g0/0/1 next-hop-ip (fully specified)
Default IPv4: ip route 0.0.0.0 0.0.0.0 next-hop-ip
Default IPv6: ipv6 route ::/0 next-hop-ip
Floating: append AD (e.g., 95) to the end of any static route command
Host IPv4: ip route x.x.x.x 255.255.255.255 next-hop-ip
Host IPv6: ipv6 route prefix/128 next-hop-ip
Link-local next-hop: ipv6 route prefix exit-intf fe80::x (exit-intf REQUIRED)
Verify table: show ip route static / show ipv6 route static
Verify config: show run | section ip route / show run | section ipv6 route
