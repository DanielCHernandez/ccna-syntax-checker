14.1Path Determination▾

14.1.1 Two Functions of a Router

A router connects multiple networks — each interface belongs to a different IP network. The two primary functions are:

FunctionDescription
1. Determine the best pathExamine the destination IP address and search the routing table for the longest matching prefix
2. Forward the packetEncapsulate the IP packet in the correct Layer 2 frame for the outgoing interface and send it toward the destination

14.1.3 Best Path = Longest Match

The longest match is how a router selects the best route. It is the routing table entry with the greatest number of matching far-left bits compared to the destination IP address.

  • Each route entry has a prefix (network address) and prefix length
  • For a route to be a match, the minimum number of far-left bits defined by the prefix length must match the destination IP
  • The route with the most matching bits wins — regardless of any other factor
  • The IP packet contains only the destination IP address — not the prefix length
🔍 IPv4 Longest Match Example — Destination: 172.16.0.10
Route 1: 172.16.0.0/12 12 bits
Route 2: 172.16.0.0/18 18 bits
Route 3: 172.16.0.0/26 26 bits ✅ WINNER
🔍 IPv6 Longest Match Example — Destination: 2001:db8:c000::99
Route 1: 2001:db8:c000::/40 40 bits
Route 2: 2001:db8:c000::/48 48 bits ✅ WINNER
Route 3: 2001:db8:c000:5555::/64 ❌ NOT a match

Route 3 requires 64 matching bits but only 48 exist. A route whose prefix length demands more bits than actually match is NOT a match at all.

🚨
A "close" route that requires more matching bits than exist is NOT a match. Route 3 above looks like it covers the destination, but its /64 requires 64 bits to match — only 48 do. The router ignores it completely. This is a frequently tested trap.

14.1.6 Build the Routing Table

Routers populate their routing table from three sources:

SourceHow AddedRequires
Directly ConnectedAutomatically when interface is configured with IP and active (up/up)Just interface configuration + no shutdown
Static RoutesManually configured by administrator — explicit path to a specific networkAdmin must type each route; must be updated manually when topology changes
Dynamic Routing ProtocolsEIGRP, OSPF, RIP automatically exchange routing info between routersProtocol must be configured on all participating routers
💡
Default Route — Gateway of Last Resort
When no specific route matches the destination, the router uses the default route.
IPv4 default: 0.0.0.0/0 — zero bits need to match — catches everything
IPv6 default: ::/0 — same concept for IPv6
Can be set as a static route or learned from a dynamic protocol.
14.2Packet Forwarding▾

14.2.1 Packet Forwarding Decision Process

  1. Data link frame with encapsulated IP packet arrives on ingress interface — router strips the L2 frame
  2. Router examines the destination IP address in the packet header
  3. Router searches routing table for the longest matching prefix
  4. Router encapsulates the packet in the correct L2 frame for the egress interface and forwards it
  5. If no matching route exists and no default route → packet is dropped (ICMP unreachable sent to source)

Three Possible Outcomes After Longest Match

OutcomeSituationAction
Forward to directly connected deviceDestination is on a directly connected networkRouter needs the destination's MAC → sends ARP request (IPv4) or ICMPv6 NS (IPv6)
Forward to next-hop routerEgress interface leads to a remote networkRouter resolves next-hop router's MAC (not the packet destination's MAC) via ARP/neighbor cache; re-encapsulates and forwards
Drop the packetNo matching route and no default routePacket discarded; ICMP Destination Unreachable sent to source
⚠️
For the next-hop scenario: the router looks up the next-hop router's IP address in its ARP table — NOT the packet's final destination IP. The destination IP travels unchanged inside the packet all the way to the final router. Only the Layer 2 frame changes at each hop.

14.2.2 End-to-End Packet Forwarding

The data link frame changes at every hop — the router strips the incoming frame and re-encapsulates the IP packet in a new frame for the outgoing interface. The IP packet itself (source/destination IP) never changes:

  PC1 ──Ethernet──► R1 ──Ethernet──► R2 ──Serial──► R3 ──Ethernet──► PC2

  Hop 1 (PC1 → R1):  Ethernet frame  │ ARP for R1's MAC (default gateway)
  Hop 2 (R1 → R2):   Ethernet frame  │ ARP for R2's next-hop MAC
  Hop 3 (R2 → R3):   HDLC/PPP frame  │ No ARP needed — point-to-point link
  Hop 4 (R3 → PC2):  Ethernet frame  │ ARP for PC2's MAC (destination)

  IP packet (source IP / destination IP) = UNCHANGED throughout
💡
Point-to-point serial links have no MAC addresses. The router encapsulates in HDLC or PPP and uses the broadcast-equivalent Layer 2 address. No ARP needed — there are only two devices on the link and the router always knows who the other end is.

14.2.3 Packet Forwarding Mechanisms

Process Switching
⚠️ Legacy — Rarely Used
  • Every packet sent to the CPU for routing table lookup
  • CPU consulted for every single packet — even consecutive packets to the same destination
  • Extremely slow — CPU becomes the bottleneck
  • Still available on Cisco routers but almost never used
Fast Switching
⚡ Older — Cache-Based
  • First packet in a flow is process-switched → result cached in fast-switching cache
  • Subsequent packets to the same destination use the cache — no CPU lookup
  • Significantly faster than process switching
  • Successor to process switching — now largely replaced by CEF
CEF — Cisco Express Forwarding
✅ Default on All Modern Cisco Devices
  • Builds a FIB (Forwarding Information Base) from the routing table
  • Builds an adjacency table from the ARP table — stores L2 next-hop info
  • Both tables are pre-built when the network converges — not per-packet
  • Tables update only on topology changes — not triggered by packet arrivals
  • All packets processed entirely in the data plane — no CPU involvement
  • Fastest mechanism — default on all modern Cisco routers and multilayer switches
🎯 CEF IS THE DEFAULT — KNOW THIS
When the exam asks about the default Cisco packet forwarding mechanism: CEF.

FIB = the forwarding table (built from routing table)
Adjacency table = Layer 2 next-hop info (built from ARP table)
Both are pre-populated after convergence. No per-packet CPU lookup. Fastest.

14.3.2 Full Router Configuration — R1

Complete R1 configuration — hostname, security, interfaces, IPv4 and IPv6 
Router> enable
Router# configure terminal
Router(config)# hostname R1

! Security
R1(config)# enable secret class
R1(config)# service password-encryption
R1(config)# banner motd #
***WARNING: Unauthorized access is prohibited!***
#

! Console line
R1(config)# line console 0
R1(config-line)# logging synchronous
R1(config-line)# password cisco
R1(config-line)# login
R1(config-line)# exit

! VTY lines (Telnet/SSH)
R1(config)# line vty 0 4
R1(config-line)# password cisco
R1(config-line)# login
R1(config-line)# transport input ssh telnet
R1(config-line)# exit

! Enable IPv6 routing (required for IPv6 routing table)
R1(config)# ipv6 unicast-routing

! GigabitEthernet 0/0/0 — LAN interface
R1(config)# interface gigabitethernet 0/0/0
R1(config-if)# description Link to LAN 1
R1(config-if)# ip address 10.0.1.1 255.255.255.0
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64
R1(config-if)# ipv6 address fe80::1:a link-local
R1(config-if)# no shutdown
R1(config-if)# exit

! Serial 0/1/1 — WAN link to R2
R1(config)# interface serial 0/1/1
R1(config-if)# description Link to R2
R1(config-if)# ip address 10.0.3.1 255.255.255.0
R1(config-if)# ipv6 address 2001:db8:acad:3::1/64
R1(config-if)# ipv6 address fe80::1:c link-local
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# end
R1# copy running-config startup-config
💡
ipv6 unicast-routing is required to enable IPv6 routing on a Cisco router. Without this command, the router does not process or forward IPv6 packets — it only processes IPv4. This command is frequently omitted in labs and causes all IPv6 connectivity to fail.

14.3.4 Filter Command Output with Pipe ( | )

The pipe character | filters show command output. Four filter parameters:

FilterWhat It Does
section [text]Shows the entire config section starting with the matching line
include [text]Shows only lines that contain the match — hides everything else
exclude [text]Shows all lines EXCEPT those containing the match
begin [text]Shows all lines starting from the first match onward
Pipe filter examples 
R1# show running-config | section line vty       ! Show VTY config section only
R1# show ipv6 interface brief | include up        ! Show only "up" interfaces
R1# show ip interface brief | exclude unassigned  ! Hide interfaces with no IP
R1# show ip route | begin Gateway                 ! Start output from "Gateway" line

14.4.1 Route Source Codes

The first letter of each routing table entry identifies how the route was learned:

C
Connected
AD = 0
L
Local
AD = 0
S
Static
AD = 1
O
OSPF
AD = 110
D
EIGRP
AD = 90
R
RIP
AD = 120

* next to a code (e.g., S*) = this route is a candidate default route (gateway of last resort)

14.4.2 Three Routing Table Principles

PrinciplePlain English
Every router decides alone based on its own tableR1 makes forwarding decisions using only R1's routing table. It has no knowledge of what's in R2's or R3's table.
Routing tables don't need to match between routersR1 having a route to Network X via R2 does NOT mean R2 has that same route. Each router's table is independent.
A forward route does not imply the return route existsR1 knowing how to reach PC3 does NOT mean R1 knows the return path from PC3 back to R1. Routing is asymmetric by default.

14.4.3 Route Entry Anatomy

Every routing table entry contains seven fields. Here is a sample OSPF route dissected:

O 10.0.4.0/24 [110/50] via 10.0.3.2, 00:24:22, Serial0/1/1
Route sourceO = learned via OSPF
Destination10.0.4.0/24 = network prefix and prefix length
AD[110 = Administrative Distance — trustworthiness of OSPF routes
Metric/50] = OSPF cost to reach this network
Next-hopvia 10.0.3.2 = IP address of the next router to send packets to
Timestamp00:24:22 = how long since this route was learned
Exit interfaceSerial0/1/1 = outgoing interface used to reach the destination

14.4.4 C and L Routes — Directly Connected

When an interface is configured with an IP address and becomes active (up/up), two routes are automatically added:

Directly connected routes — C and L 
C    10.0.1.0/24 is directly connected, GigabitEthernet0/0/0
L    10.0.1.1/32 is directly connected, GigabitEthernet0/0/0
CodeWhat It IsPrefix LengthPurpose
CThe directly connected network prefixAs configured (e.g., /24)Tells the router this network is reachable through this interface
LThe router's own IP address on that interface/32 (IPv4) or /128 (IPv6)Allows the router to recognize packets addressed to itself — so it processes them locally instead of forwarding them

14.4.5 Static Routes

Manually configured by the administrator. Not automatically updated when topology changes.

  • Less CPU and bandwidth than dynamic protocols
  • More secure — don't advertise network information
  • Must be manually reconfigured when topology changes

Three primary uses:

  • Default route — stub router pointing to ISP; forward all unmatched traffic to one next-hop
  • Stub networks — networks accessed by only one path; no need for dynamic protocol overhead
  • Explicit path control — admin forces traffic through a specific path regardless of what dynamic protocols prefer
Static routes in show ip route / show ipv6 route 
R1# show ip route static
S    10.0.4.0/24 [1/0] via 10.0.3.2   ! S = static, AD=1, metric=0

R1# show ipv6 route static
S    2001:DB8:ACAD:4::/64 [1/0]
      via 2001:DB8:ACAD:3::2

14.4.7 Dynamic Routes

Dynamically learned from other routers via routing protocols. Automatically update when topology changes.

Dynamic routes — OSPF example 
R1# show ip route
O    10.0.4.0/24 [110/50] via 10.0.3.2, 00:24:22, Serial0/1/1
O    10.0.5.0/24 [110/50] via 10.0.3.2, 00:24:15, Serial0/1/1

R1# show ipv6 route
O    2001:DB8:ACAD:4::/64 [110/50]
      via FE80::2:C, Serial0/1/1   ! IPv6 uses LINK-LOCAL of next-hop — not global unicast
🚨
IPv6 dynamic routes show the link-local address of the next-hop router — not the global unicast address. In show ipv6 route, the "via" field shows FE80::x:x. This catches many students off guard.

14.4.9 Default Route — Gateway of Last Resort

Matches any packet when no more-specific route exists. Used as a catch-all for traffic with no other match.

ProtocolDefault Route EntryMeaning
IPv40.0.0.0/0Zero bits need to match — any IPv4 destination matches this
IPv6::/0Zero bits need to match — any IPv6 destination matches this
Default route in routing table — S* means gateway of last resort 
R2# show ip route
S*    0.0.0.0/0 [1/0] via 209.165.200.226   ! S* = static default route

R2# show ipv6 route
S    ::/0 [1/0]
      via 2001:DB8:FEED:224::2               ! IPv6 static default route
✅
The * marks this as the candidate default route. When R2 advertises this default via OSPF, R1 installs it as its gateway of last resort — any traffic R1 can't route specifically goes to R2, which sends it to the ISP. This is how a stub router connects to the internet.

14.4.10 IPv4 vs IPv6 Routing Table Structure

FeatureIPv4 Routing TableIPv6 Routing Table
StructureClassful hierarchy — parent routes + indented child routesNo classful history — all entries aligned the same way
Parent routeLeft-aligned, no route source code (e.g., 10.0.0.0/8 is variably subnetted)Does not exist in IPv6
Child routesIndented below parent — actual subnet entriesAll entries are at the same level
ReadabilityMore complex to read — legacy classful structureCleaner — every entry formatted identically
IPv4 parent/child structure in show ip route 
R1# show ip route
      10.0.0.0/8 is variably subnetted, 8 subnets, 2 masks   ← PARENT (classful /8)
C        10.0.1.0/24 is directly connected, Gi0/0/0           ← child subnet
L        10.0.1.1/32 is directly connected, Gi0/0/0           ← child local route
C        10.0.3.0/24 is directly connected, Serial0/1/1       ← child subnet
O        10.0.4.0/24 [110/50] via 10.0.3.2, Serial0/1/1      ← child OSPF route

14.4.12 Administrative Distance (AD)

When the router learns the same network from multiple sources, AD determines which route is installed in the routing table. Lower AD = more trusted = preferred.

0Directly Connected
1Static Route
90Internal EIGRP
110OSPF
120RIP
170External EIGRP
200Internal BGP
⚠️
AD is NOT a measure of which protocol is "better." It only determines installation priority when multiple sources know the same network. A static route (AD 1) always beats OSPF (AD 110) for the same destination — intentional, so admins can override dynamic routing. AD does NOT affect how a routing protocol selects its best path internally — that's what metrics are for.
14.5Static and Dynamic Routing▾

14.5.1 When to Use Static vs Dynamic

FeatureDynamic RoutingStatic Routing
Configuration complexityIndependent of network size — same protocol config regardlessIncreases with network size — every route must be typed manually
Topology changesAdapts automatically — finds alternate pathsAdmin must manually reconfigure every affected router
ScalabilitySimple to very complex topologiesSimple topologies only — impractical for large networks
SecurityRouting updates must be explicitly securedInherently more secure — routes not advertised to other routers
Resource usageCPU, memory, and link bandwidth for protocol messagesNo additional overhead — routes are fixed
Path predictabilityDepends on topology and protocol algorithmFully predictable — admin defines every path explicitly
✅
Real networks use both. Static routes handle default routes and stub networks; dynamic protocols handle scalable automatic routing. They complement each other.

14.5.2 Dynamic Routing Protocol Evolution

ProtocolTypeKey Notes
RIPv1Distance vector1988; first widely used; 15-hop maximum; classful only
RIPv2Distance vectorClassless; supports VLSM; still 15-hop limit; limited scalability
IGRPCisco proprietaryReplaced by EIGRP
EIGRPCisco hybridAdvanced distance vector; composite metric; supports unequal-cost load balancing
OSPFLink stateOpen standard; scales to large networks; cost-based metric
BGPPath vector (EGP)Internet standard; connects ISPs and autonomous systems; routes all internet traffic
IPv6 variantsVariousRIPng, EIGRP for IPv6, OSPFv3, IS-IS for IPv6, BGP-MP

14.5.3 Dynamic Routing Protocol Components

ComponentDescriptionExamples
Data structuresTables and databases stored in RAMRouting table, topology table (OSPF LSDB), neighbor table (EIGRP)
Routing protocol messagesMessages to discover neighbors, share routing info, and maintain accuracyOSPF Hello, LSA; EIGRP Hello, Update, Query, Reply; RIP Response
AlgorithmA finite set of steps to determine the best path and update the routing tableDijkstra SPF (OSPF), DUAL (EIGRP), Bellman-Ford (RIP)

14.5.4 Best Path — Metrics

Each dynamic routing protocol uses its own metric. Lower metric = preferred path.

RIP
Hop Count

Each router along the path counts as 1 hop. Maximum 15 hops — 16 = unreachable. Simple but completely ignores link bandwidth. A 1-hop path over a 56K modem beats a 2-hop path over 10 Gbps fiber.

OSPF
Cost

Based on cumulative bandwidth. Reference bandwidth (default 100 Mbps) divided by link bandwidth = cost. Faster links = lower cost = preferred. Much more accurate than hop count. Cost is additive along the path.

EIGRP
Composite Metric

Based on slowest bandwidth and cumulative delay by default. Can optionally include load and reliability. Most flexible and most accurate of the three. Supports both equal and unequal-cost load balancing.

14.5.5 Load Balancing

When two or more paths to the same destination have identical metrics, the router installs all paths in the routing table and distributes traffic across all of them — equal-cost load balancing.

  • Enabled automatically by all routing protocols — no configuration required
  • Also works with multiple static routes to the same destination using different next-hops
  • Improves overall throughput and utilizes all available links
🎯 EIGRP ONLY — UNEQUAL-COST LOAD BALANCING
EIGRP is the only routing protocol that supports unequal-cost load balancing using the variance command.

All other protocols (OSPF, RIP, static routes) only load balance across equal-cost paths.

This is a very frequently tested exam distinction.

🎯Common Exam Traps — Module 14▾
❌
Trap 1: Longest match = most matching far-left bits.
A /26 always beats a /18 for the same destination. More bits = more specific = preferred. Never pick the "closest-looking" route — always count the matching bits.
❌
Trap 2: A route that needs more bits than actually match is NOT a match at all.
A /64 route that only has 48 matching bits is completely ignored — the router treats it as if it doesn't exist. This is one of the most tricky longest-match exam questions.
❌
Trap 3: CEF is the default Cisco packet forwarding mechanism.
Not process switching, not fast switching. CEF pre-builds the FIB (from routing table) and adjacency table (from ARP). All packets are processed in the data plane. No per-packet CPU involvement.
❌
Trap 4: IPv6 dynamic routes show the link-local address of the next-hop.
In show ipv6 route, the "via" field for OSPF/EIGRP routes shows FE80::x:x — not the global unicast address. This surprises students who expect to see a global address.
❌
Trap 5: AD determines route installation — lower AD wins.
Connected=0, Static=1, EIGRP=90, OSPF=110, RIP=120. A static route (AD 1) always beats OSPF (AD 110) for the same destination. AD is NOT a measure of which protocol is "better" — it only controls which source gets its route into the table.
❌
Trap 6: The L (local) route is /32 for IPv4 — not /24 or the same as C.
When G0/0/0 has IP 10.0.1.1/24, the routing table shows both C (10.0.1.0/24) and L (10.0.1.1/32). The /32 local route lets the router recognize packets addressed directly to itself without full table lookup.
❌
Trap 7: ipv6 unicast-routing must be explicitly configured.
Without this global command, a Cisco router will not route IPv6 packets — even if IPv6 addresses are configured on every interface. All IPv6 connectivity fails silently. This is the #1 IPv6 lab error.
⚠️
Trap 8: Only EIGRP supports unequal-cost load balancing.
All other protocols (OSPF, RIP) only load balance across equal-cost paths. EIGRP uses the variance command to allow unequal-cost. This is directly tested on the M14–16 checkpoint exam.
⚠️
Trap 9: Routing table principles — every router is independent.
R1 knowing a route does NOT mean R2 knows the same route. R1 knowing the forward path to PC3 does NOT guarantee R1 knows the return path. Routing is completely independent per router.
⚠️
Trap 10: The default route — 0.0.0.0/0 (IPv4) and ::/0 (IPv6).
Zero bits need to match — it catches any destination with no better match. It is the gateway of last resort. Marked with * in the routing table (e.g., S* = static default candidate).
⚠️
Trap 11: IPv4 routing table has parent/child structure — IPv6 does not.
The classful hierarchy is visible in show ip route — left-aligned parent routes with indented child subnets. IPv6 has no classful history so every entry is formatted the same. Don't confuse the parent route line as a usable route entry.
⚠️
Trap 12: Metrics — RIP=hop count, OSPF=cost (bandwidth), EIGRP=composite.
RIP's maximum is 15 hops (16 = unreachable). OSPF cost = reference bandwidth ÷ link bandwidth (default 100 Mbps reference). EIGRP uses slowest bandwidth + cumulative delay by default.
⚠️
Trap 13: Point-to-point serial links need no ARP.
Serial interfaces have no MAC addresses. The router encapsulates in HDLC or PPP. No ARP is needed because there are only two devices on the link — the router already knows who the other end is.
✅
Module 14 quick-reference summary:

Longest match: most far-left matching bits wins
Default forwarding: CEF (FIB + adjacency table)
Route codes: C=connected, L=local(/32), S=static, O=OSPF, D=EIGRP, R=RIP
AD: Connected=0 > Static=1 > EIGRP=90 > OSPF=110 > RIP=120
Metrics: RIP=hops(max 15), OSPF=cost(bandwidth), EIGRP=composite
Unequal-cost load balancing: EIGRP only
IPv6 dynamic via: link-local address of next-hop
Default route: 0.0.0.0/0 (IPv4) / ::/0 (IPv6)
Enable IPv6 routing: ipv6 unicast-routing (global config)
