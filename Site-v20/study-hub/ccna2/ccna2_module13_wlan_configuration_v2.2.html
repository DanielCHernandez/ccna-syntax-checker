13.1Remote Site WLAN Configuration▾

13.1.2 The Wireless Router

Remote workers, small branch offices, and home networks use a wireless router — also called an integrated router because it combines three roles in one device:

  • Access Point — provides 802.11 wireless access and broadcasts the SSID
  • Switch — typically a 4-port Ethernet switch for wired devices
  • Router — provides the default gateway for internet access

Connected to a cable or DSL modem for internet. Also provides: WLAN security, DHCP services, NAT, and QoS.

🚨
Change all defaults immediately. Default IP addresses, usernames, and passwords for wireless routers are freely searchable on the internet. Your very first action after accessing a new wireless router must be to change the admin credentials.

13.1.3 Log in to the Wireless Router

Access the GUI through a web browser using the router's default IP address — commonly 192.168.0.1 or 192.168.1.1. Default credentials are typically admin / admin — check the device documentation. Change these immediately after first login.

13.1.4 Basic Network Setup — Six Steps

  1. Log in to the router from a web browser — use the default IP address to reach the GUI
  2. Change the default administrative password — found under Administration tab; default credentials are publicly known
  3. Log in with the new administrative password — confirm the new password works before continuing
  4. Change the default DHCP IPv4 addresses — change from default subnet; example: use 10.10.10.1/24 instead of 192.168.0.1/24
  5. Renew the IP address — run ipconfig /renew on the PC; when the router IP changes, the PC loses access and must renew its DHCP lease
  6. Log in to the router with the new IP address — resume configuration at the new management IP
💡
Why `ipconfig /renew` is required at Step 5: When you change the router's LAN IP through the GUI and save, the PC immediately loses access — its gateway and DNS are now wrong. Running ipconfig /renew forces the PC to request a fresh DHCP lease from the router's new IP, restoring connectivity.

13.1.5 Basic Wireless Setup — Six Steps

  1. View the WLAN defaults — review what is already configured (SSID, channel, security) before making changes
  2. Change the network mode — select the 802.11 standard. "Legacy" or "Mixed" supports multiple generations simultaneously; mixed mode runs at the speed of the slowest connected client
  3. Configure the SSID — change from the default to a descriptive name (e.g., "OfficeNet"). If SSID broadcast is disabled, clients must manually enter the SSID to connect
  4. Configure the channel — select a non-overlapping channel (1, 6, or 11 for 2.4 GHz) to avoid interference from adjacent APs. Example: router on channel 6
  5. Configure the security mode — select WPA2 Personal (WPA2-PSK) with AES encryption — currently the strongest recommended mode for home/small office
  6. Configure the passphrase — the WPA2 Personal pre-shared key that wireless clients must enter to connect. Stronger = better.

13.1.6 Configure a Wireless Mesh Network

A single wireless router covers approximately 45 meters indoors / 90 meters outdoors. To extend coverage, add APs with the same WLAN settings. Key rules:

  • All APs share the same SSID and security settings
  • Adjacent APs must use different non-overlapping channels to avoid interference
  Example mesh — 3 devices covering a large office:
  Wireless Router:  Channel 6   ← center of building
  AP1:              Channel 1   ← left wing
  AP2:              Channel 11  ← right wing

  Channels 1, 6, and 11 don't overlap → no mutual interference
💡
Modern WMN systems (Eero, Google Nest, Netgear Orbi) are configured through smartphone apps — very simplified setup. Search "best wi-fi mesh network system" for current options.

13.1.7 NAT for IPv4

The wireless router uses NAT (Network Address Translation) to allow all LAN devices with private IPv4 addresses to share a single public IP address for internet access.

InterfaceIP AddressTypeRoutable?
WAN (internet-facing)209.165.201.11Public✅ Yes — internet routable
LAN (internal network)10.10.10.1Private❌ No — not internet routable

NAT translates private → public for outbound traffic and reverses for inbound. All devices on the LAN appear to the internet as sharing the same single public IP address.

✅
If the ISP provides IPv6, each device gets its own unique globally routable IPv6 address — NAT is not needed. NAT is an IPv4 workaround for address exhaustion.

13.1.8 Quality of Service (QoS)

QoS prioritizes certain traffic types to guarantee performance for time-sensitive applications:

  • Voice and video — time-sensitive — given higher priority
  • Email and web browsing — not time-sensitive — given lower priority
  • Traffic can also be prioritized per specific port number

QoS settings are found under Advanced menus — sometimes labeled "bandwidth control." Consult the router's documentation for exact location.

13.1.9 Port Forwarding

Wireless routers block all unsolicited inbound TCP/UDP ports by default. Port forwarding creates rules that map external ports to internal devices:

TypeHow It WorksExample
Port ForwardingStatic rule — external port always forwards to a specific internal IP and portPort 80 (HTTP) → internal web server at 10.10.10.50 — all inbound HTTP requests go to that server
Port TriggeringDynamic rule — outbound traffic on a trigger port range temporarily opens an inbound port for that device onlyGame traffic on outbound ports 27000–27100 triggers inbound port 56 (chat) to open for that device only
💡
Port triggering vs port forwarding: Port forwarding is always active — any inbound request on that port is forwarded. Port triggering is temporary and device-specific — it only opens when triggered by outbound traffic from that specific device, and closes when the trigger traffic stops.

13.2.3 Log in to the WLC

Access the WLC through a web browser using the management IP address. Credentials are configured during initial WLC setup (first-time wizard).

The Network Summary dashboard shows at a glance:

  • Number of configured WLANs
  • Number of associated APs
  • Number of active clients
  • Number of detected rogue APs and clients

13.2.5 Advanced Settings

The basic WLC view shows limited options. Click Advanced in the upper right corner to access the full feature set — all WLC configuration capabilities are available from the Advanced Summary page.

💡
The figures in NetAcad show the Cisco 3504 Wireless Controller GUI. Other WLC models have similar menus and features. The Cisco 3504 can support 150 APs and 4096 VLANs through just 5 physical ports.

13.2.6 WLC Ports vs Interfaces

🔌
Physical Ports

Sockets for physical connections to the wired network — like switch ports. The Cisco 3504 has 5 physical ports. Each port acts as a trunk carrying traffic from multiple VLANs and multiple APs simultaneously.

💻
Virtual Interfaces

Created in software — like VLAN interfaces. Each WLAN maps to a different virtual interface, which corresponds to a different VLAN. A WLC with 5 ports can support 4096 virtual interfaces.

✅
Think of WLC physical ports as trunks — each carries many VLANs. Each WLAN = one VLAN = one virtual interface. The 5-port WLC can run hundreds of APs and thousands of WLANs because the ports trunk all that traffic.

13.2.6 Configure a WLAN — Seven Steps

⚙️ Basic WLAN Configuration on the WLC
1
WLANs → Create New → Go
Create the WLAN — assign a profile name and SSID (e.g., "Wireless_LAN"). The WLAN ID is an arbitrary display number.
2
General tab → Status checkbox
Apply and Enable the WLAN — new WLANs are created disabled. Must check Enable before clients can connect. Multiple WLANs can be configured before enabling any.
3
General tab → Interface/Interface Group dropdown
Select the Interface — choose which virtual interface (VLAN) carries this WLAN's traffic
4
Security tab → Layer 2 Security → PSK
Secure the WLAN — WPA+WPA2 is selected by default. Click PSK, enter the pre-shared key → Apply. WPA2 with AES is the default encryption.
5
Left menu → WLANs
Verify the WLAN is Operational — confirm WLAN ID, name, SSID, enabled status, and security method in the WLANs list
6
Monitor tab → Summary
Monitor the WLAN — shows active client count per WLAN in real time
7
Left menu → Clients
View Wireless Client Details — shows each client's IP address, associated AP, and WLAN — confirms successful DHCP assignment
🚨
New WLANs are DISABLED by default. Creating the WLAN is not enough — you must explicitly check the Enable checkbox (Step 2) before any clients can connect. This is one of the most commonly missed steps in labs.

13.3Configure WPA2 Enterprise WLAN on the WLC▾

13.3.2 SNMP and RADIUS

Enterprise WLAN configuration uses two external servers:

ServerPurposeWhat It Does on the WLC
SNMP ServerNetwork monitoringWLC sends SNMP trap messages (log events) to the SNMP server for monitoring and alerting
RADIUS ServerAAA — Authentication, Authorization, AccountingValidates individual user credentials for WPA2 Enterprise; tracks and audits per-user access; required for 802.1X authentication
💡
With WPA2 Enterprise, each user enters their own unique username and password — not a shared PSK. The RADIUS server validates each credential individually. User accounts can be added, modified, or revoked centrally without changing the WLAN configuration.

13.3.3 Configure SNMP Server Information

📊 SNMP Trap Receiver Configuration
1
MANAGEMENT → SNMP → Trap Receivers → New…
Enter the SNMP Community name and IP address of the SNMP server → Apply. The WLC will now forward all SNMP log messages (traps) to that server.

13.3.4 Configure RADIUS Server Information

🔐 RADIUS Authentication Server Configuration
1
SECURITY → RADIUS → Authentication → New…
Enter the IP address of the RADIUS server and the shared secret (password between WLC and RADIUS server — NOT the user password) → Apply. Server now appears in the RADIUS Authentication Servers list.
⚠️
The shared secret is between the WLC and RADIUS server only. End users never see or use this key. Users authenticate with their own individual credentials via 802.1X/EAP. The shared secret only authenticates the WLC itself to the RADIUS server.

13.3.7 Configure a New VLAN Interface — Six Steps

Each WLAN needs its own virtual interface. The new enterprise WLAN will use VLAN 5 (192.168.5.0/24). R1 has subinterface Fa0/1.5 at 192.168.5.254 already configured.

13.3.11 Configure a WPA2 Enterprise WLAN — Six Steps

By default, all newly created WLANs on the WLC use WPA2 with AES and 802.1X. Since the RADIUS server is already configured on the WLC, the only extra step compared to WPA2-PSK is assigning the RADIUS server in the AAA Servers tab:

🏢 WPA2 Enterprise WLAN Configuration
1
WLANs tab → Go
Create a new WLAN
2
Profile Name + SSID fields
Configure WLAN name and SSID — e.g., "CompanyName", ID: 5 → Apply
3
General tab → Status + Interface dropdown
Enable for VLAN 5 — Status: Enabled, Interface: vlan5 → Apply → OK
4
Security tab → Layer 2
Verify AES and 802.1X defaults — confirm AES encryption and 802.1X key management are already selected (these are the defaults on new WLANs)
5
Security tab → AAA Servers tab → Server 1 dropdown
Configure RADIUS server — select the previously configured RADIUS server from the dropdown → Apply. This is the only step different from WPA2-PSK.
6
WLANs list
Verify the WLAN is available — both WLANs should now be listed and enabled. Wireless_LAN: WPA2-PSK. CompanyName: WPA2-802.1X.

CMP WPA2-PSK vs WPA2-Enterprise — Configuration Comparison

🔑 WPA2-PSK (Personal)
  • Security tab → Layer 2 Security: WPA+WPA2
  • Click PSK
  • Enter the pre-shared key (passphrase)
  • Click Apply
  • No AAA Servers tab needed — no RADIUS server
  • All users share the same passphrase
  • Suitable for: home, small office
🏢 WPA2-Enterprise (802.1X)
  • Security tab → Layer 2 Security: WPA+WPA2
  • Leave 802.1X selected (default)
  • Verify AES encryption is selected
  • Click AAA Servers tab
  • Select the RADIUS server from the dropdown
  • Click Apply
  • Each user has individual credentials
  • Suitable for: enterprise, audited environments
🎯 KEY DIFFERENCE
WPA2-PSK → Security tab → PSK → enter passphrase → done
WPA2-Enterprise → Security tab → 802.1X (default) → AAA Servers tab → select RADIUS server → done

The only extra step for Enterprise is the AAA Servers tab. Everything else (WPA2, AES) is already the default on new WLANs.

13.4Troubleshoot WLAN Issues▾

13.4.1 Troubleshooting Approach — Six Steps

A systematic methodology based on the scientific method — eliminates one problem at a time:

1
Identify the Problem
Talk to the user — understand what is wrong, when it started, what changed. Determine scope: one device affected or all devices? If one device, start there. If all, start at the common connection point (AP or router).
2
Establish a Theory of Probable Causes
List all possible causes — network config, device hardware, physical layer, security mismatch, interference. Generate multiple theories before testing any.
3
Test the Theory to Determine Cause
Apply quick fixes one at a time to test each theory. If a quick fix doesn't work, research further. Stop when you find the actual cause.
4
Establish a Plan of Action and Implement
Once the cause is confirmed, determine the fix, plan the implementation, and execute it.
5
Verify Full Functionality
Confirm the fix works completely. Implement preventive measures to stop recurrence.
6
Document Findings, Actions, and Outcomes
Record what was found, what was done, and what the result was. Essential for future reference and pattern analysis.

13.4.2 Wireless Client Not Connecting

Process of elimination — check in this order:

Step 1 — Check the PC's IP configuration

Check if DHCP assignment succeeded 
C:\> ipconfig

! If you see 169.254.x.x (APIPA address) → DHCP failed
! Check DHCP server, VLAN configuration, and SSID association

! If address looks correct:
C:\> ping 192.168.x.1    ! Ping the default gateway

! If gateway unreachable → check AP, VLAN, and physical connectivity

Step 2 — Test wired connectivity

Connect the device to a wired LAN port and ping a known IP. If wired works but wireless doesn't → the problem is wireless-specific.

Step 3 — Check wireless NIC drivers

Reload or update wireless NIC drivers. Try a different wireless NIC if necessary.

Step 4 — Check security settings (most common cause)

🚨
Security mismatch is the #1 cause of wireless connection failure. If the client is configured for WPA2 but the AP is using a different mode, or if the passphrase doesn't match, the client simply fails to connect with no useful error message. Verify security mode and passphrase match exactly on both the client and the AP.

If connected but performing poorly

  • Distance — is the client outside the planned BSA coverage area?
  • Channel settings — client software should auto-detect the correct channel when SSID is configured correctly
  • Interference — check for 2.4 GHz interference: cordless phones, baby monitors, microwave ovens, wireless security systems, rogue APs
  • Physical layer — are all devices powered on? Check cables and connectors
  • Ping the AP — if the AP is unreachable from the client, the issue is with the AP or its configuration

13.4.3 Troubleshooting When the Network Is Slow

Two primary solutions for poor wireless performance:

SolutionHow It HelpsImplementation
Upgrade wireless clientsOlder clients (802.11b/g) force the AP to accommodate the slowest standard — slowing all other clients. Upgrading eliminates the lowest common denominator.Replace 802.11b/g NICs with 802.11n or 802.11ac. Current recommended enterprise standard: 802.11ac.
Split traffic across bandsSeparates congested 2.4 GHz traffic from clean 5 GHz traffic — assigns each type to the appropriate band.Give each band a different SSID. Route basic traffic (email, web) to 2.4 GHz. Route real-time traffic (video, VoIP) to 5 GHz.
  Split-band strategy:
  
  SSID: "OfficeNet_2.4"  → 2.4 GHz band
  Use for: web browsing, email, downloads (not time-sensitive)
  Shared with other nearby 2.4 GHz WLANs — more congested
  
  SSID: "OfficeNet_5"    → 5 GHz band
  Use for: video streaming, VoIP, video conferencing (time-sensitive)
  Far less crowded; 24 non-overlapping channels; lower latency
💡
Why give each band its own SSID? By default, dual-band routers use the same SSID on both bands. Clients then automatically connect to whichever band they detect first. With separate SSIDs, users consciously choose which band — and time-sensitive applications go to 5 GHz where they belong.

Additional range/performance fixes

  • Remove physical obstructions from around the AP (furniture, appliances, walls)
  • If range is still insufficient: deploy a Wi-Fi Range Extender or Powerline wireless technology

13.4.4 Updating Firmware

Always keep firmware up to date — releases contain bug fixes and security patches:

Device TypeUpdate MethodImpact
Autonomous AP / Wireless routerCheck manufacturer's website; update through device's management GUIBrief disruption during update and reboot
WLC-managed APs (Cisco 3504)WIRELESS → Access Points → Global Configuration → AP Image Pre-downloadAll wireless clients are disconnected during the upgrade — schedule during maintenance window
⚠️
WLC firmware updates disconnect all wireless users. When the WLC pushes firmware to managed APs, every client loses WLAN and internet access for the duration of the upgrade. The router/AP may reboot multiple times before normal operations resume. Always schedule during a maintenance window.

🔄 WLC Enterprise WLAN — Complete Configuration Order

When building a WPA2 Enterprise WLAN from scratch on a WLC, follow this sequence:

  1. Log in to WLC — access via management IP in web browser
  2. Configure SNMP server — Management → SNMP → Trap Receivers → New
  3. Configure RADIUS server — Security → RADIUS → Authentication → New (enter IP + shared secret)
  4. Create new VLAN virtual interface — Controller → Interfaces → New (name, VLAN ID, IP, gateway, DHCP server)
  5. Configure DHCP scope (if WLC provides DHCP) — Internal DHCP Server → DHCP Scope → New (address range, gateway, enable)
  6. Create new WLAN — WLANs → Create New (name, SSID, enable, select VLAN interface)
  7. Configure WLAN security — Security tab → Layer 2 → verify 802.1X → AAA Servers tab → select RADIUS server → Apply
  8. Verify — WLANs list (both WLANs enabled), Monitor tab (clients connecting), Clients menu (IP assignment confirmed)

🎯Common Exam Traps — Module 13▾
❌
Trap 1: Change wireless router defaults immediately — username, password, AND default IP.
Default credentials are freely available online. The first action after accessing a new wireless router is changing the admin password. The default IP address (192.168.0.1) should also be changed to a less predictable subnet.
❌
Trap 2: After changing the router's LAN IP, run `ipconfig /renew`.
When you change the router's IP through the GUI, your PC immediately loses access because it still has the old gateway. `ipconfig /renew` forces a fresh DHCP lease and restores access at the new IP. This exact step is tested in labs.
❌
Trap 3: New WLANs on the WLC are DISABLED by default.
After creating a WLAN, you must explicitly enable it using the Enable checkbox before any clients can connect. This is one of the most commonly missed configuration steps in both labs and exam scenarios.
❌
Trap 4: WLC ports are physical (trunks); WLC interfaces are virtual (VLANs).
A WLC with 5 physical ports can support 150 APs and 4096 VLANs because the ports act as trunks. Each WLAN maps to a virtual interface which corresponds to a VLAN. Confusing ports and interfaces is a common exam mistake.
❌
Trap 5: Security mismatch = client cannot connect, with no clear error.
If the client's security settings don't match the AP (wrong mode, wrong passphrase), the client simply fails to connect — no helpful error message. Always check security mode and passphrase first when troubleshooting a client that can't connect.
❌
Trap 6: The RADIUS shared secret is between WLC and RADIUS server — NOT the user password.
The shared secret only authenticates the WLC to the RADIUS server. End users authenticate with their own individual username and password via 802.1X/EAP. The shared secret is never given to end users.
⚠️
Trap 7: WPA2 and 802.1X are defaults on new WLANs — not PSK.
When you create a new WLAN on a Cisco WLC, it defaults to WPA2 with AES encryption and 802.1X authentication. For WPA2-PSK, you must go to the Security tab and specifically select PSK. For Enterprise, 802.1X is already configured — you just need to add the RADIUS server in the AAA Servers tab.
⚠️
Trap 8: Use non-overlapping channels in mesh/multi-AP deployments — 1, 6, 11.
All APs in a mesh network share the same SSID and security settings, but must use different non-overlapping channels to avoid mutual interference. This is the direct application of Module 12's channel theory to real configuration.
⚠️
Trap 9: PoE powers the AP through the Ethernet cable — no power adapter needed.
In WLC topology labs, controller-based APs receive power through the Ethernet cable from a PoE-capable switch port. Only one cable runs to the AP.
⚠️
Trap 10: Slow WLAN = split 2.4 GHz and 5 GHz with separate SSIDs.
Give each band its own SSID — use 2.4 GHz for email and web, 5 GHz for video and VoIP. Even one legacy 802.11b/g client on the 2.4 GHz network forces the AP to accommodate that slower standard — reducing performance for all clients.
⚠️
Trap 11: WLC firmware updates disconnect all wireless clients.
When the WLC pushes firmware to managed APs, every connected client is disconnected. Schedule updates during maintenance windows. The WLC and APs may reboot multiple times before normal operations resume.
⚠️
Trap 12: 169.254.x.x = DHCP failure, not wireless failure.
If a client shows an APIPA address (169.254.x.x), it received no DHCP response. Check the DHCP server, VLAN interface assignment on the WLC, and whether the AP is correctly associated with the WLC — not the wireless security settings.
⚠️
Trap 13: DHCP scope on WLC = DHCP pool on router — same information, different location.
Both define: address range (start/end IP), subnet mask, default gateway, and optionally DNS. The WLC DHCP scope is configured under Internal DHCP Server → DHCP Scope. The WLC can forward DHCP requests to an external server (like R1) or handle them internally.
✅
