13.1ICMP Messages▾

13.1.1 ICMPv4 and ICMPv6 — Purpose

Although IP is best-effort and unreliable, the TCP/IP suite provides error and informational messaging via ICMP (Internet Control Message Protocol).

⚠️
ICMP does NOT make IP reliable. It provides feedback about issues related to IP packet processing — it does NOT retransmit packets or guarantee delivery. Reliability is handled by TCP at Layer 4. ICMP messages are not required and are often blocked by firewalls for security reasons.

Three ICMP messages common to both ICMPv4 and ICMPv6:

✅ Host Reachability — Echo Request / Echo Reply
Tests whether a host is reachable on an IP network. Basis of the ping utility.
⚠️ Destination or Service Unreachable
Sent when a packet cannot be delivered. Includes a code indicating the specific reason for failure.
🔴 Time Exceeded
Sent when TTL (IPv4) or Hop Limit (IPv6) is decremented to 0. Basis of the traceroute utility.

13.1.2 Host Reachability — Echo Request and Echo Reply

The ICMP Echo Request/Reply mechanism tests Layer 3 reachability between two IP hosts:

1
Source sends an ICMP Echo Request to the target IP address
2
If the target is available and reachable, it responds with an ICMP Echo Reply
3
Ping measures the round-trip time (RTT) — time from request sent to reply received
4
After all requests: ping provides a summary with success rate and average RTT

13.1.3 Destination or Service Unreachable — Codes

When a host or router cannot deliver a packet, it sends an ICMP Destination Unreachable message back to the source. The code field indicates the exact reason.

ICMPv4 — Destination Unreachable Codes
0
Net unreachable
1
Host unreachable
2
Protocol unreachable
3
Port unreachable
ICMPv6 — Destination Unreachable Codes
0
No route to destination
1
Communication administratively prohibited (firewall)
2
Beyond scope of source address
3
Address unreachable
4
Port unreachable
⚠️
Code 1 means different things in IPv4 vs IPv6:
ICMPv4 Code 1 = Host unreachable (can reach the network but not the specific host)
ICMPv6 Code 1 = Communication administratively prohibited (blocked by firewall/ACL)

13.1.4 Time Exceeded — TTL / Hop Limit = 0

ProtocolFieldWhen Message SentUsed By
IPv4TTL (Time to Live)Router decrements TTL to 0 → discards packet → sends ICMPv4 Time Exceeded to sourcetraceroute
IPv6Hop LimitRouter decrements Hop Limit to 0 → discards packet → sends ICMPv6 Time Exceeded to sourcetraceroute
💡
Time Exceeded messages are the core mechanism that makes traceroute work. Traceroute deliberately sends packets with incrementing TTL/Hop Limit values (1, 2, 3…) to trigger Time Exceeded responses from each router along the path, revealing the hop-by-hop route.

13.1.5 ICMPv6 ND Messages — Beyond ICMPv4

ICMPv6 includes all ICMPv4 functions PLUS four Neighbor Discovery (ND) messages that have no ICMPv4 equivalent:

RA
Router Advertisement — Router → ff02::1 (all-nodes). Sent every 200 seconds or in response to RS. Contains: prefix, prefix-length, default gateway (router's LLA), DNS server, domain name. Used for SLAAC.
RS
Router Solicitation — Host → ff02::2 (all-routers). Requests an RA immediately. Sent by a host on boot to discover routers without waiting 200 seconds.
NS
Neighbor Solicitation — Two uses: (1) Address resolution — "Who has IPv6 address X? Send me your MAC." Sent to solicited-node multicast address. (2) DAD (Duplicate Address Detection) — Host sends NS for its own new address; no reply = address is unique.
NA
Neighbor Advertisement — Reply to NS. Contains the MAC address of the responding device. Unicast back to the requester.
Redirect
Redirect — Sent by router to inform a host of a better next-hop for a specific destination. Similar to ICMPv4 Redirect message.
🎯 ICMPv6 ND GROUPING
Router ↔ Device: RS (host→router) · RA (router→all nodes)
Device ↔ Device: NS (address resolution + DAD) · NA (reply with MAC)
Plus: Redirect (better next-hop)
13.2Ping and Traceroute Tests▾

13.2.1 Ping — How It Works

Ping uses ICMP Echo Request and Echo Reply messages to test connectivity. Works for both IPv4 and IPv6.

ElementDescription
Echo RequestSent to the target IP address
Echo ReplySent back by the target if reachable
RTT (Round-Trip Time)Time from request sent → reply received. Measure of network latency.
TimeoutIf no reply within timeout period → no response message shown. Could be unreachable OR security filtering.
SummaryAfter all requests: success rate + average RTT
⚠️
First ping often times out — ARP (IPv4) or ND (IPv6) address resolution must complete before the first Echo Request can be sent. This delay can cause the first ping to timeout even when connectivity is fine. Subsequent pings succeed normally.
⚠️
No ping response ≠ host is down. Many organizations block ICMP at their network perimeter for security reasons. Failed ping could mean the host is unreachable OR simply that ICMP is blocked. Never conclude a host is down based solely on a failed ping without other evidence.

13.2.2–13.2.4 Three Ping Tests — What Each Verifies

🔄 Ping the Loopback — 127.0.0.1 (IPv4) or ::1 (IPv6)
What it tests: TCP/IP stack is installed and functional on the local host. ICMP loops through the IP stack without going onto the network.

What it does NOT test:
· Whether IP address, subnet mask, or default gateway are correctly configured
· Whether the NIC has a physical connection
· Whether the lower layers (L1, L2) are working

Failure = TCP/IP is not operational on this host.
🌐 Ping the Default Gateway — e.g., 192.168.10.1
What it tests: Host can communicate on the local network AND the default gateway router interface is operational.

Troubleshooting:
· Gateway responds → host and gateway both work on local network ✅
· Gateway no response, other local host responds → router interface problem or ICMP blocked on router
· Neither responds → local network connectivity problem (cable, switch, IP config)
🌍 Ping a Remote Host — e.g., ping 8.8.8.8
What a success confirms:
· Local host TCP/IP stack is working ✅
· Default gateway router is operational ✅
· All intermediate routers along the path are working ✅
· The remote host is reachable and responding ✅

Failure could mean: Any of the above failed, OR ICMP is blocked by a firewall along the path.

13.2.5 Traceroute — How It Reveals Each Hop

Traceroute (called tracert on Windows, traceroute on Linux and Cisco IOS) generates a list of every router hop along the path from source to destination, with RTT for each hop.

What traceroute provides that ping doesn't:

  • IP address of every router along the path
  • RTT to each hop (three measurements per hop)
  • Exact location where the path fails or delays occur

How Traceroute Works — TTL Exploitation

Traceroute Step-by-Step (using TTL/Hop Limit)
1
Send packet with TTL = 1 → Router 1 decrements to 0 → discards → sends ICMP Time Exceeded to source → source records Router 1's IP address
2
Send packet with TTL = 2 → Router 1 decrements to 1, forwards → Router 2 decrements to 0 → sends Time Exceeded → source records Router 2's IP
3
Continue incrementing TTL by 1 each round until either: (a) destination host responds with Echo Reply or Port Unreachable, OR (b) maximum hop count reached
✅
Result: a complete map of every router (hop) between source and destination, with RTT for each

Reading Traceroute Output

Tracing route to 209.165.200.225 [209.165.200.225]
1 1ms 1ms 1ms 192.168.10.1 ← Default gateway (R1)
2 12ms 11ms 12ms 172.16.1.1 ← R2 (intermediate router)
3 25ms 24ms 25ms 209.165.200.225 ← Destination
Tracing route to 10.1.1.10 [10.1.1.10]
1 1ms 1ms 1ms 192.168.10.1
2 * * * Request timed out. ← Router not responding (or ICMP blocked)
3 * * * Request timed out.
OutputMeaning
* (asterisk)Packet lost OR router did not reply to ICMP. Path may still be functional — some routers are configured not to send Time Exceeded messages.
High RTT at a hopThat router or its links may be congested or stressed.
Last IP before all * responsesLikely location of the problem or security boundary.
Three RTT values per hopTraceroute sends three packets per TTL value.
🎯 TRACEROUTE COMMAND NAMES
Windows: tracert destination (no final 'e')
Linux / Cisco IOS: traceroute destination
IPv4: Uses TTL field · IPv6: Uses Hop Limit field
Both use ICMP Time Exceeded messages as the core mechanism.

🎯Common Exam Traps — Module 13▾
❌
Trap 1: ICMP does NOT make IP reliable — it only provides error feedback.
IP remains connectionless, best-effort, and unreliable. ICMP notifies the source when something goes wrong but does not retransmit packets or guarantee delivery. TCP at Layer 4 provides reliability.
❌
Trap 2: ICMPv4 Code 1 = Host unreachable. ICMPv6 Code 1 = Admin prohibited (firewall).
The code numbers mean different things in ICMPv4 vs ICMPv6. This is directly tested in matching questions. IPv4: 0=Net, 1=Host, 2=Protocol, 3=Port. IPv6: 0=No route, 1=Admin prohibited, 3=Address unreachable, 4=Port unreachable.
❌
Trap 3: Time Exceeded = TTL or Hop Limit decremented to 0. This is how traceroute works.
Traceroute exploits this mechanism by deliberately sending packets with TTL=1, then TTL=2, etc. Each router that discards a packet due to TTL=0 sends back a Time Exceeded message revealing its IP address.
❌
Trap 4: Ping the loopback tests ONLY the TCP/IP stack — NOT addressing, NOT the gateway, NOT physical connectivity.
A successful loopback ping (127.0.0.1 or ::1) confirms TCP/IP is installed and functional. It does NOT confirm the IP address is correct, the subnet mask is valid, the gateway is reachable, or the NIC has a physical cable connection.
⚠️
Trap 5: No ping response does NOT always mean the host is unreachable.
Many organizations block ICMP at the perimeter or on specific interfaces for security reasons. A failed ping should prompt further investigation — not an immediate conclusion that the destination is down.
⚠️
Trap 6: The first ping often times out due to ARP or ND resolution — not a real connectivity failure.
Before the first ICMP Echo Request can be sent, the source must resolve the destination MAC address (ARP for IPv4, ND for IPv6). This extra time can cause the first ping to timeout. This is normal and expected behavior.
⚠️
Trap 7: tracert (Windows) vs traceroute (Linux/IOS) — different command names, same function.
Windows uses tracert with no 'e' at the end. Linux and Cisco IOS use traceroute. Both work with IPv4 (TTL) and IPv6 (Hop Limit). Mixing up these command names is a common exam mistake.
⚠️
Trap 8: Asterisk (*) in traceroute = lost packet or no reply — does NOT confirm path failure.
Some routers are configured not to send ICMP Time Exceeded messages for security or performance reasons. The path may still be fully functional beyond the non-responding hop. Look at subsequent hops before concluding the path is broken.
⚠️
Trap 9: ICMPv6 ND messages — RS/RA for router-device, NS/NA for device-device.
RS = host asks routers for RA (ff02::2). RA = router responds to all nodes (ff02::1) with prefix/gateway/DNS. NS = address resolution AND DAD. NA = reply with MAC address. Redirect = better next-hop. All five appear in exam matching questions.
⚠️
Trap 10: A successful remote ping confirms: local stack + default gateway + all intermediate routers + remote host.
This is the most comprehensive single connectivity test. However, failure of any one of these components — or ICMP blocking at any point — will cause the ping to fail. Use traceroute to isolate exactly where the failure occurs.
✅
