6.1Purpose of the Data Link Layer▾

6.1.1 The Data Link Layer — NIC-to-NIC Communications

The data link layer (OSI Layer 2) prepares network data for the physical network. It is responsible for NIC-to-NIC communications within the same network segment. Without the data link layer, IP would need to make provisions for connecting to every type of media along a delivery path.

What the Data Link Layer does:

  • Enables upper layers to access the media — upper layer protocols are completely unaware of the type of media being used
  • Accepts data (usually Layer 3 IPv4 or IPv6 packets) and encapsulates them into Layer 2 frames
  • Controls how data is placed and received on the media
  • Exchanges frames between endpoints over the network media
  • Receives encapsulated data and directs it to the proper upper-layer protocol
  • Performs error detection and rejects any corrupt frame
💡
A node = any device that can receive, create, store, or forward data along a communications path. Nodes include both end devices (laptops, phones) and intermediary devices (Ethernet switches).

6.1.2 IEEE 802 LAN/MAN — Two Data Link Sublayers

Upper Layers (Network, Transport, Application…)
IP, TCP, HTTP — unaware of media type below
LLC — Logical Link Control (IEEE 802.2)
Software side · Identifies which L3 protocol is in the frame · Allows IPv4 and IPv6 to share the same interface · Communicates between upper layer software and lower hardware
MAC — Media Access Control (IEEE 802.3 / 802.11 / 802.15)
Hardware side (NIC) · Data encapsulation: Frame delimiting + Addressing + Error detection · Media access control for shared/half-duplex links
Physical Layer (Layer 1)
Bits on the wire/fiber/radio

MAC Sublayer — Three Encapsulation Functions

FunctionDescription
Frame delimitingStart and stop flags identify the beginning and end of a frame. Provides bit synchronization between transmitting and receiving nodes.
AddressingSource and destination MAC addresses for transporting the frame between devices on the same shared medium.
Error detectionTrailer with FCS/CRC value used to detect transmission errors. Corrupt frames are rejected.
💡
The MAC sublayer also provides media access control for shared (half-duplex) medium — allowing multiple devices to communicate without simultaneous collisions. Full-duplex communications do not require access control.

6.1.3 Providing Access to Media — What a Router Does at Layer 2

Each network segment packets travel through may use a different media type with different frame formats. At every router hop, the router performs these four Layer 2 functions:

  1. Accepts a frame from the incoming medium
  2. De-encapsulates the frame — extracts the Layer 3 packet
  3. Re-encapsulates the packet into a new frame — appropriate for the next media type
  4. Forwards the new frame out the appropriate interface
✅
Example: A router may have an Ethernet interface (LAN) and a serial interface (WAN). It receives an Ethernet frame, strips it, reads the IP packet, builds a PPP frame for the WAN link, and forwards it. There may be many such media transitions in a single end-to-end journey.

6.1.4 Data Link Layer Standards

Data link layer protocols are generally NOT defined by IETF RFCs (unlike upper-layer TCP/IP protocols). Standards bodies for the network access layer:

OrganizationKey Standards
IEEE802.3 Ethernet · 802.11 WLAN · 802.15 Bluetooth/Zigbee

6.2Topologies▾

6.2.1 Physical vs Logical Topologies

TypeWhat It ShowsData Link Relevance
Physical TopologyPhysical connections between devices — cables, rooms, racks, device locations. Usually point-to-point or star.Shows how cables are run; doesn't determine framing or access control
Logical TopologyHow frames travel from node to node — virtual connections, device interfaces, IP addressing scheme.The data link layer "sees" the logical topology. It determines framing type and media access control method.
💡
Adding intermediary physical devices does NOT change the logical topology. A logical point-to-point connection between two routers remains point-to-point even if there are physical devices between them on the WAN circuit.

6.2.2–6.2.3 WAN Topologies

↔️ Point-to-Point
Simplest and most common WAN topology. Permanent link between exactly two endpoints. When using serial protocols like PPP, a node does NOT need to determine if incoming frames are destined for it — all frames go to or from the two nodes only. Logical topology remains point-to-point even with intermediary physical devices.
🌟 Hub and Spoke
WAN version of the star topology. A central site interconnects branch sites via point-to-point links. Branches cannot exchange data directly — must go through the central hub site.
🔷 Mesh
Every end system interconnected to every other. High availability but very high administrative and physical cost. Each link = a point-to-point link. Partial mesh (hybrid) = some (not all) end devices are interconnected.

6.2.4 LAN Topologies

⭐ Star (Current)
End devices connected to a central Ethernet switch. Easy to install, scalable, easy to troubleshoot. Most common modern LAN topology.
⭐⭐ Extended Star (Current)
Multiple switches interconnected, expanding the star. Used for multi-floor buildings or campuses.
🚌 Bus (Legacy)
All end systems chained together; no switch needed; terminated at each end. Early Ethernet over coaxial cable. Half-duplex.
⭕ Ring (Legacy)
End systems connected to neighbors forming a ring; no termination needed. Used by Token Ring and FDDI.
💡
Early star topologies used hubs (multiport repeaters) instead of switches. A hub with two devices = Ethernet in a point-to-point topology. Two directly connected routers on an Ethernet link = also a point-to-point topology.

6.2.5 Half-Duplex vs Full-Duplex

⟵ Half-Duplex ⟶
Both devices can transmit and receive but NOT simultaneously. Only one device sends at a time on the shared medium. Used by: WLANs, legacy bus Ethernet with hubs. Requires media access control.
⟵⟶ Full-Duplex ⟵⟶
Both devices can simultaneously transmit and receive. Data link layer assumes media is always available. Used by: Ethernet switches (default). Does NOT require media access control.
🚨
Duplex mismatch — if two connected interfaces use different duplex modes (one half, one full), the link suffers significant inefficiency and latency. Both ends MUST match. Modern switches auto-negotiate duplex but mismatches still occur with older or misconfigured devices.

6.2.6 Access Control Methods

A multiaccess network = two or more end devices can attempt to access the network simultaneously (Ethernet LANs, WLANs).

⚡ Contention-Based Access
All nodes operate in half-duplex, competing for the medium. Only one device can send at a time. Process exists for when multiple devices transmit simultaneously.
Examples: CSMA/CD (legacy wired Ethernet with hubs) · CSMA/CA (WLANs)
🔄 Controlled Access
Each node has a designated time to use the medium. Deterministic — no collisions — but inefficient (devices must wait their turn even if medium is idle).
Examples: Legacy Token Ring · Legacy ARCNET
🎯 EXAM KEY
Modern Ethernet LANs using switches operate in full-duplex and require NO access control method. CSMA/CD and CSMA/CA are only needed for half-duplex shared media environments.

6.2.7–6.2.8 CSMA/CD vs CSMA/CA

CSMA/CD — Collision DETECTION
Used by: legacy bus-topology Ethernet, legacy hub-based Ethernet
  • Device listens for carrier signal (checks if medium busy)
  • If clear → transmits
  • If two devices transmit simultaneously → collision
  • Both NICs detect the collision (compare TX vs RX data, or detect abnormally high signal amplitude)
  • Both stop → random backoff timer → retransmit
Hub sends received frame out ALL other ports. Only device with matching MAC accepts it.
CSMA/CA — Collision AVOIDANCE
Used by: IEEE 802.11 WLANs
  • Devices cannot detect collisions while transmitting (TX signal overpowers RX)
  • Avoids collisions instead of detecting them
  • Each device includes time duration needed in its frame
  • All other wireless devices see this and know how long medium is unavailable
  • Receiver sends an acknowledgment back to confirm frame arrived
Does not scale well under heavy media use.
6.3Data Link Frame▾

6.3.1 The Frame — Three Parts

The data link layer encapsulates the Layer 3 packet with a header and trailer to create a frame. Every data link layer frame has three basic parts:

HEADER
Addressing · Type · Control · Start flag
DATA (Payload)
IP Packet · Segment · Application Data
TRAILER
Error Detection · FCS/CRC · Stop flag
⚠️
Unlike other encapsulation protocols, the data link layer appends information in a TRAILER at the END of the frame — not just a header. This is how error detection (FCS) is handled at the rear of each frame.

There is no single universal frame structure. The frame format varies by protocol and environment. More hostile/noisy environments require larger headers and trailers (more control information) = more overhead = lower effective data rate.

6.3.2 Frame Fields

Start/Stop Flags
Header/Trailer
Identifies the beginning and end limits of the frame. Provides synchronization between transmitting and receiving nodes.
Addressing
Header
Source and destination MAC addresses — specifies the nodes on the shared local media.
Type
Header
Identifies the Layer 3 protocol in the data field (e.g., IPv4 = 0x0800, IPv6 = 0x86DD, ARP = 0x0806). Tells the receiving node which upper-layer protocol gets the payload.
Control
Header
Identifies special flow control services such as QoS. VoIP frames receive forwarding priority because they are delay-sensitive.
Data
Middle
Frame payload — contains the IP packet (which itself contains segment header and application data).
Error Detection (FCS)
Trailer
Frame Check Sequence — contains the CRC (Cyclic Redundancy Check) value. A mathematical summary of all bits in the frame. Receiver recalculates CRC; if it doesn't match FCS → frame is corrupted → frame is discarded.
💡
Error detection ≠ error correction. The data link layer only detects corrupted frames and discards them. It does NOT correct them. Upper-layer protocols (like TCP at Layer 4) are responsible for requesting retransmission of lost data.

6.3.3 Layer 2 Addresses — Physical, Local, Hop-by-Hop

Data link layer addresses are called physical addresses. Key properties:

  • Only used for local delivery — no meaning beyond the local network segment
  • NOT hierarchical — do not indicate which network the device is on (unlike IP)
  • A device retains the same Layer 2 address even if moved to another network
  • NIC can quickly check destination L2 address to decide whether to accept the frame before reading the full payload

Frame Rewriting at Every Hop

🔄 IP Addresses Unchanged — MAC Addresses Change at Each Router
HopSrc MACDst MACSrc IPDst IP
Host → Router 1 Host MAC R1 Fa0/0 MAC 10.1.1.10 172.16.1.99
Router 1 → Router 2 R1 S0/0 MAC R2 S0/0 MAC 10.1.1.10 172.16.1.99
Router 2 → Server R2 Fa0/0 MAC Server MAC 10.1.1.10 172.16.1.99

At each router: the incoming frame is de-encapsulated → IP packet examined → new frame created with new MAC addresses for the next segment → forwarded out the appropriate interface.

6.3.4 LAN and WAN Frame Protocols

Ethernet
IEEE 802.3 · Most common wired LAN · Multiaccess with many hosts · High bandwidth
802.11 WLAN
Wireless LAN · CSMA/CA · Multiaccess · Growing rapidly
PPP
Point-to-Point Protocol · Serial WAN links · Still used
HDLC
High-Level Data Link Control · Cisco default on serial links · Point-to-point
Frame Relay
Legacy WAN · Hub-and-spoke topology · Being replaced by Ethernet
ATM / X.25
Legacy WAN protocols · Largely replaced
💡
Why different protocols for LAN vs WAN? LANs cover small areas with high user density — high bandwidth is cost-effective. WANs cover large geographic areas — long-distance physical links make high bandwidth very expensive, resulting in lower bandwidth and different protocols. Modern WANs increasingly use Ethernet even over long distances (Metro Ethernet).
🎯Common Exam Traps — Module 6▾
❌
Trap 1: Data link layer = NIC-to-NIC (local). NOT end-to-end.
Layer 2 only delivers the frame from one NIC to the very next NIC on the same network segment. Layer 3 IP handles end-to-end delivery across all networks. The MAC address changes at every router hop; the IP address stays the same throughout.
❌
Trap 2: LLC = software (identifies L3 protocol). MAC = hardware (encapsulation + media access + addressing).
LLC is IEEE 802.2 and sits above MAC. MAC implements the specific standard (802.3 for Ethernet, 802.11 for WLAN). LLC allows both IPv4 and IPv6 to share the same NIC. Students often confuse which sublayer does what.
❌
Trap 3: Data link standards come from IEEE/ITU/ISO/ANSI — NOT IETF RFCs.
IETF publishes RFCs for upper-layer TCP/IP protocols (HTTP, TCP, IP, DNS). Physical and data link layer standards come from electrical engineering bodies. This distinction is directly tested.
❌
Trap 4: CSMA/CD = collision DETECTION (wired, legacy). CSMA/CA = collision AVOIDANCE (wireless).
Wired Ethernet with hubs: devices can detect collision while transmitting → detect and back off. Wireless: device cannot detect collision while transmitting (its own TX signal overpowers the RX signal) → must avoid collisions by checking medium first and including duration in frame.
❌
Trap 5: The frame has THREE parts — Header + Data + Trailer. The TRAILER contains error detection (FCS/CRC).
Unlike upper-layer protocols that only add headers, the data link layer also adds a TRAILER at the END. The FCS (Frame Check Sequence) field in the trailer holds the CRC value. If CRC mismatch → frame discarded.
⚠️
Trap 6: Error detection ≠ error correction. Corrupt frames are DISCARDED — not fixed.
The data link layer detects errors via CRC/FCS and discards corrupt frames. It does NOT correct them or request retransmission. Layer 4 TCP handles end-to-end reliability and retransmission. Layer 2 just throws away bad frames silently.
⚠️
Trap 7: MAC addresses are NOT hierarchical and do NOT indicate network location.
IP addresses are hierarchical (network portion + host portion) and tell you where on the internet a device is. MAC addresses are flat — they identify a specific NIC but give no information about which network that NIC is on. A device keeps its MAC address even if it moves to a completely different network.
⚠️
Trap 8: Duplex mismatch = inefficiency and latency. Both ends must match.
If one interface is full-duplex and the connected interface is half-duplex, the half-duplex side will see constant late collisions. The link appears to work but performs very poorly. Always verify duplex settings match on both sides of a link during troubleshooting.
⚠️
Trap 9: Hub and Spoke — branches CANNOT communicate directly. Must go through hub.
This is a key architectural limitation of hub-and-spoke WAN topology. All inter-branch traffic must travel to and from the central hub site. This doubles the WAN bandwidth used and adds latency compared to a full mesh.
⚠️
Trap 10: Modern switched Ethernet = full-duplex = NO access control method required.
CSMA/CD is only needed for half-duplex hub-based Ethernet. Modern switches create dedicated full-duplex connections between each device and the switch. There is no shared medium, no collisions possible, and no need for CSMA/CD. CSMA/CA is only for WLANs.
⚠️
Trap 11: The Type field in the frame identifies which Layer 3 protocol is in the payload.
The Type field (also called EtherType in Ethernet frames) tells the receiving NIC which upper-layer protocol gets the data — IPv4 (0x0800), IPv6 (0x86DD), ARP (0x0806), etc. This is how LLC's protocol identification function works in practice.
⚠️
Trap 12: The logical topology — not the physical topology — determines framing and access control.
The data link layer "sees" the logical topology. Two different physical layouts can have the same logical topology. The logical topology determines whether CSMA/CD, CSMA/CA, PPP, or another protocol is used. Adding physical intermediary devices doesn't change the logical topology.
✅
