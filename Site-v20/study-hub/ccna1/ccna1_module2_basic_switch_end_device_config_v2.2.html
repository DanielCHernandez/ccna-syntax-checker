2.1Cisco IOS Access▾

2.1.1 OS Structure — Shell, Kernel, Hardware

Shell — User Interface
User interacts via CLI or GUI · Requests tasks from the computer
Kernel — Hardware-Software Bridge
Communicates between hardware and software · Manages how hardware resources meet software requirements
Hardware — Physical Layer
Physical components · Underlying electronics of the device

2.1.1–2.1.2 CLI vs GUI · Cisco IOS

FeatureCLIGUI
InterfaceText-based, command promptGraphical icons, menus, windows
Knowledge requiredMust know command structureLess knowledge needed
OverheadVery low — more stableHigher resource use; can crash
Feature accessFull access to all featuresMay not expose all features
Network device use✅ Standard for Cisco devices❌ Not used for Cisco IOS management

Cisco IOS = Cisco Internetwork Operating System. Used on many Cisco routers and switches regardless of type or size. Each device type uses a different version. Other Cisco OS families: IOS XE, IOS XR, NX-OS.

💡
Home routers use firmware configured via a web browser GUI — not Cisco IOS. Cisco IOS is used on enterprise-class routers and switches.

2.1.4 Three Access Methods

🔌 Console — Out-of-Band
Physical management port. Provides access even when no networking services are configured (e.g., initial setup, recovery). Requires console cable + terminal emulation software (PuTTY, Tera Term). Out-of-band = uses a dedicated management channel separate from the data network.
🔐 SSH — Recommended Remote Access
In-band remote access. Encrypted and secure. Establishes CLI session through a virtual interface over a network. Requires active networking services and a configured IP address on the device. Most IOS versions include SSH server and client. Always prefer SSH over Telnet.
⚠️ Telnet — INSECURE (Lab Only)
In-band remote access. Sends ALL data — including usernames and passwords — in plaintext over the network. Never use in production. Use only in lab environments. IOS includes both a Telnet server and client.
⚠️
AUX port (legacy): Out-of-band access via telephone using a modem — does not require networking services. Rarely used today but still appears on older routers.

2.1.5 Terminal Emulation Programs

Used to connect to a device via console (serial) or SSH/Telnet. Common programs: PuTTY, Tera Term, SecureCRT. Features include adjustable window sizes, font sizes, and color schemes to enhance productivity.

2.2IOS Navigation▾

2.2.1 Two Primary Command Modes

Switch>
User EXEC Mode
Limited access — basic monitoring commands only. Cannot execute any commands that change device configuration. Often called "view-only" mode. Prompt ends with >
Switch#
Privileged EXEC Mode
Full access — all commands, monitoring, configuration, and management. Higher modes (global config) can only be reached from here. Prompt ends with #. Also called "enable mode."

2.2.2 Global Config and Subconfiguration Modes

ModePromptPurpose
Global ConfigurationSwitch(config)#Changes that affect the entire device. Must enter before any other config mode.
Line ConfigurationSwitch(config-line)#Configure console, SSH, Telnet, or AUX access
Interface ConfigurationSwitch(config-if)#Configure a switch port or router network interface

2.2.4 Navigating Between IOS Modes

🗺️ IOS Mode Navigation Flow
Switch>enable→Switch#
Switch#disable→Switch>
Switch#configure terminal→Switch(config)#
Switch(config)#line console 0→Switch(config-line)#
Switch(config)#interface vlan 1→Switch(config-if)#
Switch(config-line)#exit→Switch(config)# ← one level up
Switch(config-line)#end→Switch# ← jumps to privileged EXEC
Switch(config-line)#Ctrl+Z→Switch# ← same as end
💡
You can move directly between subconfiguration modes without using exit. For example, from (config-line)# you can type interface FastEthernet 0/1 and jump straight to (config-if)#.

2.3The Command Structure▾

2.3.1 Command Syntax — Keywords and Arguments

Every IOS command follows the format: command [keyword] [argument]

  • Keyword — specific parameter defined in the operating system (e.g., ip, protocols)
  • Argument — NOT predefined; user-supplied value (e.g., 192.168.10.5, GigabitEthernet0/1)

Press Enter after every complete command to submit it to the command interpreter.

2.3.2 Syntax Conventions

ConventionMeaningExample
boldfaceEnter exactly as shown — commands and keywordsping, enable secret
italicsUser-supplied argument — you provide the valueip-address, password
[x]Optional element — may be omitted[brief] in show ip interface [brief]
{x}Required element — must be included{static | time | type}
[x {y | z}]Required choice within optional elementComplex commands

2.3.3 IOS Help Features

Two forms of help:

  • Context-sensitive help (?) — type ? at any prompt to see available commands, commands starting with specific letters, or arguments for a command
  • Command syntax check — IOS evaluates each command left to right; provides error feedback if a command is wrong (e.g., % Invalid input detected at '^' marker)
Using context-sensitive help
Switch# ?                   ← lists all commands in current mode
Switch# s?                  ← lists commands starting with 's'
Switch# show ?              ← lists all options for 'show'
Switch# show ip ?           ← lists options after 'show ip'

2.3.5 Hot Keys and Shortcuts

Command abbreviation: Shorten commands to the minimum unique characters. configure → conf ✅ · con ❌ (ambiguous). Press Tab to auto-complete.

Tab
Auto-complete a partial command entry
Ctrl+A
Move cursor to the beginning of the line
Ctrl+E
Move cursor to the end of the command line
Up Arrow / Ctrl+P
Recall previous command from history buffer
Ctrl+Z
Return to privileged EXEC from any config mode (same as end)
Ctrl+C
Abort config mode; return to privileged EXEC. In setup mode: abort back to command prompt.
Ctrl+Shift+6
Break sequence — abort DNS lookups, traceroutes, pings in progress
Backspace
Erase the character to the left of the cursor
Ctrl+U / Ctrl+X
Erase the entire command line
Ctrl+K
Erase from cursor to end of line
Ctrl+W
Erase the word to the left of the cursor

--More-- prompt (paged output): Enter = next line · Space = next screen · Any other key = exit back to prompt

2.4Basic Device Configuration▾

2.4.1 Device Names — Hostname Rules

The first configuration command on any device should be assigning it a unique hostname. Default name for all Cisco switches = Switch.

Hostname naming rules:

  • Must start with a letter
  • Must end with a letter or digit
  • No spaces
  • Use only letters, digits, and dashes
  • Less than 64 characters in length
  • IOS preserves capitalization exactly as typed
Configure hostname 
Switch# configure terminal
Switch(config)# hostname Sw-Floor-1
Sw-Floor-1(config)#

! To remove the hostname and return to default:
Sw-Floor-1(config)# no hostname
Switch(config)#

2.4.2 Password Guidelines

  • More than 8 characters in length
  • Mix of uppercase, lowercase, numbers, and special characters
  • Different password for each device
  • Avoid common words or dictionary words
  • Lab environments use simple passwords (cisco, class) for convenience only — never in production

2.4.3 Configure Passwords — Three Areas

1. Console Line — Secures Physical Access (User EXEC)

Console password 
Sw-Floor-1# configure terminal
Sw-Floor-1(config)# line console 0
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# end
💡
login is required — it tells IOS to prompt for the password when someone connects. Without login, the password is set but never asked for.

2. Privileged EXEC — Secures Administrative Access

Enable secret 
Sw-Floor-1(config)# enable secret class

! enable secret = stores password as MD5 hash (strong)
! enable password = stores as plaintext (avoid this)

3. VTY Lines — Secures Remote Access (Telnet/SSH)

Cisco switches support up to 16 VTY lines numbered 0–15.

VTY password 
Sw-Floor-1(config)# line vty 0 15
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# end

2.4.4 Encrypt Passwords — service password-encryption

By default, running-config and startup-config display most passwords in plaintext — a serious security risk.

Encrypt all plaintext passwords 
Sw-Floor-1(config)# service password-encryption

! Verify encryption was applied:
Sw-Floor-1# show running-config
line con 0
 password 7 094F471A1A0A    ← "7" = Type 7 (weak) encryption
 login
⚠️
service password-encryption applies weak Type 7 encryption only — prevents casual shoulder-surfing but can be reversed with free tools. It does NOT protect passwords in transit over the network. enable secret uses stronger MD5 (Type 5) automatically and is not affected by this command.

2.4.5 Banner Messages — MOTD

Banners legally establish that only authorized users should access the device. Required in some jurisdictions before prosecution of unauthorized access is possible.

Configure MOTD banner 
Sw-Floor-1(config)# banner motd #Authorized Access Only#

! '#' is the delimiting character — can be any character
! not present in the message body
! Banner displays on ALL access attempts until removed

2.5Save Configurations▾

2.5.1 Two Configuration Files

⚡ running-config
  • Stored in RAM (volatile)
  • Lost on power-off or reload
  • Changes take effect immediately
  • Viewed with: show running-config
💾 startup-config
  • Stored in NVRAM (non-volatile)
  • Survives power-off and reload
  • Loaded on startup/reboot
  • Viewed with: show startup-config
Save running config to startup config 
Sw-Floor-1# copy running-config startup-config
Destination filename [startup-config]? 
Building configuration...
[OK]
🎯 KEY RULE — ALWAYS SAVE AFTER CONFIG
Any change made to running-config is immediately active but will be lost on reboot unless saved. Always run copy running-config startup-config (or abbreviated copy run start) after completing a configuration session.

2.5.2 Alter, Discard, or Erase Configuration

ScenarioSolution
Unsaved changes need to be discardedreload — reloads from startup-config. IOS asks "Save changed config?" → enter n. Brief downtime.
Bad changes were already saved to startup-config1. erase startup-config (confirm with Enter)
2. reload — loads factory defaults
Remove a single commandPrecede with no: no hostname, no ip address, no shutdown

2.5.4 Capture Configuration to a Text File

Using terminal software (PuTTY, Tera Term):

  1. Enable session logging → specify filename and location
  2. Run show running-config → all output is captured to the file
  3. Disable logging when complete

To restore from text file: enter global config mode → paste file content into terminal window → commands apply as running config. Edit first if needed (remove any non-command lines).

2.6Ports and Addresses▾

2.6.1 IP Addresses — IPv4 and IPv6

Every end device on a network must be configured with an IP address to communicate.

FieldDescriptionExample
IPv4 AddressDotted decimal notation — four decimal numbers 0–255192.168.1.10
Subnet Mask32-bit value differentiating network portion from host portion255.255.255.0
Default GatewayIP address of the router used to reach remote networks and the internet192.168.1.1

IPv6: 128-bit address — 32 hexadecimal digits separated by colons (:). Every 4 bits = one hex digit. Not case-sensitive. Can be written in lowercase or uppercase.

2.6.2 Switch Virtual Interface (SVI)

Layer 2 switches do NOT support IP addresses on physical ports. Instead they use a Switch Virtual Interface (SVI):

  • SVI is a virtual interface — no physical hardware; created entirely in software
  • Default SVI = interface VLAN 1
  • IP address assigned to SVI is used for remote management only (SSH, Telnet)
  • The SVI IP address is NOT required for the switch to forward Ethernet frames — the switch works at Layer 2 regardless
💡
Think of the SVI as a "management window" into the switch. It lets administrators reach the switch remotely without needing physical console access. The switch's actual forwarding function uses MAC addresses, not IP addresses.
2.7Configure IP Addressing▾

2.7.1 Manual IPv4 Configuration on Windows

Windows path: Control Panel → Network Sharing Center → Change adapter settings → right-click adapter → Properties → Internet Protocol Version 4 (TCP/IPv4) → Properties → enter IP address, subnet mask, default gateway, and DNS server addresses.

💡
DNS server addresses are the IPs of servers that translate domain names (e.g., www.cisco.com) to IP addresses. Without DNS, you'd have to type IP addresses to reach every website.

2.7.2 Automatic IP Configuration — DHCP and SLAAC

DHCP (Dynamic Host Configuration Protocol) — automatically assigns IP address, subnet mask, default gateway, and DNS server to every end device. Eliminates manual configuration and prevents duplicate IP address assignments.

Windows: Select "Obtain an IP address automatically" and "Obtain DNS server address automatically."

ProtocolIP VersionDescription
DHCPIPv4Server assigns IPv4 address, subnet mask, gateway, DNS
DHCPv6IPv6Server assigns IPv6 global unicast address and other info
SLAACIPv6Stateless Address Autoconfiguration — device generates its own IPv6 address from router prefix
Verify Windows PC IP configuration
C:\> ipconfig

Windows IP Configuration

Ethernet adapter Local Area Connection:
   IPv4 Address. . . . . : 192.168.1.10
   Subnet Mask . . . . . : 255.255.255.0
   Default Gateway . . . : 192.168.1.1

2.7.4 Configure the Switch Virtual Interface (SVI)

Configure SVI for remote management 
Switch# configure terminal
Switch(config)# interface vlan 1
Switch(config-if)# ip address 192.168.1.20 255.255.255.0
Switch(config-if)# no shutdown
Switch(config-if)# end
Switch#

! no shutdown is REQUIRED to bring the interface up
! Without it the interface stays administratively down
🚨
Most common student error: Forgetting no shutdown after assigning the IP address to the SVI. Without it, the interface remains administratively down and cannot be used for remote management — even though the IP address is configured.

🎯Common Exam Traps — Module 2▾
❌
Trap 1: Console = out-of-band (no network needed). SSH = in-band encrypted. Telnet = in-band INSECURE.
Console works with zero network configuration — essential for initial setup and recovery. Telnet sends everything including passwords in plaintext. Always use SSH in production. These three are frequently tested as matching questions.
❌
Trap 2: User EXEC = > (view only, cannot configure). Privileged EXEC = # (full access).
User EXEC has limited monitoring commands only. Privileged EXEC allows all commands and is required to enter global configuration mode. A very common exam question shows a prompt and asks which mode it represents.
❌
Trap 3: exit goes up ONE level. end and Ctrl+Z jump directly to privileged EXEC (#).
From (config-line)#, exit → (config)#. From (config)#, exit → #. From any subconfig, end → always # regardless of how deep you are.
❌
Trap 4: Both password AND login are required for console and VTY lines.
Setting password cisco without login = the password exists but is never asked for (no authentication). Setting login without password = error, line blocks access. Both must be present together.
❌
Trap 5: enable secret stores as MD5 hash (strong). enable password stores as plaintext (avoid).
If both are configured, enable secret always takes precedence. service password-encryption does NOT affect enable secret — it's already encrypted with MD5. Never use enable password alone in production.
❌
Trap 6: service password-encryption is WEAK — prevents reading, but not cracking.
Type 7 encryption applied by this command can be reversed with free online tools. Its purpose is only to prevent casual over-the-shoulder reading of config files. It does NOT encrypt passwords sent over the network.
⚠️
Trap 7: running-config = RAM (lost on reload). startup-config = NVRAM (survives power-off).
Changes to running-config are immediate but temporary. You MUST run copy running-config startup-config to make them permanent. Forgetting this is the #1 student mistake in labs — all config is lost on the next reload.
⚠️
Trap 8: no shutdown is required after assigning an IP to the SVI.
By default, all interfaces are administratively shut down. After ip address, you MUST type no shutdown or the interface remains down and cannot be used for remote management. This is one of the most common errors in labs.
⚠️
Trap 9: SVI IP address is for management only — not required for the switch to forward frames.
Layer 2 switches forward based on MAC addresses, not IP addresses. The SVI (VLAN 1) IP only allows remote management (SSH/Telnet) access to the switch. The switch forwards Ethernet frames perfectly well with no IP address configured at all.
⚠️
Trap 10: DHCP automatically provides IP address, subnet mask, default gateway, AND DNS server.
All four pieces of configuration are provided by DHCP. Without DHCP, an admin must manually configure all four on every device. IPv6 equivalents are DHCPv6 (stateful) and SLAAC (stateless).
⚠️
Trap 11: VTY lines 0–15 = 16 simultaneous remote sessions. Configure all with line vty 0 15.
If you only configure line vty 0 4, lines 5–15 may have no password — leaving a security hole. Best practice is always line vty 0 15 to secure all 16 lines at once.
⚠️
Trap 12: Hostname rules — starts with a letter, ends with letter or digit, no spaces, max 64 characters.
IOS will reject hostnames starting with numbers or containing spaces. IOS preserves capitalization exactly as entered. Common exam question shows several options and asks which one is a valid hostname.
⚠️
Trap 13: banner motd requires a delimiting character before AND after the message.
The delimiter can be any character not in the message body (# is common). The banner displays on all access attempts (console, SSH, Telnet) until removed. Legal purpose: establishes unauthorized access notice required for prosecution in some jurisdictions.
⚠️
Trap 14: Ctrl+Shift+6 breaks an active operation; Ctrl+C aborts config mode.
When a ping or DNS lookup hangs, Ctrl+Shift+6 terminates it and returns to the prompt. Ctrl+C exits config mode back to privileged EXEC. These do different things and appear in keyboard shortcut questions.
