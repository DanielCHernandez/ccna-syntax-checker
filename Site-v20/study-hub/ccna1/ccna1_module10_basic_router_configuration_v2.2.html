10.1Configure Initial Router Settings▾

10.1.1 Seven Basic Router Configuration Steps

A router cannot create a routing table or forward packets until it is configured. Complete these steps in order:

1
Configure device name
hostname R1
2
Secure privileged EXEC mode — always use enable secret, NOT enable password
enable secret class
3
Secure user EXEC (console)
line console 0 → password cisco → login
4
Secure remote access (VTY lines) — best practice: SSH only
line vty 0 4 → password cisco → login → transport input ssh
5
Encrypt all passwords — Type 7 (weak but better than plaintext)
service password-encryption
6
Configure legal notification banner
banner motd # WARNING: Authorized access only! #
7
Save the configuration — running-config (RAM) → startup-config (NVRAM)
copy running-config startup-config
🎯 KEY MEMORY ITEMS
· enable secret = MD5 encrypted · enable password = plaintext (never use)
· service password-encryption = Type 7 weak encryption — encrypts console/VTY passwords but NOT a substitute for enable secret
· running-config = RAM (lost on power loss) · startup-config = NVRAM (survives reboot)
· line vty 0 4 = 5 VTY lines (0 through 4) allowing 5 simultaneous remote sessions
· transport input ssh = SSH only (best practice) · transport input ssh telnet = both
💡
Three essential lab commands — you will see these in the NetAcad Syntax Checker and in real Cisco configurations. Understanding why they are used:

no ip domain-lookup
By default, when you mistype a command the router assumes it is a hostname and attempts a DNS lookup — this causes a 30-second delay before you get an error. This command disables that behavior so typos give an immediate error message. Always use this in lab environments.

logging synchronous
IOS syslog messages (like %LINK-5-CHANGED) can appear mid-line while you are typing, breaking your command. logging synchronous holds those messages until you press Enter, keeping your typed commands clean and readable. Applied on the console line and VTY lines.

exec-timeout 0 0
By default the console session times out after 10 minutes of inactivity and logs you out. exec-timeout 0 0 sets the timeout to 0 minutes 0 seconds — meaning it never times out. Useful in labs where you frequently pause. In production networks you would use a real timeout (e.g. exec-timeout 5 0 for 5 minutes) for security.

10.1.2 Complete Initial Configuration Example

R1 — Full Initial Configuration
Router> enable
Router# configure terminal
Router(config)# hostname R1

R1(config)# no ip domain-lookup

R1(config)# enable secret class

R1(config)# line console 0
R1(config-line)# password cisco
R1(config-line)# login
R1(config-line)# logging synchronous
R1(config-line)# exec-timeout 0 0
R1(config-line)# exit

R1(config)# line vty 0 4
R1(config-line)# password cisco
R1(config-line)# login
R1(config-line)# logging synchronous
R1(config-line)# exec-timeout 0 0
R1(config-line)# transport input ssh
R1(config-line)# exit

R1(config)# service password-encryption

R1(config)# banner motd #
Enter TEXT message. End with a new line and the #
***********************************************
WARNING: Unauthorized access is prohibited!
***********************************************
#

R1(config)# end
R1# copy running-config startup-config

10.2Configure Interfaces▾

10.2.1 Router Interface Configuration

Routers are not reachable by end devices until interfaces are configured and activated. The Cisco ISR 4321 has two Gigabit Ethernet interfaces: G0/0/0 and G0/0/1.

Interface Configuration Syntax
Router(config)# interface type-and-number
Router(config-if)# description description-text
Router(config-if)# ip address ipv4-address subnet-mask
Router(config-if)# ipv6 address ipv6-address/prefix-length
Router(config-if)# no shutdown
CommandRequired?Notes
descriptionOptionalStrongly recommended in production. Documents what is connected. Max 240 chars. Does not affect operation.
ip addressRequired for IPv4Sets the interface IP and subnet mask
ipv6 addressRequired for IPv6Sets the IPv6 address and prefix length
no shutdownRequiredActivates the interface. Router interfaces are admin down by default — unlike switch ports.
🚨
Router interfaces are administratively DOWN by default. You MUST issue no shutdown to activate them. Even after no shutdown, the interface also needs a physical cable connected to an active device for the line protocol to come up. Both conditions must be met.

10.2.2 Interface Configuration Example

R1 — Configure G0/0/0 and G0/0/1
R1(config)# interface gigabitEthernet 0/0/0
R1(config-if)# description Link to LAN
R1(config-if)# ip address 192.168.10.1 255.255.255.0
R1(config-if)# ipv6 address 2001:db8:acad:10::1/64
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface gigabitEthernet 0/0/1
R1(config-if)# description Link to R2
R1(config-if)# ip address 209.165.200.225 255.255.255.252
R1(config-if)# ipv6 address 2001:db8:feed:224::1/64
R1(config-if)# no shutdown
R1(config-if)# exit
💡
After a successful no shutdown, the router displays informational messages:
%LINK-3-UPDOWN: Interface GigabitEthernet0/0/0, changed state to up
%LINEPROTO-5-UPDOWN: Line protocol on Interface GigabitEthernet0/0/0, changed state to up

On direct inter-router connections (no switch between routers), BOTH ends must be configured and have no shutdown before the link comes up.

10.2.3 show ip interface brief — Status and Protocol

The most commonly used verification command for interfaces:

show ip interface brief output
R1# show ip interface brief
Interface              IP-Address       OK? Method Status          Protocol
GigabitEthernet0/0/0   192.168.10.1    YES manual up              up
GigabitEthernet0/0/1   209.165.200.225 YES manual up              up
Vlan1                  unassigned      YES unset  administratively down  down

Status and Protocol Column Meanings

up / up
✅ Fully operational. Layer 1 physical = up. Layer 2 protocol = up. Interface is working normally.
up / down
⚠️ Physical connection good (cable connected, other end up) but Layer 2 protocol issue — encapsulation mismatch, keep-alive failure, or other L2 problem.
admin down / down
🔴 Interface was manually shut down with shutdown command. Issue no shutdown to re-enable.
down / down
🔴 Physical layer problem — no cable, cable disconnected, other end is down or off. Interface is not admin-down but has no physical signal.
show ipv6 interface brief output
R1# show ipv6 interface brief
GigabitEthernet0/0/0       [up/up]
    FE80::201:C9FF:FE89:4501   <-- Link-Local Address (auto-generated)
    2001:DB8:ACAD:10::1        <-- Global Unicast Address (manually configured)
GigabitEthernet0/0/1       [up/up]
    FE80::201:C9FF:FE89:4502
    2001:DB8:FEED:224::1

10.2.4 Routing Table After Interface Configuration

Each active, configured interface automatically creates two entries in the routing table:

show ip route — after configuring R1 interfaces
C192.168.10.0/24 is directly connected,GigabitEthernet0/0/0
L192.168.10.1/32 is directly connected,GigabitEthernet0/0/0
C209.165.200.224/30 is directly connected,GigabitEthernet0/0/1
L209.165.200.225/32 is directly connected,GigabitEthernet0/0/1
💡
C = Connected network route (the subnet the interface belongs to)
L = Local route (the router's own IP address as a /32 host route)
Both are added automatically when an interface is configured with an IP address and activated with no shutdown.

All Verification Commands

show ip interface briefAll interfaces, IPv4 addresses, Layer 1 status and Layer 2 protocol status — most used verification command
show ipv6 interface briefAll interfaces, IPv6 addresses (LLA + GUA), status/protocol
show ip routeIPv4 routing table stored in RAM — shows C, L, S, O, D routes
show ipv6 routeIPv6 routing table stored in RAM
show interfacesFull statistics for all interfaces — includes MAC address, duplex, speed, error counters (CRC, input errors, output drops)
show ip interfaceDetailed IPv4 statistics per interface
show ipv6 interfaceDetailed IPv6 stats — shows LLA, GUA, and all multicast groups the interface belongs to

10.3Configure the Default Gateway▾

10.3.1 Default Gateway on a Host

The default gateway is only used when sending to a remote network. For same-network communication, the host sends directly — no router needed.

💡
Requirement: The host IP and the router's interface IP (default gateway) must be on the same network.

Example: Host IP = 192.168.10.10/24 · Default gateway = 192.168.10.1 (R1's G0/0/0)
Both are on 192.168.10.0/24 — valid configuration.

Example scenario:

  • R1 G0/0/0 = 192.168.10.1 → LAN with PC1 and PC2 (192.168.10.0/24)
  • R1 G0/0/1 = 192.168.11.1 → LAN with PC3 (192.168.11.0/24)
  • PC1 → PC3 (remote): PC1 sends frame to default gateway 192.168.10.1 → R1 routes to PC3
  • PC1 → PC2 (same network): PC1 sends directly to PC2 — default gateway NOT involved
🚨
Without a correctly configured default gateway: the host can communicate only with devices on its local network. It cannot reach any remote network — including the internet. This is one of the first things to check during connectivity troubleshooting.

10.3.2 Default Gateway on a Switch

💻 Host Default Gateway
  • Configured in OS network settings or via DHCP
  • Used to forward packets to remote networks
  • IPv4: manually configured or DHCP
  • IPv6: manually configured or from RA message
🔀 Switch Default Gateway
  • Needed only for remote management
  • Switch forwards frames via MAC addresses — no IP needed for that
  • IP (SVI) + default gateway = management only
  • IPv4: ip default-gateway ip-address
  • IPv6: auto-received from router RA message

Why a switch needs a default gateway: When a remote admin sends a management packet to the switch's SVI IP, the switch must reply back. Without a default gateway, the switch cannot forward its reply packet to the router → the admin's remote management session fails.

Switch — Configure Default Gateway (IPv4)
S1# configure terminal
S1(config)# ip default-gateway 192.168.10.1
S1(config)# exit
! 192.168.10.1 = the router interface IP on the same network as the switch SVI
✅
IPv6 switch default gateway: A switch configured with an IPv6 SVI address does NOT need to manually configure the IPv6 default gateway. The switch automatically learns its default gateway from the router's ICMPv6 Router Advertisement (RA) message. No ipv6 default-gateway command is needed.

🎯Common Exam Traps — Module 10▾
❌
Trap 1: Router interfaces are admin DOWN by default. Switch ports are UP by default.
This is the most critical difference. Every router interface requires no shutdown to become active. Switch ports work as soon as something is connected. Forgetting no shutdown is the most common router configuration mistake.
❌
Trap 2: no shutdown is not enough — physical connection to an active device is also required.
The Status column in show ip interface brief shows physical (L1) status. Even with no shutdown, if no cable is connected (or the other end is down/off), the interface stays down/down. Both no shutdown AND a live physical connection are needed for up/up.
❌
Trap 3: enable secret = MD5 (strong). enable password = plaintext (never use). service password-encryption = Type 7 (weak).
Always configure enable secret — never enable password. service password-encryption protects console and VTY line passwords from casual viewing but uses weak, reversible Type 7 encryption. It is NOT a replacement for enable secret.
❌
Trap 4: copy running-config startup-config saves to NVRAM. Without it, config is lost on reboot.
running-config lives in RAM — volatile, lost on power cycle. startup-config lives in NVRAM — non-volatile, survives reboots. Always save after configuration changes or the work is lost the moment the router restarts.
❌
Trap 5: show ip interface brief — Status = Layer 1 (physical). Protocol = Layer 2. Both must be "up" for normal operation.
"administratively down" in Status = shutdown command was issued → fix with no shutdown. "down" in Status with no admin-down = physical problem (cable, other end). "up/down" = physical good but L2 problem. "up/up" = fully operational.
⚠️
Trap 6: Each active interface creates TWO routing table entries: C (connected network) and L (local /32 host route).
C = the network the interface belongs to (e.g., 192.168.10.0/24). L = the router's own specific IP address as a host route (/32). Both are added automatically when the interface is configured and activated. This is always the case — no static route needed for directly connected networks.
⚠️
Trap 7: host default gateway IP and router interface IP must be on the SAME network.
If a host is 192.168.10.10/24 and the default gateway is configured as 192.168.11.1, the host can never reach the gateway (it's on a different network). The gateway IP must be reachable without going through a router — i.e., on the same local subnet as the host.
⚠️
Trap 8: Switch needs default gateway ONLY for remote management from another network. Not for frame forwarding.
A Layer 2 switch forwards frames using MAC addresses — it doesn't need an IP for that function. The SVI IP and default gateway are ONLY needed so network administrators can SSH/Telnet to the switch from a remote network. If the admin is on the same network as the switch SVI, no default gateway is needed.
⚠️
Trap 9: Switch IPv6 default gateway is auto-learned from router RA message. IPv4 requires ip default-gateway command.
IPv4 switch default gateway: must be manually configured with ip default-gateway ip-address in global config. IPv6 switch default gateway: automatically received from the router's ICMPv6 Router Advertisement — no manual command needed.
⚠️
Trap 10: line vty 0 4 = five lines (0 through 4). transport input ssh = SSH only (best practice).
VTY 0 4 configures five simultaneous remote management sessions. Best practice is transport input ssh only — Telnet sends credentials in cleartext. transport input ssh telnet allows both. transport input all allows everything including insecure protocols.
⚠️
Trap 11: show interfaces (plural) shows MAC address, speed, duplex, and error counters — not just IP and status.
Unlike show ip interface brief which is summary-level, show interfaces shows the full detail including the interface MAC address, current duplex and speed settings, and error statistics (CRC errors, input errors, output drops). Use this for detailed physical layer troubleshooting.
⚠️
Trap 12: description command is optional but strongly recommended. Does not affect interface operation.
The description is purely documentation — it appears in the running config and show interfaces output but has zero effect on routing, switching, or interface state. It helps identify what is connected to each interface, especially useful during troubleshooting in production environments.
✅
