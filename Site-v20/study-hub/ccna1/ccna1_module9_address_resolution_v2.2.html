9.1MAC and IP▾

9.1.1–9.1.2 Two Addresses — Two Purposes

🔌 Physical Address (MAC) — Layer 2
Used for NIC-to-NIC communication on the same Ethernet network segment.

Changes at every router hop. Only meaningful on the local segment. Provided by ARP (IPv4) or ND (IPv6).
🌐 Logical Address (IP) — Layer 3
Used to send the packet from original source to final destination — same or remote network.

Stays the same throughout the entire journey (except when translated by NAT).

9.1.1 Same Network — Direct Frame Delivery

When destination IP is on the same network as the source:

  • Destination MAC = MAC of the destination device itself
  • Frame is delivered directly — no router involved
  • Source still needs to know destination MAC → uses ARP (IPv4) or ND (IPv6) to find it
✅ Same Network Example — PC1 → PC2 (192.168.10.x)
PC1 → PC2 (direct, no router)
L2 Frame: Src MAC = aa-aa-aa (PC1) · Dst MAC = 55-55-55 (PC2)
L3 Packet: Src IP = 192.168.10.10 · Dst IP = 192.168.10.11

9.1.2 Remote Network — Frame Goes to Default Gateway

When destination IP is on a remote network:

  • Destination MAC = MAC of the default gateway (router's local interface)
  • The IP packet inside still has the final destination IP unchanged
  • At each router hop: old frame removed → IP examined → new frame created with new MACs
  • This continues until the packet reaches the final destination
🌐 Remote Network Example — PC1 → Web Server across two routers
Hop 1: PC1 → Router R1
L2 Frame: Src MAC = PC1-MAC · Dst MAC = R1-G0/0-MAC (default gateway)
L3 Packet: Src IP = 10.1.1.10 · Dst IP = 172.16.1.99 (unchanged)
Hop 2: R1 → Router R2 (new frame, same packet)
L2 Frame: Src MAC = R1-G0/1-MAC · Dst MAC = R2-G0/0-MAC
L3 Packet: Src IP = 10.1.1.10 · Dst IP = 172.16.1.99 (still unchanged)
Hop 3: R2 → Web Server (final hop)
L2 Frame: Src MAC = R2-G0/1-MAC · Dst MAC = WebServer-MAC
L3 Packet: Src IP = 10.1.1.10 · Dst IP = 172.16.1.99 (unchanged)
🎯 KEY RULE
IP addresses = end-to-end (never change)
MAC addresses = hop-by-hop (change at every router)

· IPv4: ARP maps IPv4 → MAC at each hop
· IPv6: Neighbor Discovery (ND) maps IPv6 → MAC at each hop

9.2ARP — Address Resolution Protocol (IPv4)▾

9.2.1 ARP Overview

ARP = Address Resolution Protocol. Used on IPv4 networks to discover the MAC address of a device when only its IPv4 address is known.

ARP provides two basic functions:

  1. Resolving IPv4 addresses to MAC addresses
  2. Maintaining a table of IPv4-to-MAC address mappings (ARP table / ARP cache)

9.2.2 ARP Table Lookup Process

When a device prepares to send an Ethernet frame:

1
Device checks its ARP table (ARP cache) stored in RAM — looks for the destination IPv4 address (or default gateway IP if destination is remote)
✅
Found: Uses the corresponding MAC address → builds the Ethernet frame → sends normally
❓
Not found: Sends an ARP request broadcast to discover the MAC address

ARP table entry types:

IPv4 AddressMAC AddressType
192.168.1.1c8-d7-19-cc-a0-86dynamic
192.168.1.10108-3e-0c-f5-f7-77dynamic

255.255.255.255ff-ff-ff-ff-ff-ffstatic
💡
Dynamic entries — learned via ARP process; time-stamped; automatically expire.
Static entries — manually configured; do NOT expire; must be manually removed.

9.2.3–9.2.4 ARP Request and ARP Reply

📢 ARP Request — Broadcast
  • Sent when target MAC is NOT in ARP table
  • No IPv4 header — encapsulated directly in Ethernet frame
  • Dst MAC = FF-FF-FF-FF-FF-FF (broadcast)
  • Src MAC = sending device's MAC
  • EtherType = 0x0806 (ARP)
  • Contains target IPv4 address (MAC unknown)
  • Switch floods out ALL ports except incoming
  • Router does NOT forward broadcasts
  • All devices process · Only target replies
📩 ARP Reply — Unicast
  • Sent only by the device whose IP matches the target
  • Dst MAC = MAC of original requester (unicast)
  • Src MAC = MAC of replying device
  • EtherType = 0x0806 (ARP)
  • Contains the MAC-to-IP mapping
  • Only the original requester receives the reply
  • Requester adds entry to ARP table
  • If no reply → packet is dropped

9.2.5 ARP for Remote Communications

When destination IP is on a remote network, the host cannot send the frame directly. It must find the MAC of the default gateway (router):

1
Host compares destination IP to own subnet → determines destination is remote
2
Host checks ARP table for the default gateway's IP address
✅
Gateway MAC found in ARP table → sends frame directly to gateway
❓
Gateway MAC not in ARP table → sends ARP request for default gateway's IP
✅
Receives ARP reply → caches gateway MAC → builds frame with gateway MAC as destination → sends packet
🚨
Critical distinction: When reaching a remote host, the destination IP address in the packet = final destination. But the destination MAC address in the frame = the router's MAC. Students frequently confuse these. The host ARPs for the router, not the final destination.

9.2.6 ARP Table Aging

  • ARP cache timer automatically removes entries not used for a specified period
  • Windows: dynamic entries expire between 15 and 45 seconds
  • Cisco routers: ARP entries displayed with age in minutes in show ip arp
  • After expiry: ARP request/reply process repeats before next frame can be sent
  • Manual removal: commands can clear specific or all ARP entries
  • Static entries: do NOT expire — must be manually removed

9.2.8 ARP Issues — Broadcasts and ARP Spoofing

ARP Broadcast Impact

ARP requests are broadcasts — received and processed by every device on the local network. On most networks, this has minimal impact. However, if many devices power on simultaneously and all send ARP requests, brief performance degradation can occur. After initial ARP exchanges, impact is minimized.

ARP Spoofing (ARP Poisoning Attack)

🔴 ARP Spoofing Attack — How It Works
1
PC-A sends an ARP request for the default gateway IP address
2
Threat actor sends a fake ARP reply — mapping the gateway's IP to the attacker's own MAC
3
PC-A adds the wrong mapping to its ARP table: gateway IP → attacker's MAC
4
PC-A now sends all internet-bound traffic to the attacker instead of the real gateway
5
Attacker intercepts, reads, and may modify traffic → man-in-the-middle attack
💡
Mitigation: Enterprise switches use Dynamic ARP Inspection (DAI) — validates ARP packets against a trusted DHCP snooping binding table before allowing them. DAI is beyond the scope of this course but is covered in CCNA 2.

9.3IPv6 Neighbor Discovery (ND)▾

9.3.1 IPv6 Uses ND — NOT ARP

IPv6 does NOT use ARP. Instead it uses ND (Neighbor Discovery Protocol) — also called NDP — defined in IETF RFC 4861.

ND provides three services for IPv6 using ICMPv6 messages:

  1. Address resolution — discovers the MAC address for a known IPv6 address (replaces ARP)
  2. Router discovery — finds routers on the local network (used for SLAAC)
  3. Redirection — better next-hop path selection

9.3.2 Five ICMPv6 ND Messages

NSNeighbor Solicitation
Address resolution — "What MAC address has this IPv6 address?" Sent to solicited-node multicast address. ≈ ARP Request
NANeighbor Advertisement
Address resolution reply — "Here is my MAC address." Unicast back to requester. ≈ ARP Reply
RSRouter Solicitation
Device asks: "Are there any routers on this network?" Used for router discovery and SLAAC.
RARouter Advertisement
Router announces: "I am a router; here is my prefix, gateway info, and other configuration." Used for SLAAC and DHCPv6.
RedirectRedirect Message
Sent by router to inform a host of a better next-hop for a specific destination. Beyond scope of this course.

9.3.3 IPv6 Address Resolution — NS and NA

To find the MAC address for a known IPv6 address, IPv6 uses Neighbor Solicitation (NS) and Neighbor Advertisement (NA):

1
PC1 wants to ping PC2 at 2001:db8:acad::11 but doesn't know PC2's MAC
2
PC1 sends an ICMPv6 Neighbor Solicitation (NS) to the solicited-node multicast address derived from PC2's IPv6 address (not a broadcast)
3
PC2 receives the NS, recognizes its own address, sends an ICMPv6 Neighbor Advertisement (NA) reply containing its MAC address — unicast back to PC1
4
PC1 adds the IPv6-to-MAC mapping to its Neighbor Cache (IPv6 equivalent of the ARP table)
✅
Key efficiency advantage of IPv6 ND over ARP:
ARP request = broadcast → ALL devices on the network must receive and process it (CPU overhead for every device).
NS = solicited-node multicast → only the targeted device (and others sharing that multicast address) must process it. Far more efficient on large networks.

9.3 ARP vs Neighbor Discovery — Side by Side

ARP — IPv4
  • Protocol: ARP (EtherType 0x0806)
  • Request type: Broadcast (FF-FF-FF-FF-FF-FF)
  • Reply type: Unicast
  • Table: ARP table / ARP cache
  • Commands: show ip arp (IOS) · arp -a (Windows)
  • All devices must process request
  • Stopped by routers
Neighbor Discovery — IPv6
  • Protocol: ICMPv6 (RFC 4861)
  • NS type: Solicited-node Multicast
  • NA type: Unicast
  • Table: Neighbor Cache
  • 5 message types: NS · NA · RS · RA · Redirect
  • Only targeted device processes NS
  • More efficient than ARP

🎯Common Exam Traps — Module 9▾
❌
Trap 1: Same network → Dst MAC = destination device. Remote network → Dst MAC = default gateway (router).
This is the most fundamental rule of address resolution. When the destination is remote, the host never puts the final destination's MAC in the frame — it puts the router's MAC. The IP packet inside still has the final destination IP.
❌
Trap 2: ARP = IPv4 only. ND = IPv6 only. They are separate protocols.
ARP is NOT used for IPv6. ND is NOT used for IPv4. If the question involves IPv4, the answer involves ARP. If IPv6, the answer involves ND. Both protocols resolve IP addresses to MAC addresses but are completely different.
❌
Trap 3: ARP request = BROADCAST (FF-FF-FF-FF-FF-FF). ARP reply = UNICAST.
The request must go to all devices because nobody knows which device has the target IP. Only the matching device replies, and it replies directly (unicast) to the requester. Both request and reply use EtherType 0x0806.
❌
Trap 4: ARP frames have NO IPv4 header. ARP is encapsulated directly in an Ethernet frame.
EtherType 0x0806 (not 0x0800 which is IPv4). ARP bridges Layer 2 and Layer 3 — it operates below IP. This is why ARP can discover MAC addresses even when IP isn't yet fully functional on the sending device.
❌
Trap 5: Routers do NOT forward ARP broadcasts. ARP is local network only.
ARP broadcasts are stopped at the router interface. This means ARP only works on the local network segment. For remote hosts, the host ARPs for the default gateway (router) MAC — not the final destination's MAC.
⚠️
Trap 6: When reaching a remote host, the host ARPs for the DEFAULT GATEWAY IP — not the final destination IP.
The host knows the final destination's IP but can't reach it directly. It needs to send the frame to the router. To send to the router, it needs the router's MAC. So it ARPs for the router's local interface IP.
⚠️
Trap 7: ARP spoofing = attacker sends fake ARP reply mapping their MAC to a legitimate IP (like the gateway). Victim updates ARP table incorrectly → man-in-the-middle attack.
ARP has no authentication — any device can send any ARP reply. The victim simply trusts the most recent ARP reply it receives. Enterprise mitigation = Dynamic ARP Inspection (DAI).
⚠️
Trap 8: IPv6 NS uses solicited-node MULTICAST — NOT broadcast like ARP request.
This makes ND more efficient than ARP. Only the specific target device (and those sharing the solicited-node multicast address) processes the NS. ARP forces EVERY device on the network to process the request — wasted CPU cycles on large networks.
⚠️
Trap 9: Five ND message types — NS, NA, RS, RA, Redirect. NS≈ARP Request. NA≈ARP Reply.
Students commonly only remember NS and NA. RS and RA are for router discovery and are used by SLAAC for automatic IPv6 address configuration. The Redirect message handles better path selection. All five appear in matching questions.
⚠️
Trap 10: show ip arp (Cisco IOS router) vs arp -a (Windows PC). Age dash = router's own interface IP.
In show ip arp output, a dash (–) in the Age column means that entry is the router's own IP address on that interface (not learned from ARP, just the router's own address). A number means minutes since last ARP update.
⚠️
Trap 11: IPv6 uses Neighbor Cache (not ARP table). Populated by NS/NA exchange.
The Neighbor Cache is the IPv6 equivalent of the ARP table. It stores IPv6-to-MAC address mappings per interface. It's populated when a host receives a Neighbor Advertisement.
⚠️
Trap 12: If no device replies to an ARP request → the packet is dropped.
Without a MAC address, the Ethernet frame cannot be built. No frame = packet can't be sent = packet is dropped. ARP failure is a common cause of connectivity problems even when IP configuration is correct.
✅
