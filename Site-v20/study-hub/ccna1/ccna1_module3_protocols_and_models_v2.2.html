3.1The Rules▾

3.1.2 Communications Fundamentals

All communication methods share three elements in common:

ElementDescription
Message Source (Sender)Person or electronic device that needs to send a message to other individuals or devices
Message Destination (Receiver)Receives the message and interprets it
ChannelMedia providing the pathway over which the message travels from source to destination

Simply having a physical connection between end devices is not enough. Devices must know how to communicate — they need protocols (rules).

3.1.5 Five Network Protocol Requirements

Protocol requirements for human communication (identified sender/receiver, common language, timing, acknowledgment) also apply to computer networks. Common computer protocols must address:

  1. Message encoding
  2. Message formatting and encapsulation
  3. Message size
  4. Message timing
  5. Message delivery options

3.1.6 Message Encoding and Decoding

Encoding = converting information into another acceptable form for transmission.
Decoding = the reverse process to interpret the information.

Messages sent across a network are first converted to bits by the sending host. Each bit is encoded into:

  • Patterns of voltages on copper wires
  • Infrared light pulses in optical fibers
  • Microwaves for wireless systems

The destination host receives and decodes the signals to interpret the message.

3.1.7 Message Formatting and Encapsulation

Messages must follow a specific format or structure depending on type and channel. The letter-in-envelope analogy:

  • The letter = the inner message (data)
  • The envelope = the outer format containing addressing information
  • If addressing or formatting is incorrect, the message won't be delivered

Encapsulation = placing one message format inside another message format (letter in envelope).
De-encapsulation = removing the outer format to access the inner message.

💡
IP (Internet Protocol) functions like the envelope in networking — it contains source and destination addresses and is responsible for delivering the packet from the original source to the final destination across one or more networks.

3.1.9 Message Timing — Three Aspects

AspectDescription
Flow ControlManages the rate of data transmission. Defines how much information can be sent and at what speed. Prevents a fast sender from overwhelming a slow receiver. Network protocols manage flow control between source and destination.
Response TimeoutDefines how long to wait for a response before taking action. If no response within specified time → resend the request, or assume no answer and move on.
Access MethodDetermines when a device can send a message. If two devices transmit simultaneously → "collision of information" → both must back off and retry. On WLANs, the NIC must check if the wireless medium is available before transmitting.

3.1.10 Message Delivery Options

👤
Unicast
Information transmitted to a single end device (one-to-one)
👥
Multicast
Information transmitted to one or more end devices (a specific subscribed group)
📢
Broadcast
Information transmitted to all end devices on the network
3.2Protocols▾

3.2.1 Four Types of Network Protocols

🌐 Network Communications Protocols
Enable two or more devices to communicate over one or more networks. Examples: IP, TCP, HTTP, Ethernet
🔐 Network Security Protocols
Secure data — provide authentication, data integrity, and encryption. Examples: SSH, SSL, TLS
🗺️ Routing Protocols
Enable routers to exchange route information, compare paths, and select the best path to the destination. Examples: OSPF, BGP
🔍 Service Discovery Protocols
Automatic detection of devices or services. Examples: DHCP (IP address allocation), DNS (name-to-IP translation)

3.2.2 Six Network Protocol Functions

FunctionDescriptionExample Protocol
AddressingIdentifies sender and intended receiver using a defined addressing schemeEthernet, IPv4, IPv6
ReliabilityProvides guaranteed delivery — if messages are lost or corrupted in transit, they are resentTCP
Flow ControlEnsures data flows at an efficient rate between two communicating devicesTCP
SequencingUniquely labels each segment; receiver uses sequence numbers to reassemble in correct order even if segments arrive out-of-orderTCP
Error DetectionDetermines if data was corrupted during transmissionEthernet, IPv4, IPv6, TCP
Application InterfaceContains information for process-to-process communications between network applicationsHTTP, HTTPS
💡
Note that Reliability, Flow Control, and Sequencing are all provided by TCP. These three functions are often tested together as a group that belongs to TCP.

3.2.3 Protocol Interaction — Web Page Request Example

A single web page request requires multiple protocols working together simultaneously:

ProtocolRole in Web Page Request
HTTPGoverns the interaction between web server and client — the content and format of requests and responses. Both client and server implement HTTP. Relies on other protocols for transport.
TCPManages individual conversations. Guarantees reliable delivery and flow control between end devices.
IPDelivers messages from sender to receiver. Routers use IP to forward packets across multiple networks.
EthernetDelivers messages from one NIC to another NIC on the same Ethernet LAN.
3.3Protocol Suites▾

3.3.1 Protocol Suite and Protocol Stack

Protocol suite = a group of inter-related protocols necessary to perform a communication function. Designed to work together seamlessly.

Protocol stack = shows how individual protocols within a suite are implemented in layers. Higher layers depend on lower layers. Lower layers move data over the network; upper layers focus on content.

3.3.2 Evolution of Protocol Suites

SuiteDeveloperStatus
TCP/IPIETF (open standard)✅ Most common today — the internet standard
OSI protocolsISO + ITU (1977)⚠️ OSI protocols replaced by TCP/IP; the OSI 7-layer reference MODEL is still widely used
AppleTalkApple Inc. (1985)❌ Replaced by TCP/IP in 1995
Novell NetWare (IPX)Novell Inc. (1983)❌ Replaced by TCP/IP in 1995

TCP/IP has two key advantages: it is open standard (freely available to any vendor) and standards-based (ensures interoperability between products from different manufacturers).

3.4Standards Organizations▾

3.4.1 Why Open Standards Matter

Open standards encourage interoperability, competition, and innovation. They prevent any single company from monopolizing the market or gaining unfair advantage. Standards organizations are typically vendor-neutral, non-profit organizations.

3.4.2 Internet Standards Organizations

ISOC
Internet Society — promotes open development and evolution of internet use worldwide
IAB
Internet Architecture Board — overall management and development of internet standards
IETF
Internet Engineering Task Force — develops, updates, and maintains internet and TCP/IP technologies. Produces RFC (Request for Comments) documents — formal specifications for new and updated protocols
IRTF
Internet Research Task Force — long-term research related to internet and TCP/IP protocols (Anti-Spam, Crypto Forum, P2P research groups)
ICANN
Internet Corporation for Assigned Names and Numbers — coordinates IP address allocation, domain name management, and assignment of other TCP/IP information
IANA
Internet Assigned Numbers Authority — manages IP address allocation, domain names, and protocol identifiers under ICANN
🎯 IANA vs ICANN — EXAM KEY
ICANN = the governance/coordination body (names and numbers for the internet)
IANA = the operational arm that does the actual work of IP address and protocol identifier management for ICANN
Think: ICANN is the organization; IANA is the function within it.

3.4.3 Electronic and Communications Standards

IEEE
Institute of Electrical and Electronics Engineers ("I-triple-E") — creates networking standards: 802.3 Ethernet and 802.11 WLAN (Wi-Fi). Also covers power/energy, healthcare, telecommunications.
EIA
Electronic Industries Alliance — standards for electrical wiring, connectors, and 19-inch racks used to mount networking equipment
TIA
Telecommunications Industry Association — standards for radio equipment, cellular towers, VoIP devices, satellite communications. Co-developed certified Ethernet cable standards with EIA.
ITU-T
International Telecommunications Union – Telecommunication Standardization Sector — one of the largest/oldest communications standards bodies. Standards for video compression, IPTV, and broadband (DSL).
3.5Reference Models▾

3.5.1 Four Benefits of a Layered Model

  1. Assists in protocol design — each layer has defined information it acts on and a defined interface to adjacent layers
  2. Fosters competition — products from different vendors interoperate because they implement the same layer standards
  3. Prevents ripple effects — technology changes in one layer don't affect other layers
  4. Provides common language — standardized terminology to describe networking functions and capabilities

3.5.2 OSI Reference Model — 7 Layers

OSI describes what must be done at each layer — not how. OSI layers are referred to by number, not by name (e.g., "Layer 3" not "Network Layer").

7ApplicationProcess-to-process communications protocols
6PresentationCommon data representation between application layer services
5SessionOrganizes dialog and manages data exchange
4TransportSegments, transfers, and reassembles data for individual end-device communications
3NetworkExchanges individual pieces of data over the network between identified end devices
2Data LinkMethods for exchanging data frames between devices over a common media
1PhysicalMechanical, electrical, functional means for bit transmission over physical connections
✅
Memory aids (7 to 1): "All People Seem To Need Data Processing"
Memory aids (1 to 7): "Please Do Not Throw Sausage Pizza Away"

3.5.3 TCP/IP Protocol Model — 4 Layers

TCP/IP is a protocol model — it closely matches the structure of actual protocols. TCP/IP layers are referred to by name, not number.

4ApplicationRepresents data to the user; encoding and dialog control
3TransportSupports communication between various devices across diverse networks
2InternetDetermines the best path through the network
1Network AccessControls the hardware devices and media that make up the network
💡
TCP/IP protocol specifications are publicly defined in IETF RFC (Request for Comments) documents — authored by networking engineers and open for public comment.

3.6Data Encapsulation▾

3.6.1 Segmentation and Multiplexing

Segmentation = dividing a stream of data into smaller units (packets/frames) for transmission. Data networks use TCP/IP to send data in individual IP packets.

Why not send one giant stream? It would monopolize the link, and if any part failed, the entire stream would need retransmission.

Two benefits of segmentation:

  1. Increases speed — many different conversations can be interleaved on the network simultaneously. This is called multiplexing.
  2. Increases efficiency — if a single segment fails to reach its destination, only that segment needs to be retransmitted — not the entire data stream.

3.6.2 Sequencing

Because segments may take different paths and arrive out of order, they need sequence numbers. TCP is responsible for sequencing individual segments so the receiver can reassemble them into the original message in correct order — even if segments arrive out of sequence, delayed, or lost.

3.6.3 Protocol Data Units (PDUs)

As data passes down the protocol stack, protocol information is added at each level. This is encapsulation. The form data takes at any layer is called a PDU (Protocol Data Unit).

Application LayerData
Transport Layer (TCP = Segment / UDP = Datagram)Segment
Network / Internet LayerPacket
Data Link LayerFrame
Physical LayerBits
⚠️
TCP Transport PDU = Segment. UDP Transport PDU = Datagram. Both are Transport layer PDUs but named differently based on which protocol is used. The Network layer PDU is always called a "Packet" (also sometimes "IP datagram"). The Data Link PDU is always "Frame."

3.6.4–3.6.5 Encapsulation and De-encapsulation

Encapsulation (sender — top down): At each layer, the upper layer PDU becomes the "data payload" of the current layer's PDU. Protocol header information is added at each step.

Application Data → [Transport header] Segment → [Network header] Packet → [DL header+trailer] Frame → Bits

De-encapsulation (receiver — bottom up): At each layer, the current layer's header is removed, and the inner PDU is passed up to the next layer.

Bits → Frame stripped → Packet extracted → Segment extracted → Data delivered to application

3.7Data Access▾

3.7.1 Two Types of Addresses

🌐 Layer 3 — IP Address (Logical)
Purpose: Delivers the IP packet from the original source to the final destination — may cross multiple networks.

Scope: End-to-end (never changes during the journey)

Format: IPv4 (32-bit dotted decimal) or IPv6 (128-bit hexadecimal)
🔌 Layer 2 — MAC Address (Physical)
Purpose: Delivers the data link frame from one NIC to the next NIC on the same network.

Scope: Hop-by-hop (changes at every router)

Format: Ethernet MAC (48-bit hexadecimal, e.g., AA-AA-AA-AA-AA-AA)

3.7.2 Layer 3 IP Address Structure

Every IP address has two parts:

PartIPv4 NameIPv6 NameDescription
Left portionNetwork portionPrefixIdentifies the network. Same for all devices on the same network.
Right portionHost portionInterface IDIdentifies the specific device. Unique per device on the network.

The subnet mask (IPv4) or prefix-length (IPv6) identifies the boundary between the network and host portions.

3.7.3–3.7.4 Same Network Communication

When source and destination share the same network portion of their IP addresses:

  • The data link frame can be sent directly to the destination device
  • Source MAC = NIC of sending device
  • Destination MAC = NIC of receiving device (on the same LAN)
✅
Example: PC1 (192.168.1.110) → FTP server (192.168.1.9)
Both share network portion 192.168.1.x → same network → frame sent directly PC1 MAC → FTP server MAC

3.7.5–3.7.7 Remote Network — Default Gateway

When source and destination have different network portions in their IP addresses:

  • The Ethernet frame cannot be sent directly to the destination — it is on a different network
  • The frame must be sent to the default gateway (router)
  • Source MAC = NIC of sending device
  • Destination MAC = MAC of the router's local interface (NOT the final destination MAC)
  • The router then forwards the packet toward the actual destination
🚨
Key distinction: When communicating with a remote host, the destination IP address is the final destination (web server, etc.), but the destination MAC address is the router's MAC. Students frequently mix these up.
✅
Example: PC1 (192.168.1.110) → Web Server (172.16.1.99)
Different network portions → PC1 sends frame to R1's MAC → R1 forwards packet to Web Server

3.7.8 MAC Addresses Change at Every Hop — IP Addresses Don't

🔄 IP Addresses Unchanged · MAC Addresses Change at Each Router
PC1

Router R1
→→
Router R2

L3 IP (stays same): Src: 192.168.1.10 → Dst: 172.16.1.99 (unchanged throughout)

🎯Common Exam Traps — Module 3▾
❌
Trap 1: OSI = 7 layers (by number). TCP/IP = 4 layers (by name). Know both.
OSI: Physical(1) · Data Link(2) · Network(3) · Transport(4) · Session(5) · Presentation(6) · Application(7)
TCP/IP: Network Access(1) · Internet(2) · Transport(3) · Application(4)
OSI layers are called "Layer 3," "Layer 2," etc. TCP/IP layers are called "Transport layer," "Internet layer," etc.
❌
Trap 2: OSI L1+L2 = TCP/IP Network Access. OSI L3 = TCP/IP Internet. OSI L4 = TCP/IP Transport. OSI L5+L6+L7 = TCP/IP Application.
This mapping is directly tested. The "split" happens at the top (3 OSI layers → 1 TCP/IP) and the bottom (2 OSI layers → 1 TCP/IP). Middle layers map directly 1:1.
❌
Trap 3: PDU names — Data (App) → Segment/Datagram (Transport) → Packet (Network) → Frame (Data Link) → Bits (Physical).
TCP PDU = Segment. UDP PDU = Datagram. These exact names are tested in matching and multiple-choice questions. "Packet" is Layer 3 only. "Frame" is Layer 2 only. Students often confuse packet and frame.
❌
Trap 4: L3 IP addresses stay the same end-to-end. L2 MAC addresses change at every router hop.
The source and destination IP addresses in an IP packet never change as it crosses the internet. The source and destination MAC addresses in the data link frame change at every router because each new link segment needs new addressing for that hop only.
❌
Trap 5: Unicast = one, Multicast = group (not all), Broadcast = all.
Multicast is often confused with broadcast. Broadcast goes to ALL devices on the network. Multicast goes to only those devices that have subscribed to a specific multicast group. Unicast = one-to-one communication.
⚠️
Trap 6: TCP provides reliability, flow control, AND sequencing — all three.
Students often know TCP provides reliability but forget sequencing (numbering segments for correct reassembly) and flow control (managing rate of transmission). All three functions are TCP's responsibility.
⚠️
Trap 7: IETF produces RFCs (Request for Comments). ISOC promotes internet use. IAB manages overall standards development.
IETF is the technical standards body for TCP/IP and internet protocols. Their output documents are called RFCs. ISOC is more of an advocacy/governance body. IAB sits between ISOC and IETF.
⚠️
Trap 8: IEEE = 802.3 Ethernet + 802.11 WLAN. EIA = wiring/connectors. TIA = radio/cellular/VoIP. ITU-T = DSL/video.
IEEE is "I-triple-E." These four organizations appear in matching questions. IEEE is the most tested because of its famous 802.3 and 802.11 standards used in every network.
⚠️
Trap 9: TFTP = connectionless, best-effort, no acknowledgment (less overhead). FTP = connection-oriented, reliable, acknowledged.
TFTP is used for simple transfers like uploading IOS firmware to a router where simplicity matters. FTP is used for general file transfers where reliability matters. SFTP = FTP over SSH (encrypted).
⚠️
Trap 10: When communicating with a remote host, the destination MAC is the router's MAC — not the final destination.
The host sends the frame to the default gateway (router) because the final destination is not on the local network. The destination IP is the final target; the destination MAC is the router. This distinction is critical for understanding ARP and routing.
⚠️
Trap 11: Encoding ≠ encryption. Encoding = converting to a transmissible format. Encryption = securing data.
Encoding converts data to bits, then bits to voltages/light/microwaves for the medium. It is a neutral process with no security intent. Encryption is a separate security function performed by protocols like SSH, SSL, TLS, and HTTPS.
⚠️
Trap 12: OSI protocols were replaced by TCP/IP. But the OSI 7-layer reference MODEL is still used today.
The actual OSI protocol suite (like AppleTalk and NetWare) no longer exists in modern networks. However, the OSI model (the 7-layer framework for describing networking) remains the standard reference model used by engineers worldwide.
✅
