15.1Application, Presentation, and Session▾

15.1.1 Application Layer

The application layer is the closest layer to the end user in both the OSI and TCP/IP models. It provides the interface between the applications used to communicate and the underlying network.

🎯 OSI vs TCP/IP LAYER MAPPING
In the TCP/IP model, the upper three OSI layers all collapse into ONE layer:

OSI: Application + Presentation + Session = TCP/IP: Application Layer

Common application layer protocols: HTTP · FTP · TFTP · IMAP · DNS

15.1.2 Presentation Layer — Three Primary Functions

📄
Format / PresentConverts data from source format to a compatible format for the destination device
🗜️
CompressCompresses data so it can be decompressed by the destination device
🔐
Encrypt / DecryptEncrypts data for transmission; decrypts upon receipt at destination

Common format standards at the presentation layer:

TypeFormats
VideoMKV (Matroska), MPG (MPEG), MOV (QuickTime)
ImagesGIF, JPG/JPEG, PNG

15.1.2 Session Layer

The session layer creates and maintains dialogs between source and destination applications. It handles:

  • Initiating dialogs between applications
  • Keeping active sessions alive
  • Restarting sessions that are disrupted or idle for a long period

15.2Peer-to-Peer▾

15.2.1–15.2.3 Client-Server vs P2P

🖥️ Client-Server Model
  • Dedicated server holds resources
  • Client requests; server responds
  • Roles are fixed
  • Upload = client → server
  • Download = server → client
  • Centralized resource management
↔️ Peer-to-Peer (P2P)
  • No dedicated server
  • Every peer = client AND server simultaneously
  • Roles set per-request
  • Resources shared directly between peers
  • Requires: user interface + background service on each device
💡
Hybrid P2P: Resource sharing is decentralized, but an index server stores the locations of resources. Peers query the index to find where a file is, then connect directly to the peer that has it. Used by some early P2P networks.

15.2.4 BitTorrent — How It Works

  • Torrent file — small file that identifies pieces needed and tracker server locations
  • Tracker — server that tracks which users have which pieces of a file
  • Swarm — group of users simultaneously sharing a file; clients download different pieces from multiple users at the same time
  • Common P2P networks: BitTorrent, Direct Connect, eDonkey, Freenet
  • Common clients: μTorrent, BitComet, DC++, Deluge, qBittorrent, emule
⚠️
Copyright warning: Many P2P-shared files are copyrighted. Downloading or distributing copyrighted material without permission is illegal and can result in criminal charges and civil lawsuits.
15.3Web and Email Protocols▾

15.3.1 HTTP — URL Structure and Operation

A URL (Uniform Resource Locator) has three parts:

URL Breakdown — http://www.cisco.com/index.html
http          ← Protocol/scheme
www.cisco.com ← Server hostname
/index.html   ← Specific file requested

HTTP operation — 4 steps:

  1. Browser interprets the three URL parts
  2. DNS lookup converts hostname (www.cisco.com) to IP address → browser sends HTTP GET request
  3. Server responds with HTML code for the page
  4. Browser deciphers HTML and renders the page in the window

15.3.2 Three HTTP Message Types

GETRequests data from server (e.g., load a web page)
POSTUploads form data to server (e.g., submit a login form)
PUTUploads a resource or content file to server (e.g., an image)

HTTP vs HTTPS

15.3.3–15.3.4 Email Protocols — SMTP · POP3 · IMAP

🚨
Email clients do NOT communicate directly with each other. All email flows through mail servers. Client sends via SMTP → server routes to recipient's server → recipient retrieves via POP3 or IMAP.
📤 SMTP — Simple Mail Transfer Protocol · Port 25 · TCP
Sends email from client to server AND between servers.
Requires: properly formatted recipient address + sender address in header.
If destination server unavailable → spools message and retries later.
If undeliverable after expiration → returned to sender as undeliverable.
📥 POP3 — Post Office Protocol v3 · Port 110 · TCP
Downloads email from server to client → deletes from server by default.
No centralized storage — email exists only on the local device after download.
Not recommended for businesses needing centralized backup.
Access from one device only (email is removed from server).
📨 IMAP — Internet Message Access Protocol · Port 143 · TCP
Downloads copies of messages to client → originals kept on server.
Users can create folder hierarchy on server; synchronized to client.
When message deleted on client → server synchronizes and deletes too.
Best for accessing email from multiple devices.
15.4IP Addressing Services▾

15.4.1 DNS — Domain Name System

DNS translates FQDNs (Fully Qualified Domain Names) like www.cisco.com into IP addresses like 198.133.219.25. If Cisco changes its IP address, the domain name stays the same — transparent to the user.

DNS operation — 5 steps:

1
User types FQDN into browser address bar
2
DNS query sent to the configured DNS server for the client
3
DNS server matches FQDN to IP address in its database (or forwards to another server)
4
DNS response with the resolved IP address returned to the client
5
Client uses the IP address to connect to the server and request the page

15.4.2 DNS Record Types

AIPv4 address of an end device. Most common DNS lookup.
AAAA (quad-A)IPv6 address of an end device. "Quad-A" = 4× IPv4 = 128 bits.
NSAuthoritative name server for a domain.
MXMail exchange record — identifies the mail server for a domain.

DNS message sections: Question · Answer · Authority · Additional

💡
DNS caching: After resolving a name, the DNS server temporarily stores the result. The local DNS client on Windows also caches results.
ipconfig /displaydns — displays all cached DNS entries on Windows.

15.4.3 DNS Hierarchy

DNS is a hierarchical database split into zones. Each DNS server only manages name-to-IP mappings for its own zone. If it can't resolve a name, it forwards the request to another server in the correct zone. This makes DNS scalable.

Common top-level domains: .com (business) · .org (non-profit) · .au (Australia) · .co (Colombia)

15.4.4 nslookup Command

nslookup — manually queries DNS servers to resolve host names and troubleshoot name resolution. Works on Windows and Linux.

15.4.6–15.4.7 DHCP — Dynamic Host Configuration Protocol

DHCPv4 automates assignment of: IPv4 address, subnet mask, default gateway, DNS server address.

Key DHCP concepts:

  • Pool — configured range of addresses the server can assign
  • Lease — time-limited assignment; address returns to pool when lease expires
  • DHCPRELEASE — message client sends to voluntarily return an address
  • DHCP for end user devices; static for routers, switches, servers, printers
  • DHCP server location: dedicated server (medium/large networks) or router (home networks)

DHCP DORA Process — Four Messages

D
DHCPDISCOVER — Client broadcasts to find any available DHCP server on the network
O
DHCPOFFER — Server offers a lease: IP address, subnet mask, default gateway, DNS server, lease duration
R
DHCPREQUEST — Client broadcasts to accept a specific server's offer (identifies chosen server; also used to renew leases)
A
DHCPACK — Server confirms the lease; client can now use the address. If address no longer available → DHCPNAK (restart with DISCOVER)
🚨
DHCPv6 does NOT provide a default gateway. DHCPv6 provides: IPv6 address (stateful), DNS server, domain name. The default gateway (router's LLA) can ONLY be obtained from the ICMPv6 Router Advertisement (RA) message.

DHCPv6 message names: SOLICIT · ADVERTISE · INFORMATION REQUEST · REPLY
15.5File Sharing Services▾

15.5.1 FTP — File Transfer Protocol

FTP uses two separate TCP connections:

TCP Port 21 — ControlEstablished FIRST. Carries client commands and server replies. Maintained throughout the entire session.
TCP Port 20 — DataCreated for each file transfer. Carries actual file data. Can transfer in either direction: download (pull) or upload (push).
✅
FTP characteristics: Reliable · Connection-oriented · Acknowledged delivery · Two separate TCP connections · Client can both upload and download · Authentication required (username/password)

15.5.2 SMB — Server Message Block

SMB is a client/server request-response protocol for sharing directories, files, printers, and serial ports on Microsoft networks.

Three SMB message functions:

  1. Start, authenticate, and terminate sessions
  2. Control file and printer access
  3. Allow application-to-application messaging between devices
FeatureFTPSMB
Connection typeNew connection per transferLong-term persistent connection
Resource appearanceRemote serverResources appear local to the client
ProtocolTCP (ports 20/21)TCP/IP with DNS (Windows 2000+)
AuthenticationUsername/passwordWindows credentials / domain authentication
💡
SAMBA = Linux/Unix implementation of SMB — allows Linux systems to share files with Microsoft Windows networks.
Apple Macintosh also supports SMB resource sharing.
Windows 2000+ uses DNS naming with TCP/IP (older versions used non-TCP/IP protocols for SMB).
🎯Common Exam Traps — Module 15▾
❌
Trap 1: TCP/IP Application Layer = OSI Application + Presentation + Session (three OSI layers → one TCP/IP layer).
In the OSI model there are three separate upper layers. In TCP/IP, all three functions collapse into one Application Layer. Don't list Presentation or Session as separate TCP/IP layers.
❌
Trap 2: Presentation = Format/Compress/Encrypt. Session = Create/Maintain/Restart dialogs. Keep these separate.
Presentation handles data format conversion (MKV, JPG, PNG), compression, and encryption. Session handles the dialog (conversation) lifecycle. Students frequently mix these two layer functions.
❌
Trap 3: Email clients do NOT communicate directly — all email flows through mail servers.
SMTP sends from client to server and between servers. POP3 or IMAP then retrieves from the server. There is no direct client-to-client email path.
❌
Trap 4: POP3 downloads and DELETES from server. IMAP keeps originals on server (downloads copies).
POP3 = one device, offline, no centralized backup. IMAP = multiple devices, synchronized, server is the master copy. SMTP is always the sending protocol regardless of which retrieval protocol is used.
❌
Trap 5: FTP uses TWO TCP connections — port 21 (control, established first) and port 20 (data, per transfer).
Control connection (21) carries commands and is maintained throughout. Data connection (20) is created and torn down for each file transfer. Both are TCP. TFTP uses UDP port 69 — completely different.
❌
Trap 6: DHCP DORA — Discover → Offer → Request → Acknowledge. DHCPNAK = negative acknowledgment (restart).
Client broadcasts DISCOVER to find servers. Server(s) respond with OFFER. Client broadcasts REQUEST to select one server's offer. Server sends ACK to finalize lease. If DHCPNAK → restart entire process with DISCOVER.
⚠️
Trap 7: DHCPv6 does NOT provide a default gateway — only RA provides it.
This is tested directly. Even in stateful DHCPv6, the default gateway (router LLA) can only be learned from the ICMPv6 Router Advertisement. DHCPv6 message names: SOLICIT, ADVERTISE, INFORMATION REQUEST, REPLY.
⚠️
Trap 8: DNS AAAA = IPv6 address (quad-A). A = IPv4. NS = name server. MX = mail server.
AAAA is called quad-A because IPv6 is 4× the bit length of IPv4 (128 vs 32 bits). These four record types appear in matching questions on every exam.
⚠️
Trap 9: HTTP GET = request a page. POST = upload form data. PUT = upload a resource/file.
GET is the most common — every time you load a web page. POST is form submission (login, contact form). PUT is resource upload. These appear in matching/multiple-choice questions.
⚠️
Trap 10: HTTPS uses SSL/TLS and port 443. HTTP is plaintext and uses port 80.
HTTPS encrypts the data stream before transport. HTTPS also authenticates the server via a certificate. HTTP sends everything — including passwords and form data — in cleartext.
⚠️
Trap 11: P2P — every peer is simultaneously client AND server. Roles are per-request.
Unlike client-server where roles are fixed, in P2P a single device can be downloading (client role) while uploading to others (server role) at the same time. This is how BitTorrent swarms work.
⚠️
Trap 12: nslookup = manually query DNS. ipconfig /displaydns = show cached DNS entries.
Different commands, different purposes. nslookup actively queries DNS servers. ipconfig /displaydns shows what's already cached locally in the DNS client cache. Both are Windows commands.
⚠️
Trap 13: SMB uses long-term connections; server resources appear local. FTP uses per-transfer connections.
SMB (Windows file sharing, SAMBA) maintains a persistent connection and maps network shares as local drives. FTP opens and closes the data connection for each file transfer — the control connection persists but the data connection does not.
✅
