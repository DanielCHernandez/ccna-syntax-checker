🎯 WHY THIS MODULE EXISTS
Networking devices only understand binary. But IPv4 addresses (32 bits) and especially IPv6 addresses (128 bits) are impractical to read as raw binary strings. Network administrators must:
· Convert binary ↔ decimal (for IPv4 subnetting)
· Convert decimal ↔ hexadecimal (for IPv6 and MAC addresses)
· Convert hexadecimal ↔ binary (the bridge between the two)

This module builds the foundation for all IPv4 subnetting in Module 11.
5.1Binary Number System▾

5.1.1 Binary Basics and IPv4 Structure

Binary = base 2 number system with only two digits: 0 and 1 (called bits). Every network device stores and processes data in binary.

IPv4 addresses are 32-bit binary numbers divided into four 8-bit sections called octets, separated by dots:

IPv4 Binary vs Dotted Decimal 192.168.10.10
Octet 1Octet 2Octet 3Octet 4
11000000101010000000101000001010
1921681010

Humans work with dotted decimal; network devices store and process binary. Converting between the two is a core networking skill.

5.1.3 Binary Positional Notation — The 8 Values to Memorize

Just like decimal uses powers of 10 (1, 10, 100, 1000…), binary uses powers of 2. Each position in a binary octet has a fixed value:

Key facts:
· Sum of all 8 values = 128+64+32+16+8+4+2+1 = 255 (maximum octet value = 11111111)
· Minimum octet value = 0 (00000000)
· Any number raised to the power 0 = 1 (2⁰ = 1)
· Each value is exactly double the one to its right

5.1.5 Binary → Decimal Conversion

Method — Binary to Decimal
  1. Write out the 8 positional values: 128 64 32 16 8 4 2 1
  2. For each bit: if the bit is 1 → add that positional value
  3. If the bit is 0 → add nothing (skip that position)
  4. Sum all values where the bit was 1

5.1.7 Decimal → Binary Conversion — Subtraction Method

Method — Decimal to Binary (Subtraction Method)
  1. Start with the leftmost positional value: 128
  2. Is the decimal number ≥ this positional value? → write 1, subtract the value, continue with the remainder
  3. Is the decimal number < this positional value? → write 0, move to next position (no subtraction)
  4. Repeat for 64, 32, 16, 8, 4, 2, 1
  5. When remainder reaches 0 → all remaining bits are 0

5.2Hexadecimal Number System▾

5.2.1 Hexadecimal Basics

Hexadecimal = base 16 number system. Uses digits 0–9 and letters A–F (where A=10, B=11, C=12, D=13, E=14, F=15).

Why hexadecimal in networking? Because IPv6 addresses are 128 bits long — too long to work with as binary or decimal. Hex compresses every 4 binary bits into one single character.

A nibble = 4 bits = one hex digit. A byte = 8 bits = two hex digits. This is the core relationship for all hex↔binary conversions.

IPv6 addresses are not case-sensitive — 2001:DB8 is the same as 2001:db8.

Hexadecimal values are often prefixed with 0x — for example 0xC0 means C0 in hex (= 192 decimal).

5.2.3 Decimal → Hexadecimal Conversion

Method — Decimal to Hex (via Binary)
  1. Convert the decimal number to its 8-bit binary representation
  2. Split the 8-bit binary string into two nibbles (groups of 4 bits each)
  3. Convert each nibble to its hex digit using the table above

🎯Common Exam Traps — Module 5▾
❌
Trap 1: Hex A=10, B=11, C=12, D=13, E=14, F=15. These MUST be memorized.
Students often forget that hex A through F represent decimal values 10–15. Every hex-to-decimal conversion depends on knowing these mappings. A quick check: the letters A–F represent the decimal values that couldn't fit in a single digit (10–15).
❌
Trap 2: The 8 binary positional values MUST be memorized: 128-64-32-16-8-4-2-1.
These are 2⁷ through 2⁰. Every binary↔decimal conversion depends on these. Sum of all 8 = 255 (maximum octet value). Each value is double the one to its right: 1→2→4→8→16→32→64→128.
❌
Trap 3: All ones (11111111) = 255. All zeros (00000000) = 0. These are the octet limits.
IPv4 octet range is 0–255 only. An octet cannot be 256 or greater — that would require 9 bits. On exams, addresses with octets outside 0–255 are always invalid IPv4 addresses.
❌
Trap 4: Decimal to binary — always start at 128 and work LEFT to RIGHT.
Never start in the middle or from the right. The method is: Is the number ≥ 128? Place 1 or 0. Work with remainder. Move to 64, then 32, and so on down to 1. Starting from anywhere else produces wrong answers.
⚠️
Trap 5: A nibble = 4 bits = 1 hex digit. A byte = 8 bits = 2 hex digits.
This relationship is the foundation of all hex conversions. When splitting an 8-bit binary number for hex conversion, always split into two groups of 4 (left nibble and right nibble) before looking up each hex digit.
⚠️
Trap 6: To convert decimal↔hex you MUST go through binary first (at CCNA level).
There is no simple direct formula from decimal to hex without the binary intermediate step. The process is: decimal → 8-bit binary → two nibbles → two hex digits (and reversed for hex to decimal).
⚠️
Trap 7: IPv6 is NOT case-sensitive. 2001:DB8 = 2001:db8.
Students sometimes think hex addresses must be uppercase. Both cases are valid and identical. Cisco IOS typically displays IPv6 addresses in lowercase. Exams may show either case — don't be tripped up.
⚠️
Trap 8: 0x prefix means hexadecimal. 0xC0 = C0 hex = 192 decimal.
The "0x" is just a notation indicator — it is NOT part of the hex value. Strip the 0x and work with the remaining hex digits. This notation appears in IOS configuration output, programming contexts, and some exam questions.
⚠️
Trap 9: When remainder hits 0 in decimal-to-binary, all remaining bits are 0.
This is a common time-wasting mistake. After your subtraction reduces the remainder to 0, immediately write 0 for ALL remaining bit positions. Don't continue checking each position one by one.
⚠️
Trap 10: Hex is used for both IPv6 addresses AND MAC addresses.
Students associate hex only with IPv6 and forget MAC addresses. Ethernet MAC addresses are 48 bits = 12 hex digits (e.g., AA-BB-CC-DD-EE-FF). Both types appear in questions asking "where is hexadecimal used in networking?"
✅

Decimal: Base 10 · Digits 0–9 · Used by humans for IPv4
Binary: Base 2 · Digits 0–1 (bits) · Used by devices for all data
Hexadecimal: Base 16 · Digits 0–9 and A–F (A=10 B=11 C=12 D=13 E=14 F=15) · Used for IPv6 and MAC
Positional values (MEMORIZE): 128 · 64 · 32 · 16 · 8 · 4 · 2 · 1
Max octet: 11111111 = 255 · Min octet: 00000000 = 0
Binary→Decimal: Add positional values where bit=1
Decimal→Binary: Work L→R through 128,64,32,16,8,4,2,1 · ≥value=1(subtract) · <value=0
Decimal→Hex: Dec→8-bit binary→split two nibbles→hex digit each
Hex→Decimal: Each hex→4-bit nibble→combine→decimal via positional values

IPv4: 32 bits · 4 octets · dotted decimal · range 0–255 per octet
IPv6: 128 bits · 32 hex digits · 8 hextets of 4 hex · colons · not case-sensitive
MAC: 48 bits · 12 hex digits · dashes or colons
0x prefix: means hexadecimal · 0x is not part of the value
