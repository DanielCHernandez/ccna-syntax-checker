12.1IPv4 Issues and IPv6 Coexistence▾

12.1.1 Why IPv6?

  • IPv4 has a theoretical maximum of 4.3 billion addresses (2³²) — nearly exhausted
  • 4 out of 5 RIRs have already run out of IPv4 addresses
  • Private addresses + NAT slowed depletion but NAT breaks end-to-end connectivity, adds latency, and complicates P2P and VoIP
  • Explosive growth of mobile devices and IoT devices accelerating the need
  • Top US mobile providers: over 90% of traffic is already over IPv6

12.1.2 IPv4 and IPv6 Coexistence — Three Migration Techniques

Both IPv4 and IPv6 will coexist for years. Three migration categories:

✅ Dual Stack — Preferred
Devices run both IPv4 and IPv6 simultaneously. Known as "native IPv6." Customer has IPv6 connection to ISP and accesses IPv6 content directly. The end goal for all networks.
🔀 Tunneling — Transition
IPv6 packet encapsulated inside an IPv4 packet to cross IPv4-only networks. Temporary technique — not the end goal. Used where native IPv6 is not yet available.
↔️ Translation (NAT64) — Transition
Translates IPv6 ↔ IPv4 packets. Allows IPv6-only devices to communicate with IPv4-only devices. Similar to NAT for IPv4. Only use where needed.
12.2IPv6 Address Representation▾

12.2.1 IPv6 Format

🎯 IPv6 FORMAT — MEMORIZE
· 128 bits total
· 32 hex digits (4 bits per hex digit)
· 8 groups of 4 hex digits separated by colons
· Each group = one hextet (16 bits)
· Not case-sensitive — 2001:DB8 = 2001:db8
· Preferred format: 2001:0db8:0000:1111:0000:0000:0000:0200

Two rules reduce the notation. Both can be applied together to get the compressed format.

12.2.2 Rule 1 — Omit Leading Zeros

Remove any leading zeros in any hextet. Only leading zeros — trailing zeros are significant and cannot be removed.

Rule 1 Examples
2001:0db8:0000:1111:0000:0000:0000:0200
↓ Remove leading zeros
2001:db8:0:1111:0:0:0:200
fe80:0000:0000:0000:0123:4567:89ab:cdef
↓
fe80:0:0:0:123:4567:89ab:cdef
0000:0000:0000:0000:0000:0000:0000:0001
↓
0:0:0:0:0:0:0:1
⚠️
Only LEADING zeros can be removed. The hextet ab00 stays as ab00 — the trailing zeros cannot be dropped. Only 0ab0 → ab0 (removes only the single leading zero).

12.2.3 Rule 2 — Double Colon (::)

Replace any single contiguous string of all-zero hextets with ::. Critical rules:

  • :: can be used ONLY ONCE in an address — using it twice creates ambiguity
  • If multiple equal-length groups of zeros exist, use :: on the longest string
  • If tied in length, use :: on the first string
Rule 2 Examples (after applying Rule 1 first)
2001:db8:0:1111:0:0:0:200
↓ :: replaces three consecutive zeros
2001:db8:0:1111::200
fe80:0:0:0:123:4567:89ab:cdef
↓
fe80::123:4567:89ab:cdef
2001:db8:aaaa:1:0:0:0:0
↓
2001:db8:aaaa:1::
0:0:0:0:0:0:0:1
↓ (loopback)
::1
0:0:0:0:0:0:0:0
↓ (unspecified)
::
🚨
INVALID — using :: twice: 2001:db8::abcd::1234
This is invalid because the expansion is ambiguous — multiple valid expansions are possible. Each time you see :: you must be able to determine exactly how many zero hextets it replaces. Using it once allows this; using it twice does not.
12.3IPv6 Address Types▾

12.3.1 Three Address Types — No Broadcast

TypeDescriptionIPv4 Equivalent
UnicastIdentifies a single interface. Packet goes to one specific device.Unicast
MulticastSent to a group of subscribed devices. Packet goes to all group members.Multicast + Broadcast
AnycastUnicast address assigned to multiple devices. Packet goes to the nearest device. Beyond scope of this course.No equivalent
🚨
IPv6 has NO broadcast addresses. All broadcast functionality is replaced by multicast. The all-nodes multicast address ff02::1 provides the same effect as an IPv4 broadcast.

12.3.3 IPv6 Unicast Address Types

IPv6 devices typically have two unicast addresses on each interface:

🌐 GUA — Global Unicast Address
Globally unique and routable on the IPv6 internet. Equivalent to a public IPv4 address.
· Currently assigned from 2000::/3 (addresses starting with 2 or 3)
· ISPs assign /48 global routing prefixes to customers
· Can be statically configured or dynamically assigned
· Optional — not required on every interface
🔗 LLA — Link-Local Address
Required on every IPv6-enabled interface — mandatory.
· Range: fe80::/10 (fe80 through febf in first hextet)
· NOT routable — confined to one link/subnet
· Routers do NOT forward packets with LLA source or destination
· Auto-created even if GUA is not configured
· Hosts use the router's LLA as default gateway (best practice)
· Routers use LLAs for routing updates with neighbors
🔄 Loopback — ::1/128
Tests the local IPv6 TCP/IP stack. Never sent onto the network. Equivalent to 127.0.0.1 in IPv4.
🔒 Unique Local — fc00::/7 to fdff::/7
Similar to RFC 1918 private addresses for IPv4. Not globally routed. Not yet commonly implemented. Used for devices that should not be accessible from outside.

IPv6 prefix length: Uses slash notation (no dotted-decimal mask). Recommended for LANs: /64. Required for SLAAC. Makes subnetting simple.

12.3.5–12.3.6 IPv6 GUA Structure

GUA Structure — /48 global routing prefix + /64 subnet example
48 bits
Global Routing Prefix
Assigned by ISP to customer. Identifies the organization globally.
Example: 2001:db8:acad
16 bits
Subnet ID
Used by org to create internal subnets. Separate field — no borrowing from Interface ID.
64 bits
Interface ID
Equivalent to host portion. EUI-64, random, or static. Supports 18 quintillion hosts per subnet.
✅
/48 global routing prefix + 16-bit Subnet ID = /64 per subnet:
· 16-bit Subnet ID → 65,536 possible subnets (2¹⁶)
· 64-bit Interface ID → 18 quintillion hosts per subnet (2⁶⁴)

In IPv6, the all-0s and all-1s Interface IDs can technically be assigned (no network/broadcast exclusion). Exception: all-0s Interface ID is reserved as Subnet-Router anycast — assign only to routers.

12.3.7 LLA — fe80::/10

The LLA range = fe80::/10. The /10 means the first 10 bits are fixed: 1111 1110 10xx xxxx. This gives a first hextet range of fe80 to febf.

  • LLA is automatically created on every IPv6 interface — even if no GUA is configured
  • Not routable — stays within the local link; routers do NOT forward LLA packets
  • Hosts configure the router's LLA as the default gateway address — not the GUA
  • Routers use LLAs to exchange routing protocol updates with neighboring routers
  • Can be statically configured (recommended on routers for readability) or dynamically assigned
12.4Static GUA and LLA Configuration▾

12.4.1 Configure GUA on a Router

First enable IPv6 routing (required to forward IPv6 packets and send RA messages):

Enable IPv6 Routing (Global Config)
R1(config)# ipv6 unicast-routing

Then configure GUA on each interface:

R1 — Configure IPv6 GUA on Interfaces
R1(config)# interface gigabitethernet 0/0/0
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface gigabitethernet 0/0/1
R1(config-if)# ipv6 address 2001:db8:acad:2::1/64
R1(config-if)# no shutdown
R1(config-if)# exit

R1(config)# interface serial 0/1/0
R1(config-if)# ipv6 address 2001:db8:acad:3::1/64
R1(config-if)# no shutdown
⚠️
Note: ipv6 address ipv6-address/prefix-length — there is NO SPACE between the IPv6 address and the prefix length. This is different from the IPv4 command (ip address ip-address subnet-mask) which uses a space between address and mask.

12.4.3 Configure LLA — link-local Keyword Required

R1 — Configure LLA on Interfaces
R1(config)# interface gigabitethernet 0/0/0
R1(config-if)# ipv6 address fe80::1:1 link-local
R1(config-if)# exit

R1(config)# interface gigabitethernet 0/0/1
R1(config-if)# ipv6 address fe80::1:2 link-local
R1(config-if)# exit

R1(config)# interface serial 0/1/0
R1(config-if)# ipv6 address fe80::1:3 link-local
R1(config-if)# exit
🚨
The link-local keyword is REQUIRED when manually configuring an LLA. Without it, Cisco IOS tries to configure fe80:: as a GUA and will fail because fe80 falls in the LLA range. The command must end with link-local.

Best practice: Use simple, predictable LLAs on router interfaces (e.g., fe80::1:1, fe80::1:2 for R1). LLAs are used as the default gateway by hosts and for routing updates between routers — memorable addresses make troubleshooting easier.

LLAs are NOT in the IPv6 routing table because they are not routable. The L (Local) entry shows the router's own GUA as a /128 host route — used by the routing table to efficiently process packets destined for the router itself.
12.5Dynamic Addressing for IPv6 GUAs▾

12.5.1 RS and RA Messages

MessageDirectionDestinationPurpose
RS (Router Solicitation)Host → Routerff02::2 (all-routers)Host requests RA immediately instead of waiting up to 200 seconds
RA (Router Advertisement)Router → All hostsff02::1 (all-nodes)Sent every 200 seconds OR in response to RS. Contains prefix, prefix-length, default gateway (router's LLA), DNS info.
🚨
Default gateway can ONLY come from the RA message — NEVER from DHCPv6. Even in Method 3 (stateful DHCPv6), the router's LLA used as the default gateway is obtained from the RA. DHCPv6 (stateless or stateful) does NOT provide the default gateway address.

12.5.2–12.5.4 Three GUA Assignment Methods

Method 1 — SLAAC Only
GUA:Host creates own from RA prefix + self-generated Interface ID. No DHCPv6 needed.
Prefix/Len:From RA message
Default GW:Router's LLA (from RA)
DNS:From RA message (or manual)
Fully stateless — no server tracks addresses.
Method 2 — SLAAC + Stateless DHCPv6
GUA:Host creates own (SLAAC) using RA prefix
Prefix/Len:From RA message
Default GW:Router's LLA (from RA)
DNS/Domain:From stateless DHCPv6 server
Stateless DHCPv6 provides DNS only — does NOT allocate GUAs or track addresses.
Method 3 — Stateful DHCPv6 (no SLAAC)
GUA:From stateful DHCPv6 server
Prefix/Len:From stateful DHCPv6 server
Default GW:Router's LLA (from RA — ALWAYS)
DNS/Domain:From stateful DHCPv6 server
Server tracks which address is assigned to which device. Similar to DHCP for IPv4.

12.5.5–12.5.6 Interface ID Generation — EUI-64 vs Random

When using SLAAC (Method 1 or 2), the host generates its own 64-bit Interface ID:

MethodDescriptionUsed By
EUI-64Takes 48-bit MAC → splits in half → inserts fffe (16 bits) in middle → flips U/L bit (bit 7 of OUI). Identifier: fffe appears in middle of Interface ID. Privacy concern: ties address to physical NIC.Windows XP, Cisco routers by default
Random 64-bitOS generates a random 64-bit value. Better privacy — no link to physical NIC. Can change over time.Windows Vista and later, most modern OS
EUI-64 Example — MAC fc99:4775:cee0 → Interface ID
1
Split MAC at midpoint: fc99:47 | 75:cee0
2
Insert fffe in the middle: fc99:47 + ff:fe + 75:cee0 = fc99:47ff:fe75:cee0
3
Flip the U/L bit (bit 7 of OUI): fc = 1111 1100 → bit 7 flips → 1111 1110 = fe
✅
Final EUI-64 Interface ID: fe99:47ff:fe75:cee0
Easy identifier: fffe appears in the middle
💡
DAD (Duplicate Address Detection): Before using any unicast address, a host sends a Neighbor Solicitation (NS) for its own address. If no reply is received → the address is unique and safe to use. Similar to a gratuitous ARP in IPv4.

12.7IPv6 Multicast Addresses▾

12.7.1–12.7.3 IPv6 Multicast

All IPv6 multicast addresses have the prefix ff00::/8. Multicast addresses are destination-only — never used as source addresses.

Well-Known IPv6 Multicast Addresses

ff02::1
All-nodes multicast — All IPv6-enabled devices on the link. Every IPv6 device joins automatically. Equivalent to IPv4 broadcast. Routers send RA messages here.
ff02::2
All-routers multicast — All IPv6 routers on the link. Hosts send RS messages here. Routers join when ipv6 unicast-routing is enabled.
ff02::5
All OSPF routers — Used by OSPFv3 routing protocol.

Solicited-Node Multicast Addresses

  • Automatically created when a GUA or LLA is assigned
  • Format: ff02::1:ff + last 24 bits of the IPv6 address
  • Mapped to a special Ethernet multicast MAC address — allows NIC to filter at hardware level
  • Used by Neighbor Discovery (ND) for address resolution (Neighbor Solicitation messages)
  • More efficient than ff02::1 (all-nodes) — only the targeted device and those sharing the multicast address must process the NS message
12.8Subnet an IPv6 Network▾

12.8.1 IPv6 Subnetting — Designed In, Not Bolted On

IPv6 was designed with subnetting in mind. Unlike IPv4, there is no need to borrow bits from the host (Interface ID) portion:

  • The Subnet ID field is a separate, dedicated area between the Global Routing Prefix and Interface ID
  • Address conservation is NOT a concern — WAN links also get /64 subnets
  • No VLSM needed — all subnets use /64
  • Subnetting doesn't require binary conversion — just count up in hexadecimal
🎯 WITH /48 GLOBAL ROUTING PREFIX + /64 SUBNET
· 16-bit Subnet ID → 65,536 subnets available (2¹⁶)
· 64-bit Interface ID → 18 quintillion hosts per subnet (2⁶⁴)
· No need to calculate borrowing, subnet masks, or VLSM
· Organizations with a /32 get 4.3 billion /64 subnets — as many as all IPv4 public addresses

12.8.2–12.8.3 IPv6 Subnetting Example

Organization assigned: 2001:db8:acad::/48 — just increment the Subnet ID hextet:

2001:db8:acad::/48 — Subnet Allocation (increment 4th hextet)
2001:db8:acad:0001::/64LAN A (Subnet ID = 0001)
2001:db8:acad:0002::/64LAN B (Subnet ID = 0002)
2001:db8:acad:0003::/64LAN C (Subnet ID = 0003)
2001:db8:acad:0004::/64LAN D (Subnet ID = 0004)
2001:db8:acad:0005::/64WAN R1-R2 (Subnet ID = 0005, also /64)
……up to 2001:db8:acad:ffff::/64 (65,536 subnets total)
✅
WAN links also get /64 in IPv6 — unlike IPv4 where you'd use a /30 (2 usable hosts) to conserve addresses. In IPv6, address conservation is irrelevant. Each WAN link gets a full /64 just like LAN subnets. This simplifies design and configuration.

🎯Common Exam Traps — Module 12▾
❌
Trap 1: IPv6 = 128 bits = 32 hex digits = 8 hextets of 4 hex digits each. A hextet = 16 bits.
Not case-sensitive. The preferred (full) format shows all 32 hex digits. The compressed format applies Rule 1 (drop leading zeros) and Rule 2 (::) to shorten it.
❌
Trap 2: Rule 1 removes LEADING zeros only — NOT trailing zeros.
0ab0 → ab0 (leading zero removed). ab00 stays ab00 (trailing zeros are part of the value). Removing trailing zeros would make the address ambiguous.
❌
Trap 3: :: can only be used ONCE per address. Using it twice = invalid.
2001:db8::abcd::1234 is INVALID. When two groups of consecutive zeros are equal length, use :: on the first string. When one is longer, use :: on the longest.
❌
Trap 4: IPv6 has NO broadcast. The all-nodes multicast ff02::1 replaces broadcast.
There is no directed broadcast or limited broadcast in IPv6. All broadcast functions are replaced by specific multicast groups. This is a deliberate IPv6 improvement over IPv4.
❌
Trap 5: LLA is REQUIRED on every IPv6 interface. GUA is optional.
The LLA (fe80::/10) is mandatory — auto-created even without any GUA. A device can have a working IPv6 LLA with no GUA at all. The GUA is optional and only needed for internet routable communications.
❌
Trap 6: Default gateway ALWAYS comes from the RA message — NEVER from DHCPv6.
Even in Method 3 (stateful DHCPv6 for everything else), the router's LLA used as the default gateway still comes from the RA. DHCPv6 (stateless or stateful) does not provide the default gateway. This is directly tested.
⚠️
Trap 7: GUA range = 2000::/3 (starts with 2 or 3). LLA range = fe80::/10 (fe80 through febf).
The /3 prefix 2000::/3 covers addresses starting with binary 001, which means the first hex digit is 2 or 3. The /10 prefix fe80::/10 means the first 10 bits are fixed, giving a first hextet range of fe80 to febf.
⚠️
Trap 8: link-local keyword is REQUIRED when manually configuring an LLA.
Without the link-local keyword at the end, IOS tries to configure fe80:: as a GUA which fails. The full command: ipv6 address fe80::1:1 link-local. Don't forget the keyword.
⚠️
Trap 9: ipv6 unicast-routing is required on Cisco routers to forward IPv6 and send RA messages.
Not enabled by default. Without this command, the router does not send RAs, does not act as an IPv6 router, and hosts on its interfaces cannot get dynamic IPv6 addresses via SLAAC.
⚠️
Trap 10: EUI-64 identifies fffe in the middle of the Interface ID. Random doesn't.
EUI-64: splits MAC, inserts fffe (ff:fe), flips U/L bit (bit 7). If you see fffe in the middle of a 64-bit Interface ID, it was EUI-64 generated. Windows Vista+ uses random by default — no fffe in the middle.
⚠️
Trap 11: IPv6 subnetting uses the Subnet ID — no borrowing from Interface ID needed.
Just increment the 4th hextet (Subnet ID). /48 prefix + 16-bit Subnet ID = 65,536 /64 subnets. No VLSM, no binary, no formula — just count up in hex. WAN links also use /64 (no conservation needed).
⚠️
Trap 12: In show ipv6 route, L = /128 host route for the router's own GUA — NOT the LLA.
LLAs are not in the routing table (not routable). The L entry shows the router's own GUA as a /128 host route used for efficient processing of packets destined to the router itself.
⚠️
Trap 13: Loopback in IPv6 = ::1 (not 127.0.0.1). Unspecified = ::
::1/128 is the loopback address — tests local IPv6 stack, never sent to network. ::/128 is the unspecified address — used as a source before a host gets an address (like 0.0.0.0 in IPv4). Know both.
⚠️
Trap 14: Three coexistence techniques — Dual Stack (preferred/native), Tunneling (IPv6 in IPv4), Translation/NAT64 (IPv6↔IPv4 translation).
Dual stack is the end goal — native IPv6 from source to destination. Tunneling and NAT64 are transition tools only used where dual stack isn't yet available.
✅
