16.1Security Threats and Vulnerabilities▾

16.1.1 Four Types of Threats

🔍 Information Theft
Breaking into a computer to obtain confidential information. Stolen info may be sold or used for competitive or financial gain (e.g., R&D data, trade secrets).
💥 Data Loss and Manipulation
Breaking in to destroy or alter data records (e.g., virus reformats a hard drive; manipulating prices in a database). Destroys or corrupts, rather than copies.
🪪 Identity Theft
Stealing personal information to impersonate someone — obtaining legal documents, applying for credit, making unauthorized purchases. Costs billions per year globally.
🚫 Disruption of Service
Preventing legitimate users from accessing services they are entitled to (e.g., DoS/DDoS attacks on servers, network devices, or communication links).

16.1.2 Three Types of Vulnerabilities

TypeExamples
TechnologicalInherent weaknesses in protocols (HTTP, FTP, ICMP, SNMP, SMTP all have known weaknesses); OS vulnerabilities (documented in CERT archives); Network equipment weaknesses (poor password protection, lack of authentication, firewall holes)
ConfigurationUnsecured user accounts; easily guessed passwords; misconfigured internet services; unsecured default settings from manufacturer; misconfigured access lists, routing protocols, or SNMP community strings
PolicyNo written security policy; political battles preventing enforcement; weak or default passwords; no logical access controls; unauthorized software/hardware changes; no disaster recovery plan

16.1.3 Physical Security — Four Classes of Physical Threats

ClassExamples
HardwarePhysical damage to servers, routers, switches, cabling plant, workstations
EnvironmentalTemperature extremes (too hot or too cold); humidity extremes (too wet or too dry)
ElectricalVoltage spikes; insufficient supply voltage (brownouts); unconditioned power (noise); total power loss
MaintenanceElectrostatic discharge (ESD); lack of critical spare parts; poor cabling; poor labeling

Physical security plan steps: (1) Lock equipment rooms; restrict access from doors, ceiling, vents, ducts (2) Monitor closet entry with electronic logs (3) Use security cameras

16.2Network Attacks▾

16.2.1 Types of Malware

Malware = malicious software — code designed to damage, disrupt, steal, or perform illegitimate actions on data, hosts, or networks.

🦠 Virus
· Attaches to an executable file; becomes part of another program
· Requires human action to spread (opening/running an infected file)
· Spreads via network, disk, file sharing, or infected email attachments
· Host program usually keeps functioning after infection
· Some viruses overwrite host programs completely
· Does NOT spread on its own — needs user to execute
🪱 Worm
· Standalone — does NOT require a host file
· NO human action needed to propagate
· Exploits OS/software vulnerabilities to spread through network unaided
· Self-replicating — makes copies of itself
· Can cause same damage as viruses (bandwidth consumption, system crashes)
· Mitigation: patch the OS vulnerability it exploits
🐴 Trojan Horse
· Disguised as legitimate, useful software
· Requires user interaction to spread (opening email attachment, downloading)
· Does NOT self-replicate or attach to other programs
· After activation: can damage, steal data, or create backdoors
· Can activate and spread other malware (viruses) once installed
· Named after the Greek myth — appears safe, is not
🎯 MALWARE QUICK COMPARE
Virus: host file required + human action required + attaches to programs
Worm: no host file + no human action + self-replicating + exploits vulnerabilities
Trojan: looks legitimate + user interaction required + no self-replication + creates backdoors

16.2.2 Three Attack Categories + Reconnaissance

CategoryGoalDescription
ReconnaissanceDiscoverMapping of systems, services, and vulnerabilities before an attack
AccessExploitUnauthorized manipulation of data, system access, or user privileges
Denial of ServiceDisruptDisabling or corrupting networks, systems, or services

Three types of reconnaissance attacks:

🔎 Internet Queries
Using Google, whois, organization websites to gather initial target information (IP space, personnel, infrastructure). No direct contact with target.
📡 Ping Sweeps
Tools like fping or gping systematically ping every IP address in a range to identify active hosts. Similar to calling every number in a phone book section.
🔌 Port Scans
Scanning active IP addresses to identify which ports are open and what services are running — reveals attack surface.

16.2.3 Four Types of Access Attacks

🔑 Password Attacks
Brute-force (try all combinations systematically) · Trojan horse (capture keystrokes/credentials) · Packet sniffers (capture credentials sent in cleartext over network)
🤝 Trust Exploitation
Attacker compromises System B (which is trusted by System A) to use System B as a stepping stone to attack System A. Example: compromise a less-secure host to reach a more-secure target.
↩️ Port Redirection
Attacker uses a compromised host as a launch point to attack other targets. Example: SSH into compromised Host A → Telnet from Host A to Host B (which trusts Host A).
👥 Man-in-the-Middle (MitM)
Attacker positions between two legitimate parties. (1) Victim's request goes to attacker (2) Attacker forwards to real server (3) Attacker can read/modify response (4) Modified page sent to victim. Intercepts and can alter all traffic.

16.2.4 DoS and DDoS Attacks

🔴 DoS — Denial of Service
Single source floods target with traffic or exploits a vulnerability to crash/overwhelm a service. Prevents legitimate users from accessing the service. Relatively simple to execute — even by unskilled actors. Can cause massive business disruption.
💀 DDoS — Distributed DoS
Originates from multiple coordinated sources simultaneously.

· Threat actor builds a botnet (network of infected zombie hosts)
· Uses a CnC (Command and Control) program to direct the botnet
· All zombies attack the target simultaneously
· Far more powerful and harder to stop than single-source DoS
💡
DoS attacks are among the most publicized and most difficult to fully eliminate. Prevention includes: keeping OS and applications patched, using rate-limiting, and deploying firewalls with SPI.
16.3Network Attack Mitigations▾

16.3.1 Defense-in-Depth (Layered Security)

No single security tool provides complete protection. Defense-in-depth combines multiple devices and services working together.

VPN (Router)Provides secure encrypted tunnels for remote users and corporate site-to-site connections
ASA FirewallDedicated stateful firewall — allows established outbound connections back in; blocks unsolicited inbound connections
IPSIntrusion Prevention System — monitors traffic for malware and attack signatures; can immediately stop detected threats
ESAEmail Security Appliance — filters spam and suspicious emails before they reach users
WSAWeb Security Appliance — filters known and suspicious malware websites; blocks access to dangerous URLs
AAA ServerSecure database of authorized users; network devices authenticate administrative users against it

16.3.2 Backups

ConsiderationDescription
FrequencyRegular backups per security policy. Full backups monthly/weekly; partial backups of changed files more frequently
StorageAlways validate backups to ensure data integrity and that restoration procedures work
SecurityProtect backups with strong passwords; store offsite on a rotation schedule (daily/weekly/monthly)
ValidationTest that backups can actually be restored — an untested backup may fail when most needed
💡
Infrastructure devices should have configuration files and IOS images backed up to an FTP or similar server. If hardware fails, the device can be quickly restored from backup rather than reconfigured from scratch.

16.3.3 Upgrade, Update, and Patch

  • Most effective mitigation for worm attacks: download OS security updates and patch all vulnerable systems
  • Most effective mitigation for virus attacks: update antivirus software definitions regularly
  • Enable automatic updates on end systems where possible
  • Deploy standard software images with approved applications; maintain consistent patching across all systems

16.3.4 AAA — Authentication, Authorization, and Accounting

🔐
AuthenticationWho are you? Verify identity before granting access. Credit card analogy: identifies who can use it.
✅
AuthorizationWhat can you do? What resources and actions are permitted? Credit card: how much can be spent.
📋
AccountingWhat did you do? Logs all actions for audit trail. Credit card: record of all purchases.

16.3.5–16.3.6 Firewalls, DMZ, and Firewall Types

A firewall resides between two or more networks and controls traffic between them. It allows established outbound connections to return; blocks unsolicited inbound connections.

DMZ (Demilitarized Zone) = special network segment for servers that must be publicly accessible (web servers, email servers). External users can access DMZ servers. The internal network is protected behind a second firewall layer. Admins apply specific policies to DMZ hosts.

Four types of firewalls:

Packet FilterAllows/denies based on IP or MAC addresses. Simple, fast, but can't detect application-level attacks.
App FilterAllows/denies based on port numbers (specific application types). Can block specific services regardless of IP.
URL FilterAllows/denies access to websites based on specific URLs or keywords. Blocks malicious/inappropriate sites.
SPI ★ BestStateful Packet Inspection — only allows inbound packets that are legitimate responses to established outbound connections. Can also recognize and filter specific attack types like DoS. Most effective type.

16.3.7 Endpoint Security

Endpoint = individual client device (laptop, desktop, server, smartphone, tablet).

Securing endpoints is one of the most challenging tasks — it involves human behavior. Requires: well-documented policies, employee training, antivirus software, host intrusion prevention, and network access control (NAC).

16.4Device Security▾

16.4.1 Cisco AutoSecure and Device Basics

Router# auto secure — Cisco feature that assists in securing the router. Not a complete solution but a good starting point that disables unnecessary services and enables basic security.

Basic security for all devices:

  • Change default usernames and passwords immediately
  • Restrict access to authorized users only
  • Turn off and uninstall any unnecessary services and applications
  • Update software and install security patches before deployment

16.4.2 Password Guidelines

GuidelineDetail
LengthMinimum 8 characters, preferably 10 or more. Longer = more secure.
ComplexityMix of uppercase, lowercase, numbers, symbols, and spaces
AvoidDictionary words, repetition, sequences (123456), usernames, names, birthdates, easily guessable personal info
MisspellSmith → 5mYth · Security → 5ecur1ty · Deliberate substitutions are harder to crack
Change oftenLimits window of opportunity if password is compromised
Don't write downNever leave passwords visible on desks, monitors, or sticky notes
💡
Passphrase = multiple words combined (e.g., "coffee table lamp 7" or "IloveNetworks!2024"). Passphrases are longer and easier to remember than random characters, yet harder to crack because of length. On Cisco devices, spaces within a password (after the first character) are valid — useful for creating space-separated passphrases.
TypeExamplesWhy
❌ Weaksecret · smith · toyota · bob1967 · Blueleaf23Dictionary words, personal info, simple sequences
✅ Strongb67n42d39c · 12^h u4@1p7Alphanumeric + symbols + spaces; no recognizable pattern

16.4.3 Additional Password Security Commands

Additional Password Security — IOS Commands
Router(config)# service password-encryption
! Encrypts all plaintext passwords in running-config (Type 7 — weak but better than plaintext)

Router(config)# security passwords min-length 8
! New passwords must be at least 8 characters long

Router(config)# login block-for 120 attempts 3 within 60
! Block VTY login attempts for 120 seconds if 3 failed attempts occur within 60 seconds
! Deters brute-force password attacks

Router(config)# line vty 0 4
Router(config-line)# exec-timeout 5 30
! Automatically disconnect idle sessions after 5 minutes 30 seconds
! Prevents exploitation of unattended privileged EXEC sessions
⚠️
service password-encryption = Type 7 (weak, reversible). It prevents casual viewing of passwords in config files but can be decoded with free online tools. It is NOT a substitute for enable secret (MD5, strong). Always use enable secret for privileged EXEC access.

16.4.4 Enable SSH — Six Configuration Steps

🚨
Telnet sends all data including passwords in cleartext. Never use Telnet in production. SSH encrypts the entire session. Always configure SSH and disable Telnet on all network device VTY lines.
1
Configure unique hostname — device must have a unique hostname other than "Router" or "Switch"
hostname R1
2
Configure IP domain name — used with hostname to create RSA key name
ip domain-name cisco.com
3
Generate RSA key pair — minimum 1024 bits recommended; creates encryption key named hostname.domain
crypto key generate rsa general-keys modulus 1024
4
Create local database username — use "secret" keyword for MD5 encryption
username admin secret cisco12345
5
Authenticate VTY against local database
line vty 0 4 → login local
6
Allow only SSH on VTY lines — restricts to SSH, disables Telnet
transport input ssh
💡
Why does SSH need a domain name?

The RSA key pair that SSH uses must have a name. Cisco IOS automatically builds that name by combining the hostname and domain name — for example hostname R1 + ip domain-name cisco.com creates a key named R1.cisco.com.

Without a domain name configured, the crypto key generate rsa command will fail with the error:
% Please define a domain-name first.

The domain name does not need to be a real registered domain — it is only used locally to name the RSA key. Common choices in labs: cisco.com, ccna-lab.com, lab.local.

Also note: ip ssh version 2 forces SSHv2 which is more secure than SSHv1. Always add this after generating the RSA keys. SSHv1 has known cryptographic weaknesses.
Complete SSH Configuration Example
Router(config)# hostname R1
R1(config)# security passwords min-length 10
R1(config)# enable secret class12345
R1(config)# ip domain-name cisco.com
R1(config)# username admin secret cisco12345
R1(config)# crypto key generate rsa modulus 1024
! Key name auto-created as: R1.cisco.com
! Output: % Generating 1024 bit RSA keys, keys will be non-exportable... [OK]
! Output: %SSH-5-ENABLED: SSH 1.99 has been enabled
R1(config)# ip ssh version 2
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh
R1(config-line)# end

16.4.5 Disable Unused Services

Only run necessary services. Unused services waste CPU/RAM and expand the attack surface.

Verify and Disable Unused Services
! Check active listening ports (IOS-XE):
Router# show ip ports all

! Check active ports (older IOS):
Router# show control-plane host open-ports
! Output may show Telnet (23) and HTTP (80) — both should be disabled

! Disable unencrypted HTTP web management:
Router(config)# no ip http server

! Restrict VTY to SSH only (disables Telnet):
Router(config)# line vty 0 15
Router(config-line)# transport input ssh
✅
IOS-XE default: Only HTTPS (443) and DHCP (67) ports are open by default — a much more secure starting point than older IOS versions which may have HTTP (80) and Telnet (23) enabled by default.

🎯Common Exam Traps — Module 16▾
❌
Trap 1: Virus needs host file + human action. Worm needs neither. Trojan = disguised software, no self-replication.
Virus: attaches to programs, spreads when user runs infected file. Worm: standalone, exploits vulnerabilities, spreads automatically. Trojan: looks legitimate, user installs it, creates backdoors but doesn't self-replicate. These distinctions appear in every exam.
❌
Trap 2: Three vulnerability types: Technological · Configuration · Policy. Four physical threat classes: Hardware · Environmental · Electrical · Maintenance.
Electrostatic discharge = maintenance. Temperature = environmental. Voltage spike = electrical. Physical damage = hardware. Know which threat goes in which physical class.
❌
Trap 3: DDoS uses a botnet of zombie hosts controlled by a CnC (Command and Control) program.
Botnet = network of infected computers (zombies). CnC = software used by the attacker to direct all zombies to attack simultaneously. DDoS is distributed across many sources — this is what makes it so much more powerful and harder to stop than single-source DoS.
❌
Trap 4: SSH requires BOTH hostname AND domain name before crypto key generate rsa will work.
The RSA key name is automatically created as hostname.domain-name. If either is missing, the key cannot be generated and SSH cannot be enabled. Minimum modulus = 1024 bits. Both must be configured BEFORE the crypto key command.
❌
Trap 5: service password-encryption = Type 7 (weak, reversible). enable secret = MD5 (strong). These are NOT equivalent.
service password-encryption protects console and VTY passwords from casual viewing in the config file — but these passwords can be decoded. enable secret uses MD5 which cannot be reversed. Never use service password-encryption as a substitute for enable secret.
⚠️
Trap 6: Three attack categories: Reconnaissance (discover) · Access (exploit) · DoS (disrupt).
Reconnaissance discovers the target — internet queries, ping sweeps, port scans. Access attacks exploit what was found — password attacks, trust exploitation, port redirection, MitM. DoS prevents legitimate access. Know which specific attacks belong to each category.
⚠️
Trap 7: SPI (Stateful Packet Inspection) is the most effective firewall type — tracks connection state.
SPI only allows inbound packets that are legitimate responses to established outbound connections. It can also detect and block DoS attacks. Packet filtering (IP/MAC), application filtering (ports), and URL filtering are simpler techniques. SPI combines all of these with state tracking.
⚠️
Trap 8: AAA — Authentication (who are you?), Authorization (what can you do?), Accounting (what did you do?).
AAA = "Triple A" = the primary framework for access control. Credit card analogy: auth=who can use it, authz=spending limit, accounting=transaction record. Know which letter covers which function.
⚠️
Trap 9: login block-for 120 attempts 3 within 60 — block for 120 seconds after 3 failed attempts in 60 seconds.
Deters brute-force password attacks. The syntax order: block duration (120s) → keyword "attempts" → threshold (3) → keyword "within" → window (60s). Applied in global configuration mode, protects VTY lines.
⚠️
Trap 10: exec-timeout 5 30 = 5 minutes 30 seconds idle timeout. Applies to console, aux, and VTY lines.
Prevents exploitation of unattended logged-in sessions. Default Cisco timeout = 10 minutes. Configured in line configuration mode. Applied per line (console 0, aux 0, vty 0 4).
⚠️
Trap 11: Worm mitigation = patch OS. Virus mitigation = update antivirus definitions.
Worms exploit OS and software vulnerabilities — patching removes the vulnerability itself. Viruses spread through files — antivirus software detects and quarantines infected files. Know which mitigation matches which malware type.
⚠️
Trap 12: DMZ = network segment for publicly accessible servers. NOT the same as the internal network.
The DMZ hosts servers that need to be reachable from the internet (web, email). They're isolated from the internal network. External users reach DMZ servers but cannot reach internal hosts. The internal network is behind both the internet firewall AND the internal firewall.
✅
