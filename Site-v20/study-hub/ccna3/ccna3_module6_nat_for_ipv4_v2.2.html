6.1NAT Characteristics▾

6.1.1 RFC 1918 Private Address Space

Private IPv4 addresses cannot be routed on the internet. They are used internally within an organization. To reach outside resources, private addresses must be translated to a public address via NAT.

A
10.0.0.0 – 10.255.255.255
10.0.0.0/8
B
172.16.0.0 – 172.31.255.255
172.16.0.0/12
C
192.168.0.0 – 192.168.255.255
192.168.0.0/16

6.1.2 What Is NAT and How It Works

NAT's primary purpose is to conserve public IPv4 addresses. A single public IPv4 address can be shared by hundreds or thousands of devices, each using a unique private address internally.

NAT-enabled routers operate at the border of a stub network — a network with a single connection in and out. The NAT router is the demarcation point between the inside (private) and outside (internet) networks.

💡
When an internal device sends traffic out, the NAT router replaces the private source IP with a public IP from the NAT pool. When return traffic arrives, the NAT router translates the destination public IP back to the private IP and forwards the packet to the internal host.

6.1.4 Four NAT Address Types

NAT terminology is always applied from the perspective of the inside device being translated:

  • Inside/Outside — which side of the NAT router is the device on?
  • Local/Global — is this address visible on the inside (local) or on the internet (global)?
Inside Local
Private · Before Translation

The private IPv4 address assigned to an inside host. This is what the host uses internally — never seen by the internet. Example: 192.168.10.10

Inside Global
Public · After Translation

The public IPv4 address of the inside host as seen from the internet. This is what the ISP and destination servers see as the source. Example: 209.165.200.226

Outside Local
Destination · Inside View

The destination address as seen from inside the network. Usually the same as the outside global address — the outside host is typically not translated.

Outside Global
Destination · Real Address

The actual public IPv4 address of the destination host on the internet. Example: 209.165.201.1 (web server)

🎯 EXAM-CRITICAL — INSIDE GLOBAL IS THE KEY TERM
Inside global = what the internet sees as the source of inside traffic.
Example: PC1 (192.168.10.10) → NAT → internet sees source as 209.165.200.226
· PC1's inside local = 192.168.10.10 (private, inside)
· PC1's inside global = 209.165.200.226 (public, translated — what ISP sees)

On show ip nat translations — the Inside global column shows the public IP the internet sees.
6.2Types of NAT▾

6.2.1–6.2.3 Three Types of NAT

🔒 Static NAT
One-to-One · Permanent
  • One inside local ↔ one inside global — never changes
  • Manually configured by administrator — always in NAT table
  • Allows external hosts to initiate connections to internal servers
  • Use case: web servers, mail servers accessible from internet
  • Requires one public IP per device using static NAT
  • Static entries never time out
🔄 Dynamic NAT
One-to-One · Temporary · First-Come First-Served
  • Uses a pool of public addresses — assigned on demand
  • One inside local → one inside global (still one-to-one)
  • Mappings created automatically when inside host initiates traffic
  • If pool is exhausted, hosts must wait for a free address
  • Default timeout: 24 hours (86400 seconds)
  • Requires enough pool addresses for all simultaneous sessions
🌐 PAT — Port Address Translation (NAT Overload)
Many-to-One · Uses Port Numbers · Most Common
  • Maps many private IPs to one (or few) public IPs
  • Sessions distinguished by TCP/UDP source port numbers
  • ICMP: uses Query ID instead of port numbers
  • Most common NAT: home routers and enterprise networks
  • ISP gives one public IP → hundreds of internal hosts share it
  • If source port already in use, PAT assigns next available from group (0–511, 512–1023, 1024–65535)
  • Configured by adding overload keyword to the NAT command

6.2.5 NAT vs PAT — Key Differences

FeatureNAT (Static / Dynamic)PAT (NAT Overload)
MappingOne-to-one: one Inside Local → one Inside GlobalMany-to-one: many Inside Local → one Inside Global
Translation basisIPv4 addresses onlyIPv4 addresses + TCP/UDP source port numbers
Public IP requirementOne unique public IP per simultaneous sessionOne public IP can serve many simultaneous sessions
show ip nat translationsShows --- in port columnsShows port numbers (e.g., 209.165.200.225:1444)

6.3NAT Advantages and Disadvantages▾

6.3.1–6.3.2 NAT Pros and Cons

✅
Conserves public IPv4 addresses — allows many devices to share one public IP via PAT overload
✅
Increases connection flexibility — multiple pools, backup pools, and load-balancing pools possible
✅
Consistent internal addressing — can change ISPs without re-addressing all internal hosts
✅
Hides internal IPv4 addresses — private addresses not visible on internet (perceived privacy; not true security)
❌
Increases forwarding delays — every packet header must be translated; first packet is always process-switched through the slower path
❌
Carrier Grade NAT (CGN) — when ISPs use private addressing for customers too, double NAT occurs (customer + ISP), causing extra delay and complexity
❌
Breaks end-to-end addressing — applications relying on unchanged source-to-destination IPs fail; digital signatures fail when source IP changes in transit
❌
Loses end-to-end traceability — tracing packets across multiple NAT hops is very difficult; complicates troubleshooting
❌
Breaks IPsec tunneling — NAT modifies IP header values; IPsec integrity checks fail because the header values no longer match the original hash
❌
Disrupts services requiring inbound TCP connections — stateless UDP protocols and services needing externally-initiated connections (e.g., passive FTP) can fail without static NAT mappings
🚨
NAT does NOT provide real security. NAT hides internal addresses as a side effect, but security experts agree that NAT is not a security mechanism. A stateful firewall provides security at the edge — not NAT.
6.4Static NAT Configuration▾

6.4.2 Configure Static NAT — Two Steps

⚙️ Static NAT — Two-Step Configuration
1
Create the static mapping between inside local and inside global address: R2(config)# ip nat inside source static [inside-local-ip] [inside-global-ip]
2
Mark interfaces as inside or outside relative to NAT: R2(config-if)# ip nat inside ← on private-side interface R2(config-if)# ip nat outside ← on public-side (ISP) interface
Static NAT — complete configuration example 
! Step 1 — Create static mapping (inside local → inside global):
R2(config)# ip nat inside source static 192.168.10.254 209.165.201.5
!                                        ^inside local  ^inside global

! Step 2 — Mark interfaces:
R2(config)# interface serial 0/1/0
R2(config-if)# ip address 192.168.1.2 255.255.255.252
R2(config-if)# ip nat inside            ← connected to private/inside network
R2(config-if)# exit
R2(config)# interface serial 0/1/1
R2(config-if)# ip address 209.165.200.1 255.255.255.252
R2(config-if)# ip nat outside           ← connected to internet/ISP

6.4.3 Static NAT Translation Process

  1. External client sends packet to the web server's inside global address (209.165.201.5) — the public address
  2. R2 receives packet on outside interface, checks NAT table — finds 209.165.201.5 → translates destination to inside local 192.168.10.254
  3. R2 forwards packet to web server using private address 192.168.10.254
  4. Web server replies using its private IP (192.168.10.254) as source
  5. R2 receives reply on inside interface, translates source from 192.168.10.254 → 209.165.201.5 (inside global) and forwards to client
✅
Static NAT is bidirectional — external hosts can initiate connections to internal servers using the inside global (public) address. The NAT router translates in both directions.

6.4.4 Verify Static NAT

show ip nat translations — static NAT verification 
! Static entry always present (no active session needed):
R2# show ip nat translations
Pro  Inside global      Inside local       Outside local      Outside global
---  209.165.201.5      192.168.10.254     ---                ---
Total number of translations: 1

! During an active session — also shows outside device address:

tcp  209.165.201.5       192.168.10.254     209.165.200.254     209.165.200.254
---  209.165.201.5       192.168.10.254     ---                 ---
Total number of translations: 2

! Statistics — clear before testing for accurate results:
R2# clear ip nat statistics
R2# show ip nat statistics

Outside interfaces: Serial0/1/1

Hits: 4   Misses: 1

6.5Dynamic NAT Configuration▾

6.5.2 Configure Dynamic NAT — Four Steps

⚙️ Dynamic NAT — Four-Step Configuration
1
Define the pool of public IP addresses available for translation: R2(config)# ip nat pool NAT-POOL1 209.165.200.226 209.165.200.240 netmask 255.255.255.224
2
Create a standard ACL to identify which inside hosts get translated: R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255
3
Bind the ACL to the pool: R2(config)# ip nat inside source list 1 pool NAT-POOL1
4
Mark interfaces as inside or outside: R2(config-if)# ip nat inside ← on inside interface R2(config-if)# ip nat outside ← on outside interface
Dynamic NAT — complete configuration example 
! Step 1 — Define pool of public addresses:
R2(config)# ip nat pool NAT-POOL1 209.165.200.226 209.165.200.240 netmask 255.255.255.224

! Step 2 — Standard ACL identifies inside hosts to translate:
R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255

! Step 3 — Bind ACL to pool:
R2(config)# ip nat inside source list 1 pool NAT-POOL1

! Step 4 — Mark interfaces:
R2(config)# interface serial 0/1/0
R2(config-if)# ip nat inside
R2(config)# interface serial 0/1/1
R2(config-if)# ip nat outside

6.5.5 Verify Dynamic NAT

show ip nat translations — dynamic NAT verification 
! Dynamic entries — created when hosts generate traffic:
R2# show ip nat translations
Pro  Inside global      Inside local       Outside local      Outside global
---  209.165.200.228    192.168.10.10      ---                ---
---  209.165.200.229    192.168.11.10      ---                ---

! Verbose adds timing info:
R2# show ip nat translations verbose
! Shows: create time, last use time, timeout remaining (default 86400s = 24hr)

! Pool usage statistics:
R2# show ip nat statistics
Total active translations: 4 (0 static, 4 dynamic; 0 extended)
Inside interfaces: Serial0/1/0
Outside interfaces: Serial0/1/1
Dynamic mappings:
-- Inside Source [Id: 1] access-list 1 pool NAT-POOL1 refcount 4
   pool NAT-POOL1: netmask 255.255.255.224
   start 209.165.200.226 end 209.165.200.240
   type generic, total addresses 15, allocated 2 (13%), misses 0

! Clear dynamic translations (static entries cannot be cleared):
R2# clear ip nat translation *                        ! Clear ALL dynamic
R2# clear ip nat translation inside 209.165.200.228 192.168.10.10   ! Clear specific

! Change default 24-hour timeout:
R2(config)# ip nat translation timeout 3600           ! Change to 1 hour
⚠️
Only dynamic translations can be cleared with clear ip nat translation. Static NAT entries are permanent — they can only be removed by deleting the ip nat inside source static command from the configuration.

6.6PAT Configuration▾

6.6.2 PAT — Single Public IP (Interface Reference)

When the ISP assigns only one public IP — the most common home/enterprise scenario. The router's outside interface IP is used as the single inside global address. Add interface [intf] instead of a pool, plus the overload keyword:

PAT — single interface IP (most common) 
! ACL identifies inside hosts:
R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255

! Bind to INTERFACE (not pool) + overload keyword:
R2(config)# ip nat inside source list 1 interface serial 0/1/1 overload
!                                                    ^outside intf  ^PAT keyword

! Mark interfaces:
R2(config)# interface serial 0/1/0
R2(config-if)# ip nat inside
R2(config)# interface serial 0/1/1
R2(config-if)# ip nat outside

6.6.3 PAT — Address Pool with Overload

When the ISP assigns a small pool of public IPs — all hosts in the inside network share the pool via port multiplexing. Same as dynamic NAT but adds overload:

PAT — address pool with overload keyword 
! Define pool:
R2(config)# ip nat pool NAT-POOL2 209.165.200.226 209.165.200.240 netmask 255.255.255.224

! ACL identifies inside hosts:
R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255

! Bind to pool + overload keyword:
R2(config)# ip nat inside source list 1 pool NAT-POOL2 overload
!                                                        ^pool name  ^PAT keyword

! Mark interfaces:
R2(config)# interface serial 0/1/0
R2(config-if)# ip nat inside
R2(config)# interface serial 0/1/1
R2(config-if)# ip nat outside
🎯 PAT COMMAND COMPARISON — KNOW BOTH FORMS
Single IP (interface):
ip nat inside source list 1 interface serial 0/1/1 overload

Address pool:
ip nat inside source list 1 pool NAT-POOL2 overload

The only differences: interface [intf] vs pool [name], and both end with overload.

6.6.6 Verify PAT

show ip nat translations — PAT output with port numbers 
! PAT entries — note port numbers distinguishing sessions:
R2# show ip nat translations
Pro  Inside global             Inside local         Outside local        Outside global
tcp  209.165.200.225:1444      192.168.10.10:1444   209.165.201.1:80     209.165.201.1:80
tcp  209.165.200.225:1445      192.168.11.10:1444   209.165.202.129:80   209.165.202.129:80
!    ^same public IP ^diff port ^diff inside hosts               ^different servers

! Key insight:
! - Both inside hosts translated to SAME public IP (209.165.200.225)
! - Port 1444 → 192.168.10.10, Port 1445 → 192.168.11.10
! - Port numbers make each entry UNIQUE in the NAT table

! PAT statistics — pool shows only 1 address allocated for multiple sessions:
R2# show ip nat statistics
Total active translations: 4 (0 static, 2 dynamic; 2 extended)
Hits: 4   Misses: 0
Dynamic mappings:
-- Inside Source [Id: 3] access-list 1 pool NAT-POOL2 refcount 2
   pool NAT-POOL2: netmask 255.255.255.224
   start 209.165.200.225 end 209.165.200.240
   type generic, total addresses 15, allocated 1 (6%), misses 0
!                                                  ^only 1 public IP used for 2 sessions
💡
PAT entries are "extended" translations — the show ip nat statistics shows 2 extended meaning these entries include port number information in addition to IP addresses. Non-PAT entries show 0 extended.

6.7NAT64 — IPv4 to IPv6 Transition▾

6.7.1–6.7.2 IPv4 → IPv6 Transition Strategies

IPv6 (128-bit addresses) was designed to make NAT unnecessary. However, during the long transition from IPv4 to IPv6, three coexistence strategies exist:

🔵 Dual-Stack
Devices run both IPv4 and IPv6 simultaneously. The preferred approach — IPv6 devices communicate natively using IPv6 while still supporting IPv4 when needed.
🟢 Tunneling
IPv6 packets encapsulated inside IPv4 packets to cross IPv4-only networks. The IPv6 packet is treated as payload inside the IPv4 tunnel — transparent to IPv4 infrastructure.
🟡 NAT64
Protocol translation between IPv6-only and IPv4-only networks. Different from IPv4 NAT — it translates between protocol versions, not just addresses. NAT-PT (older) was deprecated by IETF; NAT64 replaced it.
⚠️
NAT64 is a temporary migration tool — not a long-term strategy. The goal is native IPv6 everywhere. IPv6 ULAs (Unique Local Addresses) are similar to RFC 1918 private addresses but are for local-only site communications — they are NOT intended to extend address space or provide security.
🎯 NAT64 EXAM KEY POINTS
  • NAT64 translates between IPv6-only ↔ IPv4-only networks — not private-to-public IPv6
  • NAT-PT (older) was deprecated by IETF — replaced by NAT64
  • IPv6 ULAs ≠ RFC 1918 purpose — ULAs are for local site communication only, not address space extension
  • NAT64 is a temporary mechanism for the IPv4→IPv6 migration period
  • Dual-stack = run both protocols; Tunneling = encapsulate IPv6 in IPv4; NAT64 = translate between

All current NAT table entries — inside global, inside local, outside addresses. PAT entries include port numbers.

NAT maintenance and clearing commands

clear ip nat statistics                                  ! Reset hit/miss counters

🎯Common Exam Traps — Module 6▾
❌
Trap 1: Inside local = private IP before translation. Inside global = public IP after translation.
The most confused NAT terms. Inside local is what the host uses internally (private). Inside global is what the internet sees (public). Apply the perspective from the inside device being translated. On show ip nat translations, "Inside global" is the public address column.
❌
Trap 2: PAT requires the overload keyword — without it, it's dynamic NAT (one-to-one).
ip nat inside source list 1 pool POOL = dynamic NAT (one host per pool address). ip nat inside source list 1 pool POOL overload = PAT (many hosts per pool address). The single word overload is the entire difference between these two NAT types.
❌
Trap 3: PAT using a single IP references the interface — not a pool.
Single IP PAT: ip nat inside source list 1 interface serial 0/1/1 overload. Pool PAT: ip nat inside source list 1 pool NAT-POOL2 overload. The key difference: interface [intf] vs pool [name].
❌
Trap 4: Both interfaces MUST be marked — ip nat inside AND ip nat outside.
Forgetting either mark is the most common NAT configuration error. Without ip nat inside, the router doesn't know which traffic to translate. Without ip nat outside, it doesn't know where to send translated packets. Both commands are mandatory.
❌
Trap 5: Static NAT entries are permanent — cannot be cleared with clear ip nat translation.
clear ip nat translation * only removes dynamic (and PAT) entries. Static entries remain in the table until the ip nat inside source static command is removed from the configuration.
⚠️
Trap 6: Dynamic NAT pool must have enough addresses for simultaneous sessions.
If the pool runs out of addresses, new inside hosts must wait until an address becomes free (after 24-hour timeout or manual clearing). This is a key difference from PAT — PAT never runs out because it multiplexes port numbers on top of addresses.
⚠️
Trap 7: Dynamic NAT requires an ACL — the ACL identifies inside hosts, not outside.
The standard ACL bound to the NAT pool specifies which inside hosts are permitted to be translated. This is NOT a security ACL — it just identifies which source addresses should trigger NAT translation.
⚠️
Trap 8: PAT show ip nat translations output includes port numbers — NAT output shows "---".
Static/dynamic NAT: --- 209.165.201.5 192.168.10.254 --- ---. PAT: tcp 209.165.200.225:1444 192.168.10.10:1444 209.165.201.1:80 209.165.201.1:80. The port numbers in the inside global column are the key indicator of PAT.
⚠️
Trap 9: show ip nat statistics tells you pool usage — look for "allocated X (%)".
For dynamic NAT, this shows how many pool addresses are in use. For PAT, even with many sessions, "allocated 1 (6%)" means only one public IP was used — because PAT multiplexes all sessions through one address using different ports.
⚠️
Trap 10: NAT does NOT provide security — a stateful firewall does.
NAT hides internal addresses as a side effect, but experts agree NAT is not a security mechanism. The Cisco curriculum specifically states: "A stateful firewall is what provides security on the edge of the network" — not NAT.
⚠️
Trap 11: Carrier Grade NAT (CGN) = double NAT = ISP also uses private IPs.
When ISPs run out of public IPs, they assign customers private IPs, then NAT again at the ISP. Two NAT translations occur per packet (customer router + ISP router). This adds delay and makes troubleshooting very difficult.
⚠️
Trap 12: NAT-PT is deprecated — NAT64 replaced it.
For the IPv4→IPv6 transition: NAT-PT (older) was deprecated by IETF. NAT64 is the current standard. NAT64 translates between IPv6-only and IPv4-only networks — it is NOT the same as IPv4 NAT and should not be used as a long-term solution.
✅
