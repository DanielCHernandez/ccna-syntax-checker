2.1OSPF Router ID▾

2.1.2 Enable OSPF — router ospf Command

Enable OSPF and enter router configuration mode 
R1(config)# router ospf 10
R1(config-router)# ?
  area                   OSPF area parameters
  auto-cost              Calculate OSPF interface cost according to bandwidth
  default-information    Control distribution of default information
  network                Enable routing on an IP network
  passive-interface      Suppress routing updates on an interface
  router-id              router-id for this OSPF process
R1(config-router)#
  • process-id = 1–65,535 — chosen by the administrator
  • Locally significant — does NOT need to match on neighboring routers to form adjacencies
  • Best practice: use the same process-id on all routers in the domain for consistency
  • Entering router ospf drops into (config-router)# mode

2.1.4 Router ID Order of Precedence

Cisco routers use a three-tier method to select the OSPF Router ID. The first applicable method wins:

PrioritySourceNotes
① Bestrouter-id rid commandRecommended. Any 32-bit value in dotted decimal. Always use this.
② AltHighest loopback IPv4 addressLoopbacks never go down — provides a stable RID without manual config
③ LastHighest active physical interface IPv4 addressLeast recommended — if the highest-IP interface goes down, RID changes, disrupting OSPF
💡
OSPF does NOT need to be enabled on an interface for that interface's IP to be chosen as the Router ID — it just needs to be configured and active on the router.

2.1.5 Configure a Loopback Interface as the Router ID

Use a /32 mask on loopbacks designated only as a Router ID source — this prevents OSPF from advertising the loopback as a real network to neighbors:

Loopback as stable Router ID — /32 host mask 
R1(config)# interface Loopback 1
R1(config-if)# ip address 1.1.1.1 255.255.255.255   ! /32 = not advertised as network
R1(config-if)# end
R1# show ip protocols | include Router ID
  Router ID 1.1.1.1

2.1.6 Explicitly Configure Router ID

Best practice — always manually configure the Router ID using the router-id command:

Manually configure Router ID on R1, R2, R3 
! R1:
R1(config)# router ospf 10
R1(config-router)# router-id 1.1.1.1
R1(config-router)# end
R1# show ip protocols | include Router ID
  Router ID 1.1.1.1

! R2:
R2(config)# router ospf 10
R2(config-router)# router-id 2.2.2.2

! R3:
R3(config)# router ospf 10
R3(config-router)# router-id 3.3.3.3
✅
Convention: use the router number as all four octets (R1=1.1.1.1, R2=2.2.2.2, R3=3.3.3.3). Makes it immediately obvious in show ip ospf neighbor output which router is which.

2.1.7 Modify a Router ID

After a router selects a Router ID, it will not change until the router is reloaded or the OSPF process is reset. Preferred method to apply a new Router ID without a full reload:

Change Router ID on running router — clear ip ospf process 
R1# show ip protocols | include Router ID
  Router ID 10.10.1.1                    ! Old/wrong Router ID

R1(config)# router ospf 10
R1(config-router)# router-id 1.1.1.1
% OSPF: Reload or use "clear ip ospf process" command, for this to take effect
R1(config-router)# end

R1# clear ip ospf process
Reset ALL OSPF processes? [no]: y
! Adjacencies drop momentarily then reform with new Router ID

R1# show ip protocols | include Router ID
  Router ID 1.1.1.1                      ! New Router ID active
🚨
clear ip ospf process is the exam-expected method. Not a full reload. The command drops all adjacencies momentarily — they reform automatically with the new Router ID. IOS will not accept the new ID until this command runs or the router reboots.

2.2Point-to-Point OSPF Networks▾

2.2.1–2.2.2 network Command and Wildcard Mask

network command syntax
Router(config-router)# network network-address wildcard-mask area area-id

Wildcard mask rules:

  • Bit = 0 → match that bit exactly (like a regular subnet mask bit 1)
  • Bit = 1 → ignore/wildcard that bit
  • Quick calculation: wildcard = 255.255.255.255 − subnet mask
🔢 Wildcard Mask Quick Reference
/30
255.255.255.252 → wildcard = 0.0.0.3
P2P link
/26
255.255.255.192 → wildcard = 0.0.0.63
/24
255.255.255.0 → wildcard = 0.0.0.255
LAN
/16
255.255.0.0 → wildcard = 0.0.255.255
exact
Any mask → wildcard = 0.0.0.0 (quad-zero)
no math needed

2.2.4 Two Approaches with the network Command

🅐 Network-based wildcard — match all interfaces on that subnet
Method A — wildcard per subnet 
R1(config)# router ospf 10
R1(config-router)# network 10.10.1.0 0.0.0.255 area 0   ! /24 LAN
R1(config-router)# network 10.1.1.4 0.0.0.3 area 0      ! /30 link
R1(config-router)# network 10.1.1.12 0.0.0.3 area 0     ! /30 link
🅑 Quad-zero wildcard — exact interface IP, no math needed
Method B — 0.0.0.0 wildcard per interface IP 
R1(config)# router ospf 10
R1(config-router)# network 10.10.1.1 0.0.0.0 area 0     ! G0/0/0 exact IP
R1(config-router)# network 10.1.1.5 0.0.0.0 area 0      ! G0/0/1 exact IP
R1(config-router)# network 10.1.1.14 0.0.0.0 area 0     ! another interface
✅
Quad-zero (0.0.0.0) is the most reliable approach — no wildcard calculation needed. Point at the exact interface IP. If you enter the wrong IP it simply won't match anything.

2.2.6 Configure OSPF Using the ip ospf Interface Method

Alternative to the network command — configure OSPF directly on each interface. No wildcard mask required:

ip ospf — per-interface configuration method 
! Syntax:
Router(config-if)# ip ospf process-id area area-id

! Example on R1 — first remove old network commands, then configure per-interface:
R1(config)# router ospf 10
R1(config-router)# no network 10.10.1.1 0.0.0.0 area 0   ! remove old method
R1(config-router)# no network 10.1.1.5 0.0.0.0 area 0
R1(config-router)# interface GigabitEthernet 0/0/0
R1(config-if)# ip ospf 10 area 0
R1(config-if)# interface GigabitEthernet 0/0/1
R1(config-if)# ip ospf 10 area 0
R1(config-if)# interface Loopback 0
R1(config-if)# ip ospf 10 area 0
💡
Both methods achieve identical results. The ip ospf interface method is cleaner for large configurations — just navigate to each interface and add one line. No wildcard calculation, no risk of matching wrong interfaces.

2.2.8–2.2.9 Passive Interface

By default, OSPF sends Hello packets out all OSPF-enabled interfaces — including LAN interfaces where no OSPF neighbor exists. Three reasons this is a problem:

⚠️ Problems with Hello on LAN interfaces
📡
Inefficient bandwidth use — Hello packets consume available bandwidth on user-facing segments where no OSPF neighbor will ever respond
💻
Wasted device resources — every host on the LAN must receive, process, and discard each OSPF Hello message
🔒
Security risk — OSPF updates can be intercepted by packet sniffers and modified to inject false routes, corrupting the routing table

Method 1 — Configure individual passive interfaces:

passive-interface — stop Hellos on LAN/loopback 
R1(config)# router ospf 10
R1(config-router)# passive-interface loopback 0       ! Stop Hellos on Lo0
R1(config-router)# end
R1# show ip protocols
! Output shows:
  Passive Interface(s):
    Loopback0                                          ← passive confirmed
  Routing on Interfaces Configured Explicitly (Area 0):
    Loopback0                                          ← still advertised to neighbors ✅

Method 2 — Make all interfaces passive, then re-enable router-facing ones:

passive-interface default + no passive-interface 
R3(config)# router ospf 10
R3(config-router)# passive-interface default           ! All interfaces → passive
! Adjacencies immediately drop on G0/0/0 and G0/0/1
R3(config-router)# no passive-interface g0/0/0        ! Re-enable for OSPF
R3(config-router)# no passive-interface g0/0/1        ! Re-enable for OSPF
! Adjacencies reform automatically
🚨
passive-interface stops Hellos — but the network IS still advertised. The connected network still appears in OSPF updates sent out other interfaces. The interface just won't send or receive Hello packets, so no neighbor can form on it.

2.2.11 OSPF Network Type — Point-to-Point on Ethernet

By default, Cisco runs DR/BDR election on ALL Ethernet interfaces — even two-router point-to-point Ethernet links. This is unnecessary overhead. Disable it:

Disable DR/BDR on Ethernet point-to-point links 
R1(config)# interface GigabitEthernet 0/0/0
R1(config-if)# ip ospf network point-to-point
! Adjacency briefly drops then reforms — no DR/BDR elected

R1# show ip ospf interface GigabitEthernet 0/0/0
  Network Type POINT_TO_POINT, Cost: 1    ← confirms no DR/BDR
  State POINT_TO_POINT                    ← no DR role shown

2.2.12 Loopbacks and Point-to-Point Networks

By default, loopback interfaces are advertised as /32 host routes regardless of the subnet mask configured. This misleads other routers about the actual network size:

Fix loopback advertisement — use ip ospf network point-to-point 
! Before fix — only /32 advertised:
R2# show ip route | include 10.10.1
O        10.10.1.1/32 [110/2] via 10.1.1.5     ! /32 host route — wrong

! Apply fix on R1's loopback:
R1(config)# interface Loopback 0
R1(config-if)# ip ospf network point-to-point

! After fix — full /24 advertised:
R2# show ip route | include 10.10.1
O        10.10.1.0/24 [110/2] via 10.1.1.5     ! /24 network — correct ✅

2.3.4 Verify OSPF Router Roles — show ip ospf interface

show ip ospf interface g0/0/0 — read DR/BDR/DROTHER state 
R1# show ip ospf interface GigabitEthernet 0/0/0
GigabitEthernet0/0/0 is up, line protocol is up
  Internet Address 192.168.1.1/24, Area 0
  Process ID 10, Router ID 1.1.1.1, Network Type BROADCAST, Cost: 1
  Transmit Delay is 1 sec, State DROTHER, Priority 1    ← R1 is DROTHER, priority=1
  Designated Router (ID) 3.3.3.3, Interface 192.168.1.3 ← DR = R3
  Backup Designated Router (ID) 2.2.2.2, Interface 192.168.1.2 ← BDR = R2
  Timer intervals configured, Hello 10, Dead 40
  Neighbor Count is 2, Adjacent neighbor count is 2
    Adjacent with neighbor 2.2.2.2  (Backup Designated Router)
    Adjacent with neighbor 3.3.3.3  (Designated Router)

2.3.5 Verify DR/BDR Adjacencies — Neighbor States

show ip ospf neighbor — multiaccess network states 
R1# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/BDR        00:00:31    192.168.1.2     Gi0/0/0
3.3.3.3           1   FULL/DR         00:00:39    192.168.1.3     Gi0/0/0

! On a point-to-point link (no DR/BDR):
3.3.3.3           0   FULL/  -        00:00:35    10.1.1.13       Gi0/0/1
                                                                    ↑ dash = no DR/BDR

Four possible neighbor states on multiaccess networks:

FULL/DR
Router is fully adjacent with the Designated Router. Full LSA exchange can occur.
FULL/BDR
Router is fully adjacent with the Backup Designated Router. Full LSA exchange can occur.
FULL/DROTHER
DR or BDR is fully adjacent with a DROTHER. Full LSA exchange can occur.
2WAY/DROTHER
Two DROTHERs — only Two-Way state. They exchange Hellos only. This is normal behavior for DROTHERs with each other.

2.3.6 Default DR/BDR Election Process

Election order — applied sequentially:

  1. Highest interface priority wins DR role. Second highest = BDR. Default priority = 1 for all Ethernet interfaces. Priority 0 = never becomes DR or BDR.
  2. If priorities are equal → highest Router ID wins. Second highest = BDR.
⚠️
DR/BDR elections are NOT preemptive. Adding a new router with a higher priority or Router ID after the election does NOT take over the DR/BDR roles. The new router simply becomes a DROTHER. Only a failure event triggers role changes.

2.3.7 DR Failure and Recovery Scenarios

DR Fails
The pre-elected BDR automatically promotes to DR. A new BDR election occurs among remaining DROTHERs. The DROTHER with the highest priority/RID becomes the new BDR.
Former DR Re-Joins Network
The returned router does NOT reclaim the DR role. It becomes a DROTHER. Election results are non-preemptive — the current DR keeps its role.
New High-Priority Router Joins
The new router becomes a DROTHER automatically. No new election triggered. DR and BDR retain their roles regardless of the new router's priority or Router ID.
BDR Fails
DR keeps its role unchanged. A new BDR election occurs among DROTHERs — highest priority/RID DROTHER becomes the new BDR.

2.3.8–2.3.9 Control DR/BDR Election — ip ospf priority

255
Maximum — always becomes DR (if first in election). Use to guarantee a specific router is DR.
1
Default for all Ethernet interfaces. Tie broken by highest Router ID.
0
Never becomes DR or BDR. Router is always DROTHER on that interface. Use for low-resource routers that should never handle DR duties.
Configure OSPF priority — force specific DR/BDR roles 
! Make R1 the DR (priority 255), R3 never DR/BDR (priority 0):
R1(config)# interface GigabitEthernet 0/0/0
R1(config-if)# ip ospf priority 255      ! R1 = DR

R3(config)# interface GigabitEthernet 0/0/0
R3(config-if)# ip ospf priority 0        ! R3 = always DROTHER

! Must reset OSPF process on all routers to trigger new election:
R1# clear ip ospf process
R2# clear ip ospf process
R3# clear ip ospf process

! Verify R1 is now DR:
R1# show ip ospf interface g0/0/0
  Transmit Delay is 1 sec, State DR, Priority 255  ✅
⚠️
Priority changes don't take effect until the OSPF process is cleared or the router reloads. After configuring priority, run clear ip ospf process on all routers — starting with the intended DR first — to trigger a new election.

2.4.1 OSPF Cost Formula

OSPF metric = cost. Lower cost = preferred path. Cost is inversely proportional to bandwidth:

Cost formula — default 100 Mbps reference bandwidth
Cost = reference bandwidth ÷ interface bandwidth
Default reference bandwidth = 100,000,000 bps (100 Mbps)

Cost = 100,000,000 bps ÷ interface bandwidth in bps

Default costs with 100 Mbps reference bandwidth:

Serial (T1)
1.544 Mbps
64
Ethernet
10 Mbps
10
Fast Ethernet
100 Mbps
1 ⚠️
Gigabit Ethernet
1,000 Mbps
1 ⚠️
10 Gigabit Ethernet
10,000 Mbps
1 ⚠️
🚨
FastEthernet, GigabitEthernet, and 10GigE all share cost = 1 with the default 100 Mbps reference bandwidth. OSPF cannot differentiate between them. This is the primary reason to adjust the reference bandwidth in modern networks.

2.4.2 Adjust the Reference Bandwidth

auto-cost reference-bandwidth — must be applied on ALL routers 
! Adjust to 10 Gbps (expressed in Mbps):
R1(config)# router ospf 10
R1(config-router)# auto-cost reference-bandwidth 10000
% OSPF: Reference bandwidth is changed.
        Please ensure reference bandwidth is consistent across all routers.

! Must also apply on R2 and R3 — same command, same value

Costs with 10,000 Mbps (10 Gbps) reference bandwidth:

InterfaceBandwidthCost (10G ref)
10 Gigabit Ethernet10,000 Mbps1
Gigabit Ethernet1,000 Mbps10
Fast Ethernet100 Mbps100
Ethernet10 Mbps1000
⚠️
auto-cost reference-bandwidth must be identical on ALL routers in the OSPF domain. Inconsistent values cause miscalculated path costs and potentially incorrect routing decisions. Always configure it on every router at the same time.

2.4.3 OSPF Accumulates Costs

OSPF cost to a destination = sum of all link costs along the path. With 10,000 Mbps reference bandwidth and GigE links (cost=10) plus loopbacks (cost=1 by default):

show ip route — verify accumulated cost 
! R1 reaching R2's LAN (10.10.2.0/24):
! Path: R1 → R2 (GigE link cost 10) + R2 loopback (cost 1) = 11 total

R1# show ip route | include 10.10.2
O        10.10.2.0/24 [110/11] via 10.1.1.6, Gi0/0/0   ! [AD/cost] = [110/11] ✅

R1# show ip route 10.10.2.0
  Known via "ospf 10", distance 110, metric 11, type intra area

2.4.4 Manual Cost Override — ip ospf cost

Override the automatic cost calculation to influence path selection or designate backup links:

ip ospf cost — manually set cost on an interface 
! Make R1-R2 link preferred (cost 10 default) vs R1-R3 link (forced cost 30 = backup):
R1(config)# interface GigabitEthernet 0/0/1      ! link to R3
R1(config-if)# ip ospf cost 30                   ! higher cost = less preferred

R1(config-if)# interface Loopback 0
R1(config-if)# ip ospf cost 10                   ! match GigE cost for accuracy

! Verify — all traffic via R2 now (preferred):
R1# show ip route ospf | begin 10
O        10.1.1.8/30 [110/20] via 10.1.1.6, Gi0/0/0    ! via R2 ✅
O        10.10.2.0/24 [110/20] via 10.1.1.6, Gi0/0/0   ! via R2 ✅
O        10.10.3.0/24 [110/30] via 10.1.1.6, Gi0/0/0   ! via R2 (not R3 direct)
💡
ip ospf cost overrides everything — both reference bandwidth formula AND the bandwidth interface command. It is the most direct and reliable method for traffic engineering in OSPF.

2.4.7–2.4.9 Modify Hello and Dead Intervals

Default (Ethernet/P2P): Hello = 10 sec, Dead = 40 sec (4× Hello). Must match between neighbors or adjacency is lost.

Verify current timers 
R1# show ip ospf interface g0/0/0
  Timer intervals configured, Hello 10, Dead 40, Wait 40, Retransmit 5

R1# show ip ospf neighbor
Neighbor ID     Pri   State     Dead Time   Address     Interface
2.2.2.2           0   FULL/-    00:00:31    10.1.1.6    Gi0/0/0   ! Dead Time counting down
Modify Hello and Dead intervals per-interface 
! Change Hello to 5s on R1's G0/0/0:
R1(config)# interface GigabitEthernet 0/0/0
R1(config-if)# ip ospf hello-interval 5      ! Hello = 5 seconds
R1(config-if)# ip ospf dead-interval 20      ! Dead = 20 seconds (explicit)
! IOS auto-sets dead to 4x hello, but best practice to set explicitly

! Adjacency DROPS immediately — R2 still has Hello=10, Dead=40
*OSPF-5-ADJCHG: Nbr 2.2.2.2 from FULL to DOWN, Neighbor Down: Dead timer expired

! Must also change R2's G0/0/0 to match, or adjacency stays down:
R2(config)# interface GigabitEthernet 0/0/0
R2(config-if)# ip ospf hello-interval 5
! Adjacency reforms automatically
*OSPF-5-ADJCHG: Nbr 1.1.1.1 from LOADING to FULL, Loading Done

! Reset to defaults:
R1(config-if)# no ip ospf hello-interval
R1(config-if)# no ip ospf dead-interval
🎯 TIMER MISMATCH = ADJACENCY LOSS — NO ERROR MESSAGE
When timers don't match, OSPF simply never forms the adjacency (or drops it if it was formed). IOS does NOT print a clear warning message identifying the timer mismatch as the cause. You must use show ip ospf interface to compare timer values on both sides of a link.

2.5Default Route Propagation▾

2.5.1 Propagate a Default Route — default-information originate

The edge router connecting the OSPF domain to the internet is called the ASBR (Autonomous System Boundary Router). Two steps to propagate a default route to all OSPF neighbors:

🌐 Default Route Propagation — Two Steps
1
Configure the default static route on the ASBR pointing to the ISP or next-hop:
ip route 0.0.0.0 0.0.0.0 [next-hop-ip | exit-intf]
2
Tell OSPF to propagate it using default-information originate in router OSPF config mode. This makes R2 the source of the default route and includes it in OSPF LSAs to all neighbors.
Configure and propagate default route from R2 (ASBR) 
! Step 1 — Create default static route (loopback simulates ISP connection):
R2(config)# interface loopback 1
R2(config-if)# ip address 64.100.0.1 255.255.255.252
R2(config-if)# exit
R2(config)# ip route 0.0.0.0 0.0.0.0 loopback 1

! Step 2 — Propagate via OSPF:
R2(config)# router ospf 10
R2(config-router)# default-information originate

2.5.2 Verify the Propagated Default Route

Verify default route propagation — R1 and R3 routing tables 
! R2 routing table — shows static default:
R2# show ip route | begin Gateway
Gateway of last resort is 0.0.0.0 to network 0.0.0.0
S*    0.0.0.0/0 is directly connected, Loopback1

! R1 routing table — receives OSPF external default:
R1# show ip route | begin Gateway
Gateway of last resort is 10.1.1.6 to network 0.0.0.0
O*E2  0.0.0.0/0 [110/1] via 10.1.1.6, GigabitEthernet0/0/0
!↑ O*E2 = OSPF external type 2 = propagated default route

! R3 routing table — also receives the default:
R3# show ip route | begin Gateway
Gateway of last resort is 10.1.1.9 to network 0.0.0.0

🎯Common Exam Traps — Module 2▾
❌
Trap 1: process-id is locally significant — does NOT need to match between neighbors.
Two routers with router ospf 10 and router ospf 20 CAN form an adjacency. The process-id only identifies the local OSPF process. Best practice to keep consistent — but not a requirement for adjacency.
❌
Trap 2: Use clear ip ospf process — not reload — to apply a new Router ID.
After changing router-id, IOS tells you to reload or use clear ip ospf process. The exam-expected answer is clear ip ospf process. Adjacencies drop momentarily and reform with the new ID.
❌
Trap 3: Wildcard mask = 255.255.255.255 − subnet mask.
/24 → 0.0.0.255. /26 → 0.0.0.63. /30 → 0.0.0.3. Quad-zero (0.0.0.0) = exact match, no calculation. Know both the formula and how to compute common prefix lengths.
❌
Trap 4: passive-interface stops Hellos but the network IS STILL advertised.
Passive means no Hello packets sent or received on that interface — so no OSPF neighbor can form. But the connected network still appears in OSPF updates sent out other interfaces. The network is not hidden from OSPF.
❌
Trap 5: auto-cost reference-bandwidth MUST be the same on ALL routers.
If R1 has reference-bandwidth 10000 and R2 has the default 100, their cost calculations will be inconsistent, causing OSPF to make incorrect path decisions. The IOS warning says it — always apply to every router.
❌
Trap 6: Loopbacks advertise /32 by default — use ip ospf network point-to-point to fix.
Without this command on the loopback, other routers see a /32 host route instead of the full /24 (or whatever mask is configured). Apply ip ospf network point-to-point on loopbacks used to simulate LAN networks.
⚠️
Trap 7: DR/BDR elections are NOT preemptive.
A new router with higher priority or Router ID joining after the election becomes a DROTHER automatically. Only failures trigger role changes (DR fails → BDR promotes → new BDR elected). Must use clear ip ospf process to force a new election.
⚠️
Trap 8: ip ospf priority 0 = never DR or BDR — always DROTHER.
Setting priority to 0 on an interface permanently excludes that router from DR/BDR roles on that segment. Useful for low-resource routers. Priority changes take effect only after clear ip ospf process.
⚠️
Trap 9: Timer mismatch drops adjacency with no clear error message.
When Hello or Dead intervals don't match, OSPF simply fails to maintain the adjacency — no helpful error is printed. Compare timers on both sides using show ip ospf interface. When you change Hello, IOS auto-sets Dead to 4×, but always set Dead explicitly too.
⚠️
Trap 10: default-information originate requires BOTH a static default AND the command.
The ASBR must have: (1) ip route 0.0.0.0 0.0.0.0 pointing to the ISP, AND (2) default-information originate in OSPF config. Either one alone is not sufficient. Other routers install it as O*E2.
⚠️
Trap 11: FULL/- in show ip ospf neighbor = point-to-point link, normal behavior.
The dash after FULL means no DR/BDR election occurred on that link — expected for point-to-point network types. Do NOT confuse this with an adjacency problem. On multiaccess, you'd see FULL/DR or FULL/BDR instead.
⚠️
Trap 12: By default, Cisco Ethernet interfaces run DR/BDR election — even on 2-router links.
Even if only two OSPF routers share an Ethernet link, IOS elects a DR and BDR by default (BROADCAST network type). Use ip ospf network point-to-point on both interfaces to disable the unnecessary election.
⚠️
Trap 13: O*E2 = OSPF propagated default route — cost is flat.
External type 2 routes have a flat cost (doesn't accumulate with distance from the ASBR). All routers in the domain see cost=1 for the default route, regardless of how many hops they are from the ASBR.
✅
Module 2 quick-reference summary — all key commands:

Enable OSPF: router ospf [pid] (pid = locally significant)
Set RID: router-id x.x.x.x → apply with clear ip ospf process
Advertise (method 1): network [addr] [wildcard] area 0
Advertise (method 2): ip ospf [pid] area 0 (on interface)
Passive: passive-interface [intf] or passive-interface default
P2P network type: ip ospf network point-to-point (disables DR/BDR)
Fix loopback /32: ip ospf network point-to-point on loopback
Reference BW: auto-cost reference-bandwidth [Mbps] (all routers!)
Manual cost: ip ospf cost [value]
Timers: ip ospf hello-interval [sec] / ip ospf dead-interval [sec]
DR priority: ip ospf priority [0–255] (0=never DR, 255=always)
Propagate default: default-information originate + static default route
Verify neighbors: show ip ospf neighbor
Verify settings: show ip protocols / show ip ospf
Verify interfaces: show ip ospf interface [intf] / show ip ospf interface brief
