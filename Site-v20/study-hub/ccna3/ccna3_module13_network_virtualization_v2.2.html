13.1Cloud Computing▾

13.1.2 Cloud Overview

Cloud computing = large numbers of computers connected through a network, physically located anywhere. Organizations use cloud computing's "pay-as-you-go" model — treating compute and storage as a utility rather than a capital investment. This transforms CapEx (capital expenditures) into OpEx (operating expenditures).

  • Enables access to organizational data anywhere and at any time
  • Streamlines IT operations — subscribe only to needed services
  • Eliminates or reduces onsite IT equipment, maintenance, and management
  • Reduces costs for equipment, energy, physical plant, and personnel training
  • Enables rapid response to increasing data volume requirements

13.1.3 Three Cloud Service Models (NIST SP 800-145)

SaaS — Software as a Service
User provides: data only

Cloud provider manages everything: applications, runtime, middleware, OS, virtualization, hardware. User accesses applications and services delivered over the internet. No management of any aspect of cloud services except limited user-specific settings.
Examples: Email, Office 365, communication apps, payroll systems
PaaS — Platform as a Service
Users: typically programmers

Cloud provider manages platform and infrastructure. Users get access to development tools and services to build and deploy applications. Users may control configuration settings of the cloud hosting environment.
Examples: AWS Elastic Beanstalk, Google App Engine
IaaS — Infrastructure as a Service
Users: IT managers

Cloud provider manages physical hardware and networking. Users get access to network equipment, virtualized network services, and supporting network infrastructure. IT managers can deploy and run OS and applications.
Examples: AWS EC2, Azure VMs, Google Compute Engine
💡
ITaaS (IT as a Service): Extension where cloud providers also provide IT support for the cloud services. Extends network capability without new infrastructure investment, new personnel training, or new software licensing. Services available on demand, delivered economically to any device anywhere.

13.1.4 Four Cloud Models

🌐 Public Cloud
Available to the general population. Free or pay-per-use. Uses the internet for access.
🔒 Private Cloud
Intended for a specific organization (e.g., government). Can use org's private network or externally managed with strict access security. Expensive to build and maintain.
🔀 Hybrid Cloud
Two or more clouds (private + public) connected via a single architecture. Each part remains a separate object. Users have degrees of access based on rights.
🏥 Community Cloud
Exclusive use by a specific community with shared functional needs. Example: healthcare organizations requiring HIPAA compliance — special authentication and confidentiality.

13.1.5 Cloud Computing vs Data Center

TermDefinition
Data CenterPhysical storage and processing facility run by in-house IT or leased offsite. Can occupy a room, floor, or entire building. Very expensive to build and maintain.
Cloud ComputingOff-premise service providing on-demand access to a shared pool of configurable computing resources. Rapidly provisioned and released with minimal management effort.
💡
Data centers are the physical infrastructure that provides compute, network, and storage needs for cloud services. Large organizations build private data centers; smaller organizations lease server and storage services from larger data center organizations in the cloud.
13.2Virtualization▾

13.2.1 Cloud Computing vs Virtualization — Key Distinction

🚨
"Cloud computing" and "virtualization" are NOT the same thing and are NOT interchangeable.
Virtualization = the foundation and underlying technology. Separates the OS from the hardware.
Cloud computing = the delivery model and services built on top of virtualization.
Without virtualization, cloud computing as widely implemented would not be possible.

13.2.2 Dedicated Servers — Two Problems

Traditional: one server OS on specific hardware, all RAM/CPU/disk dedicated to one service.

ProblemDescription
Single Point of FailureWhen a hardware component fails, the entire service it provides becomes unavailable. No redundancy means total outage.
Server SprawlDedicated servers sit idle most of the time, waiting for demand. Wastes energy, rack space, and cooling — even when providing minimal service.

13.2.3 Server Virtualization and Hypervisors

Virtualization consolidates many dedicated servers onto fewer physical servers using a hypervisor.

Example: 100 physical servers consolidated to 10 physical servers using hypervisors (10 VMs per physical server).

💡
Hypervisor = program, firmware, or hardware that creates an abstraction layer on top of physical hardware. The abstraction layer allows VMs to access CPUs, memory, disk controllers, and NICs. Each VM runs a complete and separate OS.

Redundancy options in virtualization:

  • If a hypervisor fails → VM can be restarted on another hypervisor
  • Same VM can run on two hypervisors simultaneously — copying RAM and CPU state between them. If one fails → VM continues running on the other without interruption
  • Services running on VMs are virtual and can be dynamically installed or uninstalled as needed

13.2.4 Advantages of Virtualization

Primary Advantage: Cost Reduction

💰
Less equipment required — server consolidation means fewer physical servers, fewer networking devices, less supporting infrastructure, lower maintenance costs
⚡
Less energy consumed — consolidating servers lowers monthly power and cooling costs; smaller carbon footprint
📐
Less space required — fewer servers, network devices, and racks reduces data center floor space requirements

Additional Benefits

🧪
Easier prototyping — self-contained labs on isolated networks for testing; can revert to previous snapshot if mistake made; testing can run online but isolated from end users
🚀
Faster server provisioning — creating a VM is far faster than provisioning physical hardware (minutes vs days)
⏰
Increased server uptime — live migration, storage migration, high availability, and distributed resource scheduling
🔄
Improved disaster recovery — hardware abstraction means recovery site doesn't need identical hardware; failover automation and testing before a disaster occurs
📦
Legacy support — extends life of older OSs and applications, giving organizations more time to plan migration to newer solutions

13.2.5 Abstraction Layers

A computer system has four abstraction layers (bottom to top): Hardware → Firmware → OS → Services

A hypervisor is inserted between the Firmware and OS layers. It intercepts OS calls to hardware and manages resource access, allowing multiple OS instances to share one physical machine.

13.2.6 Type 2 Hypervisors — Hosted

Type 2 — Hosted Hypervisor
  • Installed on top of existing host OS (macOS, Windows, Linux)
  • Guest OS instances run on top of the hypervisor
  • No management console required — managed through host OS
  • Popular with consumers and for testing/experimentation
  • Host machine must be powerful enough for host OS + all VMs
Examples: VMware Workstation, Oracle VM VirtualBox, VMware Fusion, Parallels (macOS), Virtual PC
Type 1 — Bare Metal Hypervisor
  • Installed directly on hardware (no host OS)
  • OS instances run on top of the hypervisor
  • Requires management console to configure and manage
  • Direct hardware access → more efficient
  • Better scalability, performance, and robustness
Used in: Enterprise servers, data center networking devices
Example: Cisco UCS Manager (management console)
13.3Virtual Network Infrastructure▾

13.3.1 Type 1 Hypervisors — Bare Metal

Type 1 = "bare metal" because the hypervisor is installed directly on the server hardware with no host OS underneath.

  • Direct hardware access → more efficient than hosted (Type 2)
  • Improves scalability, performance, and robustness
  • Requires a management console — cannot configure from the basic boot screen
  • Management software manages multiple servers using the same hypervisor
  • Can automatically consolidate servers and power them on/off as required
  • Provides recovery from hardware failure — automatically migrates VM to another server
💡
Over-allocation: A management console can allow more VM RAM to be allocated than the server physically has. Example: Server with 16GB RAM → 4 VMs × 10GB allocated = 40GB total allocated. Works because all VMs rarely need their full allocation simultaneously. This is a common and accepted practice.

13.3.3 East-West vs North-South Traffic · VRF

Server virtualization creates network challenges because traffic flows differ substantially from the traditional client-server model:

Traffic TypeDirectionDescription
East-WestWithin the data centerTraffic exchanged between virtual servers inside the data center. Can change in location and intensity over time. Requires flexible, dynamic network resource management.
North-SouthBetween distribution/core and offsiteTraffic between the data center and external destinations — other data centers, cloud providers, or the internet. More predictable flow.

Network function virtualization — VRF:

  • VRF (Virtual Routing and Forwarding) = virtualized routing. Allows multiple independent routing table instances to coexist on a single router.
  • Other network functions that can be virtualized: subinterfaces, virtual interfaces, VLANs, routing tables
  • The key to understanding how the network is virtualized: networking devices operate using a control plane and a data plane
13.4Software-Defined Networking (SDN)▾

13.4.2 Three Network Planes

🧠 Control Plane — "The Brains"
Makes forwarding decisions. Contains Layer 2 and Layer 3 route forwarding mechanisms: routing protocol neighbor tables, topology tables, IPv4/IPv6 routing tables, STP, ARP table. Information processed by the CPU.
⚡ Data Plane — Forwarding Plane
Also called the forwarding plane. Typically the switch fabric connecting network ports. Used to forward actual traffic flows. Uses information from the control plane to forward incoming traffic out the correct egress interface. Processed by a special data plane processor — NOT the CPU.
🔧 Management Plane
Manages device configuration via network connection. Network administrators access it using SSH, TFTP, SFTP, HTTPS. Also used by SNMP. This is how you've configured devices throughout your networking studies.

13.4.2 Cisco Express Forwarding (CEF)

CEF = advanced Layer 3 IP switching technology that enables packet forwarding at the data plane without consulting the control plane CPU:

  • Control plane's routing table pre-populates the FIB (Forwarding Information Base) in the data plane
  • Control plane's ARP table pre-populates the adjacency table in the data plane
  • Packets forwarded directly by the data plane using FIB + adjacency table — no CPU involvement
  • Result: high-speed hardware-accelerated packet forwarding

13.4.3 Two Major Network Virtualization Architectures

ArchitectureTypeDescription
SDN (Software-Defined Networking)Software/logicalVirtualizes the network; simplifies and streamlines administration and management; separates control and data planes
Cisco ACI (Application Centric Infrastructure)Purpose-built hardwareIntegrates cloud computing and data center management; policy element removed from the data plane

SDN Components

  • OpenFlow — developed at Stanford University; manages traffic between routers, switches, APs, and a controller; foundational element of SDN; original and most widely implemented southbound API
  • OpenStack — virtualization and orchestration platform for scalable cloud environments; IaaS solution; often used with Cisco ACI
  • Other: I2RS, TRILL, Cisco FabricPath (FP), IEEE 802.1aq Shortest Path Bridging (SPB)

13.4.4 Traditional vs SDN Architecture · APIs

AspectTraditionalSDN
Control planeOn each individual deviceCentralized in the SDN controller
Data planeOn each individual deviceRemains on individual devices
Routing decisionsMade by device OSMade by SDN controller; pushed to devices
ConfigurationDevice-by-deviceCentralized through controller and APIs

The SDN controller = logical entity that enables network administrators to manage and dictate how the data plane of switches and routers handles traffic. It orchestrates, mediates, and facilitates communication between applications and network elements.

🔌 SDN API Architecture — Northbound and Southbound
Applications
(Traffic shaping, service deployment, business logic)
Northbound APIs ↕
Between SDN controller and upstream applications. Help network admins shape traffic and deploy services.
SDN Controller
Central control plane — manages all network devices; computes paths; enforces policies
Southbound APIs ↕
Between SDN controller and downstream switches/routers. OpenFlow = original, widely implemented southbound API.
Switches / Routers
(Data plane only — forward traffic based on controller instructions)
13.5Controllers▾

13.5.1 SDN Controller and OpenFlow Operations

  • Every flow must first get permission from the SDN controller — verifies communication is permissible per network policy
  • If allowed → controller computes a route and adds a flow entry to each switch along the path
  • Controller populates flow tables; switches manage the flow tables
  • OpenFlow protocol + TLS (Transport Layer Security) secures control plane communications between controller and switches

Three Table Types in OpenFlow Switches

Flow Table
Matches incoming packets to a particular flow; specifies functions to perform on those packets. Multiple flow tables can operate in a pipeline fashion.
Group Table
A flow table may direct a flow here. Can trigger a variety of actions affecting one or more flows simultaneously.
Meter Table
Triggers performance-related actions on a flow — including the ability to rate-limit traffic.

13.5.3 Cisco ACI — Three Core Components

Cisco ACI = purpose-built hardware solution for integrating cloud computing and data center management. Policy element removed from the data plane → simplifies data center network creation.

ANP — Application Network Profile
A collection of end-point groups (EPGs), their connections, and the policies that define those connections. EPGs can represent VLANs, web services, applications, and other network segments.
APIC — Application Policy Infrastructure Controller ⭐ (The Brains)
Centralized software controller managing and operating a scalable ACI clustered fabric. Designed for programmability and centralized management. Translates application policies into network programming.
Key distinction: APIC does NOT manipulate the data path directly. Instead, it centralizes policy definition and programs leaf switches to forward traffic based on defined policies.
Cisco Nexus 9000 Series Switches
Application-aware switching fabric. Work with APIC to manage both virtual and physical network infrastructure.

13.5.4 Spine-Leaf Topology

Cisco ACI uses a two-tier spine-leaf topology composed of APIC and Cisco Nexus 9000 switches:

DeviceConnection Rules
Leaf switchesAlways attach to spine switches. NEVER attach to each other.
Spine switchesOnly attach to leaf and core switches. NEVER attach to each other.
💡
Result: Everything is one hop from everything else in the two-tier topology. All end devices, servers, and APICs physically connect to leaf switches.

13.5.5 Three SDN Types

1. Device-Based SDN
Devices are programmable by applications running on the device itself or a server in the network. Requires programming skills (C, Java, Python). Least abstraction.
Example: Cisco OnePK — enables programmers using C, Java, or Python to integrate with and interact with Cisco devices
2. Controller-Based SDN
Centralized controller has knowledge of all devices in the network. Applications interface with the controller to manage devices and manipulate traffic flows throughout the network. Requires programming to use controller APIs.
Example: Cisco Open SDN Controller (commercial distribution of OpenDaylight)
3. Policy-Based SDN ⭐ Most Robust
Similar to controller-based but adds a Policy Layer at higher level of abstraction. Built-in applications automate advanced configuration tasks via guided workflow and user-friendly GUI. No programming skills required.
Example: Cisco APIC-EM (Application Policy Infrastructure Controller – Enterprise Module)
🎯 SDN TYPE HIERARCHY — EXAM KEY
Device-based → Controller-based → Policy-based
Each level adds more abstraction and easier management.
Policy-based = most robust — simple mechanism to control and manage policies across the entire network with no programming required.
Cisco APIC-EM = Cisco's policy-based SDN for enterprise and campus deployments.

13.5.6–13.5.7 APIC-EM Features and Path Trace

Cisco APIC-EM provides a single interface for network management:

  • Discover and access device and host inventories
  • View network topology
  • Trace a path between endpoints
  • Set policies across the network

APIC-EM Path Trace tool:

  • Visualizes traffic flows between two end nodes
  • Discovers conflicting, duplicate, or shadowed ACL entries along the entire path
  • Displays which ACLs permitted or denied traffic at each hop
  • Allows administrators to make targeted ACL adjustments across complex paths
  • Extremely useful for ACL troubleshooting in large enterprise networks
🎯Common Exam Traps — Module 13▾
❌
Trap 1: Cloud computing ≠ virtualization. Virtualization is the FOUNDATION of cloud computing.
They are NOT interchangeable terms. Virtualization separates the OS from the hardware. Cloud computing is the service delivery model and business model built on top of virtualization. Without virtualization, cloud computing as widely implemented would not be possible.
❌
Trap 2: Know what each user provides in SaaS vs PaaS vs IaaS.
SaaS = user provides data only (Office 365, email, payroll). PaaS = user gets development tools (programmers). IaaS = user gets network equipment and infrastructure (IT managers). Each tier gives the customer more control but also more responsibility. A payroll system = SaaS, not IaaS.
❌
Trap 3: Four cloud models — know what each one is for.
Public = anyone/general population. Private = one specific organization (government, enterprise). Hybrid = two or more clouds connected as one architecture. Community = specific community with shared compliance needs (HIPAA healthcare). Community cloud is NOT the same as public — it has customized functional requirements.
❌
Trap 4: Type 1 = bare metal (direct on hardware, management console required). Type 2 = hosted (on top of OS, no management console needed).
Type 1 is used in enterprise/data centers — more efficient because it has direct hardware access. Type 2 is for consumer/experimental use — easier to manage but less efficient. Examples: VirtualBox, VMware Workstation, Parallels = all Type 2.
❌
Trap 5: Single point of failure = dedicated server hardware failure. Server sprawl = idle servers wasting resources.
Both are problems solved by server virtualization. Virtualization provides redundancy (if one hypervisor fails, VM restarts on another) and consolidation (multiple servers on fewer physical hosts).
❌
Trap 6: Control plane = brains (CPU-processed). Data plane = forwarding (special processor, not CPU).
SDN separates these: the control plane is centralized in the SDN controller; the data plane stays on individual switches and routers. CEF pre-populates FIB from routing table and adjacency table from ARP table — enabling hardware-speed forwarding without CPU involvement.
⚠️
Trap 7: Northbound APIs = controller to applications. Southbound APIs = controller to switches/routers.
Northbound: SDN controller communicates upward to applications for traffic shaping and service deployment. Southbound: SDN controller communicates downward to define data plane behavior on switches/routers. OpenFlow = original and most widely used southbound API, developed at Stanford University.
⚠️
Trap 8: APIC ≠ SDN controller. APIC does NOT directly manipulate the data path.
An SDN controller directly manipulates flow tables on switches. Cisco APIC (ACI) instead centralizes policy definition and programs leaf switches based on those policies — but does not directly alter forwarding paths. APIC translates application policies into network programming.
⚠️
Trap 9: Spine-Leaf topology rules — leaves NEVER connect to each other; spines NEVER connect to each other.
In ACI spine-leaf: leaf switches connect only to spines. Spine switches connect only to leaves (and cores). Everything is one hop from everything else. All end devices and APICs physically connect to leaf switches. This ensures consistent low latency across the fabric.
⚠️
Trap 10: Three SDN types — Device-based (OnePK), Controller-based (OpenDaylight), Policy-based (APIC-EM).
Policy-based is the most robust and requires no programming skills — uses GUI-driven workflows. APIC-EM is Cisco's policy-based SDN for enterprise/campus. Device-based requires programmers to write code that runs on the device itself. This order represents increasing levels of abstraction.
⚠️
Trap 11: APIC-EM Path Trace finds conflicting, duplicate, or shadowed ACL entries — not just path.
The Path Trace tool does more than show the path — it examines every ACL along the path between two endpoints, showing which ones permitted or denied traffic at each hop. Essential for diagnosing complex ACL issues across enterprise networks.
⚠️
Trap 12: East-West traffic = within data center between virtual servers. North-South = to offsite destinations.
East-West traffic is dynamic and variable — VM workloads move, so traffic patterns change. Traditional static network configurations can't handle this well. This is why flexible, dynamic network management (SDN, ACI) is needed in modern data centers.
⚠️
Trap 13: VRF = Virtual Routing and Forwarding = virtualized routing.
VRF allows multiple independent routing table instances on a single router. This is network function virtualization applied to routing. A router running VRF appears as multiple routers to different traffic groups, providing isolation between them.
⚠️
Trap 14: OpenFlow uses TLS to secure communications between SDN controller and switches.
OpenFlow is the southbound API protocol. TLS (Transport Layer Security) encrypts the control plane communications traveling over the network between the SDN controller and OpenFlow-compatible switches. Flows need controller permission before traversing the network.
✅
