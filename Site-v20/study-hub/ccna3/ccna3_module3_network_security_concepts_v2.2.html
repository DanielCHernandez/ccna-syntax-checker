3.1Current State of Cybersecurity▾

3.1.1 Core Security Terms

TermDefinition
AssetAnything of value — people, equipment, resources, and data
VulnerabilityA weakness in a system or its design that could be exploited by a threat
ThreatA potential danger to an organization's assets, data, or network functionality
ExploitA mechanism that takes advantage of a vulnerability
MitigationCounter-measure that reduces likelihood or severity of a potential threat or risk
RiskLikelihood of a threat exploiting a vulnerability × impact. Risk = probability × consequence.
💡
The security chain: Assets must be identified → Vulnerabilities addressed before they are exploited → Mitigation applied before, during, and after an attack.

3.1.2 Attack Vectors — External and Internal

An attack vector is the path by which a threat actor gains access to a server, host, or network. Vectors originate from inside or outside the corporate network.

🚨
Internal threats are often more dangerous than external threats because insiders have: direct physical access to the building and infrastructure, and detailed knowledge of the corporate network, resources, and confidential data. An internal user can cause damage accidentally or intentionally.

Internal users can accidentally or intentionally:

  • Steal and copy confidential data to removable media, email, or messaging software
  • Compromise internal servers or network infrastructure devices
  • Disconnect critical network connections causing outages
  • Connect an infected USB drive into a corporate computer system

3.1.3 Data Loss Vectors

Data exfiltration = data intentionally or unintentionally lost, stolen, or leaked outside the organization. Consequences include brand damage, loss of competitive advantage, revenue loss, and litigation.

Data Loss VectorDescription
Email / Social NetworkingIntercepted email or IM messages can reveal confidential information
Unencrypted DevicesIf no encryption is used, a stolen device gives the thief full access to data
Cloud StorageWeak cloud security settings allow unauthorized access to sensitive data
Removable MediaUnauthorized USB transfers; USB drives with corporate data physically lost
Hard CopyConfidential documents not properly shredded can be recovered
Improper Access ControlWeak or compromised passwords give threat actors easy access to corporate systems
3.2–3.3Threat Actors and Tools▾

3.2.1 White, Gray, and Black Hat Hackers

🤍
White Hat

Ethical hackers. Test networks legally to find vulnerabilities. Report findings to developers to fix before exploitation.

🩶
Gray Hat

Commit crimes but not for personal gain or malicious damage. May disclose vulnerabilities to the organization after compromising it.

🖤
Black Hat

Criminals who compromise systems for personal gain or malicious reasons — attacking networks, stealing data, causing damage.

💡
"Threat actor" is the preferred modern term — not "hacker." A threat actor includes hackers but also any device, person, group, or nation-state that is intentionally or unintentionally the source of an attack.

3.2.2 Modern Threat Actor Categories

Cyber CriminalsBlack hats — self-employed or in criminal organizations; operate underground economy (buy/sell attack toolkits, zero-day exploits, botnets, keyloggers)
State-SponsoredGovernment-backed; steal secrets, gather intelligence, sabotage networks; use zero-day vulnerabilities (previously undiscovered flaws). Example: Stuxnet (Iran nuclear facilities)

3.4Malware▾

3.4.2 The Big Three — Virus, Worm, Trojan Horse

🦠
Virus
Requires human action to spread

Attaches to code, software, or documents. Executes when opened by user (email attachment, USB, download). Can corrupt files, capture data, spread via email, lay dormant. Types: boot sector, firmware, macro, program, script.

🪱
Worm
Self-replicating — NO user action needed

Automatically exploits vulnerabilities in legitimate software. Uses the network to find other vulnerable hosts. Intent is usually to slow or disrupt network operations. Does NOT need a host file — it is a standalone program.

🐴
Trojan Horse
Disguised as useful software — NOT self-replicating

Looks like a legitimate program (e.g., free game). User installs it willingly. Hidden malicious payload activates after installation. Types include: remote-access, data-sending, keylogger, destructive, DoS Trojans.

🎯 THE KEY DISTINCTIONS — EXAM CRITICAL
  • Virus — requires human action · attaches to existing files · self-replicates only when triggered by user
  • Worm — NO human action needed · standalone · self-replicates automatically across network
  • Trojan — NOT self-replicating · disguised as legitimate software · user must install it

3.4.3 Other Malware Types

💰
Ransomware
Encrypts files — demands payment

Denies user access to their own files by encrypting them. Demands ransom (typically cryptocurrency like Bitcoin) for the decryption key. Victims without backups must pay or lose data permanently.

🔑
Rootkit
Admin-level access — hardest to detect

Gains administrator-level access. Extremely difficult to detect — modifies OS commands, firewall, and antivirus to conceal itself. Special removal tools required; complete OS reinstall may be necessary.

👁️
Spyware
Gathers info without consent

Collects user data and sends to threat actors without user knowledge. Low threat: browsing data. High threat: personal and financial information, passwords.

📢
Adware
Unsolicited advertising

Displays pop-up ads, new toolbars, or redirects web pages. Usually distributed with downloaded free software. Pop-up windows may be impossible to control.

3.5Common Network Attacks▾

3.5.1 Three Attack Categories

🔍 Reconnaissance Attacks
  • Information gathering — always the first phase before access or DoS attacks
  • Unauthorized discovery and mapping of systems, services, and vulnerabilities
🔓 Access Attacks
  • Exploit vulnerabilities in authentication, FTP, and web services
  • Goal: gain unauthorized access, retrieve data, or escalate privileges
  • Includes: password attacks, spoofing, trust exploitation, MITM, buffer overflow
💥 DoS / DDoS Attacks
  • Create interruption of network services to legitimate users
  • Methods: overwhelming traffic flood OR maliciously formatted packets
  • DDoS = distributed, coordinated from multiple sources via botnet

3.5.3 Reconnaissance Attacks — Five Steps

🕵️ Reconnaissance Attack Progression
1
Information Query — gather initial info about the target using Google, whois, target website, job postings. Reveals network structure, personnel, technologies. Tools: whois, Google, LinkedIn
2
Ping Sweep — discover which IP addresses in the target network are active/reachable. Tools: fping, Nmap ping scan
3
Port Scan — probe active hosts to discover which TCP/UDP ports are open and which services are running. Tools: Nmap, SuperScan, Angry IP Scanner
4
Vulnerability Scan — query identified ports to determine app versions and OS. Find known vulnerabilities in discovered services. Tools: Nessus, OpenVAS, Core Impact
5
Exploitation — attempt to exploit vulnerable services discovered in step 4. Tools: Metasploit, Social Engineer Toolkit

3.5.5 Access Attacks

Attack TypeHow It Works
Password AttacksBrute force or dictionary attacks to discover passwords. Once gained, attacker has full rights of that account.
SpoofingIP, MAC, or DHCP spoofing — device poses as another to gain access or intercept traffic
Trust ExploitationUse unauthorized privileges to access a system by exploiting existing trust relationships between hosts
Port RedirectionUse a compromised host as a relay/pivot to attack other targets that trust the compromised host
Man-in-the-MiddlePosition between source and destination; read or modify data passing between two legitimate parties
Buffer OverflowOverwhelm buffer memory with unexpected values → system crashes or becomes inoperable → DoS effect

3.5.6 Social Engineering Attacks

Social engineering targets people, not technology. Attackers exploit human willingness to help, trust, and authority.

Pretexting
Pretend to need personal/financial data to confirm recipient's identity — fabricated scenario
Phishing
Fraudulent email disguised as legitimate trusted source → install malware or share credentials
Spear Phishing
Targeted phishing tailored for a specific individual or organization — more convincing than generic phishing
Spam
Unsolicited email (junk mail) containing harmful links, malware, or deceptive content
Baiting
Malware-infected USB left in a public location; victim inserts it and unknowingly installs malware
Impersonation
Pretend to be someone else (IT support, manager) to gain victim's trust and extract information
Tailgating
Quickly follow an authorized person through a secure door to gain physical access to a restricted area
Shoulder Surfing
Inconspicuously look over someone's shoulder to steal passwords or PINs being typed
Quid Pro Quo
Request personal info in exchange for a gift, service, or "prize" — "something for something"
Dumpster Diving
Rummage through trash bins for discarded confidential documents, printouts, or storage media

3.5.9 DoS and DDoS Attacks

DoS creates interruption of services. Two methods:

  • Overwhelming traffic — flood network/host with more data than it can handle → slowdown or shutdown
  • Maliciously formatted packets — send packets the receiver cannot process → crash
🤖 DDoS Botnet Architecture
Bot malware
Infects a host and makes it a zombie — communicates with the CnC system
Zombie
A compromised host infected with bot malware; controlled remotely by the threat actor
Botnet
A collection of zombies — the threat actor's army of compromised machines
CnC System
Command and Control — the threat actor's infrastructure for controlling zombies and launching attacks
DDoS attack
CnC instructs botnet to simultaneously flood the target — distributed, coordinated, hard to block
3.6–3.7IP, TCP, and UDP Vulnerabilities▾

3.6.2 IP Attack Overview

IP does not validate that the source IP address in a packet actually came from that source — threat actors can easily forge it.

IP Attack TechniqueDescription
ICMP AttacksUse ICMP echo (ping) to map networks, discover hosts, DoS flood, or alter routing tables
Amplification & ReflectionSpoof victim's IP in requests sent to many hosts → all hosts reply to victim → amplified flood (e.g., Smurf attack)
Address SpoofingForge source IP to hide identity, pose as legitimate user, or bypass access controls
MITMPosition between source and destination; eavesdrop, capture, or alter packets transparently
Session HijackingUse MITM position to take over an already-authenticated session

3.6.3 ICMP Attacks

ICMP is used for network diagnostics — threat actors abuse it for:

  • Reconnaissance — map topology, identify active hosts (ping sweep), OS fingerprinting, probe firewall state
  • DoS flood attacks — overwhelm target with ICMP echo requests
ICMP MessageHow Attackers Use It
Echo Request / ReplyHost verification and DoS flood attacks
UnreachableNetwork reconnaissance and scanning — maps network structure
Mask ReplyMaps internal IP network addressing
RedirectLure target to send all traffic through compromised device → MITM
Router DiscoveryInject bogus routes into target host's routing table

3.6.5 Amplification and Reflection — Smurf Attack

  1. Amplification — threat actor sends ICMP echo requests to many hosts with the victim's spoofed IP as the source address
  2. Reflection — all those hosts reply to the victim's IP — victim is overwhelmed with traffic it never requested
⚠️
Modern variants include DNS-based amplification and NTP amplification attacks, which achieve even higher amplification factors because DNS/NTP responses are much larger than the queries that triggered them.

3.6.6 Address Spoofing Attacks

Spoofing TypeDescription
Non-blind IP spoofingAttacker can see the reply traffic — used to inspect replies, predict sequence numbers, hijack authorized sessions
Blind IP spoofingAttacker cannot see replies — used in DoS attacks where replies don't matter
MAC spoofingAttacker changes their MAC to match a known target's MAC → switch updates CAM table → frames destined for target delivered to attacker → MITM
DHCP spoofingRogue DHCP server on the network provides false IP configuration — wrong gateway (MITM), wrong DNS (redirect), wrong IP (DoS)

3.7.3 TCP Attacks

TCP SYN Flood Attack

💥 TCP SYN Flood — Half-Open Connection Exhaustion
1
Threat actor sends many TCP SYN packets with randomly spoofed source IPs to the target server
2
Server replies with SYN-ACK for each SYN and waits for the final ACK to complete the three-way handshake
3
The final ACKs never arrive — server accumulates thousands of half-open TCP connections
4
Server's connection table fills up → legitimate users cannot connect → effective DoS

TCP Reset Attack

Threat actor sends a spoofed packet with the RST (Reset) bit set to one or both endpoints. TCP immediately terminates the connection — abrupt teardown with no graceful FIN-ACK sequence. Used to forcibly disconnect legitimate sessions.

TCP Session Hijacking

Threat actor spoofs the IP of an authenticated host, predicts the next sequence number, and sends an ACK to the other host — taking over the authenticated session. If successful, the attacker can send (but not receive) data as the hijacked host.

3.7.5 UDP Flood Attack

UDP has no encryption, no connection, no acknowledgments. In a UDP flood:

  1. Tool (UDP Unicorn, Low Orbit Ion Cannon) sends a flood of UDP packets from a spoofed host to the target
  2. The attack sweeps through all known ports looking for closed ports
  3. Server replies with ICMP "port unreachable" messages for every closed port hit
  4. Massive ICMP response traffic consumes all available bandwidth → DoS-like effect
3.8IP Services: ARP, DNS, and DHCP▾

3.8.2 ARP Cache Poisoning

ARP has no authentication. Any host can send an unsolicited (gratuitous) ARP reply claiming ownership of any IP or MAC address. Threat actors exploit this to create MITM attacks.

☠️ ARP Cache Poisoning — MITM Setup
Attacker
Sends two spoofed gratuitous ARP replies — one to the victim claiming "I am the gateway," one to the router claiming "I am the victim"
Victim
Updates ARP cache: default gateway IP now maps to attacker's MAC. All traffic intended for the gateway goes to attacker instead.
Router
Updates ARP cache: victim's IP now maps to attacker's MAC. All traffic intended for the victim goes to attacker instead.
Result
Attacker is positioned between victim and router — full MITM. Can eavesdrop (passive) or modify data (active).
💡
ARP poisoning tools: dsniff, Cain & Abel, ettercap, Yersinia. Defense: Dynamic ARP Inspection (DAI) on switches (covered in CCNA 2 M11).

3.8.4 DNS Attacks

DNS Attack TypeDescription
DNS Cache PoisoningInject falsified resource records into a DNS resolver → redirect users from legitimate sites to malicious ones
DNS Amplification/ReflectionUse DNS open resolvers to amplify DoS — send DNS queries with victim's spoofed IP → large DNS replies flood the victim
DNS Resource ExhaustionDoS attack consuming all DNS resolver resources → resolver unavailable
Fast FluxRapidly change DNS IP addresses (within minutes) to hide malware/phishing sites; botnets use this
Double IP FluxRapidly change both hostname-to-IP AND authoritative name server → harder to trace source
Domain Generation AlgorithmsMalware randomly generates domain names used as C&C rendezvous points — hard to blacklist
Domain ShadowingSteal domain credentials → silently create sub-domains pointing to malicious servers without alerting the domain owner

3.8.5 DNS Tunneling

Encodes non-DNS traffic inside DNS queries to bypass security controls and firewalls:

  1. Data (e.g., C&C commands or exfiltrated files) is split into encoded chunks
  2. Each chunk is placed inside a DNS query's domain name label
  3. DNS query forwarded through recursive DNS servers — appears as legitimate DNS traffic
  4. Reaches the threat actor's authoritative name server
  5. Responses from the threat actor's server carry encoded commands back to the compromised host
  6. Malware reassembles the chunks and executes the hidden commands
⚠️
Defense: Filter inspecting DNS traffic for unusually long queries or suspicious domain names. Cisco OpenDNS blocks DNS tunneling traffic by identifying suspicious patterns.

3.8.7 DHCP Spoofing Attack

A rogue DHCP server on the network responds to client DHCP Discover messages faster than the legitimate server. The client accepts the first offer — if it's the rogue, it gets false configuration:

  • Wrong default gateway → traffic routed through attacker → MITM
  • Wrong DNS server → users directed to malicious websites
  • Wrong IP address → client has invalid network config → DoS
💡
Defense: DHCP Snooping on switches — only trusted ports can send DHCP Offer/ACK messages (covered in CCNA 2 M11).

3.10Cryptography▾

3.10.2 Four Elements of Secure Communications

✅
Data Integrity
Message was not altered in transit. Implemented with hashing (MD5, SHA). Detects any change to the data.
🪪
Origin Authentication
Message actually came from the stated sender. Implemented with HMAC (hash + secret key). Defeats MITM.
🔐
Data Confidentiality
Only authorized users can read the message. Implemented with symmetric (AES) or asymmetric (RSA) encryption.
✍️
Non-Repudiation
Sender cannot deny sending the message. Implemented with digital signatures (unique private key proof).

3.10.3–3.10.4 Hash Functions — Data Integrity

A hash function takes input data and produces a fixed-length digest (fingerprint). Any change to the data produces a completely different hash — detects tampering.

MD5
128-bit
Legacy
Use only when no better alternative is available
SHA-1
160-bit
Deprecated
Has known flaws — avoid; use SHA-2 instead
SHA-2
256/384/512
✅ Recommended
SHA-256, SHA-384, SHA-512 — use whenever possible
🚨
Hashing alone is NOT secure against MITM. Anyone with the hash function can intercept a message, modify it, recompute the hash, and append the new hash. The receiver sees a valid hash and can't tell the data was altered. To also authenticate the origin, use HMAC.

3.10.5 HMAC — Origin Authentication

HMAC (Hash-based Message Authentication Code) adds a secret key to the hashing process — providing both integrity AND origin authentication:

  • Both sender and receiver share the same secret key
  • Hash is computed on: data + secret key
  • Only parties with the secret key can produce or verify a valid HMAC
  • A threat actor intercepting and modifying the message cannot produce a valid HMAC without the secret key → MITM attack defeated
✅
OSPF uses HMAC for routing update authentication. R1 sends LSU + HMAC digest (data + secret key). R2 recomputes the HMAC with the same secret key. If they match → update accepted. If not → update discarded. This prevents fake routing updates from being injected.

3.10.6–3.10.7 Data Confidentiality — Symmetric vs Asymmetric

🔑 Symmetric Encryption
Same key to encrypt AND decrypt
Both parties share a pre-shared key in advance

✅ Fast — used for bulk data (VPN traffic)

Algorithms:
  • DES — 56-bit, legacy, insecure
  • 3DES — DES × 3; well-tested, trustworthy
  • AES — 128/192/256-bit; recommended, widely used
  • SEAL — 160-bit; faster software alternative
  • RC4 — stream cipher; used in SSL/TLS; now considered weak
🗝️ Asymmetric Encryption
Public key + Private key pair
Encrypted with public key → only private key decrypts
Encrypted with private key → only public key decrypts

⚠️ Slow — used for key exchange and digital signatures

Algorithms:
  • DH — key exchange; IPsec, SSL, SSH
  • RSA — encryption + signatures; e-commerce
  • DSA — digital signatures only
  • ECC — same security as RSA with smaller keys (160-bit)

3.10.9 Diffie-Hellman Key Exchange

DH allows two parties to create a shared secret key without ever transmitting the key over the network. Both independently compute the same result using public values and their own private values:

  1. Both parties agree on a common public value (the "yellow color" — not secret)
  2. Each party selects their own private secret value (never shared)
  3. Each party combines the common value with their private value → sends the mixed result to the other
  4. Each party mixes the received value with their own private value → both arrive at the same shared secret
  5. A third party watching all traffic cannot derive the shared secret from the exchanged public values
🎯 DH COMMON USES + KEY LIMITATION
DH is used in: IPsec VPN key exchange · SSL/TLS (HTTPS) · SSH remote access

DH limitation: Asymmetric algorithms (including DH) are too slow for bulk data. Common approach: use DH to establish the shared secret key, then use that key with a fast symmetric algorithm (AES) to encrypt actual traffic. This is how IPsec and TLS work.

🎯Common Exam Traps — Module 3▾
❌
Trap 1: Virus requires human action — Worm does NOT.
Virus spreads when a user opens an attachment, runs a file, or inserts media. Worm is self-replicating and propagates automatically by exploiting network vulnerabilities — no user action needed. This distinction is the most frequently tested malware question.
❌
Trap 2: Trojan horse is NOT self-replicating.
It disguises itself as useful/legitimate software. User installs it willingly — the hidden malicious payload then activates. Unlike viruses, it does not attach to other files or spread to other hosts on its own.
❌
Trap 3: Hashing alone does NOT protect against MITM.
A threat actor can intercept a message, modify it, recompute the hash, and append the new hash — the receiver sees a valid hash and cannot detect the tampering. Use HMAC (hash + secret key) to also authenticate the origin.
❌
Trap 4: HMAC provides BOTH integrity AND origin authentication.
Regular hashing only verifies data integrity. HMAC combines hashing with a shared secret key — only parties with the key can produce or verify a valid HMAC. An attacker without the key cannot forge a valid HMAC even if they intercept and modify the message.
❌
Trap 5: Symmetric = same key (fast, bulk data). Asymmetric = different keys (slow, key exchange/signatures).
AES (symmetric) is the recommended modern algorithm for encrypting data. DH (asymmetric) is used for key exchange. RSA (asymmetric) for digital signatures and small data encryption. VPN traffic uses AES; the VPN key is exchanged using DH.
❌
Trap 6: DH never transmits the shared secret key.
Diffie-Hellman creates the same shared secret independently on both ends without ever sending the key across the network. Both parties exchange public values, then each independently derives the shared secret. An eavesdropper cannot compute the secret from the exchanged public values.
⚠️
Trap 7: Reconnaissance always precedes access and DoS attacks.
Recon is the first phase — information query → ping sweep → port scan → vulnerability scan → exploitation. You cannot effectively attack what you haven't mapped first. The order of these steps is tested.
⚠️
Trap 8: Social engineering attacks target people, not technology.
Phishing, spear phishing, baiting, tailgating, pretexting, shoulder surfing — these manipulate human psychology, not technical vulnerabilities. The most technically sophisticated security system is undermined by one employee who holds a door open (tailgating) or clicks a phishing link.
⚠️
Trap 9: DDoS uses a botnet of zombies controlled by a CnC system.
Individual DoS = one attacker. DDoS = attacker infects many hosts with bot malware (making them zombies) → botnet controlled via Command and Control (CnC) → coordinated attack launched from all zombies simultaneously.
⚠️
Trap 10: TCP SYN Flood exploits half-open connections.
Attacker sends many SYNs with spoofed IPs → server sends SYN-ACKs but final ACKs never arrive → server's connection table fills with half-open connections → legitimate users cannot connect → effective DoS even without actually crashing the server.
⚠️
Trap 11: ARP has no authentication — any host can claim any IP or MAC.
Gratuitous ARP replies are accepted without verification. Threat actor sends spoofed gratuitous ARPs to poison the victim's and router's ARP caches — both point to the attacker's MAC. Result: full MITM position. Defense: Dynamic ARP Inspection (DAI).
⚠️
Trap 12: Rootkit is the hardest malware to remove.
It modifies the OS kernel, commands, firewall, and antivirus to conceal its presence. Standard removal tools often cannot detect it. Special rootkit removal tools are required; a complete OS reinstall may be the only reliable option.
⚠️
Trap 13: SHA-2 is the current recommended hash — not MD5, not SHA-1.
MD5 (128-bit) = legacy, use only if no alternative. SHA-1 (160-bit) = deprecated, known flaws. SHA-256/384/512 = current standard — use whenever possible. SHA-2 is the correct answer for "which hash algorithm should be used today."
⚠️
Trap 14: State-sponsored hackers use zero-day vulnerabilities.
A zero-day = a vulnerability not yet known to or patched by the software vendor. State actors have the resources to discover, develop, and weaponize zero-days. Example: Stuxnet malware used multiple zero-days to target Iran's nuclear centrifuges.

CIA Triad: Confidentiality (AES) · Integrity (SHA) · Availability (redundancy)
4 Secure comm elements: Integrity (hash) · Authentication (HMAC) · Confidentiality (encrypt) · Non-repudiation (signature)
Malware key distinctions: Virus=human action · Worm=self-replicating auto · Trojan=disguised/not self-replicating · Ransomware=encrypts for ransom · Rootkit=hardest to remove
Attack categories: Recon → Access → DoS (in that order)
Hashing: MD5=128-bit legacy · SHA-1=160-bit deprecated · SHA-2=use this
HMAC: hash + secret key = integrity + authentication
Symmetric: AES=recommended, fast, bulk data, same key
Asymmetric: DH=key exchange (never sends key) · RSA=encryption+signatures, slow
TCP SYN flood: half-open connections exhaustion
ARP poison: spoofed gratuitous ARP → MITM
DNS tunneling: non-DNS data hidden in DNS queries
IDS=detect+alert · IPS=detect+alert+BLOCK
