10.1Device Discovery with CDP▾

10.1.1 CDP Overview

  • Cisco proprietary Layer 2 protocol — only works between Cisco devices
  • Gathers information about directly connected Cisco devices sharing the same data link
  • Media and protocol independent — runs on routers, switches, and access servers
  • Sends periodic advertisements every 60 seconds (default); holdtime = 180 seconds
  • Enabled by default on all Cisco devices
  • Use cases: network mapping, topology discovery, troubleshooting, documentation
🚨
Security risk: CDP reveals device type, IOS version, IP addresses, and interface details to anyone on the same data link. Disable CDP on interfaces facing untrusted networks (ISP links, public ports) using no cdp enable on the interface.

10.1.2 Configure and Verify CDP

CDP configuration and verification commands 
! Check CDP global status (shows timers and version):
Router# show cdp

! Enable CDP globally (default state):
Router(config)# cdp run

! Disable CDP globally on all interfaces:
Router(config)# no cdp run

! Disable CDP on a specific interface (still runs globally):
Router(config-if)# no cdp enable

! Re-enable CDP on a specific interface:
Router(config-if)# cdp enable

! Show all CDP-enabled interfaces and their status:
Router# show cdp interface

! Show brief list of all CDP neighbors:
Router# show cdp neighbors

! Show full details for all CDP neighbors (INCLUDES IP address, IOS version):
Router# show cdp neighbors detail

show cdp neighbors — Output Columns

ColumnDescription
Device IDHostname of the CDP neighbor
Local InterfaceWhich port on this device connects to the neighbor
HoldtimeSeconds remaining before entry expires (reset each advertisement)
CapabilityR=Router · S=Switch · I=IGMP · H=Host · P=Phone
PlatformHardware model (e.g., WS-C3560, ISR4331)
Port IDWhich port on the neighbor connects to us
💡
show cdp neighbors does NOT show IP addresses. Use show cdp neighbors detail to get the neighbor's IP address and IOS version.

10.1.3 Network Mapping with CDP

CDP can rebuild an unknown network topology even without existing documentation:

  1. show cdp neighbors on R1 → discover S1 connected on G0/0/1 (platform WS-C3560)
  2. show cdp neighbors detail on R1 → get S1's IP address (e.g., 192.168.1.2)
  3. SSH into S1 → show cdp neighbors → discover S2 and see R1 from S1's view
  4. show cdp neighbors detail on S1 → get S2's IP address
  5. SSH into S2 → show cdp neighbors → only S1 visible = no more devices to discover
  6. Document the complete topology from gathered data

10.2Device Discovery with LLDP▾

10.2.1 LLDP Overview

  • IEEE 802.1AB standard — vendor-neutral; works with non-Cisco devices
  • Same function as CDP: advertises identity and capabilities to Layer 2 neighbors
  • May or may not be enabled by default depending on Cisco device model
  • Sends advertisements every 30 seconds; holdtime = 120 seconds

10.2.2 Configure and Verify LLDP

LLDP configuration and verification commands 
! Enable LLDP globally:
Switch(config)# lldp run

! Disable LLDP globally:
Switch(config)# no lldp run

! Enable LLDP transmit on interface (configured SEPARATELY from receive):
Switch(config-if)# lldp transmit

! Enable LLDP receive on interface:
Switch(config-if)# lldp receive

! Disable LLDP transmit:
Switch(config-if)# no lldp transmit

! Disable LLDP receive:
Switch(config-if)# no lldp receive

! Verify LLDP status (shows timers):
Switch# show lldp

! Show brief LLDP neighbor list:
Switch# show lldp neighbors

! Show full LLDP neighbor details (IOS version, IP address, capabilities):
Switch# show lldp neighbors detail

CDP vs LLDP Side-by-Side Comparison

🔵 CDP — Cisco Discovery Protocol
  • Cisco proprietary
  • Layer 2 — same data link only
  • Enabled by default
  • Timer: 60s · Holdtime: 180s
  • Per-interface: cdp enable / no cdp enable (one command)
  • Capability codes: R=Router, S=Switch, I=IGMP
  • Works only between Cisco devices
🟢 LLDP — Link Layer Discovery Protocol
  • IEEE 802.1AB — vendor-neutral
  • Layer 2 — same data link only
  • May not be enabled by default
  • Timer: 30s · Holdtime: 120s
  • Per-interface: separate lldp transmit + lldp receive
  • Capability codes: R=Router, B=Bridge (=switch), T=Telephone
  • Works with any IEEE-compliant device
🎯 EXAM KEY — CDP vs LLDP
CDP = Cisco only · enabled by default · S=Switch · 60s timer · single interface command
LLDP = vendor-neutral · may need enabling · B=Bridge (not S) · 30s timer · separate tx/rx commands

Both: Layer 2 · same data link only · show [cdp|lldp] neighbors detail adds IP + IOS version

10.3NTP — Network Time Protocol▾

10.3.1 Why Synchronized Time Matters

Without synchronized time across all network devices it is impossible to determine the order of events or the cause of an incident from log files. All devices must share the same time reference for:

  • Correlating syslog messages across multiple devices
  • Accurate security audit trails
  • Troubleshooting order-of-events analysis
  • Certificate validity checking (SSL/TLS certificates have validity timestamps)
💡
NTP uses UDP port 123 (RFC 1305). Manual time setting: R1# clock set 20:36:00 nov 15 2019. NTP is preferred over manual setting because it automatically stays synchronized and survives reboots.

10.3.2 NTP Stratum Hierarchy

⏱ NTP Stratum Hierarchy
Stratum 0
Authoritative time source — atomic clock, GPS receiver. Never directly on the network. Zero delay assumed. Also called the "reference clock."
Stratum 1
Directly connected to stratum 0 devices. Primary network time standard. Servers at this level are highly accurate.
Stratum 2+
Synchronized from stratum 1 via NTP packets over the network. Can serve stratum 3 devices. Each hop adds a small amount of potential drift.
Stratum 16
Unsynchronized — device does not have a reliable time source. Maximum valid stratum = 15. Stratum 16 = not usable.
💡
Smaller stratum = more accurate = closer to atomic clock. Same-stratum servers can peer with each other for redundancy and verification. When a device syncs from a stratum N server, it becomes stratum N+1.

10.3.3 Configure and Verify NTP

NTP configuration and verification commands 
! Configure NTP server (global config mode):
R1(config)# ntp server 209.165.200.225

! Verify time source (shows whether time is from NTP or manual config):
R1# show clock detail
21:01:34.563 UTC Fri Nov 15 2019
Time source is NTP         ← NTP is active and working

! If manually set instead:
Time source is user configuration

! Show NTP associations — which server we are syncing with:
R1# show ntp associations
  address         ref clock   st   when   poll reach  delay  offset   disp
*~209.165.200.225 .GPS.        1     61     64   377  0.481   7.480  4.261
! * = system peer (currently syncing from this server)
! ~ = configured server (we added it with ntp server command)
! st = stratum of the NTP server (1 = stratum 1)

! Show NTP sync status and our own stratum level:
R1# show ntp status
Clock is synchronized, stratum 2, reference is 209.165.200.225

! Configure a downstream device to sync from R1:
S1(config)# ntp server 192.168.1.1    ← R1's IP address
! S1 will now be stratum 3 (one hop further from atomic clock)

! Verify S1's sync:
S1# show ntp status
Clock is synchronized, stratum 3, reference is 192.168.1.1

10.4SNMP — Simple Network Management Protocol▾

10.4.1 SNMP Overview — Three Components

SNMP Manager (NMS)
Part of the Network Management System. Runs SNMP management software. Polls agents using get requests. Changes device configs using set requests. Receives unsolicited trap messages from agents.
SNMP Agent
Software module on the managed device (router, switch, server, firewall). Stores device data in the MIB. Responds to manager get/set requests. Sends trap notifications to the manager when events occur.
MIB — Management Information Base
Hierarchical database of variables (OIDs) on the managed device. Stores device info and operational statistics. Each variable uniquely identified by an Object Identifier (OID). Authenticated remote users can read/write MIB variables.
UDP 161 SNMP get/set (Manager→Agent)
UDP 162 SNMP traps (Agent→Manager)

10.4.2 SNMP Operations

get-request
NMS retrieves a specific variable value from agent MIB
get-next-request
Sequential search — NMS retrieves next variable in a table (no need to know exact name)
get-bulk-request
Retrieves large data blocks (multiple rows). SNMPv2+ only
get-response
Agent's reply to any get-request or set-request from the NMS
set-request
NMS changes a variable value on the agent. Can trigger actions: reboot, copy config file, etc.
trap
Unsolicited message FROM agent TO manager — immediate event notification without polling

10.4.3 SNMP Traps

Traps are unsolicited messages from agents → manager that alert immediately when events occur:

  • Interface up or down state change
  • Improper user authentication attempt
  • Device restart / reboot
  • TCP connection close
  • Loss of OSPF/BGP neighbor
  • MAC address table changes
✅
Traps vs Polling trade-off: Periodic polling detects changes only at polling intervals — there's a delay between event and detection. Traps provide immediate notification but require the agent to be configured to send them. Most enterprise networks use both: polling for baseline metrics + traps for critical events.

10.4.4 SNMP Versions

SNMPv1
Community string auth. No encryption. Legacy — minimal security. RFC 1157. Still encountered but not recommended.
SNMPv2c
Community string auth. No encryption. Adds bulk retrieval (get-bulk) and better error codes. Many orgs use in read-only mode. RFC 1901–1908.
SNMPv3 noAuthNoPriv
Username authentication (improvement over community string). No encryption. No message integrity.
SNMPv3 authNoPriv
Authentication via HMAC-MD5 or HMAC-SHA. No encryption. Message integrity is verified.
SNMPv3 authPriv ⭐
Most secure. Authentication via HMAC-MD5 or HMAC-SHA. Encryption via DES or AES. Full message integrity + confidentiality. Requires cryptographic software image.
🎯 SNMP VERSION KEY
v1 = community string, no encryption (legacy)
v2c = community string, no encryption, adds bulk retrieval
v3 noAuthNoPriv = username only
v3 authNoPriv = HMAC auth, no encryption
v3 authPriv = HMAC auth + AES/DES encryption = recommended for production

10.4.6 Community Strings — Read-Only vs Read-Write

Used by SNMPv1 and SNMPv2c as plaintext passwords to control MIB access:

TypeKeywordAccessNotes
Read-OnlyroCan read MIB variables — cannot change themMany orgs use SNMPv2c in ro mode for safety
Read-WriterwFull read and write access to all MIB objectsCan change config, trigger reboots — use with caution

10.4.7 MIB Object IDs (OID)

The MIB organizes variables hierarchically as a tree. Each variable is uniquely identified by an OID — a dotted number sequence:

Cisco OID structure
! Cisco OID hierarchy:
.iso(1) → .org(3) → .dod(6) → .internet(1) → .private(4) → .enterprises(1) → .cisco(9)

! Full numeric OID for Cisco: 1.3.6.1.4.1.9

! Example snmpget to retrieve 5-minute CPU busy % from a device:
snmpget -v2c -c community 10.250.250.14 1.3.6.1.4.1.9.2.1.58.0
! -v2c        = SNMP version 2c
! -c community = community string (the "password")
! 10.250.250.14 = IP address of the managed device to query
! 1.3.6.1.4.1.9.2.1.58.0 = OID of the specific MIB variable

10.5Syslog▾

10.5.1 Syslog Overview

  • Most common method for accessing system messages from network devices
  • Uses UDP port 514 — sends event notifications across IP networks
  • RFC 3164 (originally developed for UNIX in 1980s)
  • Three primary functions: gather logging info · select message types to capture · specify destinations

Syslog Message Destinations

  • Logging buffer — RAM inside the router or switch (viewable via CLI only with show logging)
  • Console line — displayed directly on console terminal
  • Terminal line — displayed on active Telnet/SSH session
  • Syslog server — external server; persistent storage; viewable without device access; supports reporting
UDP 514 Syslog
UDP 123 NTP
UDP 161 SNMP polls
UDP 162 SNMP traps

10.5.3 Syslog Severity Levels 0–7

Smaller number = more critical. Level 0 = worst. Level 7 = least urgent.

0
Emergency
System Unusable — entire system has halted
1
Alert
Immediate Action Needed — e.g., loss of ISP connection
2
Critical
Critical Condition — e.g., loss of backup ISP connection
3
Error
Error Condition — e.g., interface going down
4
Warning
Warning Condition — device functionality potentially affected
5
Notification
Normal but Significant — e.g., interface up/down, system restart
6
Informational
Normal information message — e.g., boot events, license acceptance
7
Debugging
Output from debug commands — very verbose; use for troubleshooting only

10.5.4 Syslog Message Format and Facilities

Default syslog message format on Cisco IOS:

Syslog message format
%facility-severity-MNEMONIC: description

! Real example:
%LINK-3-UPDOWN: Interface Port-channel1, changed state to up
!  ^LINK   = facility (what part of IOS generated this message)
!  ^3      = severity level (Error)
!  ^UPDOWN = mnemonic (short code identifying specific event)
!  description = human-readable explanation

Common facilities on Cisco IOS routers: IP · OSPF · SYS (operating system) · IPsec · IF (interface)

10.5.5 Configure Syslog Timestamps

⚠️
Timestamps are NOT added to syslog messages by default. Without timestamps, messages have no date/time — making correlating events across devices impossible. Always enable timestamps in production.
Enable timestamps on syslog messages 
! Enable timestamps (requires NTP for accuracy):
R1(config)# service timestamps log datetime

! Without this command — no timestamp:
%LINK-5-CHANGED: Interface GigabitEthernet0/0/0, changed state to administratively down

! With this command — timestamp included:
*Mar 1 11:52:45: %LINK-3-UPDOWN: Interface GigabitEthernet0/0/0, changed state to up

10.6Router and Switch File Maintenance▾

10.6.1 Router File Systems

File system navigation commands 
! Show all available file systems:
Router# show file systems
! Key file systems:
! flash: (bootflash:) — IOS image + config files
!   * = default file system  # = bootable
! nvram:  — startup-config storage
! tftp:   — remote TFTP server
! usbflash0: — USB flash drive (if present)

! List contents of current (default = flash) directory:
Router# dir

! Change to NVRAM directory:
Router# cd nvram:

! Show current working directory:
Router# pwd

! List NVRAM directory contents (startup-config visible here):
Router# dir
! Shows: startup-config, private-config, etc.

! List contents of USB drive:
Router# dir usbflash0:
💡
In show file systems output: asterisk (*) = current default file system. Pound sign (#) appended to prefix = bootable disk. The IOS image lives in flash and is the bootable file system.

10.6.3–10.6.7 Back Up and Restore Configurations

📝 Method 1 — Text File (Tera Term)
Backup: File → Log → select path → run show running-config → Close log
Restore: File → Send file → select the saved config file → Tera Term pastes it as CLI commands
Note: Remove encrypted passwords, --More-- prompts, and non-command text before restoring
📡 Method 2 — TFTP
Backup running-config: copy running-config tftp
Backup startup-config: copy startup-config tftp
Restore to running: copy tftp running-config
Restore to startup: copy tftp startup-config
🔌 Method 3 — USB Flash Drive
Verify USB present: show file systems (look for usbflash0:)
Backup: copy running-config usbflash0:/
View file: dir usbflash0:
Restore: copy usbflash0:/R1-Config running-config
TFTP backup and restore — full example 
! Backup running-config to TFTP:
R1# copy running-config tftp

Write file R1-Jan-2019 to 192.168.10.254? [confirm]

10.6.8 Password Recovery — Six Steps

💡
Console access is required. Terminal settings: 9600 baud · No parity · 8 data bits · 1 stop bit · No flow control. Break sequence in PuTTY: Ctrl+Break.
  1. Enter ROMMON mode — use break sequence during boot (PuTTY: Ctrl+Break) or remove flash card while device is powered off. Prompt changes to rommon 1 >
  2. Change configuration register to bypass startup-config — confreg 0x2142 tells device to ignore NVRAM on next boot, then type reset to reboot
  3. Copy startup-config to running-config — copy startup-config running-config (restores all config into RAM without needing the password)
  4. Change the password — enable secret [newpassword] (or any other password commands needed)
  5. Restore config register and save — config-register 0x2102 (restores normal boot), then copy running-config startup-config
  6. Reload — reload — device boots normally, loads new startup-config with new password
🚨
Critical mistake to avoid in Step 3: The correct command is copy startup-config running-config — this restores the saved config into RAM. Do NOT run copy running-config startup-config here — that would OVERWRITE the saved startup-config with the current empty RAM config, erasing all your device configuration.

10.7.3 Backup IOS Image to TFTP Server

Three-step IOS backup to TFTP 
! Step 1 — Verify connectivity to TFTP server:
R1# ping 172.16.1.100

! Step 2 — Check IOS image name and size in flash:
R1# show flash0:
! Note the filename: isr4200-universalk9_ias.16.09.04.SPA.bin (517153193 bytes)
! Ensure TFTP server has enough disk space

! Step 3 — Copy IOS to TFTP server:
R1# copy flash: tftp:
Source filename []? isr4200-universalk9_ias.16.09.04.SPA.bin
Address or name of remote host []? 172.16.1.100
Destination filename [isr4200-universalk9_ias.16.09.04.SPA.bin]?  [Enter to accept]
Writing isr4200-universalk9_ias.16.09.04.SPA.bin...
517153193 bytes copied in 863.468 secs

10.7.4 Copy New IOS from TFTP to Router

Three-step IOS upgrade from TFTP 
! Step 1 — Ping TFTP server:
R1# ping 172.16.1.100

! Step 2 — Verify free flash space:
R1# show flash:
! Note: "6294806528 bytes available" — must exceed new IOS file size

! Step 3 — Copy new IOS from TFTP to flash:
R1# copy tftp: flash:
Address or name of remote host []? 172.16.1.100
Source filename []? isr4200-universalk9_ias.16.09.04.SPA.bin
Destination filename [isr4200-universalk9_ias.16.09.04.SPA.bin]?  [Enter]
517153193 bytes copied in 868.128 secs

10.7.5 boot system Command and Verification

Set boot image and verify after reload 
! Tell router which IOS to load at next boot:
R1(config)# boot system flash0:isr4200-universalk9_ias.16.09.04.SPA.bin
R1(config)# exit
R1# copy running-config startup-config   ! Save the boot system command
R1# reload                               ! Reboot with new IOS

! Verify which IOS loaded after reboot:
R1# show version
Cisco IOS XE Software, Version 16.09.04
System image file is "flash:isr4200-universalk9_ias.16.09.04.SPA.bin"
💡
Without a boot system command: router loads the first valid IOS image found in flash by default. Multiple boot system commands can be stacked to create a fault-tolerant boot plan — the router tries each in order if the previous fails.

copy flash: tftp:              ! Backup IOS image to TFTP server
copy tftp: flash:              ! Download new IOS from TFTP to flash
boot system flash0:filename    ! Set IOS image to load at boot
show version                   ! Verify loaded IOS version

! Password recovery (ROMMON mode):
confreg 0x2142                 ! Bypass startup-config on next boot

copy startup-config running-config  ! Step 3: restore config to RAM
config-register 0x2102         ! Restore normal boot behavior
🎯Common Exam Traps — Module 10▾
❌
Trap 1: CDP is Cisco proprietary. LLDP is vendor-neutral (IEEE 802.1AB).
CDP only works between Cisco devices. LLDP works with any vendor's IEEE-compliant device. Both can run simultaneously on Cisco hardware.
❌
Trap 2: LLDP capability code for switch = B (Bridge), NOT S.
CDP uses S=Switch. LLDP uses B=Bridge to represent a switch. This is a direct exam trick — when reading LLDP output, Bridge = switch.
❌
Trap 3: LLDP transmit and receive are configured separately. CDP uses one command.
CDP: one command per interface — cdp enable / no cdp enable. LLDP: two separate commands — lldp transmit and lldp receive. To fully disable LLDP on an interface, both must be disabled.
❌
Trap 4: show cdp neighbors detail (with "detail") shows IP address and IOS version.
show cdp neighbors (without detail) shows hostname, platform, capability, and port — but NOT the IP address. Add detail keyword to get IP addresses and IOS version. Same applies to LLDP: show lldp neighbors detail.
❌
Trap 5: SNMP manager polls agents on UDP 161. Agents send traps to manager on UDP 162.
Direction matters: NMS → agent = UDP 161 (get/set requests). Agent → NMS = UDP 162 (traps). These port numbers are directly tested. NTP = UDP 123. Syslog = UDP 514.
❌
Trap 6: Password recovery Step 3 — copy startup-config running-config (NOT the reverse).
copy startup-config running-config = restores your saved config into RAM (correct). copy running-config startup-config = overwrites your saved startup-config with the current blank/default RAM config (DESTROYS your config). The order matters completely.
⚠️
Trap 7: CDP is enabled by default. LLDP may or may not be enabled by default.
On most Cisco devices, CDP is always on without any configuration. LLDP must be explicitly enabled with lldp run on some devices. Always configure LLDP before testing in labs.
⚠️
Trap 8: Syslog severity — smaller number = more critical. Level 0 = worst.
Emergency (0) is the most critical. Debugging (7) is the least urgent. Students often assume higher number = more severe — the opposite is true. "0 = Emergency" is a reliable anchor: the system is unusable at level 0.
⚠️
Trap 9: Timestamps are NOT on by default in syslog — must be configured.
Without service timestamps log datetime, log messages have no date or time. This makes troubleshooting across devices nearly impossible. Always enable in production. Timestamps require accurate NTP for meaningful values.
⚠️
Trap 10: NTP stratum — smaller = closer to atomic clock = more accurate.
Stratum 1 = directly connected to GPS/atomic (stratum 0). Stratum 16 = unsynchronized. Max valid = 15. When a device syncs from a stratum 2 server, it becomes stratum 3.
⚠️
Trap 11: confreg 0x2142 bypasses startup-config. confreg 0x2102 = normal boot.
0x2142 = ignore NVRAM startup-config on boot (used for password recovery). 0x2102 = normal operation (load startup-config from NVRAM). Must set back to 0x2102 at end of recovery or device never loads its saved config again.
⚠️
Trap 12: SNMPv1 and v2c use community strings — no encryption. SNMPv3 authPriv adds encryption.
Community strings are plaintext passwords. SNMPv3 authPriv uses HMAC-MD5/SHA for authentication and DES/AES for encryption. For secure SNMP in production, use SNMPv3 authPriv.
⚠️
Trap 13: Flash is marked with * (default) and # (bootable) in show file systems.
The asterisk before flash in show file systems = current default file system. The # after the prefix (e.g., bootflash:#) = bootable disk. The IOS runs from flash. NVRAM holds startup-config.
⚠️
Trap 14: Without boot system command, router loads first valid IOS in flash.
If no boot system command is configured, the router scans flash and loads the first valid IOS image it finds. Multiple boot system commands create a priority-ordered fault-tolerant boot plan.
⚠️
Trap 15: no cdp enable disables CDP on one interface only — CDP still runs globally.
no cdp enable stops CDP advertisements on that specific interface only. no cdp run disables CDP globally on all interfaces. Use no cdp enable on ISP-facing or untrusted interfaces to prevent leaking device information.
✅
