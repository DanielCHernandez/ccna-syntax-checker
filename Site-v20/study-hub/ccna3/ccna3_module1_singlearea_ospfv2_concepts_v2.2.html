1.1OSPF Features and Characteristics▾

1.1.1 Introduction to OSPF

OSPF (Open Shortest Path First) is a link-state routing protocol developed as a scalable alternative to RIP. RIP used hop count as its only metric — it can't distinguish between a 1-hop 56K modem link and a 15-hop 10 Gbps fiber path. OSPF fixes this with a cost-based metric tied to bandwidth.

FeatureRIPOSPF
TypeDistance vectorLink-state
MetricHop countCost (based on bandwidth)
Max hops15 (16 = unreachable)No limit
ConvergenceSlowFast
ScalabilitySmall networks onlyLarge enterprise networks
AlgorithmBellman-FordDijkstra SPF
Administrative Distance120110
💡
A link in OSPF = an interface on a router, a segment connecting two routers, or a stub network (Ethernet LAN on a single router). Link-state information always includes three things: network prefix, prefix length, and cost.

1.1.2 Three Components of OSPF

All routing protocols share three components. OSPF implements each:

👥
1. Routing Protocol Messages (5 packet types)

Hello · DBD · LSR · LSU · LSAck — used to discover neighbors, exchange routing info, and maintain accuracy

🗄️
2. Data Structures — Three Databases
Adjacency DB → Neighbor Table (show ip ospf neighbor)

LSDB → Topology Table (show ip ospf database)

Forwarding DB → Routing Table (show ip route)

The LSDB must be identical on all routers in the same area. The routing table is unique per router.

⚙️
3. Algorithm — Dijkstra SPF

Shortest Path First algorithm runs on the LSDB. Places each router at the root of an SPF tree and calculates the shortest (lowest cost) path to every network. Best paths populate the routing table.

1.1.3 Link-State Operation — Five Steps to Convergence

  1. Establish Neighbor Adjacencies — OSPF sends Hello packets on all OSPF-enabled interfaces to discover neighbors and form adjacencies
  2. Exchange Link-State Advertisements (LSAs) — Routers share LSAs containing the state and cost of each connected link. LSAs are flooded throughout the area until all routers have all LSAs.
  3. Build the Link-State Database (LSDB) — Each router builds its topology table from the received LSAs. All routers in the area end up with an identical LSDB.
  4. Execute the SPF Algorithm — Each router independently runs the Dijkstra SPF algorithm on its LSDB, building an SPF tree with itself at the root.
  5. Choose the Best Route — Best paths from the SPF tree are installed in the routing table. A lower-AD route (e.g., static route AD=1) to the same network overrides the OSPF route (AD=110).

💡
This module covers single-area OSPFv2 only. Multiarea OSPF is covered in the CCNA 3 curriculum as background. The CCNA exam focuses on single-area configuration and concepts.

1.1.5 Multiarea OSPF — Three Advantages

Dividing a large OSPF domain into areas provides three key benefits:

  • Smaller routing tables — Route summarization between areas reduces the number of entries. Summarization is NOT enabled by default.
  • Reduced link-state update overhead — Smaller areas mean less memory and processing per router. Each router only maintains a full LSDB for its own area.
  • Reduced frequency of SPF calculations — A topology change in area 51 triggers SPF only in area 51. Routers in other areas receive an update but do NOT re-run SPF — they only update their routing table. LSA flooding stops at the area boundary (ABR).

1.1.6 OSPFv3

OSPFv3 is the IPv6 equivalent of OSPFv2:

FeatureOSPFv2OSPFv3
Network layerIPv4IPv6
AdvertisesIPv4 routes (networks)IPv6 prefixes
Peers withOSPFv2 routers onlyOSPFv3 routers only
TablesSeparate neighbor, LSDB, routing tableSeparate neighbor, LSDB, routing table (independent)
AlgorithmDijkstra SPFDijkstra SPF (identical)
💡
OSPFv2 and OSPFv3 run as completely separate, independent processes on the same router — separate neighbor tables, separate LSDBs, separate routing tables. Enabling OSPFv2 does NOT enable OSPFv3.
1.2OSPF Packets▾

1.2.2 Five OSPF Packet Types

OSPF uses five specific link-state packet (LSP) types to build and maintain neighbor adjacencies and synchronize the LSDB:

1
Hello
Discovers OSPF neighbors · Establishes and maintains adjacencies · Elects DR/BDR on multiaccess networks · Sent to 224.0.0.5 (All OSPF Routers)
2
Database Description (DBD)
Abbreviated LSDB summary — contains LSA entry headers only (not full LSAs) · Used to check for database synchronization · Router with higher Router ID sends first during ExStart
3
Link-State Request (LSR)
Requests specific LSA entries from a neighbor · Sent when a router sees entries in the received DBD that it doesn't have or has an older version of
4
Link-State Update (LSU)
Carries one or more complete LSAs · Reply to LSRs · Also used for topology change announcements · Sent incrementally when topology changes, and every 30 minutes as a refresh
5
Link-State Acknowledgment (LSAck)
Confirms receipt of an LSU · The data field is empty — just an ACK. Ensures reliable delivery of LSU packets.

1.2.3 LSU vs LSA — Know the Difference

🚨
LSU ≠ LSA — these are frequently confused.
LSU (Link-State Update) = the packet — the envelope that carries routing information.
LSA (Link-State Advertisement) = the content — the actual routing advertisement inside the LSU.
One LSU can carry multiple LSAs. OSPFv2 defines 11 different types of LSAs. The exam uses these terms interchangeably in informal descriptions, but questions about packet types specifically mean LSU (Type 4).

1.2.4 Hello Packet — Key Fields

The Hello packet (Type 1) is the foundation of OSPF operation — neighbor discovery, adjacency maintenance, and DR/BDR election all depend on it. Sent to 224.0.0.5 every Hello interval.

FieldDefault / ValueMust Match Between Neighbors?
Router ID32-bit (looks like IPv4 address) — uniquely identifies the router❌ Must be UNIQUE (not matching)
Area IDArea number of the sending interface✅ YES — must match
Network MaskSubnet mask of the sending interface✅ YES (on multiaccess networks)
Hello Interval10 seconds (Ethernet default)✅ YES — must match or no adjacency
Dead Interval40 seconds (4 × Hello interval)✅ YES — must match or no adjacency
Router Priority1 (default); range 0–255; 0 = never DR/BDR❌ Each router has its own value

List of NeighborsRouter IDs seen on this interface❌ Informational only
🎯 ADJACENCY FORMATION REQUIREMENTS
For two OSPF routers to form an adjacency, these parameters MUST match on the connecting interfaces:

✅ Hello interval (default: 10 sec on Ethernet)
✅ Dead interval (default: 40 sec = 4 × Hello)
✅ Area ID
✅ Subnet/Network mask (on multiaccess networks)
✅ Authentication (if configured)
✅ Stub area flag

Mismatched Hello/Dead timers = most common OSPF adjacency failure. No error message is shown — routers simply never form an adjacency.
1.3OSPF Operation▾

1.3.2 Seven OSPF Operational States

OSPF progresses through seven states from initial startup to full convergence. The Full state is the goal:

📶 OSPF State Machine — Down to Full
DOWN
No Hello packets received. Router begins sending Hellos on OSPF-enabled interfaces to discover neighbors.
INIT
Hello received from neighbor. Contains the neighbor's Router ID. Router adds neighbor to its neighbor list.
TWO-WAY
Router sees its own Router ID in a received Hello's neighbor list — bidirectional communication confirmed. DR/BDR election happens here on multiaccess networks. P2P links skip to ExStart.
EXSTART
Routers negotiate which one sends the first DBD packet. Router with the higher Router ID sends first. Initial DBD sequence number is set.
EXCHANGE
Routers exchange DBD packets (abbreviated LSDB summaries — LSA headers only). Each acknowledges with LSAck. Routers compare DBDs against their own LSDB.
LOADING
Router sends LSR for any entries it needs (missing or outdated). Neighbor replies with full LSU. Receiving router sends LSAck. SPF algorithm begins processing received data.
FULL ✅
LSDB is fully synchronized. Neighbor relationship is complete. Routing table is updated. This is convergence. LSUs are only sent on topology changes or every 30 minutes.
🚨
If neighbors are stuck in a state other than Full — there is a problem. Common causes: Hello/Dead timer mismatch, area ID mismatch, authentication mismatch, MTU mismatch (stuck in Exchange/Loading), duplicate Router ID.

1.3.3 Establish Neighbor Adjacencies — Step by Step

  1. Down → Init: OSPF enabled on interface. Router sends Hello to 224.0.0.5 containing its own Router ID. No neighbors known yet.
  2. Init State: Neighbor receives Hello, adds sender's Router ID to its neighbor list, sends Hello back with: its own Router ID + sender's Router ID in its neighbor list.
  3. Two-Way State: Original router receives Hello and sees its own Router ID listed in the neighbor's Hello. Seeing your own RID in a received Hello = Two-Way state. Decision point:
    • Point-to-point link → skip DR/BDR, proceed directly to ExStart
    • Multiaccess network (Ethernet) → DR/BDR election must occur
  4. DR/BDR Election (multiaccess only): Highest Router Priority wins. Tie = highest Router ID wins. Default priority = 1 for all routers. Priority 0 = never becomes DR or BDR (always DROTHER).

Router ID — 3-Tier Selection (Cisco)

① Best
Manually configured using router-id x.x.x.x
Always preferred. Cisco best practice — always configure this for easy identification in troubleshooting. Takes effect after clear ip ospf process.
② Alt
Highest IPv4 address on a loopback interface
Used if no manual Router ID is configured. Loopback interfaces never go down, so this provides a stable RID.
③ Last
Highest active physical interface IPv4 address
Last resort if no manual RID and no loopbacks. Risk: if the highest-IP interface goes down, the RID could change — disrupting the OSPF process.

1.3.4 Synchronizing OSPF Databases — Three Steps

After Two-Way state, routers synchronize their LSDBs:

  1. Decide First Router (ExStart): Router with the higher Router ID sends the first DBD packet. Both agree on the initial DBD sequence number.
  2. Exchange DBDs (Exchange state): Routers exchange DBD packets — abbreviated LSDB summaries with LSA headers only (not full LSAs). Each router acknowledges received DBDs with LSAck. Routers compare received DBDs against their own LSDB. Sequence numbers in LSA headers determine which entry is newer.
  3. Send LSR (Loading state): If a router finds entries it needs (missing or older versions) → sends LSR for those specific entries → neighbor replies with full LSU → router sends LSAck → process repeats until all LSRs satisfied → Full state achieved.
✅
After Full state: LSUs are only sent when a topology change is detected (incremental updates) or every 30 minutes (periodic refresh). OSPF does not continuously flood routing updates like distance vector protocols.

1.3.5 The Need for a DR — The Adjacency Problem

On a multiaccess Ethernet network with multiple OSPF routers, full adjacencies with every neighbor creates an explosion of LSAs:

Adjacencies = n(n-1) ÷ 2
5 routers: 5(4)/2 = 10 adjacencies
20 routers: 20(19)/2 = 190 adjacencies
Each adjacency = more LSA flooding = network chaos

Two problems arise without a DR:

  • Creation of multiple adjacencies — every router forming Full adjacency with every other router creates n(n-1)/2 relationships
  • Excessive LSA flooding — every router floods LSAs to every other router, then each of those re-floods — creating redundant, exponential traffic

1.3.6 LSA Flooding With a DR — The Solution

On multiaccess networks, OSPF elects a DR (Designated Router) as the central collection and distribution point for all LSAs:

RoleDescriptionAdjacencies
DRCentral LSA collection and distribution point. Floods LSAs to all routers via 224.0.0.5.Full adjacency with ALL routers on segment
BDRBackup — takes over immediately if the DR fails. Also listens to all LSAs.Full adjacency with ALL routers on segment
DROTHERAll other routers — neither DR nor BDR. Send LSAs to DR/BDR only.Full adjacency with DR and BDR only; Two-Way with other DROTHERs

Multicast Addresses Used

All OSPF Routers
224.0.0.5

Used for: Hello packets (all routers), DR flooding LSAs to all routers. All OSPF routers process packets to this address.

All DR Routers
224.0.0.6

Used by DROTHERs to send LSAs — only the DR and BDR process packets to this address. DROTHERs use 224.0.0.6 to reach the DR/BDR.

⚠️
The DR only manages LSA distribution — it does NOT forward user data packets. Routers still use the best next-hop in their routing table for actual packet forwarding. The DR election determines who manages OSPF topology information, not who forwards traffic.
✅
No DR/BDR on point-to-point links. Serial (P2P) links have only two routers — no need for centralized LSA management. Both routers form a Full adjacency directly with each other, skipping the DR/BDR election step entirely.

🎯Common Exam Traps — Module 1▾
❌
Trap 1: OSPF is link-state — NOT distance vector.
RIP = distance vector (hop count, Bellman-Ford, AD=120). OSPF = link-state (cost/bandwidth, Dijkstra SPF, AD=110). Know the distinction — it is directly tested.
❌
Trap 2: All routers in the same OSPF area MUST have identical LSDBs.
The LSDB (topology table) is shared and synchronized across all routers in an area. The routing table is unique per router — built individually from the LSDB using SPF. These are different things.
❌
Trap 3: Hello interval AND Dead interval MUST match between neighbors.
Mismatched timers = no adjacency formed, with no helpful error message. Default: Hello = 10 sec, Dead = 40 sec (4 × Hello). This is the most common OSPF misconfiguration tested on the exam.
❌
Trap 4: LSU ≠ LSA.
LSU (Type 4) = the packet/container. LSA = the routing advertisement content inside the LSU. One LSU can carry multiple LSAs. OSPFv2 defines 11 LSA types. When the exam asks about OSPF packet types — the answer is LSU (not LSA).
❌
Trap 5: Router ID selection — manual router-id is always first choice.
Three-tier: ① manual router-id command ② highest loopback IP ③ highest active physical interface IP. Cisco best practice = always manually configure with router-id. Changes require clear ip ospf process to take effect.
❌
Trap 6: DR/BDR election — priority first, then Router ID.
Highest priority wins (default=1). Ties broken by highest Router ID. Priority 0 = router can never become DR or BDR (DROTHER always). Know the election order.
⚠️
Trap 7: DR is per segment — not per router or per OSPF domain.
A router can be DR on one interface and DROTHER on another. The election happens per multiaccess network segment (per interface), not globally for the entire OSPF area.
⚠️
Trap 8: No DR/BDR election on point-to-point links.
Serial (P2P) links have only two routers — no need for centralized LSA management. DR/BDR only happens on multiaccess networks like Ethernet. On P2P links, both routers form Full adjacency directly and skip the Two-Way → DR election step.
⚠️
Trap 9: DROTHERs form Full adjacency ONLY with DR and BDR — not each other.
On a multiaccess network, DROTHERs reach only Two-Way state with each other. They only achieve Full adjacency with the DR and BDR. This reduces the total number of Full adjacencies needed on the segment.
⚠️
Trap 10: 224.0.0.5 vs 224.0.0.6.
224.0.0.5 = All OSPF Routers — Hellos; DR floods LSAs here to all. 224.0.0.6 = All DR Routers — DROTHERs send their LSAs here; only DR and BDR process it. Both addresses are exam-tested.
⚠️
Trap 11: The DR manages LSA distribution only — NOT packet forwarding.
The DR election determines who distributes OSPF routing information. Routers still forward actual user data packets using the best next-hop in their own routing table. The DR does not handle user traffic.
⚠️
Trap 12: Multiarea OSPF — topology change only reruns SPF in the affected area.
A link change in area 51 triggers SPF recalculation only in area 51. Routers in other areas receive an LSA update but only update their routing table — they do NOT re-run SPF. LSA flooding stops at the ABR (area boundary).
✅
