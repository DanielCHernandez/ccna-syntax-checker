5.1Configure Standard IPv4 ACLs▾

5.1.2 Numbered Standard IPv4 ACL Syntax

Numbered standard ACL — global configuration command
Router(config)# access-list access-list-number {deny | permit | remark text} source [source-wildcard] [log]

! Remove entire numbered ACL:
Router(config)# no access-list access-list-number
ParameterDescription
access-list-numberStandard ACL range: 1–99 or 1300–1999
deny / permitAction taken when condition matches
remark textOptional documentation — max 100 characters. Shown in show run but NOT in show access-lists
sourceSource network or host. Use any for all, host ip-address for one specific host
source-wildcardOptional wildcard mask. If omitted: defaults to 0.0.0.0 (exact host match)
logOptional — generates log message on first match. Use for troubleshooting only.

5.1.3 Named Standard IPv4 ACL Syntax

Named standard ACL — ip access-list command 
! Create named standard ACL and enter config mode:
Router(config)# ip access-list standard ACCESS-LIST-NAME
Router(config-std-nacl)# [sequence-number] {permit | deny | remark} source [wildcard]

! Remove named ACL:
Router(config)# no ip access-list standard ACCESS-LIST-NAME
  • Names are alphanumeric, case-sensitive, and must be unique
  • Convention: CAPITAL LETTERS to stand out in show running-config
  • ADMIN-HOST and admin-host are two different ACLs
  • No spaces or punctuation in names

5.1.4 Apply a Standard ACL to an Interface

ip access-group — bind ACL to interface 
! Apply ACL to interface:
Router(config-if)# ip access-group {access-list-number | access-list-name} {in | out}

! Remove ACL from interface only (ACL still exists on router):
Router(config-if)# no ip access-group {number | name} {in | out}

! Remove ACL from router entirely:
Router(config)# no access-list number               ! numbered ACL
Router(config)# no ip access-list standard name     ! named ACL
💡
Removing an ACL from an interface with no ip access-group does NOT delete the ACL definition. The ACL still exists in the router's memory — it's just no longer applied to that interface. Use no access-list to delete the ACL itself.

5.1.5 Numbered Standard ACL — Complete Example

Policy: Only PC1 (192.168.10.10) and all LAN2 hosts (192.168.20.0/24) can reach the internet. All other 192.168.10.0 hosts are denied. Applied outbound on Serial 0/1/0.

Configure and apply numbered standard ACL 10 
R1(config)# access-list 10 remark ACE permits ONLY host 192.168.10.10 to the internet
R1(config)# access-list 10 permit host 192.168.10.10
R1(config)# access-list 10 remark ACE permits all hosts in LAN 2
R1(config)# access-list 10 permit 192.168.20.0 0.0.0.255
R1(config)# interface Serial 0/1/0
R1(config-if)# ip access-group 10 out
R1(config-if)# end

! Verify — show access-lists does NOT show remarks:
R1# show access-lists
Standard IP access list 10
    10 permit 192.168.10.10
    20 permit 192.168.20.0, wildcard bits 0.0.0.255

! show run DOES show remarks:
R1# show run | section access-list
access-list 10 remark ACE permits host 192.168.10.10
access-list 10 permit 192.168.10.10
access-list 10 remark ACE permits all hosts in LAN 2
access-list 10 permit 192.168.20.0 0.0.0.255

! Verify ACL applied to interface:
R1# show ip int Serial 0/1/0 | include access list
  Outgoing access list is 10
  Inbound  access list is not set

5.1.6 Named Standard ACL — Complete Example

Same policy, implemented as named ACL PERMIT-ACCESS:

Configure and apply named standard ACL PERMIT-ACCESS 
R1(config)# no access-list 10                       ! Remove old numbered ACL first
R1(config)# ip access-list standard PERMIT-ACCESS
R1(config-std-nacl)# remark ACE permits host 192.168.10.10
R1(config-std-nacl)# permit host 192.168.10.10
R1(config-std-nacl)# remark ACE permits all hosts in LAN 2
R1(config-std-nacl)# permit 192.168.20.0 0.0.0.255
R1(config-std-nacl)# exit
R1(config)# interface Serial 0/1/0
R1(config-if)# ip access-group PERMIT-ACCESS out
R1(config-if)# end

R1# show access-lists
Standard IP access list PERMIT-ACCESS
    10 permit 192.168.10.10
    20 permit 192.168.20.0, wildcard bits 0.0.0.255

R1# show ip int Serial 0/1/0 | include access list
  Outgoing access list is PERMIT-ACCESS

5.2Modify IPv4 ACLs▾

5.2.1 Two Methods to Modify an ACL

📝 Method 1 — Text Editor
  • Best when many ACEs need to change
  • Copy ACL from show running-config → paste into text editor
  • Make corrections in the editor
  • Delete the old ACL from router first: no access-list number
  • Paste corrected version into router
🔢 Method 2 — Sequence Numbers
  • Best for one or two ACE changes
  • show access-lists reveals sequence numbers
  • Enter: ip access-list standard {number|name}
  • Delete: no {sequence-number}
  • Re-add: {seq-num} {permit|deny} ...
🚨
Text editor method: delete the old ACL BEFORE pasting the corrected version. If you paste new ACE commands without removing the original ACL, IOS simply appends the new commands to the end of the existing list. The result is a combined broken ACL — not the intended replacement.

5.2.3 Sequence Numbers — Edit a Specific ACE

🔢 Fix Wrong ACE Using Sequence Numbers
1
Check current ACL with show access-lists — identify wrong ACE and its sequence number
2
Enter edit mode: R1(config)# ip access-list standard {number|name}
3
Delete wrong ACE: R1(config-std-nacl)# no 10 (replace 10 with the sequence number)
4
Add corrected ACE at same position: R1(config-std-nacl)# 10 deny host 192.168.10.10
5
Verify with show access-lists — confirm correction is in place
Sequence number edit — full example 
! Step 1 — identify problem (19 instead of 192):
R1# show access-lists
Standard IP access list 1
    10 deny   19.168.10.10    ← WRONG
    20 permit 192.168.10.0, wildcard bits 0.0.0.255

! Steps 2–4 — enter edit mode, delete wrong ACE, re-add correct one:
R1# configure terminal
R1(config)# ip access-list standard 1
R1(config-std-nacl)# no 10
R1(config-std-nacl)# 10 deny host 192.168.10.10
R1(config-std-nacl)# end

! Step 5 — verify:
R1# show access-lists
Standard IP access list 1
    10 deny   192.168.10.10   ← CORRECT
    20 permit 192.168.10.0, wildcard bits 0.0.0.255

5.2.4 Insert an ACE Between Existing Entries

Sequence numbers are spaced in increments of 10 (10, 20, 30...) to allow inserting ACEs between existing entries:

Insert ACE 15 between ACE 10 and ACE 20 
! Problem: Need to also deny 192.168.10.5, but can't append to end —
! ACE 20 (permit 192.168.10.0 0.0.0.255) would match it first

R1# show access-lists
Standard IP access list NO-ACCESS
    10 deny   192.168.10.10
    20 permit 192.168.10.0, wildcard bits 0.0.0.255

! Solution: insert ACE 15 (between 10 and 20):
R1(config)# ip access-list standard NO-ACCESS
R1(config-std-nacl)# 15 deny 192.168.10.5     ! "host" keyword is optional here

R1# show access-lists
Standard IP access list NO-ACCESS
    15 deny   192.168.10.5   ← appears first (IOS hashing puts hosts first)
    10 deny   192.168.10.10
    20 permit 192.168.10.0, wildcard bits 0.0.0.255
⚠️
Standard ACL hashing function: IOS reorders host statements before range statements in show access-lists output — regardless of entry order. ACE 15 appears before ACE 10 even though 15 > 10. This optimization does NOT apply to extended ACLs, which always display in the exact order entered.

5.2.5 ACL Statistics and Clearing Counters

show access-lists shows how many times each ACE has been matched. The implicit deny at the end does NOT increment — add an explicit deny any to count denied packets.

ACL match statistics and clear counters 
R1# show access-lists
Standard IP access list NO-ACCESS
    10 deny   192.168.10.10  (20 matches)     ← matched 20 times
    20 permit 192.168.10.0, wildcard bits 0.0.0.255  (64 matches)

! Reset counters for one ACL:
R1# clear access-list counters NO-ACCESS

! Reset counters for all ACLs:
R1# clear access-list counters

R1# show access-lists
Standard IP access list NO-ACCESS
    10 deny   192.168.10.10                   ← counters cleared
    20 permit 192.168.10.0, wildcard bits 0.0.0.255

5.3Secure VTY Ports with a Standard IPv4 ACL▾

5.3.1 access-class vs ip access-group

Interface ACLs
ip access-group

Applied in interface config mode (config-if)#. Filters traffic entering or leaving a physical/logical interface. Applies to routed traffic.

VTY Line ACLs
access-class

Applied in line config mode (config-line)#. Filters who can establish a Telnet or SSH session TO or FROM this router. Does NOT use ip access-group.

🎯 MOST-TESTED COMMAND DISTINCTION IN MODULE 5
VTY line ACLs use access-class — NOT ip access-group.
Using ip access-group on a vty line is wrong syntax.

Two key rules for VTY ACLs:
  • Apply to ALL VTY lines (e.g., line vty 0 4) — users can connect to any VTY line
  • Apply in the inbound direction to filter who can connect TO the router

5.3.2 Secure VTY Access — Complete Example

Policy: Only PC1 (192.168.10.10) can SSH to R1. All other hosts are denied.

Three-step VTY security configuration 
! Step 1 — Create local user for authentication:
R1(config)# username ADMIN secret class

! Step 2 — Create ACL identifying permitted admin hosts:
R1(config)# ip access-list standard ADMIN-HOST
R1(config-std-nacl)# remark This ACL secures incoming vty lines
R1(config-std-nacl)# permit 192.168.10.10
R1(config-std-nacl)# deny any             ! Explicit deny for counter tracking
R1(config-std-nacl)# exit

! Step 3 — Apply ACL to ALL VTY lines using access-class:
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh      ! Production: SSH only (not telnet)
R1(config-line)# access-class ADMIN-HOST in    ← access-class (NOT ip access-group!)
R1(config-line)# end
💡
For Telnet-only (lab/demo only): use transport input telnet. For production: always use transport input ssh. For both: transport input ssh telnet. The Cisco exam default for labs is Telnet, but SSH is the correct security answer.

5.3.3 Verify the VTY ACL is Working

Verify VTY ACL — show access-lists after test connections 
! After PC1 (permitted) connects and PC2 (denied) attempts:
R1# show access-lists
Standard IP access list ADMIN-HOST
    10 permit 192.168.10.10  (2 matches)  ← PC1 connected successfully
    20 deny   any            (2 matches)  ← PC2 was denied

! Console shows login event for authorized user:
%SEC_LOGIN-5-LOGIN_SUCCESS: Login Success [user: ADMIN] [Source: 192.168.10.10]
5.4Configure Extended IPv4 ACLs▾

5.4.2 Numbered Extended IPv4 ACL Syntax

Extended ACL syntax — full parameter set
Router(config)# access-list number {deny|permit|remark} protocol source source-wildcard [operator [port]] destination destination-wildcard [operator [port]] [established] [log]

! Remove numbered extended ACL:
Router(config)# no access-list number
! Remove named extended ACL:
Router(config)# no ip access-list extended name
ParameterDescription
numberExtended ACL range: 100–199 or 2000–2699
protocolip (all IP), tcp, udp, icmp, or protocol number (1=ICMP, 6=TCP, 17=UDP)
source source-wildcardSource address with wildcard mask. Use any or host ip
operatoreq (equal) · neq (not equal) · lt (less than) · gt (greater than) · range
portPort number 0–65535 or keyword (www=80, ftp=21, telnet=23, smtp=25, domain=53)
destination destination-wildcardDestination address with wildcard mask
establishedTCP only — matches packets with ACK or RST flag set (returning traffic from established connection)
logOptional — logs matched packets; use for troubleshooting only
💡
Extended ACL order is PRESERVED exactly as entered. Unlike standard ACLs which apply a hashing function to host entries, extended ACLs display and process entries in exactly the order they were configured. Use sequence numbers to insert entries at specific positions.

5.4.5 Numbered Extended ACL — HTTP/HTTPS Example

Policy: Permit HTTP and HTTPS from 192.168.10.0/24 to any destination. Applied inbound on G0/0/0 (close to source).

Extended ACL 110 — permit web traffic outbound 
R1(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq www
R1(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq 443
R1(config)# interface g0/0/0
R1(config-if)# ip access-group 110 in
R1(config-if)# exit

5.4.6 TCP established Keyword — Basic Stateful Firewall

The established keyword matches TCP packets that have the ACK or RST flag set — these are return packets from an existing TCP connection. Initial SYN packets from external hosts have no ACK flag — they are blocked.

🔒 How TCP established Creates a One-Way Firewall
OUTBOUND
Inside host (192.168.10.x) sends TCP SYN to web server on internet → ACL 110 inbound on G0/0/0 permits it (matches source network + port 80/443)
ALLOW
Web server sends TCP SYN-ACK reply back → ACK flag IS set → established keyword matches → ACL 120 outbound on G0/0/0 permits it
BLOCK
External host tries to initiate NEW connection to inside host → sends TCP SYN with NO ACK flag → established does NOT match → packet dropped by implicit deny
ACL 110 (outbound) + ACL 120 (return only) — established pair 
! ACL 110 inbound — permits inside hosts to initiate outbound web connections:
R1(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq www
R1(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq 443

! ACL 120 outbound — permits ONLY returning traffic (ACK or RST flag must be set):
R1(config)# access-list 120 permit tcp any 192.168.10.0 0.0.0.255 established

R1(config)# interface g0/0/0
R1(config-if)# ip access-group 110 in
R1(config-if)# ip access-group 120 out
R1(config-if)# end

R1# show access-lists
Extended IP access list 110
    10 permit tcp 192.168.10.0 0.0.0.255 any eq www
    20 permit tcp 192.168.10.0 0.0.0.255 any eq 443 (657 matches)
Extended IP access list 120
    10 permit tcp any 192.168.10.0 0.0.0.255 established (1166 matches)
⚠️
established only works with TCP — NOT UDP or ICMP. UDP and ICMP have no ACK/RST flags, so the established keyword cannot be applied to them. For UDP return traffic, other methods (like an outbound permit for returning UDP) are needed.

5.4.8 Named Extended ACL — SURFING / BROWSING Example

Same policy as 5.4.6 but using named extended ACLs:

Named extended ACLs SURFING (inbound) and BROWSING (outbound) 
R1(config)# ip access-list extended SURFING
R1(config-ext-nacl)# Remark Permits inside HTTP and HTTPS traffic
R1(config-ext-nacl)# permit tcp 192.168.10.0 0.0.0.255 any eq 80
R1(config-ext-nacl)# permit tcp 192.168.10.0 0.0.0.255 any eq 443
R1(config-ext-nacl)# exit

R1(config)# ip access-list extended BROWSING
R1(config-ext-nacl)# Remark Only permit returning HTTP and HTTPS traffic
R1(config-ext-nacl)# permit tcp any 192.168.10.0 0.0.0.255 established
R1(config-ext-nacl)# exit

R1(config)# interface g0/0/0
R1(config-if)# ip access-group SURFING in
R1(config-if)# ip access-group BROWSING out
R1(config-if)# end

5.4.9 Edit Extended ACLs — Sequence Numbers

Extended ACLs use the same sequence number editing method as standard ACLs. Unlike standard ACLs, extended ACLs do NOT reorder entries — the order displayed is the order processed.

Fix wrong ACE in extended ACL using sequence numbers 
! Problem — ACE 10 has wrong source address (19 instead of 192):
R1# show access-lists
Extended IP access list SURFING
    10 permit tcp 19.168.10.0 0.0.0.255 any eq www   ← WRONG
    20 permit tcp 192.168.10.0 0.0.0.255 any eq 443

! Fix using sequence numbers:
R1(config)# ip access-list extended SURFING
R1(config-ext-nacl)# no 10
R1(config-ext-nacl)# 10 permit tcp 192.168.10.0 0.0.0.255 any eq www
R1(config-ext-nacl)# end

! Verify:
R1# show access-lists
Extended IP access list SURFING
    10 permit tcp 192.168.10.0 0.0.0.255 any eq www   ← CORRECT
    20 permit tcp 192.168.10.0 0.0.0.255 any eq 443

5.4.10 PERMIT-PC1 / REPLY-PC1 — Multi-Port Example

Policy: PC1 (192.168.10.10) only may use FTP, SSH, Telnet, DNS, HTTP, HTTPS. All other hosts in 192.168.10.0/24 are denied. Return traffic to PC1 is permitted.

PERMIT-PC1 (inbound) and REPLY-PC1 (outbound) on G0/0/0 
R1(config)# ip access-list extended PERMIT-PC1
R1(config-ext-nacl)# Remark Permit PC1 TCP access to internet
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 20    ! FTP data
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 21    ! FTP control
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 22    ! SSH
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 23    ! Telnet
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 53    ! DNS
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 80    ! HTTP
R1(config-ext-nacl)# permit tcp host 192.168.10.10 any eq 443   ! HTTPS
R1(config-ext-nacl)# deny ip 192.168.10.0 0.0.0.255 any         ! deny all other .10 hosts
R1(config-ext-nacl)# exit

R1(config)# ip access-list extended REPLY-PC1
R1(config-ext-nacl)# Remark Only permit returning traffic to PC1
R1(config-ext-nacl)# permit tcp any host 192.168.10.10 established
R1(config-ext-nacl)# exit

R1(config)# interface g0/0/0
R1(config-if)# ip access-group PERMIT-PC1 in
R1(config-if)# ip access-group REPLY-PC1 out
R1(config-if)# end
✅
Note how IOS converts port numbers to keywords in show access-lists output — eq 21 displays as eq ftp, eq 80 displays as eq www. SSH (22) and HTTPS (443) have no keywords so they display as numbers. This is display-only — functionally identical.

5.4.11 Verify Extended ACLs

show access-lists
All ACLs with match statistics. Shows sequence numbers. Does NOT show remarks. IOS displays port keywords where available.
show run | begin ip access-list
Full ACL config from first ACL entry. Shows remarks. Does NOT show sequence numbers or match statistics.
show ip int [intf] | include access list
Which ACL is applied to an interface and in which direction. Quick single-line answer.
Verification command examples — extended ACLs 
! Show all ACLs with statistics:
R1# show access-lists
Extended IP access list PERMIT-PC1
    10 permit tcp host 192.168.10.10 any eq 20
    20 permit tcp host 192.168.10.10 any eq ftp       ← IOS shows keyword (eq 21 → ftp)
    30 permit tcp host 192.168.10.10 any eq 22
    40 permit tcp host 192.168.10.10 any eq telnet
    50 permit tcp host 192.168.10.10 any eq domain
    60 permit tcp host 192.168.10.10 any eq www
    70 permit tcp host 192.168.10.10 any eq 443        ← no keyword for 443
    80 deny ip 192.168.10.0 0.0.0.255 any
Extended IP access list REPLY-PC1
    10 permit tcp any host 192.168.10.10 established

! Show which ACL applied to interface (filter for speed):
R1# show ip interface g0/0/0 | include access list
  Outgoing access list is REPLY-PC1
  Inbound  access list is PERMIT-PC1

! Show full config with remarks:
R1# show running-config | begin ip access-list

Extended ACL Commands

Extended ACL — all commands

access-list {100-199|2000-2699} {permit|deny|remark} protocol src src-wc [op port] dst dst-wc [op port] [established] [log]

! Create named extended ACL:
ip access-list extended NAME
  [seq] {permit|deny|remark} protocol src src-wc [op port] dst dst-wc [op port] [established]

! Remove named extended ACL:
no ip access-list extended NAME

! Apply to interface (same as standard):
ip access-group {number|NAME} {in|out}

VTY Security Command

VTY ACL — access-class (NOT ip access-group) 
line vty 0 4
  access-class {number|NAME} {in|out}    ← access-class, not ip access-group!

Modification Commands

Edit ACE by sequence number 
! Enter edit mode (works for both numbered and named):
ip access-list standard {number|NAME}
ip access-list extended {number|NAME}

! Inside edit mode:
no {sequence-number}                    ! Delete ACE by sequence number
{sequence-number} {permit|deny} ...     ! Add ACE at specific position

Verification Commands

All ACL verification commands 
show access-lists                              ! All ACLs — sequences + statistics (no remarks)
show access-lists {number|NAME}                ! One specific ACL
show ip interface {intf} | include access list ! Which ACL on interface + direction
show run | section access-list                 ! Numbered ACL config + remarks (no sequences)
show run | section ip access-list              ! Named ACL config + remarks (no sequences)

🎯Common Exam Traps — Module 5▾
❌
Trap 1: VTY lines use access-class — NOT ip access-group.
This is the single most tested distinction in Module 5. Interface ACLs use ip access-group in (config-if)# mode. VTY ACLs use access-class in (config-line)# mode. Using ip access-group on a VTY line is wrong syntax. Know both commands cold.
❌
Trap 2: Apply VTY ACL to ALL lines (0 4) in the INBOUND direction.
Users can attempt to connect to any VTY line. If only some lines are protected, an attacker connects to an unprotected one. The in direction filters who can connect TO the router. Apply identically to all VTY lines.
❌
Trap 3: show access-lists shows sequences and statistics — NOT remarks.
Remarks are only visible in show running-config. If the exam asks "which command shows remark statements," the answer is show running-config. If it asks "which command shows match statistics," the answer is show access-lists.
❌
Trap 4: show running-config shows remarks — NOT sequence numbers or statistics.
These two commands are complementary: show access-lists = sequences + match counters. show run = remarks + wildcard notation. Neither alone gives the full picture.
❌
Trap 5: SSH (22) and HTTPS (443) have no IOS port keyword — must use numbers.
eq 22 for SSH, eq 443 for HTTPS. There is no eq ssh or eq https in IOS. Students who try to type these will fail. Know which ports DO have keywords: www=80, ftp=21, telnet=23, smtp=25, domain=53.
❌
Trap 6: Delete the old ACL BEFORE pasting corrected version (text editor method).
Pasting corrected ACL commands without first removing the original appends them to the end — creating a combined, broken ACL. Always: no access-list number first, then paste the corrected version.
⚠️
Trap 7: established matches TCP ACK or RST flags — blocks new external TCP connections.
Initial SYN from external host has no ACK → blocked. Return SYN-ACK from server has ACK → permitted. This creates a basic one-way firewall for TCP. Does NOT work for UDP or ICMP (no ACK/RST flags in those protocols).
⚠️
Trap 8: Standard ACL hashing reorders host entries — extended ACL order is preserved.
In standard ACLs, IOS applies a hashing function that moves host-specific entries before range entries in show access-lists output. Extended ACLs always display exactly as entered. Don't be surprised when sequence 15 appears before sequence 10 in a standard ACL.
⚠️
Trap 9: deny ip any any vs deny any — syntax differs between standard and extended.
Standard ACL: deny any (source-only; "any" means any source). Extended ACL: deny ip any any (protocol required; "any any" means any source to any destination). Using deny any in an extended ACL is a syntax error.
⚠️
Trap 10: Removing ACL from interface doesn't delete the ACL from the router.
no ip access-group 10 out removes the binding from the interface but the ACL still exists. no access-list 10 deletes the ACL entirely. Two separate operations.
⚠️
Trap 11: IOS shows port keywords in show access-lists even if you entered numbers.
If you configure eq 80, show output displays eq www. If you configure eq 21, output shows eq ftp. This is display-only — the ACL functions identically. For SSH (22) and HTTPS (443), IOS shows the number since no keyword exists.
⚠️
Trap 12: Explicit deny any at end for statistics — implicit deny is invisible.
The implicit deny any at the end of every ACL does NOT increment a counter and is NOT visible in show access-lists. To track how many packets were dropped, add an explicit deny any as the last ACE — it will show match statistics.
✅
Module 5 quick-reference summary — all key commands:

Standard numbered: access-list {1-99|1300-1999} {permit|deny} source [wc]
Standard named: ip access-list standard NAME → then ACEs
Extended numbered: access-list {100-199|2000-2699} {permit|deny} proto src swc [op port] dst dwc [op port] [established]
Extended named: ip access-list extended NAME → then ACEs
Apply to interface: ip access-group {num|NAME} {in|out}
Apply to VTY: access-class {num|NAME} in ← NOT ip access-group!
Edit ACE: ip access-list std|ext {num|NAME} → no {seq} → {seq} permit|deny ...
Verify (sequences+stats): show access-lists
Verify (remarks): show run | section access-list
Verify (interface): show ip int [intf] | include access list
Clear stats: clear access-list counters [name]
Port keywords: www=80 · ftp=21 · telnet=23 · smtp=25 · domain=53 · SSH=no kw=22 · HTTPS=no kw=443
