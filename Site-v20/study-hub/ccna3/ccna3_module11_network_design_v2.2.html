11.1Hierarchical Networks▾

11.1.2 The Need to Scale the Network

All enterprise networks must be able to:

  • Support critical applications — mission-critical services with high availability
  • Support converged network traffic — data files, email, IP telephony, and video on one network
  • Support diverse business needs — multiple departments, branch offices, remote workers
  • Provide centralized administrative control — manage from one location or NMS
💡
A campus network interconnects a group of LANs spread over a small geographic area — from a single floor using one switch to large multi-building networks with thousands of connections. As businesses grow, the network must scale without losing availability or performance.

11.1.3 Cisco Borderless Switched Network

The Cisco Borderless Network architecture connects anyone, anywhere, anytime, on any device — securely, reliably, and seamlessly. It:

  • Unifies wired and wireless access under one framework
  • Provides policy, access control, and performance management across diverse devices
  • Built on a hierarchical, scalable, and resilient hardware infrastructure
  • Delivers two primary service sets: network services + user and endpoint services

11.1.4 Four Hierarchical Design Principles

🏛️
Hierarchical

Each device has a clear role at every tier. Simplifies deployment, operation, and management. Reduces fault domains at each tier.

🧩
Modularity

Allows seamless network expansion and on-demand integrated service enablement. Layers can be added, upgraded, or modified independently.

🔄
Resiliency

Satisfies user expectations for keeping the network always on. Designed for minimal downtime through redundancy and failover.

⚡
Flexibility

Allows intelligent traffic load sharing using all available network resources. Supports changing business requirements.

11.1.5 Access, Distribution, and Core Layer Functions

Top Layer
🔴 Core Layer — The Backbone
  • Aggregates all distribution layer devices
  • Ties the campus together with the rest of the network
  • Primary purpose: fault isolation and high-speed backbone connectivity
  • Focus: speed and reliability — NOT policy enforcement or QoS
  • Design for fast convergence and minimal downtime
  • Failures here have the largest impact → invest in highest reliability equipment
Middle Layer
🔵 Distribution Layer — Aggregation and Policy
  • Interfaces between the access and core layers
  • Aggregates large-scale wiring closet networks
  • Aggregates Layer 2 broadcast domains and Layer 3 routing boundaries
  • Provides intelligent switching, routing, and network access policy
  • Provides high availability through redundant distribution switches
  • Provides equal cost paths to the core
  • Provides differentiated services (QoS) to different traffic classes
  • Best place to limit failure domain size
Bottom Layer
🟢 Access Layer — The Network Edge
  • Represents the network edge — where traffic enters or exits the campus
  • Primary function: provide network access to end users and devices
  • Connects to distribution layer switches
  • Modern access switches: PoE for IP phones and APs, QoS marking, wireless integration
  • Building intelligence into access switches improves application efficiency and security

11.1.6 Three-Tier vs Two-Tier Design

🏢 Three-Tier Model
  • Access, Distribution, and Core are physically separate layers
  • Used for large campus environments
  • Recommended physical topology: extended star from a centralized building to all others
  • Provides maximum scalability, flexibility, and fault isolation
  • More expensive to implement and manage
🏠 Two-Tier (Collapsed Core)
  • Distribution and Core combined into one layer
  • Used for smaller campuses, single buildings, or limited scalability needs
  • Also called: collapsed core network design
  • Lower cost; fewer devices to manage
  • Not a compromise — correct design for the environment
🎯 EXAM KEY — THREE-TIER TOPOLOGY RECOMMENDATION
For a three-tier campus design, build an extended star from a centralized site to all other campus buildings.
This is recommended for efficiency, scalability, and cost-effectiveness.
A full mesh is much more expensive. Bus and dual ring are harder to troubleshoot.
11.2Scalable Networks▾

11.2.1 Design for Scalability — Key Recommendations

  1. Use expandable, modular equipment or clustered devices — add modules to existing hardware; cluster devices to act as one for simpler management
  2. Design a hierarchical network with independent modules — each layer can expand without affecting others (e.g., add access switches without changing distribution/core)
  3. Create a hierarchical IP address strategy (IPv4 and IPv6) — careful address planning avoids re-addressing when users and services are added
  4. Use routers or multilayer switches to limit broadcasts — filter undesirable traffic; use Layer 3 to reduce traffic reaching the core
Redundant Links
Implement between critical devices and between access and core layers. Prevents single points of failure.
EtherChannel
Aggregate multiple links into one logical link for increased bandwidth. Uses existing ports — no expensive upgrades.
Scalable Routing Protocol
Use features to isolate routing updates and minimize routing table size. OSPF is well-suited for large hierarchical networks.
Wireless Connectivity
Extends access layer for mobility. Consider device types, coverage, interference, and security.

11.2.2 Plan for Redundancy

Two methods of implementing redundancy:

  • Duplicate equipment — failover services for critical devices
  • Redundant paths — alternate physical paths for data to traverse the network
⚠️
Redundant paths in switched networks create Layer 2 loops. STP (Spanning Tree Protocol) eliminates loops by blocking redundant paths logically — re-enabling them only when a failure occurs. STP is open standard and required in any redundant Layer 2 design.
✅
Alternative to STP: use Layer 3 in the backbone. Layer 3 routing provides redundancy without needing STP — it naturally selects the best path and converges faster on failure. Layer 3 also provides broadcast containment.

11.2.3 Reduce Failure Domain Size

A failure domain = the area of a network impacted when a critical device or service fails.

  • Smaller failure domains reduce impact on productivity and simplify troubleshooting
  • Core layer failures = large impact → focus redundancy investment here but keep design simple
  • Distribution layer = easiest and least expensive place to control failure domain size
💡
Switch block deployment: Routers or multilayer switches deployed in pairs, with access layer switches evenly divided between them. Each switch block acts independently. Failure of one entire switch block does not bring down users on other switch blocks — only those connected to that block are affected.

11.2.4 Increase Bandwidth — EtherChannel

EtherChannel aggregates multiple physical Ethernet links into one logical link:

  • Uses existing switch ports — no need to upgrade to faster, more expensive interfaces
  • Configuration done on the EtherChannel interface (not individual ports) — ensures consistency
  • Provides load balancing across member links
  • Prevents uplink bottlenecks where multiple access links converge onto one distribution uplink
  • Budget-friendly alternative when fiber runs or new interfaces are too expensive

11.2.5 Expand the Access Layer — Wireless

Wireless extends access layer connectivity to mobile users and areas without cable infrastructure:

  • End devices require: wireless NIC (radio transmitter/receiver + driver)
  • Infrastructure requires: wireless router or AP
  • Key considerations: device types, coverage requirements, interference, security
  • Benefits: increased flexibility, reduced costs, adaptable to changing needs

11.2.6 Tune Routing Protocols — OSPF

OSPF (Open Shortest Path First) is a link-state routing protocol well-suited for large hierarchical networks:

  • Routers establish and maintain neighbor adjacencies with connected OSPF routers
  • Routers synchronize their link-state database to build a complete topology map
  • When a change occurs, link-state updates propagate → all routers recalculate best path
  • Fast convergence — well-suited for large hierarchical networks
  • Scales efficiently in hierarchical designs using areas to limit update flooding
11.3Switch Hardware▾

11.3.1 Switch Platform Categories

Campus LAN
Core, distribution, access, and compact switches for enterprise LANs. Cisco 2960, 3560, 3650, 3850, 4500, 6500, 6800 Series. Vary from 8-port fanless to 13-blade chassis with hundreds of ports.
Cloud-Managed
Virtual stacking — configure and monitor thousands of switch ports via web without onsite IT staff. Example: Cisco Meraki.
Data Center
Promotes infrastructure scalability, operational continuity, and transport flexibility for data center environments. Example: Cisco Nexus Series.
Service Provider
Two types: aggregation switches (carrier-grade, edge of network) and Ethernet access switches (application intelligence, unified services, virtualization).
Virtual Networking
Secure multi-tenant services with virtualization intelligence for data center networks. Example: Cisco Nexus virtual networking.

11.3.2 Switch Form Factors

Fixed Configuration
Features and ports are preset at purchase — cannot be changed. Examples: Cisco 2960, 3560. Suitable for access layer. Thickness typically expressed in rack units (1U = 1.75 inches).
Modular Configuration
Chassis accepts field-replaceable line cards — highly flexible. Add or replace interface modules as needs change. Example: Cisco Catalyst 9400 (up to 384 switchport interfaces).
Stackable Configuration
Special cables connect multiple switches so they appear and operate as one large logical switch. Simplifies management — one IP, one config for the entire stack.

11.3.3 Port Density

Port density = number of ports available on a single switch.

  • Fixed switches: typically 12, 24, or 48 ports (e.g., Cisco Catalyst 3850 in 12/24/48-port configs)
  • Modular switches: very high density (e.g., Catalyst 9400 supports up to 384 switchport interfaces)
  • High-density modular switches save rack space and power vs many fixed switches
  • Uplink bottleneck concern: Fixed switches consume additional ports for inter-switch aggregation; modular switches use the chassis backplane instead — not consuming user ports

11.3.4 Forwarding Rates and Wire Speed

Forwarding rate = how much data the switch can process per second (processing capability).

Wire speed = the maximum data rate each port can achieve (100 Mbps, 1 Gbps, 10 Gbps, 100 Gbps).

📊 Forwarding Rate by Layer — Design Principle
Access Layer
Can use lower forwarding rates — access switches are physically limited by their uplinks to distribution. Less expensive switches acceptable here.
Distribution Layer
Higher forwarding rates needed — all access layer traffic converges here. Performance at distribution directly impacts all users on attached access switches.
Core Layer
Highest forwarding rates required — all campus traffic passes through the core. Forwarding rate has greatest network performance impact at this layer.
💡
Example: A 48-port gigabit switch at full wire speed generates 48 Gbps of traffic. If the switch only supports a 32 Gbps forwarding rate, it cannot run all ports at full speed simultaneously. At the access layer, this is usually acceptable because the uplinks are the actual bottleneck.

11.3.5 Power over Ethernet (PoE)

  • Delivers electrical power to a device over existing Ethernet cabling — no separate power outlet needed
  • Use cases: IP phones, wireless access points — can be placed anywhere there's an Ethernet cable
  • PoE switches cost more — verify PoE is actually required before purchasing
  • Cisco Catalyst 2960-C and 3560-C — support PoE pass-through: power connected PoE devices AND the switch itself from an upstream PoE port
  • Chassis-based switches may support redundant power supplies for higher availability

11.3.6 Multilayer Switching

  • Deployed at distribution and core layers
  • Can: build routing tables, support routing protocols, forward IP packets near Layer 2 speed
  • Use ASICs (Application-Specific Integrated Circuits) for hardware-accelerated IP forwarding independent of the CPU
  • Industry trend: pure Layer 3 switched environment — all switches will eventually incorporate routing
  • Cisco Catalyst 2960 with IOS 15.x: supports multiple active SVIs (previously only one SVI was active) — can be remotely managed via multiple IPs on distinct networks

11.3.7 Business Considerations for Switch Selection

ConsiderationDescription
CostDepends on interface count and speed, supported features, and expansion capability
Port densityMust support the required number of network devices both now and in the future
Power (PoE)IP phones, APs, and compact switches all may require PoE; chassis switches may need redundant power
ReliabilityProvides continuous network access; enterprise switches offer higher MTBF than entry-level

11.4Router Hardware▾

11.4.1 Router Functions

Routers use the network prefix of the destination IP address to route packets. All hosts specify the router interface as their default gateway.

Additional router functions:

  • Broadcast containment — limits broadcasts to the local network (unlike switches, which forward broadcasts to all ports)
  • Interconnect geographically separated locations — WAN connectivity between sites
  • Group users logically — by application or department, regardless of physical location
  • Enhanced security — filter traffic using ACLs
  • Protocol translation — accept Ethernet packets, re-encapsulate for serial WAN, etc.
  • Select alternate paths — reroute traffic automatically when a link fails

11.4.2 Cisco Router Categories

Branch Routers
Cisco ISR 4000 Series

Optimize branch services on a single platform — WAN connectivity, security, switching all in one. Designed for 24×7×365 uptime. Fast recovery from faults with minimal service impact. Maximizes availability at the branch.

Network Edge Routers
Cisco ASR 9000 Series

High-performance, highly secure services uniting campus, data center, and branch networks. Enhanced QoS, video, and mobile capabilities. Deliver content anytime, anyplace, over any device.

Service Provider Routers
Cisco NCS 6000 Series

End-to-end scalable solutions with subscriber-aware services. Simplify and enhance service-delivery networks. Help operators optimize operations, reduce expenses, and improve scalability for next-generation internet experiences.

Industrial Routers
Cisco 1100 Series Industrial ISR

Enterprise-class features in rugged, harsh environments. Compact, modular, ruggedized design for mission-critical industrial applications. Temperature extremes, vibration, and dust resistant.

🎯Common Exam Traps — Module 11▾
❌
Trap 1: Know what each layer does — Access, Distribution, Core.
Access = user edge (provides network access, PoE, wireless). Distribution = aggregation + routing + policy (broadcast domain boundaries, QoS, redundant uplinks). Core = high-speed backbone (fault isolation, speed — no policy). Exam questions describe a function and ask which layer performs it.
❌
Trap 2: Three-tier campus topology = extended star, NOT mesh.
Building an extended star from a centralized site to all other campus buildings is recommended for efficiency, scalability, and cost-effectiveness. A full mesh topology is much more expensive. Bus and dual ring are harder to troubleshoot and maintain.
❌
Trap 3: Two-tier model = collapsed core — Distribution and Core combined.
Not a "downgraded" design — it's the correct architecture for smaller environments (single building, fewer users, limited scalability needed). The term "collapsed core" identifies this design on the exam.
❌
Trap 4: Redundant paths in Layer 2 networks require STP.
Redundant physical links between switches create Layer 2 loops. STP eliminates loops by blocking redundant paths until needed. Alternatively, use Layer 3 in the backbone — routing naturally eliminates Layer 2 loops and provides faster convergence.
❌
Trap 5: Distribution layer = best place to control failure domain size.
Core failures impact everyone. Access failures impact only one segment. Distribution limits failures to a switch block — affecting only users connected to that block. The distribution layer is the most cost-effective place to invest in failure domain management.
⚠️
Trap 6: EtherChannel — configure on the EtherChannel interface, NOT individual ports.
EtherChannel creates one logical link from multiple physical links. Configuration consistency is maintained by configuring the bundle interface. Most settings on individual ports just need to match (speed, duplex, VLAN) for the bundle to form.
⚠️
Trap 7: Access layer switches don't need full wire-speed forwarding rate.
Access switches are physically limited by their uplinks to distribution. Their forwarding rate doesn't need to match the sum of all access port speeds. Distribution and core switches need higher forwarding rates because all traffic converges there.
⚠️
Trap 8: PoE pass-through = Catalyst 2960-C and 3560-C only.
These compact switches can be powered by an upstream PoE port AND simultaneously supply PoE to connected devices. Not all PoE switches support pass-through. Standard PoE switches require their own separate power supply.
⚠️
Trap 9: Multilayer switches route AND switch — deployed at distribution and core.
Multilayer switches (Layer 3 switches) can build routing tables, run routing protocols, and forward IP packets at near-Layer 2 speeds using ASICs. They are NOT just switches — they perform both Layer 2 switching and Layer 3 routing. Do not deploy at the access layer (unless required for specific applications).
⚠️
Trap 10: Know the Cisco router categories and their series numbers.
Branch = ISR 4000 (optimize branch, 24×7 uptime). Edge = ASR 9000 (high-performance, campus+DC+branch). Service Provider = NCS 6000 (subscriber-aware, scalable). Industrial = 1100 Industrial ISR (rugged environments). These appear in classification questions on the exam.
⚠️
Trap 11: Cisco Meraki = cloud-managed switches. Cisco Nexus = data center switches.
Campus LAN switches (2960, 3560, 3850 etc.) are the most commonly tested. Meraki is unique for cloud management without onsite IT. Nexus is specific to data center environments. Virtual networking (Nexus virtual) = multi-tenant services.
⚠️
Trap 12: Cisco Catalyst 2960 with IOS 15.x supports multiple active SVIs.
Before IOS 15.x, the 2960 only supported one active SVI. With IOS 15.x, multiple SVIs are active — allowing the switch to be managed via multiple IP addresses on different VLANs. This is part of the trend toward a pure Layer 3 switched environment.
⚠️
Trap 13: Four design principles — Hierarchical, Modular, Resiliency, Flexibility.
All four together define the Cisco Borderless Switched Network design principles. Don't confuse the "Hierarchical" principle (all four together create hierarchy) with the three-tier hierarchy model (which is just the physical structure). They are related but different concepts.
✅
